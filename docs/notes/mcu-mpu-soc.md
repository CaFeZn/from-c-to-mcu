# MCU、MPU 与 SoC 的区别

同样写着“Arm”，一块 STM32F407 板能很快开始采样、控制电机，另一块 STM32MP157 板却要准备 DDR、启动介质和系统镜像。有人说后者是 MPU，所以“比 MCU 高一级”；还有人说它是 SoC，仿佛又高了一级。可 F407 已经把 CPU、存储器和外设集成到同一颗芯片，难道这不算一个系统？

先别背缩写。假设你负责两个产品，把要求写成数字，再去查两份数据手册。选型结果应当能回答“哪里够、哪里不够、还欠什么验证”，而不是只给芯片贴标签。

## 案例一：采集终端真的需要大系统吗

给定任务如下，预算是练习输入，不是某个现成固件的实测值：

- 8 路模拟量，每路每秒记录 2000 个样本；每个样本按 16 位、2 字节存储。
- RAM 保留最近 0.5 秒的数据，DMA 循环写入，分成两个半区轮流处理。
- 另有 48 KiB 静态数据预算、16 KiB 栈及余量；程序和只读数据的 Flash 预算为 180 KiB。
- 每 1 ms 完成一次控制计算，输出 PWM；无 Linux 软件依赖，不外接 RAM。这里 `1 KiB = 1024` 字节。

**先算后查。** 环形缓冲区需要 `8 × 2000 × 0.5 × 2 = 16000` 字节，每半区 8000 字节。总 RAM 预算为 `16000 + 48 × 1024 + 16 × 1024 = 81536` 字节，约 79.6 KiB。12 位 ADC 的结果装进 16 位槽位时，不能按 1.5 字节计算，除非你另外实现了压缩。

接着打开文末的 DS8626，按下面路线做一次纸面验收：

1. 在器件表中选 **STM32F407xG**，核对它的 1 MiB Flash，而不是把整个系列的“最高容量”套给所有型号。
2. 找 3.6 节及总线框图，记录 192 KiB SRAM 中含 **64 KiB CCM 数据 RAM**，普通 SRAM1、SRAM2 合计 128 KiB。另列的 4 KiB 备份 SRAM，不加入本例 DMA 缓冲区预算。
3. 在 RM0090 的存储器与总线章节追 DMA 的连接：F407 的 DMA 不能访问 CCM。暂把全部 81536 字节安排到普通 SRAM，仍有 49536 字节账面余量。
4. 查引脚表与复用表：所选封装是否同时引出需要的 ADC 通道、PWM 和调试引脚？“芯片有这些外设”不等于板上都能用。

预期判定是：**F407xG 通过了这一轮容量初筛**，180 KiB 也小于 1 MiB。尚不能签字说产品可用：要检查链接映射中的实际段位置、DMA 缓冲区地址，并在最坏中断负载下测控制周期和采样吞吐。1 ms 是截止期限，不是 Cortex-M4 名称自动附送的保证。

这一步还揭示了一个常见错误：“还剩 64 KiB”不一定意味着“DMA 还有 64 KiB 可用”。容量、可达性、连续性是三件事；即使两个 RAM 区域能被同一个 CPU 访问，也不能随意拼成一块连续数组。

## 案例二：加一块屏幕，要不要换平台

现在需求改了：必须复用已有 Linux 图形和网络程序，应用运行工作集预计 128 MiB，显示为 800 × 480、RGB565，并采用双帧缓冲。先只算两张图：

```text
每像素 = 16 bit = 2 字节
双帧缓冲 = 800 × 480 × 2 × 2
           = 1536000 字节，约 1.46 MiB
```

这一项就超过 F407 的片内 RAM；整个工作集更不在同一量级。提高主频、换优化选项都不会凭空增加存储空间。F407 还能驱动带自身显存的小屏，也可以采用局部刷新，但那是在**改变需求与实现方案**，不是原方案已经通过。

换查 STM32MP157C/F 的 DS12505。首页、图 1、3.1～3.5 节能找到双 Cortex-A7、一个 Cortex-M4、图形单元和外部 DDR 控制器。注意手册写的“支持最高 1 Gbyte 外部 DDR”是**控制器能力**，不是芯片里自带 1 GB RAM。购买开发板时，仍须核对实际焊接的 DDR 容量、启动存储和软件支持。

把候选方案具体化：选用配有 512 MiB DDR、启动存储及匹配 Linux 板级支持包的 STM32MP157C 板。它值得进入下一轮验证，但 512 MiB 不能全部算给应用；内核、图形栈、缓存及保留区都要占用。测峰值内存、显示带宽、启动时间和功耗之后，才能决定是否满足产品目标。**板级支持包（BSP）**是让操作系统认识具体板卡所需的驱动与配置等支持，不是换一颗同系列芯片就天然兼容。

若图形终端仍有严格的采样截止期限，可以考虑由 A7 运行 Linux、M4 承担实时控制。此时还新增了核间通信、共享内存和外设归属问题：两个核不能各自初始化同一个串口，就假定互不干扰。“多一个核”给了分工机会，不会替你完成系统设计。

## 现在给这些选择命名

**MCU（Microcontroller Unit，微控制器）**侧重控制用途和较完整的片上资源。F407 把 CPU、Flash、RAM、定时器、ADC、通信外设等放在一起，适合直接运行固件或 RTOS（实时操作系统）。它仍需要电源、必要的时钟与外围电路，“单片”不是整台产品只有一个元件。

**MPU（Microprocessor Unit，微处理器）**在这里是芯片类别名称。应用处理器路线常配合外部大容量 RAM，运行 Linux 等复杂系统。STM32MP157 中的 A7 带 MMU，便于操作系统实现虚拟地址映射和进程隔离；这是能力描述，不是说 MPU 必须运行 Linux，也不是所有叫 MPU 的历史产品都具有完全相同的结构。

**SoC（System on Chip，片上系统）**描述集成方式：把处理核、总线、存储接口以及多种功能模块整合到一颗芯片。它与前两者不是同一条分类轴。按广义集成含义，MCU 也可以视为一种 SoC；复杂应用处理器同样常被称为 SoC。厂商命名习惯会有差异，不宜拿它当严格互斥的三选一。

还要拆开一个同名缩写。F407 手册 3.3 节的 **MPU 是 Memory Protection Unit，内存保护单元**，负责按区域限制访问；它不把 F407 变成“微处理器类芯片”。MMU 是 Memory Management Unit，内存管理单元，常承担地址转换。内存保护、地址转换、芯片产品类别，不能因为几个字母相似就混为一谈。

## 不要拿标签代替验收

- **“MCU 不能跑操作系统”不成立。** RTOS 很常见；反过来，带 Linux 也不自动保证实时性。谈本课 F407 时，不要把它没有常规分页 MMU、资源有限的条件推广到所有 MCU 产品。
- **主频和核数不是充分条件。** DMA 是否可达、封装是否引出接口、启动时间与最低功耗，往往比频率更早淘汰一个候选。
- **“SoC 已经集成一切”不成立。** 外接 DDR、存储、电源管理或物理层芯片可能仍是必需的；比较成本应比较整板与开发维护成本。
- **两种路线不是终身绑定。** 资源足够时，不必为了一个小界面引入 Linux；已有成熟 Linux 依赖时，也别只为省芯片价把整套软件重写成裸机。先列硬约束，再讨论优化。

## 练习：总容量看似够，为什么仍要退回

保持案例一的采样格式，把每路采样率提高到每秒 20000 个，仍保存 0.5 秒。有人算出缓冲区小于 192 KiB，就说“F407 的 DMA 肯定装得下”。指出两处问题，再给出一个不立即换芯片的修改方向。另一位同学只是给原采集器加一块自带显存、通过 SPI 更新的小屏，是否因此必须改用 MPU？

<details><summary>展开答案与判定依据</summary>

新缓冲区为 `8 × 20000 × 0.5 × 2 = 160000` 字节。第一，它已超过 DMA 可访问的 128 KiB 普通 SRAM，不能拿 CCM 补齐；第二，加上原来的 64 KiB 其他 RAM 预算，总计 225536 字节，连 192 KiB 总账也超了。

可以缩短缓存窗口，例如减到 0.1 秒，缓冲区降为 32000 字节，总账成为 97536 字节，再检查 DMA、处理和发送速度能否跟上。也可边采边处理，但必须明确允许的数据丢失策略和最坏堵塞时间，不能靠“平均速度够”掩盖覆盖风险。

SPI 小屏并不直接迫使平台改变；先算刷新量和缓冲需求，检查它是否影响 1 ms 控制期限。真正推动第二个案例换路线的是 Linux 软件依赖和大内存等组合约束，而不是“有屏幕”三个字。

</details>
