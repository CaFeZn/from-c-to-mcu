# 参数求值顺序与未定义行为

> 前置：[函数与作用域](/lessons/1-4)。本篇先在电脑上实验，不需要开发板。

## 打印两次计数，为什么不能猜两个答案

调串口时，你想把当前计数和下一个计数一次打印出来，于是写了下面的语句。看起来只是把两个数交给函数，似乎最多交换一下左右位置。

```c
/* 反例：C99 中行为未定义，不要运行来寻找标准答案。 */
int i = 3;
printf("%d %d\n", i++, i++);
```

这里不能承诺打印 `3 4`，也不能把允许结果限定成 `3 4` 或 `4 3`。先把反例放在纸上，运行一份只依赖语言保证的程序，再解释它和普通的“没规定先后”差在哪里。

## 先预测，再运行五组检查

下面的完整程序不读取输入。初始值都写在代码里，先预测：两个不同变量的自增是否有冲突？拆开的两次 `i++` 是否确定？同一个变量出现两次，就一定出错吗？尤其留意 `j` 最终是几，以及除数为零时是否真的执行除法。

```c
#include <assert.h>
#include <stdio.h>

static int add(int a, int b)
{
    return a + b;
}

int main(void)
{
    int a = 4;
    int b = 7;
    int sum = add(a++, b++);
    assert(sum == 11 && a == 5 && b == 8);
    printf("independent: sum=%d a=%d b=%d\n", sum, a, b);

    int i = 3;
    int first = i++;
    int second = i++;
    assert(first == 3 && second == 4 && i == 5);
    printf("split: first=%d second=%d i=%d\n", first, second, i);

    int j = 0;
    int chain = (j++ == 0 && j++ == 1);
    int divisor = 0;
    int divided = (divisor != 0 && 12 / divisor > 1);
    assert(chain == 1 && j == 2 && divided == 0);
    printf("short: result=%d j=%d divided=%d\n", chain, j, divided);

    int k = 0;
    int chosen = (k++ == 0 ? k++ : 99);
    assert(chosen == 1 && k == 2);
    printf("conditional: chosen=%d k=%d\n", chosen, k);

    int marker = 0;
    int value = (marker++, marker + 10);
    assert(value == 11 && marker == 1);
    printf("comma: value=%d marker=%d\n", value, marker);
    return 0;
}
```

在仓库根目录执行下面两行命令，前提是 GCC 已加入 `PATH`。不定义 `NDEBUG`，让断言保持启用：

```sh
gcc -std=c99 -Wall -Wextra -Werror -pedantic-errors -O0 examples/notes/c-semantics/evaluation-order.c -o artifacts/course-completion/c-semantics/evaluation-order.exe
./artifacts/course-completion/c-semantics/evaluation-order.exe
```

固定输出应为：

```text
independent: sum=11 a=5 b=8
split: first=3 second=4 i=5
short: result=1 j=2 divided=0
conditional: chosen=1 k=2
comma: value=11 marker=1
```

把 `-O0` 改成 `-O2` 后重编译，仍应得到相同输出。本例故意不测“编译器先算哪个实参”，只检查无论采用哪种允许顺序都应成立的事实；两次测试一致也不能证明任意程序都没有未定义行为。

## 函数括号没有给参数排队

`add(a++, b++)` 中，两个实参分别修改两个独立对象，最终传入的值是 `4` 和 `7`。函数开始执行前，这些实参的求值及相关副作用已完成；但 C99 没有规定实参之间的求值次序。这叫**顺序未指定**：标准留下选择，并不是授权程序做任何事情。

开头的语句则在缺少必要顺序保证的地方修改了同一个 `i` 两次，越过了标准限制。这叫**未定义行为**，标准对这种执行不再提出要求，不能靠观察一个编译器的输出替它补上语义。`printf` 并不特殊，换成自己写的函数也一样。

还要把三件事拆开：优先级决定表达式怎样分组，结合性解决同级运算符的分组方向，求值顺序决定运行时先做什么。`f() + g() * h()` 要把乘积加到另一个值上，不等于先调用 `g`、再调用 `h`、最后调用 `f`。给每个调用额外套括号，也不会建立这种先后关系。参数传到哪个寄存器或栈位置，同样不是源码的求值规则。

## C99 用哪些位置分隔副作用

修改变量是副作用。C99 把一些保证先前副作用完成的位置称为**序列点**。N1256 的 6.5 第 2 段要求：相邻序列点之间，同一对象保存的值最多被修改一次；对其原值的读取还必须用于确定要存回的值。因此 `i = i + 1` 可以成立，`add(i++, i)` 中另一实参单独读取 `i` 却不能这样辩解。

函数实参全部求值之后、真正调用之前有序列点。关键是“全部之后”，不是“每两个实参之间”。`add(i++, i++)` 不能借用调用前的这一个点，把两次修改隔开。

安全程序里的边界可以逐个手算：

- 每个完整表达式结束时有序列点。`first` 和 `second` 的初始化分别完成，因此依次拿到 `3`、`4`，最后 `i` 为 `5`。这不是“换行”的功劳，换行本身不保证顺序。
- `&&` 先求左侧，在左侧之后有序列点，左侧为假就不求右侧。`j` 在第二次比较前已变为 `1`，所以两次比较都真，结果为 `1`，最终 `j` 为 `2`。除数检查为假，右侧除法根本没有执行。`||` 类似，但左侧为真就跳过右侧。
- `?:` 先求条件，在条件之后有序列点，再只求被选中的一支。条件自增把 `k` 变为 `1`，真分支取得旧值 `1`，并把 `k` 变为 `2`。
- 逗号**运算符**先完成左侧，再求右侧。因此 `(marker++, marker + 10)` 为 `11`。函数实参列表里的逗号只是分隔符，没有这个作用。

这些规则解释了为什么“同一行出现两次自增必错”也不准确。不过，业务代码没必要为了压缩一行，专门考验读者识别序列点的能力。

## 修复时先表达你要的时间关系

发现实参互相依赖，先问清要传旧值、新值，还是两个连续采样值。需要连续计数时，就像实验那样先分别保存 `first`、`second`，再调用函数。需要“先读取状态，再读取数据”时，也应把两次读取放到独立的完整表达式，再把结果交给后续函数。拆分不仅消除冲突，还给调试器留下可观察的中间值。

几个常见误区需要单独排除：

- 把 `i` 改成 `volatile`，或关闭优化，都不会使开头的未定义行为合法。资格限定符没有给函数实参增加序列点。
- 函数每个实参只求值一次，不等于实参按从左到右求值。改用 `static inline` 能解决宏重复求值，却不能挽救 `max_int(i++, i++)`。
- `&` 和 `|` 不是短路逻辑运算符。把除数检查中的 `&&` 改成 `&`，不能再保证跳过除零操作；这个改动只作纸面反例，不要运行。
- 编译器警告是线索，不是完整证明。宏展开、指针别名或跨函数的依赖可能使问题更难被诊断；“没有警告”和“运行一百次一致”都不是语言保证。

审查时还应按实际对象归组，而不只是数变量名。即使 `p` 和 `q` 都是有效指针，`add((*p)++, (*q)++)` 也不能凭名字就认定没有冲突：它们若指向同一个 `int`，问题仍然存在；指向不同对象时，还需保证自增不溢出。反过来，只读取同一对象两次而不修改，并不是本条规则禁止的冲突。先列出每个表达式读写谁，再找分隔访问的序列点，比背诵几个禁写形式可靠。

## 练习：判断，并保留真正意图

每小题单独开始，初值分别重新设置。先在纸上判断哪些表达式有定义，再计算结果；不要运行未定义行为反例。

1. `int i = 1; int r = (i++, i + 10);` 的 `r` 和 `i` 是多少？
2. `int i = 1; int r = i++ + i;` 能否用加法的左结合性确定结果？
3. 假设 `data` 是 `int` 数组，`pos` 为 `int`，且数组访问及随后自增均已做范围检查。要让 `emit(data[pos++], pos)` 发送“当前元素和它原来的下标”，应该怎样改写？`emit` 只接收两个值，不修改数组或 `pos`。

<details>
<summary>展开答案与推导</summary>

第一题的逗号是运算符，左侧自增在右侧求值前完成，所以 `r` 为 `12`，`i` 为 `2`。第二题没有所需序列点，一边修改 `i`，另一边读取它用于求和，行为未定义；结合性不能补救。

第三题既有未定义行为，也把“旧下标还是新下标”藏在实参里。假设 `pos` 为 `int`，且检查已经保证访问和随后自增都合法，可以改成下面的接口片段：

```c
int index = pos;
int value = data[index];
++pos;
emit(value, index);
```

先把旧下标命名，再取元素，最后推进游标。即使换优化级别，也不需要重新猜两个实参之间的顺序。

</details>

## 适用范围与依据

本文按 C99 的单线程表达式规则讨论，整数取值均很小，不涉及有符号溢出；不把这些顺序关系当成线程同步、CPU 屏障或外设完成保证。C11 使用 `sequenced before`、`unsequenced` 等关系描述相关限制，不能把 C++ 的实参规则移植过来解释本篇。

- [WG14 N1256，C99 合并 TC1–TC3 的委员会草案](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1256.pdf)：3.4.3–3.4.4 区分未定义与未指定；5.1.2.3、6.5 第 2–3 段、6.5.2.2 第 10 段规定副作用与调用次序；6.5.13–6.5.15、6.5.17、6.8 第 4 段及附录 C 给出上述边界。
- [WG14 N1570，C11 委员会草案](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：6.5 第 2–3 段、6.5.2.2 第 10 段，用于对照新版术语，而非冒充 C99 原文。
