# 晶振精度与时钟抖动

两块板的 LED 都按“每秒翻转”编程，刚通电时同步，一天后却已经错开几秒。再把一块板的 PWM 接到自己的输入捕获，频率又显示得漂亮极了。哪次测量错了？两次都可能忠实反映各自的比较对象：**同板自测容易量到分频比例，而不是外部世界的一秒。**

另一种现象更隐蔽：平均频率正好，示波器叠加的边沿却有宽度。平均快慢与单次边沿的摆动不是同一个指标。本篇用可算的样本把它们分开，再回到 [5.3 PWM 与输入捕获](/lessons/5-3) 的测量实验。

## 先把“快一点”换算成一天差多少

定义频率相对偏差：

```text
epsilon = (实际频率 - 标称频率) / 标称频率
ppm = epsilon × 1000000
固定频偏下的走时差 ≈ 实际经过时间 × epsilon
```

一个标称 32768 Hz、实际快 20 ppm 的源，实际频率为 `32768×1.000020=32768.65536 Hz`。用固定分频把它当作标准秒，日历一天约快 1.728 s，30 天约快 51.84 s。这里“快”表示相同真实时间内软件计数更多，不是把某次中断提前了整整 1.728 s。

如果甲板相对标准快 20 ppm，乙板慢 20 ppm，二者可相差约 40 ppm，即一天约 3.456 s。不能只看每块板的“20 ppm”就以为它们彼此最多差 20 ppm。正负方向未知时，最坏偏差预算要考虑相反的方向。

把 CPU 从 84 MHz 倍频到 168 MHz，并不会把晶体的 20 ppm 自动变成 10 ppm：理想倍频同时放大标称频率与实际频率，相对偏差不变。绝对赫兹差变大，比例没有变。PLL 自己还可能引入相位噪声；它不是天然的“精度净化器”。

## 跟做：两组周期，平均与摆动分开看

设理想周期 1000 ns，分别观察下面四个周期。它们是为了验证概念而构造的数字，不是 F407 的实测噪声规格。

| 样本组 | 四个周期/ns | 平均周期/ns | 相对该组均值的峰峰摆动 |
|---|---|---|---|
| A | 1001、1001、1001、1001 | 1001 | 0 ns |
| B | 998、1002、999、1001 | 1000 | 4 ns |

A 的样本没有观察到周期摆动，却整体慢了；其频率是 `1e9/1001≈999000.999 Hz`，相对 1 MHz 约 -999.001 ppm。注意“周期多 1000 ppm”和“频率少 1000 ppm”只在小偏差时近似互为负数，不是严格相等。

B 的平均周期正好，但相对均值的误差为 -2、+2、-1、+1 ns。若本实验定义总体 RMS 为 `sqrt((4+4+1+1)/4)`，得到约 1.581 ns。平均正确并不能推出每个周期都正确；而四个数字也不能确定真实噪声分布或极端概率。

用 C99 写一个最小计算，不把单位交给读者猜：

```c
#include <assert.h>
#include <math.h>
#include <stddef.h>
#include <stdio.h>

int main(void)
{
    const double period_ns[] = {998.0, 1002.0, 999.0, 1001.0};
    const size_t n = sizeof period_ns / sizeof period_ns[0];
    double sum = 0.0;
    for (size_t i = 0; i < n; ++i) {
        sum += period_ns[i];
    }
    const double mean = sum / (double)n;
    double squares = 0.0;
    for (size_t i = 0; i < n; ++i) {
        double error = period_ns[i] - mean;
        squares += error * error;
    }
    const double rms = sqrt(squares / (double)n);
    assert(mean == 1000.0);
    assert(fabs(rms - 1.58113883008419) < 1e-10);
    printf("mean=%.3f ns, rms=%.3f ns\n", mean, rms);
    return 0;
}
```

预期输出 `mean=1000.000 ns, rms=1.581 ns`。使用 GCC 时某些平台要在链接末尾加 `-lm`。这里计算的是相对样本均值的周期 RMS，不是频谱仪给出的某段带宽积分相位抖动，也不是“相邻两个周期之差”的 cycle-to-cycle 指标。报告时把定义、单位、样本数和观测带宽一起写明。

## 一次边沿测量里混进了什么

晶体偏差并不只来自标牌上的初始容差。温度变化、老化、负载电容偏离要求、PCB 寄生与电源噪声都可能改变表现；实际幅度应查所选晶体和振荡器电路的数据，不能替任意 32.768 kHz 晶体承诺一个统一的 ppm。

测量链也有自己的误差。逻辑分析仪以有限采样时钟量边沿，量化台阶会被看成抖动；输入阈值和上升时间使电压噪声转成时间误差；探头、接地线和带宽会影响显示。直接把普通探头压在晶体引脚上还可能增加负载、改变振荡。优先观察合适的缓冲时钟输出或硬件 PWM，并按仪器与板级要求连接。

尤其不要在 ISR 里翻转 GPIO，再把翻转时间的摆动全部归因于晶振。中断屏蔽、抢占、总线访问与程序路径都能改变软件边沿的到达时间。硬件输出比较/PWM 更适合先隔离软件调度误差；若故意测系统响应，就保留软件翻转，但把结果叫作响应延迟或调度抖动。

## 给主线实验增加一个独立参考

第一步仍可把同板 TIM3 的 PWM 回送 TIM2，检查分频、捕获与回绕逻辑。若两者都来自同一主时钟，源频率偏差可能在比值里抵消；这一步主要证明内部配置自洽。

第二步才是绝对验证：用有明确参考时基规格的频率计、校准过的仪器或合适的外部参考，记录累计周期或长时间偏差。先写误差预算，例如“待测源可能 20 ppm，参考允许 1 ppm，门限量化约 2 ppm”，最坏同向影响可能接近 23 ppm。没有独立性依据，不要随意用平方和开根号把最坏界缩小。

第三步改变观测时长和环境：固定温度下拉长闸门，量化比例通常会降低；换一个温度后重新观察慢变偏差。若误差随观测长度不再下降，要问是不是参考误差、系统偏差或温度漂移占主导，而不是继续无意义地增加小数位。

长时间平均可降低某些零均值随机成分，却不会消掉固定频偏，也不一定能消掉相关噪声、确定性干扰或慢漂移。“平均一万次就精确一万倍”没有一般保证。

## 结合 F407 做选择，而不是套用一个口号

F407 的 HSI 是内部 RC，HSE 可接外部晶体或外部时钟，LSE 常用于 RTC。选择依据是启动、功耗、接口允许的误差和电路成本，不是“外部一定完美”。精确容差与工作条件看数据手册及实际器件。

RM0090 的 F407 PLLM 说明要求 VCO 输入落在 1–2 MHz，并建议选 2 MHz 以限制 PLL 抖动。这是具体配置建议，不能推导为所有 STM32 都只能用这一范围，也不能从中得出某个纳秒抖动数。按芯片型号分别核对。

RTC 平滑校准则通过补入或掩去脉冲修正平均走时。修正平均值不等于每个短周期都均匀；RM0090 也提示校准输出的某些边沿可能有轻微不规则。因此校准后既要在足够长的窗口看平均误差，也要确认应用是否在意短期边沿均匀性。

## 练习：一天慢了三秒

以独立可靠参考为准，设备运行 86400 s 后，日历少走了 3 s。假设这一天频偏恒定，估计频偏是多少 ppm？能否由这一个结果判断单周期抖动大小？

<details><summary>展开答案</summary>

`-3/86400×1e6≈-34.72 ppm`，符号为慢。不能判断单周期抖动：许多不同的短期周期序列可以有相同的全天平均偏差。若要评估抖动，还要采集规定条件下的周期或相位序列，并定义观测带宽和指标。

</details>
