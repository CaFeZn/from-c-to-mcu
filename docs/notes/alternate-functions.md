# 引脚复用机制

把串口发送线从 PA9 改接 PB6，程序里的发送函数一字没变，终端却安静了。再用 GPIO 写 PB6 高低电平，万用表又能看到变化。线没断，引脚也没坏，缺的是哪一步？

GPIO 能控制这个焊盘，不代表 USART1 的发送信号已经连到它。引脚内部有选择电路；选择了外设，还要让外设本身工作。本文把这两件事拆开，接续 [4.2 换个引脚](/lessons/4-2)，以 STM32F407 为具体例子，不把 F1 的重映射寄存器规则套到 F4。

## 先列一张“送到哪里”的检查单

实验沿用 [3.1 串口与日志](/lessons/3-1) 中已经能发送的 USART1 工程。只改变 TX，波特率等保持不变。先断电，核对实际封装有 PB6、开发板把它引出且未连接其他器件；USB 转串口必须是与本板兼容的 3.3 V 逻辑接口，不是 RS-232 电压接口。

1. 保存原来的串口配置，记下 PA9 的波形和终端输出。
2. 在 CubeMX 把 USART1_TX 改选为 PB6，RX 保留原来合法的选择；给 USART1_TX 选择 AF7，不是把 PB6 设成普通输出。
3. 重新生成并重新编译。检查 USART 的 MSP 初始化中有 GPIOB 时钟、PB6 配置与 USART1 时钟。
4. 断电把适配器 RX 改接 PB6，再上电。适配器与开发板共地，开发板 TX 接适配器 RX；不要把两个 TX 接起来。
5. 发送同一条日志。预期终端内容不变，示波器或逻辑分析仪在 PB6 看到帧；PA9 不再承担这一路输出，其实际状态由生成后的配置和板上电路决定。

PA9 与 PB6 都是 F407 数据手册列出的 USART1_TX 位置，对应 AF7；PA10 与 PB7 是常见 USART1_RX 位置。**TX 和 RX 可以分别选择各自合法引脚，不要求固定成某一对。** 芯片可选不等于开发板可用，排针上的标号、跳线和板载复用也必须检查。

## 用两个字段复现“选了 AF，还是不通”

先在纸上推演，只看 PA9 相关字段。其他位保持原样，不能为了教学把整个 GPIOA 寄存器清零，那会动到调试口。

| PA9 的配置 | 谁控制输出 | 预测 |
|---|---|---|
| MODER9=01，AFRH9=7 | GPIO 的 ODR | 写 ODR 能变，串口发数据不能从此脚出来 |
| MODER9=10，AFRH9=0 | AF0 所选系统功能 | 不是 USART1_TX，不能期待串口帧 |
| MODER9=10，AFRH9=7 | USART1 对应信号 | 还须 USART1 已启用且正在发送 |

第一行很容易让人误判：调试器看到 AF7 已写进去，就以为串口路由已完成。实际上 **MODER 选“使用哪类路径”，AFR 再选“哪一路外设”**。两者都对，电气配置和外设运行状态还要继续核对。

输入型外设同样需要对应路由。USART RX 在 F407 上也应选 AF 模式，不是因为数据向里流，就把它配置成普通 GPIO_Input。

## 每个引脚有自己的选择，不是全端口一换到底

F407 的一个 GPIO 端口通常有 16 个编号位置，每个引脚的 MODER 占两位。AF 编号需要四位，因此分成两只 32 位寄存器：

- AFRL，也就是 CMSIS 的 AFR[0]，管理引脚 0 到 7。
- AFRH，也就是 AFR[1]，管理引脚 8 到 15。
- 引脚 n 的 AFR 数组下标为 n / 8，字段起点为 4 × (n % 8)。

由此可算出：

| 目标 | 模式字段及置入值 | AF 字段及置入值 |
|---|---|---|
| PA9 → USART1_TX | MODER[19:18]，2 << 18 | AFRH[7:4]，7 << 4 |
| PB6 → USART1_TX | MODER[13:12]，2 << 12 | AFRL[27:24]，7 << 24 |

例如 PA9 只有目标字段置位时，模式贡献为十六进制 0x00080000，AF 贡献为 0x00000070；PB6 对应 0x00002000 和 0x07000000。它们是**字段贡献值**，不是要求你把整个寄存器写成这些数。

下面是纯 C 的字段练习，不访问芯片。文件中的断言同时检查“不碰邻居”，可在主机上执行；真实固件使用 CubeMX/HAL 或设备头文件。

~~~c
#include <assert.h>
#include <stdint.h>

static uint32_t field4(uint32_t original, unsigned pin,
                       unsigned af)
{
    unsigned shift;
    assert(pin < 16u && af < 16u);
    shift = 4u * (pin % 8u);
    return (original & ~(UINT32_C(15) << shift))
         | ((uint32_t)af << shift);
}

/* 示例输入：AFRH 原来每个四位字段都是 0xA。 */
/* field4(0xAAAAAAAA, 9, 7) == 0xAAAAAA7A */
~~~

AF7 不是“任意串口随便接任意脚”的编号。它只在数据手册某一行的 AF7 格子里表示该格写出的功能。PA9 的 AF1 是 TIM1_CH2，并不是在所有引脚上 AF1 都代表这个通道；空白格也不能用猜测填满。合法映射是硅片做好的，软件不能制造新连线。

## 路由之后，电气属性还在

选中 USART1_TX 后，输出数据来源不再是 ODR，而是外设的发送数据和输出使能。此时调用普通 GPIO 写函数可能改变 ODR 锁存，却不会成为这路 AF 输出的控制源；读 IDR 仍能看到引脚的数字状态。

AF 不会替你决定所有电气设置。USART TX 通常使用推挽；I2C 则需要 AF 开漏及符合总线电压、速度要求的上拉。OSPEEDR 控制输出边沿能力，不设波特率；PUPDR 不是外设时钟开关。不能看到“AF”两个字就把所有引脚配置复制成一套。

另一个常见遗漏是时钟分属两个对象：GPIOA/GPIOB 的寄存器需要各自 AHB1 时钟，USART1 需要 APB2 外设时钟和正确的波特率配置。GPIO 时钟开了，只能说明可以配置端口，不能证明 UART 在发送。

## 不要把另外两条路径也叫 AF7

**ADC/DAC 模拟信号**：F407 对应引脚应配置成模拟模式，再在模拟外设内选通道。不要为了启用 ADC 去找一个“ADC 的 AF 数字”。数字输入缓冲器关闭是模拟模式的重要区别。

**GPIO 外部中断**：普通按键配置为输入，并通过 SYSCFG 的 EXTI 端口选择与 EXTI 控制逻辑连到中断线。这不是在 AFR 里挑一个 AF 编号。例如 PA0 与 PB0 都要使用 EXTI0 时会遇到端口选择冲突；改变 AFR 不能让同一条 EXTI0 同时独立服务两个端口。

此外，SWD/JTAG 引脚在复位后有专用功能，不是所有引脚都默认普通输入。排查时不要整端口覆盖 MODER，也不要为了看一个波形关掉 Serial Wire，导致下一次调试连接失败。

## 运行中换脚，为什么也可能多出一个边沿

上面的实验使用“重新生成、断电改线、重新启动”，没有承诺热切换无毛刺。运行中的 USART 可能正发到半帧，定时器可能正输出高电平；这时更改复用会截断信号。若同一物理线连接两路输出，还可能出现短暂驱动冲突。

实际产品需要切换时，应先结束当前事务、停止或安全禁用原输出、准备新路径的电气属性与空闲状态，再切换、启用新输出。外部器件若对边沿敏感，还要增加外部使能或协议上的重新同步。GPIO 配置不是事务，不会自动替多个寄存器的写入提供一个同时生效的瞬间。

## 练习：一次寄存器快照能证明多少

调试器显示 PB6 的 MODER6=10、AFRL6=7，OSPEEDR 配置合理，但逻辑分析仪看到一直为高。有人断言“复用错了”，也有人断言“串口已经正常”。两句话哪一句成立？应该继续看什么？

## 适用范围与参考

这是 F407 的数字复用模型，不是所有 STM32 的统一寄存器接口。文中的寄存器字段计算可用主机示例验证；引脚搬移、输出边沿和实际串口传输需要具体板子验证，本篇未上板。

- [ST RM0090，Rev 22](https://www.st.com/resource/en/reference_manual/dm00031020-stm32f405415-stm32f407417-stm32f427437-and-stm32f429439-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)：§8.3.2、§8.3.7、§8.3.11、§8.4.9–8.4.10，复用选择、数字输入读回、AFRL/AFRH；§9.2 的 SYSCFG_EXTICR 描述用于区分 EXTI 路由。
- [ST STM32F405xx/STM32F407xx 数据手册](https://www.st.com/resource/en/datasheet/stm32f407vg.pdf)：Pinouts and pin description 中的 Alternate function mapping 表，PA9、PB6、PA10、PB7 行。封装引脚是否存在还要查同章 pin/ball definitions。
