# 随机数与熵

猜数字游戏重启两次，答案竟然一样。给它补上 `srand(time(NULL))`，快速重启仍可能撞上同一个答案。这不必然是程序坏了：如果种子相同，后面的计算本来就应当重放。真正要追问的是：你需要复现故障、公平抽签，还是生成别人猜不到的密钥？三个目标不能用一句“够随机”代替。

本篇接着[主线 1.2 的猜数字实验](/lessons/1-2)，先让一个小生成器完全透明，再讨论它做不到什么。

## 先重放，再换起点

以下实验不读取键盘或时间，固定种子为 `1`，状态范围为 `0..15`，每次调用按这个规则更新：

```c
struct toy_rng { unsigned state; };

static unsigned toy_next(struct toy_rng *rng)
{
    /* Precondition: state < 16. Teaching only. */
    rng->state = (5u * rng->state + 1u) % 16u;
    return rng->state;
}
```

先算两步：`(5*1+1)%16 = 6`，下一步是 `(5*6+1)%16 = 15`。这就是一个微型线性同余伪随机生成器（PRNG）：**种子是初始状态，状态是下一次计算的全部依据**。本例乘加最大只有 `76`，并不依赖整数溢出。它仅供手算，不是推荐的游戏或仿真算法。

在仓库根目录使用 GCC 编译配套独立示例，不要加 `-DNDEBUG`，否则会关闭断言：

```sh
gcc -std=c99 -Wall -Wextra -Wconversion -Werror -pedantic \
  examples/notes/c-numbers/randomness.c -o randomness.exe
./randomness.exe
```

输入就是源码里固定的种子、范围 `n=6` 和重试预算。实际输出应为：

```text
rand replay: ok
seed=1: 6 15 12 13 2 11 8 9
clone next: 14 14
mod counts: 3 3 3 3 2 2
reject counts: 2 2 2 2 2 2
bounded n=6: 0 (draws=1), 2 (draws=4)
boundaries: ok
```

第一行验证 C 库的两项约定：未调用 `srand` 等效于先用种子 `1`；再次用相同种子初始化，会重复同一序列。标准没有固定算法，也没有保证高质量分布，所以不要把某台电脑的五个 `rand()` 数字当成跨库答案。示例只断言重放关系，没有硬编码库输出。

第二行则来自我们明确写出的规则，可以跨实现对照。八次调用后，状态是 `9`；复制整个状态，两个副本下一次都得到 `14`。重新播种到 `1` 是回到开头，恢复状态 `9` 才是从中途继续。真实生成器可能有多个状态字段，不能只保存最后一个输出就声称能恢复。调试时还应记录算法版本、种子和调用顺序；多调用一次会改变后续输入。

反复在循环里播种也不是“添加随机性”：相同时间值经转换得到相同种子时，每次都重启同一条序列。测试应主动固定种子；需要变化时再选择合适的初始化来源。时间可能不可靠，嵌入式环境也未必有可用的日历时钟。

## 十六个输入，为什么不能公平分成六份

暂且假设一次原始输入在 `0..15` 上等概率。把它直接映射为 `x % 6`，不用跑百万次，逐一列出原像就能判断：

| 余数 | 哪些输入映射到它 | 个数 |
|---|---|---|
| 0 | 0、6、12 | 3 |
| 1 | 1、7、13 | 3 |
| 2 | 2、8、14 | 3 |
| 3 | 3、9、15 | 3 |
| 4 | 4、10 | 2 |
| 5 | 5、11 | 2 |

前四个结果概率为 `3/16`，后两个为 `2/16`。加 `1` 只会把标签改成骰子点数，并不会消除偏差。原因是 `16 = 2*6+4`，多出的四个输入无法平均分配。一般地，源空间大小 `M` 不能被目标大小 `n` 整除时，简单取模就会产生这种映射偏差。

解决办法是先去掉尾部的零头。令 `limit = M - M%n`，只接受 `x < limit`，再计算 `x%n`。此处 `limit=12`，丢弃 `12..15` 后，每个余数正好有两个原像。这叫**拒绝采样**。配套实现限定 `M=16`，以失败返回值和调用预算避免无限等待，核心如下：

```c
/* value and draws must point to writable objects. */
*draws = 0u;
if (n == 0u || n > 16u) {
    return false;
}
unsigned limit = 16u - 16u % n;
while (*draws < budget) {
    unsigned x = toy_next(rng);
    ++*draws;
    if (x < limit) {
        *value = x % n;
        return true;
    }
}
return false;
```

从种子 `1` 开始，第一个原始值 `6` 被接受，结果为 `0`；第二次请求依次见到 `15、12、13、2`，前三个拒绝，第四个接受，结果为 `2`。因此输出里的调用次数是 `1` 和 `4`，不是每次抽签都只消耗一个状态。

这里有三道边界：`n=0` 必须在取模前拒绝；`n>16` 无法由这套单样本映射覆盖；预算耗尽要报告失败，不能把最后的拒绝值偷偷当结果。推广到大整数时，也必须确保源空间大小及阈值计算可表示，不能机械地把 `16` 换成可能超范围的表达式。

另一个更重要的边界是：**拒绝采样只修映射偏差，不修坏随机源**。上述均匀性结论以均匀输入为前提；若每次输入独立且均匀，接受概率是 `12/16`，平均需 `4/3` 次尝试。但本例固定状态机完全可预测，相邻输出也不独立。遍历整个周期得到均衡计数，只能检验映射与实现，不能证明现实抽签公平。

## 输出变长，熵不会自动增加

把种子限制为均匀选择的 `0..15`，初始不确定性最多是 `log2(16)=4` 比特。无论随后打印十个数还是一万个数，都只有至多十六条可能序列；知道规则的人可以逐条试。若种子固定且公开为 `1`，相对于知道这些条件的人，后续输出没有新的不确定性。

熵描述的是随机变量分布的不确定性，不是文件长度或肉眼看到的杂乱程度。对于概率 `p_i`，香农熵为 `H=-sum(p_i*log2(p_i))`。概率不均时，不能只数可能值就断言熵等于位宽。安全评估还关心最容易猜中的值，常用最小熵 `H_min=-log2(max(p_i))`；不能把一次短样本的直方图当成熵源证明。

因此，`rand()`、这个教学生成器、可猜的时间种子，以及对这些数据再做哈希，都不能自动变成密钥来源。密码学安全的伪随机生成器仍然是确定性算法，但要结合有足够熵的初始化、合适的状态保护和经过分析的算法，才能提供所需的计算上不可预测性。密钥、令牌等应使用系统或经审查密码库的安全随机接口，检查失败，不要自行拼装。本篇不实现密码算法，也不把历史参考中的具体算法当成今日选型清单。

## F407 的 RNG 也有前置条件

STM32F407 的 RNG 与纯软件递推不同：RM0090 Rev22 第 24 章说明它使用模拟噪声产生种子，再经过内部逻辑输出 32 位数据。但“芯片有 RNG”不等于每次读寄存器都有合格数据。这里只核对手册，不提供未经板测的完整驱动：

- 时钟要同时满足外设门控和发生器条件：使能 `RCC_AHB2ENR.RNGEN`，配置由主 PLL 的 `PLLQ` 输出提供的 RNG 时钟，再使能 `RNG_CR.RNGEN`。手册给出的时钟错误条件是 `fRNG_CLK < fHCLK/16`，不能只看 CPU 时钟。
- 检查 `RNG_SR` 的错误标志，并等待 `DRDY=1` 后才读 `RNG_DR`；读后 `DRDY` 清零，软件仍要有超时退出。寄存器要求 32 位字访问。
- `CEIS/CECS` 分别表示时钟错误锁存/当前状态；应修复时钟并按规定清标志，等待当前错误消失。`SEIS/SECS` 对应种子错误；发生种子错误时，已有数据也不能使用，应清 `SEIS`，再清零并置位 `RNGEN` 重新初始化。不能只清状态就继续交付数据。

`CEIS`、`SEIS` 是写零清除，不是写一清除。手册还要求启用后的第一个数保存作比较而不交付，后续值与前值比较；重复时测试失败。遵守这些条件仍不等于整个产品通过安全评估，实际项目还需核对芯片修订、勘误和驱动错误路径。本篇没有真板测试，也没有测量硬件熵或声称安全认证。

## 留一道能手算的题

<details>
<summary>展开推演答案</summary>

原像个数依次为 `4、3、3、3、3`，因为 `0、5、10、15` 都映射到零。阈值是 `16-16%5=15`，只拒绝 `15`，剩下各三份。状态 `6` 下一步恰为 `15`，一次预算耗尽，应返回失败并保留输出参数，状态已推进到 `15`，不能假装没有消耗输入。过滤过程是确定性的，不会凭空新增熵；重新播种重复尝试还可能反复撞到同一个拒绝值。

## 适用范围与核对依据

独立示例只使用 C99，验证有限状态、重放关系、计数和错误返回；已在本机 GCC 6.3.0 严格警告选项下编译运行，断言全部通过。不据此推断长周期统计质量、跨库 `rand()` 数值、实时截止时间或密码安全。

- [WG14 N1570，2011-04-12](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：已读 §7.22.2.1–2、注 295，核对范围、重复播种、默认种子及质量限制。这是 C11 委员会草案，本例不使用 C11 新接口。
- [RFC 4086，2005-06](https://www.rfc-editor.org/rfc/rfc4086.txt)：已读 §2 和 §6.1.3，核对熵、最小熵、统计随机性与不可预测性的区别，以及线性同余生成器的安全边界。
- [ST RM0090 Rev22](https://www.st.com/resource/en/reference_manual/dm00031020-stm32f405415-stm32f407417-stm32f427437-and-stm32f429439-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)：已读 §7.3.2、§7.3.11、§24.3–24.4，核对 F407 时钟、状态及错误恢复，正文页 227、245、763–766。
