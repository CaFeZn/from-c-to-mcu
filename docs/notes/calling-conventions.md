# 调用约定与尾调用优化

你在包装函数里写了 `return abi_twice(x);`。不开优化时，调试器能停进包装函数；打开优化，反汇编里却只剩一条跳转，没有熟悉的“调用后返回”。函数没做完吗？为什么它仍能回到原来的调用者？

先别猜“编译器替我们省了一个函数”。这次把调用者和被调用者分成两个编译单元，观察参数送到哪里、哪些值必须活过一次调用，再解释为什么有时可以直接跳走。范围固定为 Cortex-M4、Thumb、AAPCS32；PC 实验用于验证 C 计算结果，不能拿 PC 寄存器布局代替 ARM 约定。

## 先复现两个结果相近、动作不同的函数

配套示例中的被调用者很简单：

```c
unsigned abi_twice(unsigned x)
{
    return x * 2u;
}

unsigned abi_sum5(unsigned a, unsigned b, unsigned c,
                  unsigned d, unsigned e)
{
    return a + b + c + d + e;
}
```

另一个编译单元声明它们，并安排三种调用。下面是核心片段，完整文件还包含 `main`、五参数调用与断言：

```c
unsigned abi_twice(unsigned x);

unsigned abi_keep(unsigned x)
{
    unsigned kept = x + 7u;
    unsigned result = abi_twice(x);
    return result + kept;
}

unsigned abi_tail(unsigned x)
{
    return abi_twice(x);
}

unsigned abi_after(unsigned x)
{
    return abi_twice(x) + 1u;
}
```

从仓库根目录执行；工具必须已在 `PATH` 中，或者通过脚本支持的 `HOST_CC`、`ARM_CC`、`ARM_OBJDUMP`、`ARM_READELF` 指定实际路径：

```bash
command -v gcc
command -v arm-none-eabi-gcc
bash examples/notes/c-functions/run-abi-tests.sh
```

脚本不改公共构建配置。PC 部分使用 `-std=c99 -Wall -Wextra -Werror -pedantic`，在 `-O0` 和 `-O2` 下分别编译运行；ARM 部分使用 `-mcpu=cortex-m4 -mthumb` 生成目标文件、汇编及 ELF 属性，不链接板级固件。两个编译单元不启用 LTO，ARM 对照另加 `-fno-inline`，避免把被观察的跨函数边界直接内联掉。

给定 `x = 5`、五个参数为 1 到 5，另有尾递归与浮点测试，PC 的固定输出是：

```text
sum5=15 keep=22 tail=10 after=11
tail_sum(3)=6 float=3.75
```

断言另覆盖 0、1、17、`UINT_MAX` 等输入。整数计算都用无符号类型，回绕由语言定义；并没有把有符号溢出或错误函数类型强转当成验证手段。

## 五个参数为什么只看到四个寄存器

C 类型声明告诉编译器“有五个 `unsigned`”，但不规定它们放在哪。**调用约定**负责连接两侧生成的机器代码，是 ABI（应用二进制接口）的一部分。

在本例 Cortex-M4 的 32 位 `unsigned`、没有隐藏结果缓冲区参数、非变参条件下，进入 `abi_sum5` 的瞬间：

| 位置 | 内容 |
| --- | --- |
| `r0`、`r1` | 1、2 |
| `r2`、`r3` | 3、4 |
| 入口 `SP` 指向的一个字 | 5 |
| 正常返回时的 `r0` | 15 |

本次 GCC 12.3.1 的 `soft、-O2` 调用者确实先把 5 写到 `[sp]`，再设置 `r0-r3`，执行 `bl abi_sum5`；被调用者用 `ldr ip, [sp]` 取第五个参数。

这里的 `ip` 是 `r12` 的别名。**“第五个参数在栈上”不等于“函数体内永远用 `[sp]` 读取”。** 如果入口先压了寄存器，SP 已改变，偏移也必须改变。本次 hard 构建恰好先压 `r4`，于是从 `[sp, #4]` 取同一个参数。

别把表格推广为“第几个 C 参数对应第几个寄存器”：64 位参数有对齐与寄存器对的规则，较大结构体返回可能占用隐藏的结果地址参数；浮点还要看后文的 ABI 变体。

## 一次调用会破坏哪些值

AAPCS32 的通用寄存器分工应这样读：

- `r0-r3` 用于参数、结果和临时值；`r12` 也是临时寄存器，链接器插入的跳板都可能使用它。调用者需要跨调用保留的数据，不能仅凭“刚才放在那里”就认为还在。
- `r4-r8`、`r10`、`r11` 属于被调用者必须保持的寄存器；用它们可以，但返回前要恢复原值。SP 也必须按约定恢复。
- `r9` 的用途由平台规定；只有把它定义为普通变量寄存器 `v6` 的变体，才按相应 callee-saved 规则处理；其他用途遵守平台专门规则，也不能任意破坏。不要无条件背成“`r4-r11` 全都一样”。
- `LR` 保存返回信息；`BL` 会更新它，所以有后续子调用的函数通常要先保护自己的返回路径。

“caller-saved”不是说调用者每次都要压入一整组；它只需保护还要使用的值。“callee-saved”也不要求每次全部压栈，不改就不用恢复。

例如 `abi_keep(5)` 要在子调用后计算 `10 + 12`。本次生成：

```asm
push {r4, lr}
mov  r4, r0
bl   abi_twice
adds r4, r4, #7
add  r0, r0, r4
pop  {r4, pc}
```

注意 `r4` 跨调用保存的是原始 `x`，不是源码里已经算出的 `kept`；编译器把加七延后了。子函数必须保持 `r4`，本函数又在返回前恢复进入时的旧 `r4`，两层责任刚好接上。变量名与寄存器没有永久的一一对应关系。

### 为什么保存 LR 之外还多减了 12

五参数调用者的开头是 `push {lr}`、`sub sp, sp, #12`。若入口 `SP = 0x20001000`，分别变成 `0x20000FFC`、`0x20000FF0`，调用时总共下降 16 字节。

AAPCS32 要求 SP 任意时刻满足 4 字节对齐，在公共调用接口保持 **8 字节对齐**。不是“每条指令执行后都必须 8 字节对齐”，也不是“只要能读写 RAM 就算对齐”。这个布局给栈参数和对齐留出了空间；不要认为源码有一个 4 字节栈参数，总帧大小就只能是 4。

## 直接跳走，为什么还回得来

本次 `-O2` 的包装函数只剩：

```asm
abi_tail:
    b abi_twice
```

`B` 不重新写 LR。原调用者进入包装函数时留下的返回地址，直接交给了 `abi_twice`。后者计算结束，用 `bx lr` 回到原调用者，根本不需要再回包装函数一趟。这叫**尾调用优化**；若包装函数已经建立栈帧，还必须在跳转前整理好栈与需要恢复的寄存器。

对比 `abi_after`：调用后还要加一，本次代码保留 `BL` 和返回后的 `adds`。不能只因源代码最后一行出现 `return`，就认定已经完成尾调用转换。

配套脚本另用 `-O2 -fno-optimize-sibling-calls` 编译对照。此时 `abi_tail` 也变成保存寄存器、`bl abi_twice`、恢复并返回。目标文件反汇编中的重定位同样不同：优化版本是 `R_ARM_THM_JUMP24`，对照版本是 `R_ARM_THM_CALL`；未链接的占位地址不是最终运行地址。

尾递归则可以把“重新进入自己”变成内部循环：

```c
unsigned abi_tail_sum(unsigned n, unsigned acc)
{
    if (n == 0u) {
        return acc;
    }
    return abi_tail_sum(n - 1u, acc + n);
}
```

输入 `(3, 0)`，参数依次为 `(2, 3)`、`(1, 5)`、`(0, 6)`，结果为 6。本次 `-O2` 的函数体是加法、减一和条件回跳，没有递归 `BL`；关闭对应优化后重新出现递归调用。

**这只是编译器提供的优化，不是 C99 对空间复杂度的保证。** 调试选项、插桩、ABI 限制、必须继续有效的局部对象等都可能妨碍转换。反过来，编译器也可能把某些并非明显尾递归的写法改成循环。嵌入式代码若依赖有界栈空间，应直接使用可审计的迭代实现，或为最终构建给出可验证的调用深度上界，不能把优化当作防溢出的保险。

## 浮点有硬件，不等于参数就走浮点寄存器

对同一个非变参函数 `float abi_fadd(float x, float y)`，函数体为 `return x + y;`。脚本固定 `-mfpu=fpv4-sp-d16`，仅改变 `-mfloat-abi`，实际编译结果如下：

| 选项 | 本函数的参数与结果 | 本次计算路径 |
| --- | --- | --- |
| `soft` | 参数在 `r0/r1`，结果在 `r0` | 调用 `__aeabi_fadd` 软件例程 |
| `softfp` | 同样使用核心寄存器接口 | `vmov` 搬入浮点寄存器，`vadd.f32` 计算后搬回 |
| `hard` | 参数在 `s0/s1`，结果在 `s0` | `vadd.f32 s0, s0, s1` |

hard 产物的 ELF 属性含 `Tag_ABI_VFP_args: VFP registers`。区别既包括“怎么计算”，也包括“边界怎么传值”；softfp 能发出硬件浮点指令，却仍使用基础传参约定。

这张表**只描述这个有两个 `float` 参数的非变参函数**。变参函数使用基础约定，不能把 `printf` 的浮点参数也按这张表去填；其他类型及聚合类型应查完整规则。浮点寄存器也有保存约定：`s16-s31` 需要跨调用保持，`s0-s15` 可作临时值。STM32F407 的单精度 FPU 不意味着所有 `double` 运算都有硬件指令。

不要混用不兼容的 hard/soft-float 调用接口，或靠函数指针强转“适配”。调用双方、库、启动配置要一致；本篇只编译核对，没有验证板上 FPU 使能与运行。

## 练习：不要只数 push

1. 若五参数例子再加第六个 32 位 `unsigned` 参数 6，在被调用者入口，两个栈参数分别在哪里？求和应返回多少？
2. 为什么 `abi_keep` 不能把还要用的 `x` 一直留在 `r0`？
3. 看到 `return helper(x);`，能否承诺调试调用栈里没有当前函数？

<details>
<summary>展开答案与理由</summary>

1. 在本题的纯 32 位整数参数前提下，第五个在入口 `[sp]`，第六个在 `[sp, #4]`，结果为 21。入口之后若修改 SP，访问偏移随之调整；调用前仍要满足 8 字节对齐。
2. `r0` 既是参数寄存器也是本例的返回值寄存器。子调用后其中是 `2*x`，而非原始 `x`。保存到受保护寄存器或栈空间都是可行实现，不一定非得用 `r4`。
3. 不能。源码只是提供了尾位置，实际转换取决于编译器、选项、ABI 和对象生存期等约束；还可能内联。需要检查相应构建的汇编与调试信息。
