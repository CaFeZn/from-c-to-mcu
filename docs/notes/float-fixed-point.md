# 浮点与定点

[3.1 的日志](/lessons/3-1) 没有启用浮点格式化，你把温度乘以 1000，再拆成整数和余数打印。23.456 摄氏度正常，降到 -0.125 时却变成了 `0.-125`。与此同时，[1.2 的实验](/lessons/1-2) 中十次 0.1 还不一定恰好等于 1。两件事都涉及小数，却不是同一种错误：前者没有设计好单位和符号，后者来自有限精度的表示与舍入。

本篇用 C99 在 PC 上验证数值处理，最后再讨论 STM32F407 的成本。先不要急着选“永远用整数”或“永远用 float”，先把要保留的量程、分辨率和误差写出来。

## 从一条能打印负温度的记录开始

假设通信协议直接传来整数 -125，约定单位为千分之一摄氏度，它表示 -0.125 摄氏度。这个存储约定就是一种**定点**：小数点的位置由缩放系数固定，而不是由变量中另一个指数决定。

下面是完整 PC 示例。将它作为 [1.0 工程](/lessons/1-0) 的一个演示目标运行；注意负号独立输出，并且在取最小负数的绝对值前先扩大类型。

```c
#include <assert.h>
#include <stdint.h>
#include <stdio.h>

static void print_milli(int32_t value) {
    uint32_t magnitude = value < 0
        ? (uint32_t)(-(int64_t)value) : (uint32_t)value;
    printf("%s%lu.%03lu\n", value < 0 ? "-" : "",
           (unsigned long)(magnitude / 1000u),
           (unsigned long)(magnitude % 1000u));
}

int main(void) {
    int32_t temperature_milli = -125;
    uint16_t raw = 2048u;
    uint32_t vref_mv = 3300u;
    uint32_t mv = (uint32_t)(((uint64_t)raw * vref_mv + 2047u)
                             / 4095u);
    assert(mv == 1650u);
    print_milli(temperature_milli);
    printf("adc=%lu mV\n", (unsigned long)mv);
    return 0;
}
```

预期输出：

```text
-0.125
adc=1650 mV
```

这个 ADC 例子采用主线的端点显示模型：原始值 0 映射到 0 mV，4095 映射到参考电压。加上整数 `4095 / 2` 后再除，做正数的最接近整数舍入。真实 ADC 的量化阶梯、参考误差、输入负载和校准不是这个公式能消除的，见 [8.2 ADC 读数换算](/lessons/8-2)。4095 端点缩放不应冒充器件理想量化步长的定义。

## 定点先约定单位，再写乘除

一个 `int32_t` 存千分之一单位，表示范围是 -2147483.648 到 2147483.647，步长为 0.001。若改成百万分之一单位，步长更细，范围就缩为约正负 2147.48。相同的位数不能既保留无限大的范围又保留无限细的刻度。

变量名里的 `_mv`、`_milli` 不只是注释。2000 mV 与 2 V 的整数值不能直接相加；相加之前必须统一尺度。乘法更要看单位：若 `x_milli` 表示 `x * 1000`，`gain_milli` 表示 `gain * 1000`，两者乘积表示实际乘积的百万倍，除以 1000 后才恢复千分之一单位。

下面片段可加入上面的程序，另包含 `stdbool.h`。`out` 必须指向可写的 `int32_t` 对象，失败时不改变它：

```c
static bool scale_milli(int32_t x_milli, int32_t gain_milli,
                        int32_t *out) {
    int64_t product = (int64_t)x_milli * gain_milli;
    int64_t scaled = product / 1000;
    if (scaled < INT32_MIN || scaled > INT32_MAX) {
        return false;
    }
    *out = (int32_t)scaled;
    return true;
}
```

输入 `(-12345, 1500)`，数学值是 -12.345 × 1.5 = -18.5175，函数输出 -18517，即 -18.517。C99 的整数除法向零截断，因此这不是四舍五入。截断策略的单次量化误差小于一个输出步长，但多次累积会产生偏差；把舍入规则写进接口，比依赖读者猜测更可靠。

这里两个 32 位有符号数的乘积能放进 64 位，但必须在乘法之前转换操作数。`int64_t product = x_milli * gain_milli;` 在常见平台上仍先做 32 位乘法，左边宽并救不了右边。相同地，先除再乘虽然可能降低溢出风险，也可能把信息提前丢掉：`1 / 1000 * 1500` 为零。

二进制定点也常见。例如把 16 位补码整数解释为“除以 32768”，常称为 Q15：范围为 -1 到 `1 - 1/32768`，步长为 `1/32768`。乘法后要恢复尺度，并单独处理 +1 不能表示的边界。不同资料的 Q 格式记号可能是否包含符号位，因此只写“Q15”还不够，接口最好同时写出公式、底层类型和舍入规则。

## 浮点把精度放在有效数字上

现在运行另一段独立实验。使用常见 IEEE 754 binary64 的 `double`、默认舍入且未启用 fast-math 时，可以观察到下面的典型结果；本课 PC 工具链已复现。

```c
#include <float.h>
#include <stdio.h>

int main(void) {
    volatile double sum = 0.0;
    for (int i = 0; i < 10; ++i) {
        sum = sum + 0.1;
    }
    printf("base=%d digits=%d\n", FLT_RADIX, DBL_MANT_DIG);
    printf("sum=%.17g equal=%d\n", (double)sum, sum == 1.0);
    return 0;
}
```

```text
base=2 digits=53
sum=0.99999999999999989 equal=0
```

`volatile` 在这里只让每轮结果落回声明的对象，便于观察逐次舍入；它不是提高精度的工具。C 不要求所有平台都采用这个浮点格式，也允许某些中间计算使用更高精度，所以不要把最后几位当成跨平台输出协议。

十进制 0.1 是 1/10，约分后的分母含有 5，无法用有限个二进制小数位表示；0.5、0.125 则可以，因为它们的分母是 2 的幂。浮点通常把数写成“符号 × 有效数字 × 基数的指数”，把有限位数花在相对精度上。常见 binary32 有 24 位二进制有效精度，binary64 有 53 位。数越大，相邻可表示数之间的绝对距离一般越大，不像定点始终保持同一格宽。

因此浮点不是“坏掉的小数”，它适合跨很大量程的计算；定点也不是“没有误差”，它只是用你指定的固定刻度量化。选择应取决于误差预算、动态范围和计算代价。

## 相等、转换和舍入各有边界

“浮点永远不能用 `==`”过于绝对。比较协议中特意设置的精确值、同一计算结果或可精确表示的简单量时，相等判断可以合理。若比较来自不同计算路径的近似测量，通常按允许误差比较：绝对差小于“绝对容差与相对容差乘数值尺度的较大者”。温度误差允许 0.01 摄氏度，就应从这条需求出发，而不是到处粘贴一个神秘的 `1e-6`。

接近零时，相对容差单独使用会失效；含 NaN 时普通相等和大小比较也不按实数直觉工作。测量接口通常应先用 `isfinite` 拒绝 NaN 和无穷，再比较或转换。容差比较并不总满足传递性，不能直接当成排序器的全序关系。

浮点转整数不是“随便截取低位”。C99 对有限值丢弃小数部分，但整数部分无法表示时是未定义行为。若一个接口只接受 -1000 到 1000 摄氏度，可以先验证有限性和这个业务范围，再乘 1000 转为 `int32_t`；这样结果有充足余量。不要先强转后检查，也不要直接用会被 `float` 舍入的 `INT32_MAX` 边界来证明安全。通过业务量程留余量通常更清楚。

负数格式化还有一个独立的坑：`-INT32_MIN` 无法用同宽有符号类型表示。开头先转 `int64_t` 再取负，正是为覆盖这个输入；打印余数前先取非负幅值，又避免了负余数出现在小数点后面。

## F407 上该怎么选

STM32F407 的 Cortex-M4F 配有 FPv4-SP 单精度 FPU。它支持单精度加、减、乘、除等运算，不能因为寄存器可按双字访问，就认为它能硬件执行双精度算术。常见 ARM GCC 配置下，`double` 运算通常需要软件例程；具体成本要看编译选项、库和反汇编，不能凭一个固定倍数推断。

需要单精度常量时写 `0.1f`，裸写 `0.1` 是 `double`，可能让表达式走双精度路径。传入 `printf` 时 `float` 又会按可变参数规则提升成 `double`；硬件能算 `float` 和库能格式化 `%f` 是两回事。

主线的电压显示、协议字段、阈值比较，用整数毫伏很自然。滤波和复杂控制算法可能用浮点更清楚，也可能用定点获得合适的资源开销；先证明范围、误差和最坏执行时间。需要限幅时明确选 [饱和运算](/notes/saturating-arithmetic)，不要让回绕代替它。
