# 编码器模式与死区

旋钮顺时针转一格，计数有时加一、有时减一；另一边，两路本来“互补”的 PWM 已经看起来一高一低，接到功率级却仍可能出现上下管短时同时导通。这两件事都和边沿顺序有关，却不是同一个功能：**编码器模式辨认输入边沿的先后，死区则故意推迟输出的导通边沿。**

先把电机和功率电源断开。本篇用状态表、计数快照和逻辑电平波形讲清楚机制；不是可以直接接桥臂上电的驱动方案。上下文来自 [5.3 PWM 与输入捕获](/lessons/5-3)。

## 两根线为什么能表示方向

把编码器 A、B 看作两位状态，先手工走一圈：

| 步骤 | A、B | 相对上一步 |
|---|---|---|
| 起点 | 00 | 不计数 |
| 1 | 10 | A 上升 |
| 2 | 11 | B 上升 |
| 3 | 01 | A 下降 |
| 4 | 00 | B 下降 |

每次只有一位变化。反着走 `00→01→11→10→00`，先后关系就反了。本篇把第一组称为正向；实际机械“顺时针”还取决于 A/B 接线、输入反相和安装方向，先用一次已知方向的转动建立约定，不凭名字猜。

在 F407 的 TIM2–TIM5 中，编码器接口使用 TI1、TI2。选择 `SMCR.SMS=011` 时，两路有效跳变都会参与计数，方向由硬件根据另一相的电平决定；`SMS=001` 只在 TI2 的边沿计数，`SMS=010` 只在 TI1 的边沿计数。这里“双边沿参与”由编码器状态机完成，不是把普通输入捕获极性随便改成双边沿。

若厂家明确把“1000 PPR”定义为 A 相每机械圈 1000 个完整周期，两相四倍计数就得到每圈 4000 个计数。PPR、CPR 的命名在产品间并不统一，选电机时必须读定义；不要对一个已经写着 4000 counts/rev 的规格再次乘四。

## 跟做：先看 CNT，再谈转速

以 TIM3 作编码器计数器：时钟和引脚复用已开启，两个输入分别映射到 TI1/TI2，不反相，`PSC=0`、`ARR=65535`，编码器模式 3，适当输入滤波，最后使能计数。A/B 需要符合芯片输入电压；开漏、差分输出应按编码器电气接口加上拉或接收器，不能都直接塞到 MCU。

初次调试只观察缓慢转动时 CNT 的增减，再看反转是否方向相反。机械触点编码器会抖动，滤波不能无代价地开到最大：滤波时间越长，可识别的最短脉冲越长，快速旋转可能丢边沿。

每 10 ms 读一次 CNT，若前后差 100，且每圈确为 4000 计数，则转速是 `100/4000/0.01×60=150 rpm`。反方向应得到 -150 rpm。但从 65530 走到 4 不是倒退 65526，而是向前走了 10。

下面的 C99 计算明确避开“把大无符号数转为小有符号数”的实现定义结果。它要求全宽 16 位计数，且两次采样间实际运动计数幅度小于半圈 32768；恰好半圈无法区分方向。

```c
#include <stdint.h>

/* 返回 1 表示可解释；返回 0 表示半圈歧义。 */
static int encoder_delta(uint16_t previous, uint16_t current,
                         int32_t *delta)
{
    uint32_t u = (uint16_t)(current - previous);
    if (u == 32768u) {
        return 0;
    }
    *delta = u < 32768u ? (int32_t)u : (int32_t)u - 65536;
    return 1;
}
```

调用者须提供有效输出指针。输入 `65530→4` 预期 +10；`4→65530` 预期 -10；`0→32768` 返回无效。这个接口不能侦测“其实跑了整整一圈”或超过半圈的运动，采样频率必须由最大转速倒推。位置累加到更宽变量时还要考虑运行寿命和越界，断电后也不能把增量编码器自动当作绝对位置传感器；零位或参考开关是另外的设计。

## “反相”为什么不等于安全互补

想象上管的 PWM 在某个边沿变低，下管立刻变高。数字引脚没有重叠，不代表实际开关器件已经彻底关断：驱动器延迟、栅极放电、器件传播时间都占时间。死区把双方的“开始有效”向后推，中间留出两边都不导通的间隔。

F407 的 TIM1/TIM8 提供高级定时器互补输出与死区，不是每一个 TIM 都有。以主输出和互补输出均高有效为例：主输出的上升沿相对 `OCxREF` 上升沿延后；互补输出的上升沿相对 `OCxREF` 下降沿延后。窄脉冲比死区还短时可能完全消失，因此“写了 1% 占空比”不代表功率端一定有 1% 导通。

这不应和前面的编码器功能强塞在同一个通道：编码器把 CH1/CH2 配成输入；驱动 PWM 要另一组输出资源。可在资源表中分配 TIM3 给编码器、TIM1 给互补 PWM，再核对封装是否把需要的 CHxN 引脚引出。

## 算一次真正的 DTG，不把它当纳秒数

设 TIM1 的 `CK_INT=168 MHz`，`CR1.CKD=00`，则 `tDTS=1/168 MHz`，约 5.952 ns。死区使用这个时钟，不是经 PSC 分频后的 CNT 时钟。DTG 的八位值采用分段编码：

| DTG 范围 | 死区包含的 tDTS 个数 |
|---|---|
| 0x00–0x7F | DTG |
| 0x80–0xBF | (64 + 低 6 位) × 2 |
| 0xC0–0xDF | (32 + 低 5 位) × 8 |
| 0xE0–0xFF | (32 + 低 5 位) × 16 |

要 500 ns，需要 84 个 tDTS，写 `0x54`。要 1 µs，需要 168 个 tDTS，第二段满足 `(64+20)×2=168`，写 `0x94`；直接把十进制 168 写进 DTG，即 `0xA8`，得到的是 208 个 tDTS，约 1.238 µs。配套算术测试还检查了 `0x7F→127`、`0x80→128`、`0xBF→254`、`0xC0→256`、`0xFF→1008`，确认档位交界并非处处连续。

若目标值落在不可表示的间隔，按器件安全要求选择向上取整并检查它没有破坏最小脉宽。把 CKD 改为二分频或四分频会一起改变 tDTS，不能只看 DTG。各互补通道共用该死区设置，不是每个 CCR 都带一份独立死区。

## 观察波形也要按层次验收

先只接逻辑分析仪或合适的示波器，核对 PWM 频率、CHx/CHxN 极性以及每次交接的空白时间。还要核对 `CCxE`、`CCxNE`、`MOE`、刹车输入和空闲输出状态；这些条件会决定“停止”后究竟是低电平还是高阻。

逻辑波形符合预期，仍不等于桥臂安全。真正的死区由驱动与开关器件最坏传播时间、温度和负载确定，需要专门的功率级验证及硬件过流保护。不要靠 ISR 轮流写两个 GPIO 模拟互补输出，也不要把置位 MOE 当作通用“解决没波形”的第一招。LOCK 等锁定位也可能使设置不能再改，初学验证阶段先明确寄存器的写入约束。

## 练习：改变采样和死区时钟

1000 PPR 的编码器按四倍计数，每 20 ms 得到 +200，转速多少？若 TIM1 仍为 168 MHz，却改为 `CKD=01`，保持 `DTG=0x54`，死区是多少？

<details><summary>展开答案</summary>

每圈 4000 计数，`200/4000/0.02×60=150 rpm`。CKD=01 让 tDTS 变为两个 CK_INT 周期，84 个 tDTS 对应 1 µs。改变 PSC 不会得到同样的死区变化；改变 CKD 则也会影响使用 tDTS 的数字滤波时钟，需一起重新核对。

</details>
