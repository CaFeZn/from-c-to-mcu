# GPIO 内部电路

灯在推挽模式下能亮，改成开漏后，同一句“写高电平”却不管用了。调试器里 ODR 明明是 1，难道库函数撒谎？

先不要换库。**ODR 保存的是输出请求，不是引脚实际电压。** 把“我要求什么”和“外面的电路变成什么样”分开，GPIO 的几种模式就不再需要死记。

本文沿用 [4.1 的点灯与按键](/lessons/4-1)，具体寄存器按 STM32F407、RM0090 Rev 22 解释。实验仅使用板上确认空闲、没有连到其他主动输出的引脚；不要占用 SWD、晶振或板载外设。下文给的是接线与预期，不是已完成的真机实测。

## 先做一个“写 1，却读到 0”的安全实验

在 CubeMX 选一个普通空闲引脚，标签设为 TEST：开漏输出、无内部上下拉、速度 Low。接一个 **10 kΩ 电阻到本板 3.3 V**，用万用表量 TEST 对 GND。先断电接线，确认没有接到 5 V。板上有其他负载时，先查原理图；不能把这张理想表直接套上去。

初始化完成后，在主循环外分别试下面两种请求，每次停留足够长，便于测量：


```c
/* 板级片段：需要 CubeMX 生成 TEST 宏和 GPIO 初始化。 */
HAL_GPIO_WritePin(TEST_GPIO_Port, TEST_Pin, GPIO_PIN_RESET);
/* 测完低电平后，下一次实验用下面一行替换上面一行： */
/* HAL_GPIO_WritePin(TEST_GPIO_Port, TEST_Pin, GPIO_PIN_SET); */
```

| 请求与接线 | ODR 对应位 | TEST 预期 | IDR 预期 |
|---|---|---|---|
| 写 0，10 kΩ 上拉保留 | 0 | 接近 0 V | 0 |
| 写 1，10 kΩ 上拉保留 | 1 | 接近 3.3 V | 1 |
| 写 1，上拉保留，再用 1 kΩ 接地 | 1 | 约 0.30 V | 0 |

第三步不是用导线短路推挽输出：TEST 此时必须仍是开漏且写 1。电流主要流过 10 kΩ 与 1 kΩ，约为 3.3 V / 11 kΩ = 0.30 mA。分压约为 3.3 × 1 / 11 = 0.30 V。做完拆掉 1 kΩ。若实测偏离很多，先查模式和已有板载负载，不要拿更小电阻“硬压”。

第三行就是本篇最重要的观察：**ODR=1 与 IDR=0 可以同时正确**。引脚的真实电压由外部网络决定，输入电路又把这个电压判成数字 0。

## 沿信号走一圈，而不是背模式名

用下面的简化图读实验。它只描述功能，不画晶体管尺寸、所有保护结构或模拟开关。


```text
ODR / 外设输出 ── 选择与输出控制 ── 推高 / 拉低 ── 引脚
                                                   │
IDR ◀──────── 数字输入缓冲器 ◀─────────────────────┘
                 引脚还可接弱上拉、弱下拉及模拟通路
```

**推挽输出**既能主动拉高，也能主动拉低。写 1 时高侧驱动导通，写 0 时低侧驱动导通；正常控制会避免两边同时导通。输出电阻不为零，因此带负载后高电平不是数学意义的 VDD，低电平也不保证绝对 0 V。

**开漏输出**不使用主动拉高的那条路。写 0 时低侧导通；写 1 时低侧关闭，输出端呈高阻态，常写作 Hi-Z。外部上拉负责充电、建立高电平。因此开漏的“1”更准确地叫**释放线路**。

输入缓冲器并没有因为配置成数字输出就消失。F407 在普通数字输出和 AF 模式下仍能通过 IDR 读引脚状态。它使用带迟滞的数字输入电路，把电压变成 0 或 1；迟滞有助于降低阈值附近的小扰动，但不是机械按键的完整消抖器，也不能把任意慢、任意噪声的信号变可靠。

## 弱上下拉不是第二套强输出

输入按键一端接地、另一端接引脚时，松开后没有主动驱动。启用上拉，相当于通过弱电阻给它一个默认高电平；按下后，开关闭合建立低电平，同时有一小股电流从上拉流到地。

内部上拉适合提供默认状态，不适合给 LED、继电器或蜂鸣器供电；其阻值和容差应查具体数据手册。长导线、较大漏电流或高速开漏总线，经常需要按噪声、电流、负载电容来选外部电阻，而不是只勾一个 Pull-up。

若两只**已确认电压兼容**的开漏输出接在同一根带上拉的线上，只有大家都释放，线路才为高；任意一只拉低，线路就为低。对正逻辑电平来说是“线与”。这不表示协议自动正确：谁何时发送、是否仲裁，仍由 I2C 等协议规定。更不能把两个推挽输出并在一起尝试这个实验；一高一低会产生驱动冲突。

## 四组配置各管哪件事

F407 每个引脚的 MODER 占两位：00 输入、01 通用输出、10 复用、11 模拟。OTYPER 每脚一位选择推挽或开漏；PUPDR 每脚两位选择无上下拉、上拉或下拉，11 保留；OSPEEDR 选择输出速度等级。

这几个维度不要混在一起：

- 输入模式关闭输出驱动，并不意味着“一定读 0”；读数由输入电压决定。
- AF 模式把输出数据及输出使能交给所选外设，GPIO 的输出类型等电气配置仍重要。
- 模拟模式关闭数字输入施密特触发器和弱上下拉；F407 此时读 IDR 得到 0。它不是“更灵敏的数字输入”。
- Speed 控制输出边沿能力，不是每秒翻转几次。LED 每 500 ms 翻一次，选 Very High 不会使它闪得更快，却可能增加振铃、干扰和瞬时电流。

普通引脚复位状态也不能概括成“所有引脚一律输入”：F407 的调试引脚有专门的复位配置，PA13/PA14 不要拿来试模式。

## 写寄存器时，先准备，再接通

如果希望上电后保持低电平，通常先在端口时钟已开启时写好输出锁存，再把模式切到输出。否则原来的锁存值可能在切换瞬间出现在引脚上。不过这只减少软件初始化带来的毛刺，不能保证从上电开始就一直安全；对电机使能、蜂鸣器等，还应由外部上下拉和驱动电路提供默认关闭状态。

F407 的 BSRR 低 16 位写 1 表示置位，高 16 位写 1 表示复位，写 0 无动作。例如置 PA5 写 `GPIOA->BSRR = 1u << 5`，复位写 `GPIOA->BSRR = 1u << 21`；正式工程应使用设备头文件和板级标签，不在 PC 上执行外设地址。

相较于对 ODR 做“读、改、写”，一次 BSRR 写入可以只改变目标位，避免在读改写中间被中断修改其他位时覆盖对方结果。但它不是万能锁：两个上下文若同时争用同一位，仍要定义所有权；“翻转”本身需要知道旧状态，也不能因为底层用了 BSRR 就自动变成并发安全。

## 练习：一个高电平为什么升得很慢

开漏输出连接 10 kΩ 上拉，总负载电容假设为 100 pF。释放后，示波器看到缓慢上升；下拉边沿却比较快。请估算 RC 时间常数，说明减小电阻的收益和代价。顺便回答：ODR 能不能证明这条线已经被对端判成高？

时间常数是 10 kΩ × 100 pF = 1 µs；理想一阶 RC 从 10% 升到 90% 约需 2.2 µs。释放后主要由上拉电阻给电容充电，下拉则由导通的输出管放电，两个边沿不必对称。

减小上拉电阻能加快上升，但拉低时电流增大，需要检查输出低电平保证、引脚电流、功耗和总线规范。ODR 只能证明请求释放；是否到达高阈值，要看引脚电压、阈值与时序。IDR 可提供本芯片的数字读数，也不能代替对端阈值和模拟波形检查。
