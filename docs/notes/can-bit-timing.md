# CAN位定时与采样点

同一块 F407，回环模式能收到自己发出的帧，接到 USB-CAN 后却一直发送失败。两边都写着“500 kbit/s”，为什么还不通？先不要改 ID。回环验证了部分控制器路径，却没有替你验证外部时钟误差、收发器延迟、接线和采样时刻。

本篇接着 [7.1 CAN 发出第一帧](/lessons/7-1)，把那组 Prescaler=6、BS1=11、BS2=2、SJW=1 拆开。对象是 **STM32F407 的 bxCAN、经典 CAN**；FDCAN 的寄存器和数据阶段定时不套用这里的编码。

## 先在纸上画出这一个比特

给定 CAN 外设时钟 PCLK1=42 MHz，目标 500 kbit/s。先预测：一个比特应该持续 2 μs，而不是 CPU 执行一条指令的时间。预分频后，一个时间量子为：

```text
tq = Prescaler / PCLK1 = 6 / 42 MHz = 142.857 ns
一位的量子数 N = 1 + BS1 + BS2 = 1 + 11 + 2 = 14
位时间 = N × tq = 2000 ns
位率 = PCLK1 / [Prescaler × (1 + BS1 + BS2)] = 500000 bit/s
采样点 = (1 + BS1) / N = 12/14 ≈ 85.714%
```

把一位画成十四格，格子不是十四次软件采样：

```text
| 同步1格 |             BS1：11格             | BS2：2格 |
0                                         ↑             2 μs
                                     约1.714 μs采样
```

**采样点在 BS1 结束处，不在 BS2 结束处。** 位率表示位的总长度；采样点表示在这一位的什么位置判断总线是显性还是隐性。总长度相同，切法仍可能不同。

把 BS1 改成10、BS2改成3，其他不动。预测结果仍是500 kbit/s，但采样点变成11/14≈78.571%，提前约143 ns。它没有“变成另一种波特率”，却改变了信号到达、稳定与重新同步的时间余量。

## 用一个完整C程序核对，而不是猜下拉框

下面程序是普通主机 C99，不访问寄存器。保存到你的练习工程并编译；它只验证本例算术，不会判断这组参数适不适合某一根线缆。

```c
#include <assert.h>
#include <stdint.h>
#include <stdio.h>

int main(void)
{
    const uint32_t pclk = 42000000u;
    const uint32_t prescaler = 6u, bs1 = 11u, bs2 = 2u;
    const uint32_t sjw = 1u;
    const uint32_t n = 1u + bs1 + bs2;
    const uint64_t divisor = (uint64_t)prescaler * n;
    const uint32_t btr = ((sjw - 1u) << 24)
                       | ((bs2 - 1u) << 20)
                       | ((bs1 - 1u) << 16)
                       | (prescaler - 1u);

    assert(prescaler >= 1u && prescaler <= 1024u);
    assert(bs1 >= 1u && bs1 <= 16u);
    assert(bs2 >= 1u && bs2 <= 8u);
    assert(sjw >= 1u && sjw <= 4u && sjw <= bs2);
    assert((uint64_t)pclk == 500000u * divisor);
    assert(btr == UINT32_C(0x001A0005));
    printf("rate=%.0f bit/s, sample=%.3f%%\n",
           (double)pclk / (double)divisor,
           100.0 * (double)(1u + bs1) / (double)n);
    printf("BTR timing fields=0x%08lX\n", (unsigned long)btr);
    return 0;
}
```

预期是 `rate=500000 bit/s, sample=85.714%` 和 `BTR timing fields=0x001A0005`。这里编码的只是正常模式下的定时字段；回环与静默模式还涉及高位。固定输入先满足范围再编码，**不能把这个片段当成任意输入解析器**；若参数来自用户，必须先验证，避免减1下溢。

在实际工程里读 CubeMX 生成的初始化：`Prescaler` 填实际分频数6，`TimeSeg1` 等则使用相应 HAL 枚举。寄存器原始字段 BRP、TS1、TS2、SJW 存的是“实际值减1”，所以分别是5、10、1、0。不要把 HAL 的字段值与寄存器编码混成同一张数字表。

## 时钟先核对，参数才有意义

F407 的 bxCAN 使用 APB1 外设时钟。常见168 MHz系统时钟、APB1分频4时，PCLK1为42 MHz。**APB1定时器的倍频规则不是CAN的规则**；拿84 MHz代入后再照抄配置，实际位率会偏一倍。也不要从CPU主频直接猜CAN时钟。

检查顺序可以固定成三步：

1. 读实际 RCC 配置与 CubeMX 时钟树，确认 PCLK1。代码修改时钟后，旧截图不算依据。
2. 读 CAN_BTR 的 BRP、TS1、TS2、SJW，按字段加1重算，确认软件实际写入值。该寄存器只能在初始化模式配置，不要在正常收发时硬改。
3. 在独立、已知良好的双节点台架上，对照分析仪位率与错误计数。回环通过不是这一步的替代品。

如果用逻辑分析仪看收发器 RXD，可以对已知位型做解码；不要随便量两个相邻边沿就当作一位，因为连续相同位没有边沿，位填充又会插入新位。看 CAN_H/CAN_L 的模拟质量，则需要合适的差分测量。

## 为什么要留BS2和SJW

两颗晶振不可能永远步调一致。控制器会在帧起始进行硬同步，并在符合协议条件的后续边沿上重新同步。bxCAN 把标准中的传播段与第一相位缓冲段合并为 BS1；BS2对应第二相位缓冲段。重新同步可能延长BS1或缩短BS2，**单次允许的最大调整量由SJW限定**。

SJW=1 tq并不是“每一位固定再加1格”，也不是让500 kbit/s变成另一档速率。名义位时间仍按原公式算。它只限制硬件为追踪相位误差所做的调整。本例保留2 tq的BS2并取1 tq的SJW；改用更差的振荡器、更长线缆或增加隔离器后，不能继续无条件宣称“1 tq够用”。

采样点靠后可以为传播留更多时间，但也会压缩BS2。线缆往返延迟、收发器与隔离器延迟、晶振容差、温度漂移和重同步能力必须一起满足。**85.7%不是通吃所有网络的标准答案，参数枚举器也只能产生候选项。**

### 换时钟以后重新计算

如果工程把PCLK1从42 MHz改为36 MHz，却保留6、11、2这组三段参数，位率将变成约428571 bit/s，而不是继续保持500 kbit/s。接收器不会因为软件注释仍写“500k”就自动补偿这14%以上的差距。排查时把时钟与BTR同时存进日志或配置表，避免只比对CubeMX下拉框。重新选择整除组合后，也应再次审查采样点与同步余量；“能整除”只是第一道筛选，不是最后的可靠性结论。

## 三个最容易误判的边界

- **同位率不等于同裕量。** 节点不必有完全相同的量子数量，但应按网络设计选用兼容的位定时与采样点。某组合在短线能收，不等于在最长线、最低温和最高负载下可靠。
- **SJW不能随便开大。** F407可编程范围是1–4 tq；还要遵守所选CAN位定时约束，至少不能超过BS2。本例的算术断言不是完整晶振容差证明。
- **“精确500000”只针对输入的名义时钟。** 若实际晶振偏移，实际位率也偏移；整数分频精确并不能消除硬件误差。
