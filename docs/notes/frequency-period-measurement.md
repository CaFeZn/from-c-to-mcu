# 测频法与测周法

用同一套频率计测 10 Hz，显示稳定；改测 100 kHz，读数却在 90.9 kHz、100 kHz、111.1 kHz 附近跳动。先别归罪于信号源。若捕获计数时钟只有 1 MHz，一个输入周期只占十格，少一格或多一格就会大幅改变结果。

反过来，开 100 ms 的窗口数输入边沿，100 kHz 能数到一万个，10 Hz 却只有一个。**测量的关键不是选一个公式，而是让被数的东西足够多，同时仍能及时响应。** 本篇接着 [5.3 PWM 与输入捕获](/lessons/5-3) 的 TIM3 输出、TIM2 捕获实验。

## 先在纸上选方法

测频法是在已知闸门时间 `Tg` 内数输入周期数 `N`，得到 `f=N/Tg`。测周法是用已知计数时钟 `fcnt` 量相邻同类边沿间的计数差 `M`，得到 `f=fcnt/M`。

取 `Tg=0.1 s`、`fcnt=1 MHz`，先按理想信号手算：

| 输入 | 闸门内计数 N | 测周差值 M |
|---|---|---|
| 10 Hz | 1 | 100000 |
| 1 kHz | 100 | 1000 |
| 100 kHz | 10000 | 10 |

把量化不确定性粗看作一个计数，测频相对量级约为 `1/N`，测周约为 `1/M`。10 Hz 时两者分别是 100% 与 0.001%；100 kHz 时则是 0.01% 与 10%。这是理想量化估计，不包含参考时钟误差、输入同步、滤波延迟、噪声和闸门实现误差，不能把它直接印成仪表精度。

按照这组参数令两种估计相等，可得交接频率约为 `sqrt(fcnt/Tg)=3162 Hz`。工程切换还要考虑时延并设置迟滞，例如上到某阈值才切测频，降到更低阈值才切回来，避免边界附近频繁抖动。

## 跟做：捕获值不一定递增

沿用主线配置：STM32F407 的 TIM2 输入时钟 84 MHz，`PSC=83`，`ARR=0xffffffff`，上升沿直接输入捕获，不做输入捕获分频。TIM2_CH1 的引脚复用、3.3 V 电平、共地和占用情况仍按板级原理图确认。

先不用中断，把以下两组数交给纯计算函数：

```c
#include <assert.h>
#include <stdint.h>
#include <stdio.h>

static int period_hz(uint32_t previous, uint32_t current,
                     uint32_t counter_hz, double *hz)
{
    uint32_t ticks = (uint32_t)(current - previous);
    if (ticks == 0u || counter_hz == 0u || hz == NULL) {
        return 0;
    }
    *hz = (double)counter_hz / (double)ticks;
    return 1;
}

int main(void)
{
    double hz = 0.0;
    assert(period_hz(100u, 1100u, 1000000u, &hz));
    assert(hz == 1000.0);
    assert(period_hz(UINT32_MAX - 499u, 500u,
                     1000000u, &hz));
    assert(hz == 1000.0);
    assert(!period_hz(100u, 100u, 1000000u, &hz));
    puts("capture: normal=1000 Hz, wrap=1000 Hz");
    return 0;
}
```

第二组从最大值前 499 开始：走 500 格后到 0，再走 500 格到 500，总差仍为 1000。该运算只适用于本例的**全宽 32 位自由运行计数器**，且两次有效捕获真实间隔必须小于 2³² 格。1 MHz 时约 4294.967296 s，即 71.58 分钟。不是“用了 32 位就永远不用管回绕”。

若换 TIM3 的全宽 16 位计数器，要按 16 位模处理；若 `ARR=999`，从 990 到 10 实际差为 20，模数是 1000，直接做 32 位减法就错了。只知道两个余数也无法恢复跨了多少整圈；低频测量需更慢计数时钟、溢出扩展或有上限的超时策略。扩展高位时还必须处理“溢出和捕获几乎同时发生”的排序，不是简单在两个 ISR 各加一句就可靠。

## 硬件捕获解决了哪种误差

输入边沿到来时，硬件把 CNT 锁存到 CCR。CPU 晚几微秒进入 ISR，读出的仍是捕获时刻，不是 ISR 入口时刻。因此用捕获记录时间比“外部中断来了就读一个软件毫秒数”更适合短周期测量。

但 CCR 不是无限队列。F407 的 `CCxIF` 表示发生捕获；在它尚未被清除时又捕获会置 `CCxOF`。这个标志意味着结果可能丢失，不能照旧当成两个相邻边沿。应标记此次测量无效、重新建立起点并统计丢失；高频时用合适的 DMA、输入捕获分频或改变测量方案。

若输入捕获配置为每 8 个有效边沿捕获一次，两个捕获间对应 8 个输入周期，公式要改成 `f=8×fcnt/M`。这与 PSC 降低计数时钟不是一回事。数字滤波同样不是“开了更准”：它可以拒绝短毛刺，也会延后边沿并限制可识别的脉宽。必须把滤波设置、输入分频和边沿极性一起记入测量配置。

## 把测频闸门做对

手工实验可在 100 ms 内数记录中的上升沿：若恰好看到 123 个，估计就是 1230 Hz。上板时不要在高频 GPIO 中断里逐个 `count++` 再靠 `HAL_Delay(100)` 结束窗口，这会把中断丢失和软件起止延迟一起混入结果。

更可控的方案是用定时器外部时钟方式累计输入边沿，再由另一硬件时基提供闸门或同步快照。具体哪些 TRGO/ITR 可以互连，要查 F407 对应定时器的触发映射表，不能随意把任意两个定时器连起来。本篇只给算法和选择方法，不提供未经板级确认的完整闸门固件。

连续计数器的两次快照相减可以减少人为开关窗口的毛刺，但仍需考虑计数器回绕、两次实际采样间隔和门边界上的输入归属。若时基有 20 ppm 频偏，测量就带着相同量级的系统误差；增加打印小数位不会消掉它。

## 让无信号成为一种状态

第一次捕获只保存起点，第二次才有周期。若输入线拔掉，CCR 不再更新，屏幕不能永远保留上一次的“1000 Hz”并称它是当前测量。维护最近有效捕获的时间和量程对应的超时：超时显示“无新信号/低于量程”，而不是立即断言频率为 0。

低频输入可能只是下一个边沿尚未到达。超时时间应大于允许的最长周期，并考虑占空比和启动等待。中断向主循环交付 `ticks`、状态和序号时，保证它们是同一份快照；只给每个字段加 `volatile` 不会自动解决“读值后、清 ready 前又来一次捕获”的事件丢失。

还有一个容易误判的验证：同板 TIM3 产生 PWM、TIM2 捕获，两者常共享同一个晶振。测得 1000.000 Hz 可能只证明分频比例正确，无法证明晶振绝对准确。绝对频率验证要用独立、规格已知的参考。

## 练习：扩大观测跨度

1 MHz 计数时钟测 100 kHz，连续两个边沿只差 10。改为记录第 1 个和第 101 个上升沿，理想差值是多少？频率公式和理想的一格相对量化量级是什么？

<details><summary>展开答案</summary>

两个端点之间是 100 个周期，不是 101 个；理想差值 1000。用 `f=100×1000000/1000=100000 Hz`，理想一格量级约 0.1%。它增加了观察跨度，也增加更新延迟；期间漏边沿、输入变频、参考误差仍须单独处理。不要把 100 个周期的平均频率说成最后一个周期的瞬时频率。

</details>
