# 定时器触发ADC采样

你在主循环里“每隔 1 ms”启动一次 ADC，采直流时没看出问题。换成变化的信号，再加一段串口处理，曲线就开始不均匀：两次启动之间有时很短，有时很长。即使毫秒计数正确，CPU 真正走到启动语句的时间仍会变化。

现在把启动动作换成硬件连线：定时器自己按固定节拍发出内部事件，ADC 看到事件后开始采样，DMA 搬结果。CPU 不必每个采样点都进入一次定时器中断。**这改变的是采样的时间基准，不是让 ADC 不再需要转换时间。**

本篇以前置 [5.2 定时器与节拍](/lessons/5-2) 和 [8.2 ADC 采集电压](/lessons/8-2) 为基础。目标为 STM32F407、ADC1 规则组、独立模式、12 位右对齐。保留主线 TIM6 的毫秒节拍，另用未被占用的 TIM2，不破坏已有软件定时器。

## 先写下想看到的结果

我们要每秒采 PA1 共 2000 次，每 64 项组成一圈 DMA 缓冲。正常持续运行时，预期：

- 相邻触发间隔为 500 µs。
- 每 32 个样本发生一次 HT 或 TC，两种事件合起来平均每 16 ms 通知一次。
- 单独观察 HT，或单独观察 TC，同类事件间隔是 32 ms。
- CPU 做额外的短工作，不应改变硬件触发频率；但仍可能让软件来不及处理缓冲。

这四个量要分开。把“每次回调约 16 ms”误认为“每个点相隔 16 ms”，会让后面的频率分析错 32 倍。

## 从时钟树算到两个寄存器

假定课程时钟树已确认为 HCLK = 168 MHz、APB1 分频为 4、PCLK1 = 42 MHz。F407 在 APB 预分频不为 1 时，对该总线上的定时器使用两倍 PCLK，因此 TIM2 的输入时钟为 84 MHz。

向上计数、每次溢出产生更新事件时：

> 更新频率 = 定时器时钟 ÷ ((PSC + 1) × (ARR + 1))

选 PSC = 83、ARR = 499：先将 84 MHz 除以 84 得到 1 MHz，再数 500 个计数周期，正好 2 kHz。不要填成 84 和 500；寄存器保存的是“减一后的值”。如果你的时钟树不是上述配置，必须按自己的 TIM2 时钟重算，而不是只抄两个数字。

ADC 时钟则来自 APB2：本例 PCLK2 = 84 MHz、ADC 分频为 4，得到 21 MHz。**定时器的两倍规则不能套到 ADC 上。** 本例按约 3.3 V 的模拟供电条件设计；改低供电时需重新核对数据手册允许的 ADC 时钟。

## 在 CubeMX 中接上内部触发线

先确保 TIM2 没被 PWM、编码器或其它模块占用，再按下表配置。界面名称随版本变化，可以用右列的寄存器含义复核生成结果。

| 模块 | 设置 |
|---|---|
| PA1 | ADC1_IN1，模拟模式、无上下拉 |
| TIM2 | Internal Clock、Up，PSC=83，ARR=499 |
| TIM2 主模式 | Trigger Output 选 Update Event，对应 MMS=010 |
| ADC1 规则序列 | 1 次转换，Rank 1=Channel 1，56 Cycles |
| ADC1 分辨率 | 12 位、右对齐，独立模式 |
| ADC1 连续转换 | Disabled，对应 CONT=0 |
| ADC1 外部触发 | TIM2 TRGO，Rising edge |
| ADC1 持续 DMA 请求 | Enabled，对应 DDS=1 |
| ADC1 DMA | DMA2 Stream 0 Channel 0，循环，外设到内存 |
| DMA 地址 | 外设固定、内存递增 |

在 F407 的规则组触发表中，TIM2_TRGO 对应 EXTSEL=0110，触发上升沿对应 EXTEN=01。TRGO 是芯片内部事件，不需要把一个定时器引脚用跳线接到 ADC。也不是随便选一个 TIMx_TRGO 就行：例如 TIM6_TRGO 不在这张规则组触发表中，不能仅凭“它也是定时器”代替 TIM2。

DMA 数据宽度必须与缓冲一致。可沿用主线的半字缓冲与半字搬运；若使用下面这个免指针强转的片段，则**外设和内存宽度都设为 Word（32 位）**，64 项占 256 字节。F407 的 ADC 数据寄存器是 32 位寄存器，右对齐的 12 位结果位于低位。不要只改 C 数组宽度却保留原 DMA 配置。

## 准备完成后，最后启动定时器

下面是集成到已有 HAL 工程中的片段，不是完整固件。假定时钟、GPIO、ADC、DMA 和 TIM2 初始化已生成；DMA 与 ADC 句柄已关联，对应 DMA 中断入口调用 HAL 处理函数，ADC 错误也有处理路径。缓冲必须位于普通 SRAM，不能放 CCM。

```c
/* 文件作用域；使用 CubeMX/HAL 已有类型和句柄。 */
static uint32_t adc_samples[64];

/* 在全部 MX 初始化完成后、仅首次启动时执行： */
if (HAL_ADC_Start_DMA(&hadc1, adc_samples, 64u) != HAL_OK) {
    Error_Handler();
}
if (HAL_TIM_Base_Start(&htim2) != HAL_OK) {
    HAL_ADC_Stop_DMA(&hadc1);
    Error_Handler();
}
```

这些语句放入初始化函数的用户区；数组放文件作用域。片段依赖已有 HAL 头文件、句柄声明和不返回的错误处理约定，尚未以完整板级工程编译或上板。纯时序计算已用独立 C99 模型验证。

启动前还要检查一个不显眼的地方：初始化 PSC/ARR 时常会通过 EGR 的 UG 生成更新事件，以装载预分频器。如果 ADC 此时已经“等触发”，这次更新也可能变成额外的一次采样。应在 ADC 尚未武装时完成定时器装载、设置 CNT 和清除旧状态，然后先启动 ADC+DMA，最后开启 TIM2 计数。运行期间不要再随手发 UG 来“刷新一下”。

这里调用的是 `HAL_TIM_Base_Start`，不是必须每拍进中断的 Start_IT。所核对的 HAL 版本在 ADC 外部触发已启用时，不会由 `HAL_ADC_Start_DMA` 再写 SWSTART，而是准备好等待事件。中途重启、错误恢复应先停触发、妥善停 DMA 与 ADC，再重新准备；不能把首次启动片段无限重复调用。

## 关掉 CONT，为什么还能一直采

CONT=0 的意思是这次规则序列结束后不自动接着开始下一轮；下一次定时器事件仍可以启动新的规则序列。DMA 的循环搬运、ADC 的持续 DMA 请求、ADC 的连续转换是三个不同开关。

若把 CONT 打开，第一次外部触发可能只是把 ADC 拉进自由运行，后续转换按 ADC 自己的速度连续发生，采样率便不再是你以为的 2 kHz。观测到回调远比预计频繁时，应先查这个开关，而不是盲目调定时器中断优先级。

## 一个触发能否来得太快

单路 56 周期采样，12 位转换再用 12 周期，总共 68 周期。在 21 MHz 下约 3.238 µs，明显短于本例 500 µs 的触发周期。实际还存在触发同步和启动延迟，设计要留余量，不能把理论除法的边界当成保证速率。

若改为三个 Rank，采样周期分别为 56、56、480，总耗时为：

> (56+12) + (56+12) + (480+12) = 628 个 ADC 周期

即约 29.90 µs。2 kHz 触发仍留有余量；50 kHz 的周期只有 20 µs，连整段转换都放不下，不能承诺每个触发都产生一帧。不要期待 ADC 为忙碌期间的事件提供无限队列。

三通道每帧产生三个结果，各通道的采样率仍为 2 kHz，总搬运速率是 6 千项/秒。缓冲排列按 Rank 顺序交错，且三路采样有时间偏移。要测真正同时发生的三相信号，还需讨论多 ADC 同步模式，不能把扫描叫作同时采样。

## 怎样验证，而不把回调当采样瞬间

先用低风险直流输入确认量程与通道，再在不阻塞的诊断路径里统计 HT/TC。2 kHz、64 项、单通道的预期已经写在开头：每秒约 31.25 次 HT、31.25 次 TC，短窗口的整数计数会有边界差。

如需验证硬件周期，可将同一定时器的合适比较输出配置到空闲引脚，用示波器核对其周期，再用回调诊断脚观察软件延迟。回调脚反映的是 DMA 完成后 CPU 何时响应，不是采样保持开关闭合的精确时刻。真实抖动、晶振误差、模拟信号建立时间和最坏处理耗时都要实测。

## 练习：改成每秒一千帧

保持 TIM2 输入 84 MHz、PSC=83，想把单通道采样率改成 1 kHz。ARR 应是多少？64 项循环缓冲的半块预算是多少？如果变成三通道扫描、缓冲仍是 64 项，为什么不能直接沿用这份预算？

<details>
<summary>展开答案</summary>

ARR=999，因为 1 MHz ÷ 1000 = 1 kHz。单通道半块为 32 项，预算 32 ms。三通道总速率变成 3000 项/秒，32 项约 10.67 ms，而且半块长度不能整除三通道帧。可改成 96 项，半块 48 项即 16 帧，预算 16 ms；不能只看触发频率而忽略每帧的数据项数。
