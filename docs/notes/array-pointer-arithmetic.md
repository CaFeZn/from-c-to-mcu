# 数组退化与指针算术

在主线里，`int a[10]` 在调用者那里有十个元素，传进函数后 `sizeof(a)` 却只剩一个指针的大小。你可能想用 `&a` 补救，或者觉得“数组本来就是指针”。这两个结论都会让接下来的二维数组和边界处理变难。

我们换一个问题：**同一块数组，在不同表达式里产生的类型是什么？** 类型决定加一跨过一个整数还是一整行，也决定 `sizeof` 量的是哪种对象；边界则决定这些运算有没有意义。

## 一个数组，三种观察方式

把下面完整程序作为独立 C99 实验，沿用 [1.0 的构建方式](/lessons/1-0)，保留断言。输入固定为四个数 `10、20、30、40`，另有一个两行三列的矩阵。先预测 `distance` 是 3 还是 12，再运行。

```c
#include <assert.h>
#include <stddef.h>
#include <stdio.h>

/* The caller supplies n readable elements; every partial sum must fit in int. */
static int sum(const int *a, size_t n)
{
    int result = 0;
    for (size_t i = 0; i < n; ++i) {
        result += a[i];
    }
    return result;
}

int main(void)
{
    int a[4] = {10, 20, 30, 40};
    const size_t n = sizeof a / sizeof a[0];
    int *p = a;
    int (*whole)[4] = &a;
    ptrdiff_t distance = (p + 3) - p;
    assert(sizeof *whole == sizeof a);
    assert((*whole)[2] == 30 && p[2] == *(p + 2));
    assert(distance == 3 && sum(a, n) == 100);
    assert(sum(NULL, 0) == 0);
    printf("count=%zu sum=%d distance=%td\n", n, sum(a, n), distance);

    size_t visited = 0;
    for (const int *it = a; it != a + n; ++it) {
        assert(*it == a[visited]);
        ++visited;
    }
    assert(visited == n);
    int matrix[2][3] = {{1, 2, 3}, {4, 5, 6}};
    int (*row)[3] = matrix;
    assert(row[1][2] == 6);
    printf("visited=%zu matrix[1][2]=%d\n", visited, row[1][2]);
    printf("array_bytes=%zu pointer_bytes=%zu row_bytes=%zu\n",
           sizeof a, sizeof p, sizeof *row);
    return 0;
}
```

前两行是语言层面的固定结果：

```text
count=4 sum=100 distance=3
visited=4 matrix[1][2]=6
```

本次 MinGW 的第三行是 `array_bytes=16 pointer_bytes=4 row_bytes=12`。换成 64 位指针环境，第二个数可能变为 8；若 `int` 大小改变，第一个和第三个数也会改变。前两行不依赖这些具体字节数。

## “退化”不是对象变身

`a` 声明时的类型是“含 4 个 int 的数组”。这块数组始终存在，不会因为赋给了指针就缩成一个地址。在大多数表达式中，数组表达式会**转换成指向首元素的指针**，常被称为数组退化。

因此 `int *p = a;` 中，右边提供 `&a[0]`，左边保存这个指针值。`p` 自己是另一个对象，可以改指向；数组名 `a` 不能像指针变量那样执行 `a = p` 或 `a++`。

C99 中常见的不发生这项转换的场合包括：数组作为 `sizeof` 的操作数、作为一元 `&` 的操作数，以及字符串字面量用于初始化数组。于是：

- `sizeof a` 得到完整数组大小；`sizeof p` 得到指针大小。
- `&a` 的类型是 `int (*)[4]`，指向**整个四元素数组**，不是 `int **`。
- `sizeof *whole` 量到一整个数组，正好等于 `sizeof a`。
- `whole + 1` 指向整个数组对象之后的位置，而 `p + 1` 指向第二个整数。都不能因“加了 1”就理解成增加一个字节。

`char word[] = "OK";` 建立的是三个字符组成的可修改数组，包含结束零；`const char *word = "OK";` 则建立一个指针，指向字符串字面量。后者的 `sizeof word` 并不统计字符串长度。

## 函数参数还有一条单独的调整规则

参数声明里的 `void f(int a[10])` 会被调整为指针参数；调用时，实参中的数组表达式又会转换成首元素指针。**声明调整与表达式转换是两件相互配合的事**。因此把参数改写成 `int a[1000]` 不会复制一千个元素，也不会自动增加运行时边界检查。

长度应在仍然知道数组类型的调用点计算，再与指针一起传入。本实验的 `sum` 接口只借用数据，不拥有它；要求前 `n` 个元素可读，且**每一步部分和**都能由 `int` 表示，不只是最终数学和。例如 `{INT_MAX, 1, -1}` 最终和可表示，但先加到第二项已发生有符号溢出。输入只有四个小整数，因此本次求和没有溢出。把它拿去累计任意采样数据时，应先设计范围或增加溢出检测，不能照抄“累加就一定安全”。

C99 的参数写法 `int a[static 10]` 则增加了调用者必须提供至少十个元素的前提。它不是自动检查器，违反约定并不会变成一种可靠的报错机制。本篇为避免混淆，直接使用“指针 + 长度”的签名。

## 加减以元素计数，但只能在同一数组里走

`a[i]` 等价于 `*(a + i)`。对 `int *` 加 1，是走到相邻的 `int` 元素；并不是把某个整数地址强行加 1。两个合法数组位置相减得到的是下标之差，类型为 `ptrdiff_t`，本实验用 `%td` 打印。

有四个元素的数组，合法元素下标是 0 到 3。`a + 4` 可以形成，作为“最后一个元素之后”的边界哨兵；但不能读取 `*(a + 4)`，也不能继续形成 `a + 5`。**不是只有解引用越界才出问题：越过允许范围的指针运算本身就可能是未定义行为。**

实验循环先判断 `it != a + n`，仅在还有元素时解引用，然后递增到下一个位置。最后一次递增刚好到 one-past，下一次判断结束循环，不会读取那里。不要改成“小于等于终点”。

指针相减要求双方来自同一个数组或它的 one-past 位置，并且差值可由 `ptrdiff_t` 表示。两个独立变量碰巧地址相邻，不构成可相减的数组。也不要通过强制转换成整数再相减，把这条语言限制伪装成合法遍历。

## 二维数组不是二级指针

`matrix` 的元素本身是“3 个 int 的数组”，所以转换后指向第一行，类型为 `int (*)[3]`。`row + 1` 跨过一整行，`row[1][2]` 才是第二行第三个数 6。

`int **` 则指向一个指针对象。把二维数组强转成 `int **` 不会凭空生成一张行指针表，之后访问不合法。遍历矩阵时，保留行类型或使用两层下标最清楚。

即使内存中的所有整数连续排列，也不要拿 `&matrix[0][0]` 当作六元素数组的开始，越过第一行做解引用。这里有嵌套数组的对象边界；“物理连续”不是跨越子数组规则的许可证。若接口确实需要一维平面数据，就一开始声明一维数组，再自行计算经过检查的行列索引。

## 空输入与 sizeof 的两个边界

本实验允许 `sum(NULL, 0)`，因为循环完全不访问指针，也不对它做加法。这是我们自己接口的约定，不代表任意库函数都接受空指针加零长度。尤其不能在进入循环前先计算 `NULL + 0`，再以为“没有移动所以合法”。

`sizeof a / sizeof a[0]` 只适用于当前表达式中的 `a` 确实是数组；将它写成接收指针的“万能长度函数”会静悄悄失效。另外，C99 的变长数组涉及运行时大小，不能把本例定长数组的行为概括为“sizeof 永远不求值、永远是编译期常量”。

## 练习：把错误改到类型上

有 `int grid[2][3]`。某人写 `int **p = (int **)grid;`，并准备调用 `p[1][2]`。请写出正确的指针声明，并说明 `sizeof *p` 应该量到什么。再判断 `grid + 2` 能否形成、能否解引用。

<details>
<summary>展开答案</summary>

正确声明为 `int (*p)[3] = grid;`。`*p` 是一行的数组，`sizeof *p` 等于 `3 * sizeof(int)`，不是指针大小。`grid + 2` 是整个两行数组的 one-past，可以用于结束判断，但不能把它当成第三行解引用。强制转换不能改变原来的对象布局。
