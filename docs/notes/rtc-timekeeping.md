# RTC 与 32.768 kHz 长期计时

设备每天打印一次日期，平时没问题，拔掉 USB 再插上却又回到初始日期。你明明接了后备电池，也在程序里每毫秒累加时间，为什么还会丢？因为普通 RAM 中的毫秒变量、RTC 日历、后备电源和开机初始化是四件不同的事。电池只能保持它实际供电的那部分电路，也拦不住软件每次开机把日期重新写成出厂值。

[5.2 定时器与节拍](/lessons/5-2) 解决的是运行中的短时间调度。本篇用 STM32F407 的 RTC 回答另一个问题：主时钟停了、普通程序重启了以后，怎样继续知道日期和时间？

## 先算清楚“32768”与“一秒”

32.768 kHz 等于 32768 Hz，也就是 2¹⁵。RTC 可把它整除为 1 Hz，无须靠软件凑一个近似小数。F407 的 RTC 使用异步与同步两级预分频：

```text
RTCCLK = 32768 Hz
PREDIV_A = 127    -> 除以 128，得到 256 Hz
PREDIV_S = 255    -> 再除以 256，得到日历更新 1 Hz
```

这里两处都要加一。把寄存器误填 128 和 256，得到 `32768/(129×257)≈0.98839 Hz`，RTC 会明显走慢，不能用晶振“稍有误差”解释。

先做一个手工观测：保持标准分频、24 小时制，不做平滑校准或移位调整，读取一份一致的秒与 SSR 快照。SSR 是同步级的**向下**计数器，不是已经流逝的毫秒数：

| 快照 | 秒值 | SSR | 本秒内已过的名义时间 |
|---|---|---|---|
| A | 10 | 255 | 0 ms |
| B | 10 | 127 | 500 ms |
| C | 10 | 0 | 996.09375 ms |
| D | 11 | 255 | 新的一秒开始 |

按 `(PREDIV_S-SSR)/(PREDIV_S+1)` 秒计算。分辨率是 1/256 s，约 3.90625 ms，**不是因为晶振是 32768 Hz，就能从这个 SSR 配置读出 30.5 µs 分辨率**。改变两级分配可以调整子秒分辨率，但会影响功耗和其他功能约束，先遵守当前项目需求。

## 先把硬件边界画出来

在 F407 上，LSE 是低速外部振荡器，LSI 是约 32 kHz 的内部 RC，二者不是同一个东西。主晶振的 HSE 分频也能作为 RTC 源，但停主供电后，不是每一种源都还能工作。

采用 LSE 且 VBAT 持续满足供电要求时，RTC 可以在 VDD 消失后继续计时。普通 CPU、SysTick 和主 RAM 里的变量不会因此继续运行或自动保留。LSI、HSE 不属于同样的 LSE 后备供电时钟路径，不能因为 RTC 还在备份域就承诺它们掉电仍走。

检查原理图：板上是否真的焊了 32.768 kHz 晶体及匹配网络，PC14/PC15 是否被其他用途占用，VBAT 是否被直接接到了 VDD，电池座极性和电源隔离是否正确。先断电确认连接，不随意给板上电源节点外加电压。没有 LSE 的板子可以先用 LSI 学软件流程，但不能把该结果当成电池后备时钟验收。

## 开机时不要每次“校准到昨天”

首次配置的逻辑次序如下，具体调用沿用目标工程的 HAL/Cube 初始化，不把这张表当裸寄存器整段赋值脚本：

1. 使能 PWR 接口时钟，按手册开放备份域写访问。
2. 启动板上实际存在的 LSE，等待 LSERDY，必须有可用的超时与错误路径。
3. 选择 RTC 时钟并使能 RTC；如果已有有效配置，不为“保险”随意复位备份域。
4. 按 RTC 写保护与初始化模式的流程进入配置，设置分频、格式与初始日历；退出后等待同步，再恢复写保护。
5. 在约定的备份寄存器写入初始化标记和配置版本；后续启动先验证标记、时钟源和日期合理性，再决定是否保留现有日历。

标记不是魔法：电池失效、备份域复位、固件改变数据格式都可能让它失效。也不要只看一个常数就信任所有字段。检查 RTC 初始化状态、配置版本和允许的日期范围，必要时让用户或可信时间源重新授时。

普通系统复位与备份域复位影响不同。特别是更换 RTC 时钟源，F407 的选择受到备份域复位约束；复位会丢掉你正想保存的日历和相关配置。设计迁移流程，不能把“重新跑一遍初始化”当无副作用操作。

## 午夜是读取一致性的好考题

假设日历刚好从某月最后一天的 23:59:59 跳到次月 1 日的 00:00:00。分别随意读时分秒和日期，可能拼出从未存在过的一刻。F407 默认 `BYPSHAD=0` 时通过影子寄存器读取：读 SSR 或 TR 会锁住更高阶日历影子，读 DR 才解除。

因此把“一次采样”封装成不可被其他读取者打断的顺序：**需要子秒时先读 SSR，再读 TR，最后一定读 DR**。只需要时间时也要完成读取日期的步骤，避免影子长期锁住。RTC_TR、RTC_DR 内的日历字段采用 BCD，SSR 是二进制计数；十六进制字段 `0x23` 的小时是 23，不是十进制 35。

正常同步模式还要满足总线与 RTC 时钟关系，本篇假定 PCLK1 至少是 RTCCLK 的七倍。系统复位、退出 Stop/Standby 或重新初始化后，按手册处理 RSF 并等影子同步。若开启 BYPSHAD 绕过影子，就必须改成手册规定的重复读取一致性检查，不能沿用一次读三项的保证。量产前也要检查精确器件修订版的勘误。

用日志验证时，故意在午夜附近连续取快照：预期是旧日 23:59:59 后出现新日 00:00:00，不出现新日 23:59:59 这种拼接；同一份数据交给显示和存储，不要让它们各自穿插读一半。

## 分频准确，为什么一个月还差几十秒

32768 是标称频率。若实际源快 20 ppm，则每天名义日历大约多走 `86400×20/1000000=1.728` 秒，30 天约 51.84 秒。整除只能保持输入频率的比例，不会修掉晶体的初始偏差、温度变化和老化。

RTC 的平滑数字校准通过在校准窗口中掩去或补入时钟脉冲调整平均走时，不是改写当前日期。按 RM0090 的 32 s 标准窗口，约 2²⁰ 个输入脉冲，每个调整单位约 0.954 ppm。若已用独立参考确认持续快约 20 ppm，负向校正大约需要掩去 21 个脉冲；设置前仍须按 CALR、RECALPF 和窗口约束执行，不是每次读数跳动就马上改参数。

一次校准只能针对测量时的条件。温度变了误差仍可能改变；通信收到时间后直接把日期拨回，也会使“墙上时间”倒退。因此任务超时继续使用单调时间戳，RTC 用于日历与日志。需要合并两者时明确重设、睡眠和授时后的策略。

## 练习与验收清单

板上 RTC 用 LSE，标准分频。你只反复读 TR，看到时间像被冻结；同时重启后又回到编译时的日期。分别先排查什么？SSR=191 时本秒内名义经过多少时间？

<details><summary>展开答案</summary>

先检查是否漏读 DR，导致影子锁没有解除，并确认 RSF 同步与正确的读取流程。重启丢日期则检查初始化是否每次重设日历或复位备份域，同时检查 VBAT 与 LSE 实际供电。SSR=191 时已走 `(255-191)/256=0.25` 秒，即 250 ms。

</details>

有板子后至少分别测试：普通复位保留时间、仅断 VDD 且保持合规 VBAT 后继续走时、移除后备电源后的失效识别，以及独立参考下的长时间偏差。每一项注明供电、晶体、温度和观察间隔，不用一次“拔线后还能显示”代替全部验收。
