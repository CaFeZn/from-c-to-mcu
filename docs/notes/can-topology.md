# CAN总线拓扑与长度

桌上20厘米的两块板能通信，装到设备里加了10米线就偶发CRC错误。位率没变，程序也没变，问题为什么出现？换线同时改变了传播延迟、阻抗不连续、支线长度和共模环境；只把“波特率相同”检查一遍还不够。

本篇继续 [7.1 CAN发出第一帧](/lessons/7-1) 的真实总线接线，针对**常见高速差分CAN线形网络**。不把规则推广到低速容错CAN、单线CAN、主动星形耦合器或所有工业接地系统。

## 先画线路，而不是先数节点

基础拓扑是一条主干，两端终端，节点以尽量短的支线接入：

```text
CAN_H  +----------+-----------+-----------+
       |          |           |           |
     120 Ω     收发器B      收发器C      120 Ω
       |          |           |           |
CAN_L  +----------+-----------+-----------+
       主干端点    中间节点用短支线接入    主干端点
```

图里的每个120 Ω都跨接CAN_H与CAN_L；不是在线上串入电阻，也不是各自接地。主干用适合CAN的双绞线，H接H、L接L。节点的电源地、通信参考地、屏蔽与保护地如何连接，需要结合隔离方式和现场地电位差设计，不能把“差分”误读成永远不需要参考路径。

真正重要的是**电气路径的端点**。某个中间节点是“主控”，不代表终端就应放在那里。若两个终端都放在机柜里，而线缆还向两边延伸，远端的反射不会因为设备名字正确就消失。

## 用万用表先做一个有输入、有预期的检查

实验前关闭并隔离所有节点、分析仪和可能经USB供电的设备电源，确认没有带电回路。电阻档不能直接用在带电总线上。对照原理图，确认没有其他跨线直流电阻路径干扰判断。

给定两端各120 Ω，其他节点没有终端，测CAN_H到CAN_L：

```text
R = 1 / (1/120 + 1/120) = 60 Ω
```

预期约60 Ω，允许电阻公差、引线和器件路径带来差异。断电状态下去掉一端终端，再测应接近120 Ω；恢复后再测回60 Ω。若另外误开一个模块自带的120 Ω开关，三只并联约40 Ω。**每个节点都接120 Ω不是“更稳”，而是不断加重驱动负载。**

测出60 Ω只证明这次直流测量接近预期，不证明终端放在正确位置，更不能证明高频阻抗、线缆屏蔽或接地正常。线头短接后也可能量到某种电阻，但显然不能工作。它是排查的第一步，不是最终验收。

## 为什么短支线与两端终端有关

CAN边沿沿线传播，遇到阻抗不连续时会产生反射。终端电阻接近线缆特性阻抗，可减少主干端点反射。典型设计使用约120 Ω的线缆与终端；这是信号传输条件，不是CAN_ID或软件配置里的数字。

中间节点伸出一根很长、末端没有匹配的支线，相当于添加了另一条反射路径。反射往返后可能在采样附近让差分电压再次越过接收门限，造成位错误或填充、CRC等后续错误。支线能多长还受驱动边沿快慢影响，**降低位率不必然等比例允许更长支线**，因为收发器边沿不一定随之变慢。

TI的SLLA270在其高速CAN讨论中给出1 Mbit/s时0.3 m支线的推荐条件，并说明更长支线需要考虑边沿、延迟和实际设计。这是有前提的参考，不是“任何网络超过30厘米都必坏”或“低于30厘米必好”。

被动星形连接把多条长支路集中在一个结点，每条线又都有反射与延迟，不再是上面的简单线形网络。真要星形，应采用明确支持相应拓扑的有源设备并重新预算；不能仅在星形的每个末端加120 Ω碰运气。

## 长度不是一个从位率查出来的绝对常数

仲裁时最远节点的状态必须有时间传播回来。只算线缆单程延迟会过于乐观；还要算驱动器、接收器、隔离器及具体路径中的其他延迟。TI应用笔记用双绞线约5 ns/m作典型示例，但你的线缆规格和温度范围才是实际依据。

做一个**明确假设的预算练习**：

- 线缆单程传播延迟假定为5 ns/m。
- 往返路径所需电子器件总延迟假定为400 ns；它是本题给定值，不对应某个型号的保证。
- 系统位定时设计为传播单独分配700 ns预算，已经打算把其他时间留给同步与裕量。

则：

```text
t_loop = t_fixed + 2 × L × t_cable
20 m : 400 + 2 × 20 × 5  = 600 ns
100 m: 400 + 2 × 100 × 5 = 1400 ns
模型允许长度 = (700 - 400) / (2 × 5) = 30 m
```

预期20 m通过这一个预算条件，100 m不通过。**30 m是本题模型的计算结果，不是500 kbit/s或F407的通用长度上限。** 假设改变，结果就改变。若固定电子延迟已经超过预算，则再短的线也不能补救这个预算设计。

前一篇算出的500 kbit/s、85.7%采样点约在1.714 μs。不能直接把整段1.714 μs都送给线缆，再宣布剩下几米可用；采样前的时段还包含同步、相位缓冲与其他约束，后段与SJW也要满足振荡器误差要求。这里的700 ns是为了教学单独给定的预算，不是从采样点百分比自动推得的标准值。

TI SLLA270的参考表包含500 kbit/s、100 m这一组建议。它适合做初筛，却不能与上面的30 m“矛盾”地二选一：两者假设不同，表格没有替你的收发器、隔离器和拓扑作完整验证。最终设计应列清每项器件的最大延迟，而不是只相加典型值。

## 一次只改一个变量的台架实验

从已能稳定通信的两个节点出发，固定消息内容与发送周期：

1. 先保存短线、正确终端时的错误计数、有效接收数和差分波形。不能只记录“灯亮”。
2. 断电后换成目标长度的线形主干，仍只保留两端终端，重新检查电阻和端点。
3. 通电观察相同时间窗口里的TEC、REC、LEC与消息丢失，不同时改变位率、采样点和发送频率。
4. 在这个基础上一次加一个中间节点；核对新模块是否暗含终端、长支线或隔离器。
5. 如需比较支线影响，仅在安全测试台架按设计允许范围更换支线，保留每次接线图与测量结果。

这些是待做的实验步骤，不是本篇已取得的实测。无差分探头时，先做直流检查和错误统计；不要用危险探头接法制造一个新的短路或地回路。

## 还有两个“看起来像距离”的问题

**节点数不是一个只由ID位数决定的数。** 每个收发器的输入负载、节点寄生电容、连接器、保护器件和支线都会改变总线。11位ID有很多取值，不代表能挂同样多的物理节点。使用具体收发器的负载能力和网络规范核算。

**通信恢复不等于裕量充分。** 降到125 kbit/s后暂时不报错，只说明新的条件更宽松或掩盖了问题；它没有证明错误终端、接地或过长支线从此合规。应在目标温度、电压、负载和干扰条件下继续验证。

## 练习：加隔离器以后

仍采用700 ns预算与5 ns/m线缆。在原400 ns电子延迟之外，往返路径总计增加120 ns隔离延迟。模型长度上限是多少？原来的20 m方案还能通过这个条件吗？

<details><summary>展开答案</summary>

固定延迟变为520 ns，剩余180 ns给线缆，长度上限`180/10=18 m`。20 m时总延迟`520+200=720 ns`，超过700 ns，不能通过这一预算。可重新选择器件或位定时/位率方案，但不能删除120 ns这一项让表格好看。通过预算仍需验证反射、共模、电压和容差，不代表直接通过整机验收。

</details>
