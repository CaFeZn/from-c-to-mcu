# 野指针与悬空指针

一段数据刚刚还能打印，交给清理函数后再打印就偶尔变成乱码。你加上一句 `if (p != NULL)`，错误仍然出现：指针明明不是空，为什么不能读？

因为“不是空指针”只排除一种特殊值，并没有回答**它是否还指向一个活着的、大小足够的、允许这种访问的对象**。内存管理出问题时，与其盯着地址数字，不如画出对象的生命周期，以及谁有权结束它。

## 先把这几种故障分开

未经初始化的自动指针没有可用的指向，把它称为“野指针”便于提醒，但不要以为它必定保存某个随机且可打印的整数。拿它做判断或解引用都不是安全的初始化办法，应从 `NULL` 或一个有效对象地址开始。

“悬空指针”通常指目标对象的寿命已经结束：局部对象离开所在块，或分配对象已释放，而程序还保留着旧的访问路径。按这里核对的 C 规则，目标寿命结束后，指向它或其 one-past 的指针值变为不确定值；不能继续把旧值打印、比较并据此证明地址有效。

还有一种问题是**内存泄漏**：对象还分配着，但程序丢失了最终应负责释放它的路径。它与“过早释放后继续用”方向相反，可能同时出现在同一个模块里。

## 让所有权写进最小接口

下面程序把一块动态数组交给 `Buffer` 管理。约定 `Buffer` 是唯一所有者，其他指针只是短期借用者。初始化、销毁都传对象地址；没有隐藏全局状态。

这是可独立构建的 C99 程序，沿用 [1.0 的实验工程](/lessons/1-0)。输入固定为三个整数空间，在第二个元素写 42。先预测销毁后哪些指针可以继续读取，再运行，保留断言。

```c
#include <assert.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int *data;
    size_t count;
} Buffer;

/* Call only on an empty, initialized owner. */
static int buffer_create(Buffer *b, size_t n)
{
    if (n == 0) {
        return 1;
    }
    if (n > SIZE_MAX / sizeof *b->data) {
        return 0;
    }
    int *p = malloc(n * sizeof *p);
    if (p == NULL) {
        return 0;
    }
    for (size_t i = 0; i < n; ++i) {
        p[i] = 0;
    }
    b->data = p;
    b->count = n;
    return 1;
}

static void buffer_destroy(Buffer *b)
{
    free(b->data);
    b->data = NULL;
    b->count = 0;
}

int main(void)
{
    Buffer owner = {NULL, 0};
    assert(buffer_create(&owner, 0));
    if (!buffer_create(&owner, 3)) {
        fputs("allocation failed\n", stderr);
        return EXIT_FAILURE;
    }
    int *borrow = owner.data;
    borrow[1] = 42;
    assert(owner.count == 3 && owner.data[0] == 0 && owner.data[1] == 42);
    printf("count=%zu value=%d\n", owner.count, borrow[1]);
    borrow = NULL;
    buffer_destroy(&owner);
    assert(borrow == NULL && owner.data == NULL && owner.count == 0);
    buffer_destroy(&owner);
    puts("owner=empty borrow=null destroy_twice=ok");
    return EXIT_SUCCESS;
}
```

分配成功时输出：

```text
count=3 value=42
owner=empty borrow=null destroy_twice=ok
```

分配失败则输出 `allocation failed` 并以失败状态返回；不能把 `malloc` 永远成功当实验前提。分配后使用循环写入整数零，明确建立元素值；未初始化的分配空间不能直接当读数使用。

## 安全来自释放协议，而不是一句判空

跟着代码走一遍：

1. `owner` 先明确初始化为 `{NULL, 0}`。`buffer_create` 要求传入的所有者有效且为空，避免覆盖已有分配造成泄漏。
2. 分配前先用除法检查 `n * sizeof *p` 是否可表示，再做乘法。拿到空指针时不修改所有者状态。
3. `borrow` 在对象存活期间借用数组，写下标 1，所有者能够看到值 42。
4. 不再需要借用后，先把 `borrow` 重新赋为 `NULL`，再销毁所有者。释放前就结束这个实验中唯一的借用关系。
5. 销毁函数释放内存，然后把**调用者的**成员改成空指针与零长度。再次销毁时传给 `free` 的是空指针，所以没有操作。

第二次销毁安全不意味着“同一个分配可以 free 两次”。安全的是本封装第一次销毁后已经把所有者状态复位；直接重复 `free` 原来的指针仍然非法。

接口并不能自动找到世界上所有别名。假如另外还有 `int *other = owner.data;`，给 `owner.data` 赋空不会同步修改 `other`。本例把借用清零只是一种局部演示，实际项目应保证所有借用在销毁之前结束，而不是希望释放函数遍历所有指针。

## 返回局部地址，为何加 static 也不是通用答案

若一个函数在内部声明普通自动数组，然后返回首元素地址，函数返回时数组寿命结束。调用者拿到地址，并不会把数组从函数中“搬出来”。调用后立即访问也不合法；“还没调用下一个函数，栈没有被覆盖”不是 C 语言的保证。

可以根据需求选择三种接口：

- **按值返回**一个小整数或小结构体，由调用者获得独立结果；
- **调用者提供缓冲区与容量**，被调用者只在约定范围内填充，寿命由调用者控制；
- **显式分配并转移所有权**，说明谁负责释放、失败返回什么。

把局部数组改成 `static` 能延长寿命，却改成了共享同一块存储。下次调用可能覆盖上次的结果，递归、多实例和中断重入也可能互相干扰。它适合某些明确共享的状态，不是可以对所有“返回地址”警告套用的修复。

## realloc 不只是“把原数组变长”

对于本篇 C99 范围，扩容可以先用临时指针接结果：分配大小为正且已检查乘法，失败则保留原对象；成功才用新返回值更新所有者。不要直接写 `p = realloc(p, bytes)` 后才判断失败，否则失败时可能丢掉原来的所有者指针。

成功的 `realloc` 结束旧对象寿命，返回新对象的指针。即使它恰好使用相同地址，旧的元素指针和旧别名也不能据“地址没变”继续使用。应先保存必要的索引或偏移，成功后从新对象重新计算访问位置，不拿旧指针与新指针比较来决定是否修复别名。

零大小分配和零大小 `realloc` 在不同标准版本与实现中有额外差异。本篇封装自己定义 `n == 0` 为保持空对象，不调用分配函数，避免把 C99、C11 与 C23 的规则混着教。它不是通用可变长容器，也没有模拟分配器的所有失败情况。

## 带到单片机，要再问“谁还在用”

异步操作把寿命问题放大了。例如函数内部有一个局部发送数组，启动 DMA 后立即返回。如果驱动仍然借用该数组，而不是在调用期间复制完成，硬件稍后还会继续读已经失效或复用的存储。阻塞式发送与异步发送的缓冲区契约不能混为一谈。

解决思路是让缓冲区至少存活到完成通知，且期间不被其他代码改写；可以由持久对象、队列槽位或明确的所有权转移来管理。单纯加 `volatile` 不延长寿命，也不防止另一个模块释放或复用数据。本篇没有启动 DMA；具体缓冲区可达性、对齐、并发与驱动接口仍要查目标芯片和驱动说明。

内存检查工具可能报告 use-after-free 或栈寿命错误，但没有报告不代表接口正确。裸机释放后的 RAM 往往仍可访问，不一定立刻故障，因此必须在设计中说明对象的生灭边界。

## 练习：按值传销毁函数，问题在哪

如果把销毁接口改成 `void buffer_destroy(Buffer b)`，在里面 `free(b.data)` 然后令 `b.data = NULL`，调用者的结构体还能重复销毁吗？如果另一模块保存了 `Buffer copy = owner`，这个拷贝是否自动获得了独立数组？

<details>
<summary>展开答案</summary>

按值传参只复制结构体成员。`free(b.data)` 仍然释放了共享指向的分配对象，但把形参成员设为空只改了副本，调用者仍保留失效状态，再销毁将出错。应传所有者结构体地址，或让接口返回新状态并明确使用。

`Buffer copy = owner` 也是浅拷贝，只复制指针与计数，并没有复制数组。它不能自动成为第二个独立所有者。需要独立副本时应另分配并复制元素；需要转移所有权时应明确移动并使旧所有者变空，所有借用同时重新审视。

</details>

## 适用范围与技术依据

本实验是单线程 C99 普通堆内存管理，不承担线程安全、实时分配或 DMA 驱动保证。已执行成功分配、零长度、借用结束、销毁复位与空对象重复销毁路径；没有人为执行 use-after-free，也没有把非法访问的某次输出当作答案。
