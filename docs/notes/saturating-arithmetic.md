# 饱和运算

> **前置**：[1.3 整型与位运算](/lessons/1-3)。本篇关注“越界以后应该怎么办”，不是给回绕换个名字。

## 亮度快到头了，再加一点却变暗

把 LED 亮度保存为 `uint8_t`，范围约定为 0 到 255。现在亮度是 250，用户按一次“增加 20”。如果写成 `level = level + 20;`，计算出的 270 存回八位无符号类型后变成 14，灯反而暗了。

回绕对循环计数很有用，对亮度却不合需求。用户期待的是：还有余量就增加，已经接近上限就停在 255。这个“停在边界”的规则叫**饱和运算**。它改变的是结果定义，不是把错误藏起来。

先预测：如果信号采样值是带符号十六位，30000 加 10000 应停在哪边？−30000 再加 −10000 呢？负数不是统一钳成零，它有自己的下限。

## 一、先把期望写成边界表

对区间 `[L, U]`，先求精确数学结果 s，再返回：小于 L 就选 L，大于 U 就选 U，否则保留 s。这叫限幅。饱和加法就是“加法结果的限幅”。

| 输入与目标 | 数学和 | 饱和结果 |
|---|---:|---:|
| 无符号八位：250 + 20 | 270 | 255 |
| 无符号八位：255 + 0 | 255 | 255 |
| 有符号十六位：30000 + 10000 | 40000 | 32767 |
| 有符号十六位：−30000 − 10000 | −40000 | −32768 |
| 有符号十六位：−32768 + 32767 | −1 | −1 |

表里区分了“恰好等于边界”和“已经超出边界”。返回值可能一样，但如果还要统计削顶次数，就必须保留是否真的发生限幅的信息。

## 二、先扩宽，再检查，最后缩窄

下面是可独立编译运行的 C99 程序。它要求实现提供 `uint8_t`、`int16_t`；这两个精确宽度类型在标准里是可选的，在课程使用的 PC 与 STM32 工具链中存在。扩宽用的 `int_least32_t` 是 C99 要求提供的最小宽度类型，不要求本机 `int` 是 32 位。

```c
#include <assert.h>
#include <stdint.h>
#include <stdio.h>

static uint8_t sat_u8_add(uint8_t a, uint8_t b)
{
    unsigned sum = (unsigned)a + (unsigned)b;
    return sum > UINT8_MAX ? UINT8_MAX : (uint8_t)sum;
}

static int16_t sat_i16_add(int16_t a, int16_t b)
{
    int_least32_t sum = (int_least32_t)a + (int_least32_t)b;
    if (sum > INT16_MAX) return INT16_MAX;
    if (sum < INT16_MIN) return INT16_MIN;
    return (int16_t)sum;
}

int main(void)
{
    assert(sat_u8_add(255, 0) == 255);
    assert(sat_i16_add(INT16_MIN, INT16_MAX) == -1);
    assert(sat_i16_add(30000, 10000) == INT16_MAX);
    assert(sat_i16_add(-30000, -10000) == INT16_MIN);
    printf("u8: wrap=%u sat=%u\n",
           (unsigned)(uint8_t)(250u + 20u),
           (unsigned)sat_u8_add(250, 20));
    printf("i16: upper=%ld lower=%ld\n",
           (long)sat_i16_add(30000, 10000),
           (long)sat_i16_add(-30000, -10000));
    return 0;
}
```

预期输出：

```text
u8: wrap=14 sat=255
i16: upper=32767 lower=-32768
```

这段代码安全，不能只凭“用了大类型”来判断，要把每一步的范围写出来：

1. 八位无符号输入相加最多是 510，C99 的 `unsigned int` 至少能表示到 65535，足够。
2. 十六位有符号输入相加，最小 −65536，最大 65534，至少 32 位的有符号类型足够。
3. 检查通过后才转回窄类型，所以最后的有符号转换一定在范围内。

强制转换写在加法的**操作数上**，不是写在整个加法外面。若先算 `a + b` 再把结果转成大类型，在 `int` 只有 16 位的实现上，加法本身就可能先溢出了；后来的扩宽救不回来。

## 三、三十二位也一样，但需要更宽的中间值

若目标是 `int32_t`，不能直接照搬“先存到 `int32_t` 再判断”。下面的函数可放在包含 `stdint.h` 的 C99 程序里：

```c
static int32_t sat_i32_add(int32_t a, int32_t b)
{
    int_least64_t sum = (int_least64_t)a + (int_least64_t)b;
    if (sum > INT32_MAX) return INT32_MAX;
    if (sum < INT32_MIN) return INT32_MIN;
    return (int32_t)sum;
}
```

输入的极端和是 −4294967296 与 4294967294，都能放进至少 64 位的中间类型。这个函数要求实现提供 `int32_t`，但不依赖可选的精确 `int64_t`。对 `INT32_MAX` 加一返回 `INT32_MAX`，对 `INT32_MIN` 减一返回 `INT32_MIN`。

在 Cortex-M4 上，宽整数运算可能需要多条指令。这是性能问题，不是正确性问题；先留下一份能证明、能测试的 C 版本，再考虑替换热点。不要为了少一条转换，把未定义行为重新塞回表达式。

## 四、Cortex-M4 确实有饱和指令，但功能不同

STM32F407 的 Cortex-M4 可以用下列指令。这里只展示手册规定的寄存器语义，不是可在 PC 上执行的 C，也不是完整固件；本文没有做上板或周期测量。

```asm
; given R0 = 40000
SSAT R1, #16, R0       ; R1 = 32767

; given R2 = 2147483647, R3 = 1
QADD R4, R2, R3        ; R4 = 2147483647
```

**SSAT 是限幅，不是加法。** 它读取一个有符号寄存器值，将结果限制到指定的有符号 n 位范围；n 可取 1 到 32。`#16` 对应 −32768 到 32767，结果仍放在 32 位寄存器里。两个十六位数可以先安全地在 32 位中相加，再用它限到十六位。

**标量 QADD 是三十二位饱和加法。** 它把两个有符号 32 位操作数相加并饱和到该范围。不能把“先执行可能溢出的普通 C 加法，再交给 SSAT”当作它的替代：参数求值时发生的 C 未定义行为，后面的指令无法补救。

PM0214 还规定：这里的 SSAT 与标量 QADD 在发生饱和时置 APSR 的 Q 位，否则保持原值。Q 是**黏性的历史标志**，不能看见一次 Q=1，就断言刚才那一步一定饱和；清零需要明确的状态寄存器操作。别把它误认为普通运算会自动更新的“本次是否越界”布尔值，也别把标量 QADD 的规则推广给所有打包 SIMD 指令。

真正接入工程时，应使用工具链/CMSIS 支持的接口并核查生成指令。函数命名、头文件、优化效果都属于具体实现契约；本文的可移植示例故意不依赖这些接口。

## 五、饱和也有代价，不能到处加

**先丢失再限幅，已经晚了。** 如果先把 270 存进 `uint8_t` 得到 14，再问“是否大于 255”，永远检测不到原来的越界。带符号溢出更危险，不是得到一个坏数字后还能补救，而是失去了语言层面的保证。

**饱和会改变代数性质。** 每一步削顶会丢掉超出的部分，后面再减回来也找不回原值。滤波器、混音和控制器需要明确在哪一层限幅；一次最终限幅与逐步饱和，不一定等价。削顶可能是产品需要的策略，也可能应该返回错误或记录告警。

**循环计数不一定想饱和。** 时间戳差值、环形索引、协议序号常常依赖模运算；把这些计数改成“到头停住”，可能使超时检测永久失效。饱和适合幅度边界，不是“所有溢出问题”的统一修复。

## 练习：交换括号，输出会一样吗

使用上面的十六位饱和函数，分别计算：

```c
sat_i16_add(sat_i16_add(30000, 10000), -10000)
sat_i16_add(30000, sat_i16_add(10000, -10000))
```

<details>
<summary>展开结果与原因</summary>

第一式先把 40000 饱和到 32767，再减 10000，得到 **22767**。第二式先得到零，再加 30000，结果是 **30000**。因此饱和加法一般不满足结合律。

若算法要求的是“三个输入的数学和最后限幅”，就把三次输入先转换到能容纳全部中间结果的类型，完成累加后再限幅一次。对这三个十六位输入，至少 32 位足够；对任意长度的数据流，不能无限套用这个结论，仍要计算累计上界。

</details>

## 适用范围与继续阅读

这里的 C99 代码只处理整数加法。乘法、浮点转整数、带小数的定点缩放，都要重新分析中间范围与舍入；不能先执行可能越界的表达式，再套一个通用限幅宏。示例同时检查上下界与异号输入，而不是只验证“正数加太大”一种情况。
