# 3.1 串口与日志

> **这一节你会做出**：让板子通过串口开口说话；亲手撞上 `printf` 在中断里的坑；然后换上一个不会卡住程序的日志层 `LOG()`。本教程往后所有板上输出都用它。
> **前置**：[[2.2_开发环境与第一次点灯]]　[[2.4_程序是怎么跑起来的]]　｜　**预计**：阅读 + 动手 60 分钟

> [!tip] 跳读自测：这一节你可能不用读
> 先回答下面几个问题（写下来，别只在心里答）。**全部答对**就直接跳到 [[3.2_调试与排错]]；有一题拿不准，就从头读。
> 1. 波特率 115200，一个字节在线上占 10 位。一个 21 字节的字符串，用阻塞方式发出去大约要多久？如果这句话放在每 1 ms 触发一次的定时器中断里，会出什么问题？
> 2. 下面这段中断回调有两处不妥，指出来：
>
>    ```c
>    void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
>    {
>        if (htim->Instance == TIM6) {
>            LOG(LOG_INFO, "x=%f\r\n", g_x);     /* g_x 是 float */
>        }
>    }
>    ```
>
> 3. 日志缓冲满了的时候，`LOG()` 会阻塞等串口吗？你怎么知道丢了多少行？
> 4. 用 DMA 发送日志，CubeMX 里除了打开 USART1，至少还要配哪两处？漏掉其中一处会是什么现象？
>
> > [!success]- 答案，以及跳过后要带走的东西
> > 1. 每个字节约 86.8 µs，21 字节约 1.8 ms，比 1 ms 的中断周期还长。中断一结束下一次又来，主循环几乎分不到时间。
> > 2. 其一，中断里不该输出，应该只记计数或标志，主循环里再打印。其二，`%f` 在默认的精简 C 库下不被支持，浮点要先转成整数再打印。
> > 3. 不会阻塞。放不下时整行丢弃并计数，用 `log_dropped()` 查。
> > 4. 一处是 USART1_TX 的 DMA（Normal 模式），另一处是 NVIC 里的 USART1 global interrupt。漏了中断，会只看到第一行日志，之后没有了。
> >
> > **带走清单**：
> > - 文件：本节「第五步」里的 `log.h` 放进 `User/Inc/`，`log.c` 放进 `User/Src/`，直接复制即可。CMake 会自动把它们收进来（顶层 `CMakeLists.txt` 里的 GLOB 那几行，见 2.2），新增文件后重新配置一次。
> > - CubeMX：USART1 异步模式 115200 8N1；USART1_TX 的 DMA（Normal）；USART1 全局中断。
> > - 用法：`main.c` 里 `#include "log.h"`，在 `MX_USART1_UART_Init` 之后调用 `log_init(&huart1)`。
> > - 约定：`LOG()` 输出的就是格式化后的原文，不加时间戳和级别标签，也不补换行，格式串自己写 `"\r\n"`；级别只用来过滤；支持 `%d %u %ld %lu %x %s %c`，不支持浮点；二进制数据用 `log_write_raw()` 原样发出；中断里不输出；`huart1` 的发送由日志层独占，`HAL_UART_TxCpltCallback` 只在 `log.c` 里重写。

## 先看一个怪现象

你要寄一个包裹。方式一：站在柜台前，看着工作人员称重、填单、装车，办完你才离开。方式二：丢进快递柜，扫码就走，快递员有空自己来取。

寄一件，两种方式没差别。可如果你同时还要照看一台每毫秒都要调整一次的电机呢？

1.1 的结尾留了一个问题：单片机上没有操作系统，没有终端，甚至没有屏幕，那句 hello 要怎么说出来？这一节回答它，顺便看清"站着等"和"扔了就走"到底差在哪。

> [!question] 先猜一猜
> 板子上没有屏幕，也没有终端。要让它"说话"，让你在电脑上看到字，最少需要凑齐哪几样东西？先在心里列一个清单。

> [!success]- 揭晓
> 三样。
> 1. 板子这头：一个能把字节一位一位发出去的外设，也就是**串口**（UART）。
> 2. 中间：一根线，加一个把板子的电平转成电脑 USB 能认的小模块，叫 **USB-TTL**。
> 3. 电脑这头：一个把收到的字节显示成文字的软件，叫**串口助手**。
>
> 清单里没有"屏幕"。屏幕是电脑的，板子只管把字节送出去。

## 动手做

### 第一步：接线，打开串口助手

你需要一个 USB-TTL 模块（常见的是 CH340、CP2102 这类芯片的小板）。如果你的开发板自带 USB 转串口，直接用 USB 线连电脑，跳过接线表，具体接哪个口以板子原理图为准。

| USB-TTL 模块 | 板子 | 说明 |
|---|---|---|
| GND | GND | 必须共地，否则电平没有参照 |
| RXD | USART1_TX（CubeMX 默认 PA9） | 板子"发"，模块"收"，所以是交叉接 |
| TXD | USART1_RX（CubeMX 默认 PA10） | 本节只发不收，可以先不接，6.1 会用到 |
| VCC / 5V | 不接 | 板子有自己的供电，两路电源对接容易出事 |

两个容易错的地方：

- **交叉**：一方的 TX 接另一方的 RX。接反是最常见的原因。
- **电平**：F407 的 IO 是 3.3 V 逻辑。模块如果有 3.3 V / 5 V 跳线，拨到 3.3 V。引脚能否承受 5 V 以数据手册为准。

电脑这边：

1. 插上模块。Windows 在设备管理器的"端口（COM 和 LPT）"里会多出一项，记下 COM 号。Linux 一般是 `/dev/ttyUSB0`。没看到的话多半是驱动没装。
2. 打开任意一款串口助手（PuTTY 选 Serial 也行，Linux 可以 `screen /dev/ttyUSB0 115200`）。参数设成：波特率 115200，数据位 8，校验无，停止位 1，流控无。显示格式选文本，不要选 HEX。
3. 一个 COM 口同一时刻只能被一个程序打开。别的串口软件先关掉。

这几个参数里最要紧的是[[【原理】UART帧格式与波特率|波特率]]：两边必须一致，否则收到的就是乱码。先照抄，原因放在分支里。

### 第二步：在 CubeMX 里打开 USART1

1. 在你 2.2 建好的工程里，Connectivity → USART1，Mode 选 Asynchronous。
2. Parameter Settings 保持默认即可：Baud Rate 115200，Word Length 8 Bits，Parity None，Stop Bits 1。
3. 引脚默认会落在 PA9 和 PA10。如果你的板子把串口接在别的脚上（比如 PB6 和 PB7），按原理图在引脚图上改。怎么看原理图见 2.3，怎么换引脚见 4.2。
4. 时钟前提：本教程示例按 CPU 168 MHz、APB1 定时器时钟 84 MHz 来写，以你 CubeMX 时钟树里实际显示的为准。
5. 生成代码。

### 第三步：先让 printf 开口

这一步先不追求好，只追求通。

先说一个容易忽略的事实：`printf` 不是语言本身，是 C 标准库提供的函数（1.1 里说过）。在电脑上，库把字符串格式化好之后，最后一步"交给谁显示"由操作系统接手。板子上没有操作系统，这一步没人接，得我们自己接。库在最后会调用一个叫 `_write` 的函数交出字节，我们自己写一个 `_write` 让它走串口，库就"接"上了。CubeMX 生成的 CMake 工程默认链接的是一个精简版 C 库，叫 newlib-nano（工具链文件 `cmake/gcc-arm-none-eabi.cmake` 的链接选项里有 `--specs=nano.specs`），它体积小，但功能有所删减，后面会碰到一处。这些细节见 [[【原理】printf为什么慢又贵|printf 为什么慢又贵]]。

**main.c 的 USER CODE BEGIN Includes 区**：

```c
/* USER CODE BEGIN Includes */
#include <stdio.h>
/* USER CODE END Includes */
```

**main.c 的 USER CODE BEGIN 0 区**：

```c
/* USER CODE BEGIN 0 */
/* printf 最后都会调用 _write 来真正输出，这里把它接到串口 1。
   CubeMX 生成的 syscalls.c 里有一个同名的"弱"版本，我们这个会盖过它。 */
int _write(int fd, char *ptr, int len)
{
    (void)fd;
    if (HAL_UART_Transmit(&huart1, (uint8_t *)ptr, (uint16_t)len, HAL_MAX_DELAY) != HAL_OK) {
        return -1;
    }
    return len;
}
/* USER CODE END 0 */
```

**main.c 的 USER CODE BEGIN 2 区和主循环里**（CubeMX 生成的 `while (1)` 以及前后的注释原样保留，你只填 USER CODE 之间的部分）：

```c
  /* USER CODE BEGIN 2 */
  setvbuf(stdout, NULL, _IONBF, 0);   /* 不让 stdio 自己攒着，每次 printf 立刻交给 _write */
  printf("hello from stm32\r\n");
  /* USER CODE END 2 */

  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    printf("tick %lu\r\n", (unsigned long)HAL_GetTick());
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);   /* 板子还活着的证据：LED 在闪 */
    HAL_Delay(500);
  }
  /* USER CODE END 3 */
```

这里的 `HAL_UART_Transmit` 是**阻塞发送**：函数会一直等，直到所有字节都发完才返回。记住这个词，后面要用。

本教程用的是 CubeMX 生成的 CMake + GCC 工程。Keil 或 IAR 的重定向写法不一样（要重写 `fputc`），这里不展开。

构建并下载（做法见 2.2），串口助手里应该看到：

```
hello from stm32
tick 2
tick 503
tick 1004
```

数字是示意，相邻两行相差约 500 才对。LED 也应该一秒两次地翻转。

如果什么都没看到，别急着改代码。先按顺序查：LED 在不在闪（板子在不在跑）、COM 号对不对、波特率是不是 115200、TX 和 RX 有没有接反。这个顺序就是 3.2 要讲的排查法的雏形。

另外，打印 `HAL_GetTick()` 要用 `%lu` 配 `(unsigned long)` 强转，因为 `uint32_t` 在这个工具链上是 `unsigned long`，不强转编译器会警告。

### 第四步：在 1 ms 中断里加一句 printf

到这里 printf 好用得很。现在我们给它加点压力：开一个每 1 ms 触发一次的定时器中断，在里面也打印一句。

**CubeMX 里**：Timers → TIM6，勾选 Activated；Parameter Settings 里 Prescaler 填 83，Counter Period 填 999；NVIC Settings 里勾选 TIM6 的全局中断（F407 上它叫 `TIM6_DAC_IRQn`）。这样 TIM6 每 1 ms 触发一次：84 MHz 除以 84，再除以 1000。为什么这么填，5.2 会讲，现在照抄。另外 SYS 里的 Timebase Source 保持默认的 SysTick，别改成 TIM6。

**main.c 的 USER CODE BEGIN 2 区**换成下面这样，多了一行启动定时器：

```c
  /* USER CODE BEGIN 2 */
  setvbuf(stdout, NULL, _IONBF, 0);
  printf("hello from stm32\r\n");
  HAL_TIM_Base_Start_IT(&htim6);      /* 启动 1 ms 节拍，并允许它产生中断 */
  /* USER CODE END 2 */
```

**main.c 的 USER CODE BEGIN 4 区**加上定时器的中断回调：

```c
/* USER CODE BEGIN 4 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM6) {
        printf("tim6 tick, ms=%lu\r\n", (unsigned long)HAL_GetTick());
    }
}
/* USER CODE END 4 */
```

这个回调只是本节的临时演示，5.2 会重新定义 `HAL_TIM_PeriodElapsedCallback` 来取代它（那时它的任务是维护全局毫秒计数 `g_ms`）。

回调里的这一句，大约输出 20 个字节。动手之前，先做个算术：

- 波特率 115200，一个字节在线上占 10 位（1 个起始位、8 个数据位、1 个停止位），所以每个字节约 86.8 µs。
- 1 ms 内，串口最多发出约 11.5 个字节。

> [!question] 先猜一猜
> 中断每 1 ms 来一次，每次要发约 20 个字节。主循环里原本每 500 ms 打一行并翻转一次 LED。下载运行后，你觉得会看到什么？
> A. 每毫秒一行，其余一切照旧
> B. 主循环慢一点，但还在正常工作
> C. 主循环几乎不再运行
> D. 板子复位重启
> 选一个，把理由也写下来，再往下翻。

> [!failure] 猜想：是串口或接线出了问题
> 如果线路有问题，开头那句 hello 也不会出来。它出来了。划掉。

> [!success]- 揭晓
> 先算账：约 20 个字节，每个 86.8 µs，一句话要约 1.8 ms。可是中断每 1 ms 就来一次。
>
> 一次中断还没做完，下一次已经在排队。中断一结束，立刻再进一次，主循环几乎分不到时间。所以更接近 C。按这个算术，你大概率会看到：
> 1. 串口助手里几乎全是 `tim6 tick` 行，主循环的 `tick` 行很快就不再出现。
> 2. LED 不再闪，或者闪得很不规律。
> 3. `ms=` 后面的数字走得比实际时间慢，甚至停住。这取决于你的中断优先级配置。
>
> 这是按算术推出来的预测，作者没有在板子上实测。你的现象和上面不完全一样也正常：把你看到的和三条逐一对照，差在哪一条，哪一条就是线索。

把它当作一个**探针**来用：把回调里的字符串缩短成 `"t\r\n"`，只有 3 个字节，约 260 µs，占去 1 ms 的四分之一多一点。重新运行。预期是主循环又活过来了，LED 恢复闪烁，只是 CPU 有约四分之一的时间花在等串口上。

这就是问题所在：**站在柜台前等快递员**。`printf` 通过阻塞发送，CPU 一个字节一个字节地陪着串口走完，期间什么也干不了。放在主循环里只是慢，放在中断里，它占着中断不放，别的活都被挡在门外。

### 第五步：换上日志层

换法就是第二种寄件方式：先把要发的字节放进一个"快递柜"，函数立刻返回；另有一个"快递员"在后台把它们送走。快递柜，也就是[[【原理】环形缓冲区|环形缓冲区]]；快递员，也就是 [[【原理】DMA工作原理|DMA]]。柜子满了怎么办？不等，把这一行丢掉，记一笔"丢了几行"。

**1. CubeMX 里**：

1. Connectivity → USART1 → DMA Settings → Add → 选 USART1_TX。Mode 选 Normal（不要选 Circular），Direction 是 Memory To Peripheral，Data Width 都是 Byte，右边 Increment Address 只勾 Memory。
2. 同一个 USART1 页面的 NVIC Settings 里，勾选 USART1 global interrupt。DMA 的中断 CubeMX 会自动勾上，但串口自己的中断常常要你手动勾。
3. 重新生成代码。

第 2 条很重要，漏掉它会出现一个很典型的故障，3.2 里我们会专门拿它当案例。

**2. 把 `_write` 删掉**。日志层要独占 `huart1` 的发送，如果 `_write` 还在，两边会抢串口。第四步里中断回调里的 `printf` 也一起删掉。

**3. 新建 `log.h` 和 `log.c`**，分别放进工程的 `User/Inc/` 和 `User/Src/`。这两个目录是你自己的地盘，CubeMX 重新生成代码时不会碰它们。顶层 `CMakeLists.txt` 里 2.2 加过的那几行 GLOB 会自动把 `User/Src` 下的 `.c` 收进编译，把 `User/Inc` 加进头文件搜索路径，所以不用改任何 CMake 配置。新增了文件之后，在 VS Code 里重新配置一次（CMake: Configure），或者命令行重新运行配置命令，保险起见别省。如果配置阶段报错，先检查工程路径是不是纯英文、没有空格，2.2 里提过。

`log.h` 是以后所有章节共用的接口，先读它：

```c
#ifndef LOG_H
#define LOG_H

#include <stdint.h>
#include <stddef.h>
#include "stm32f4xx_hal.h"   /* 为了 UART_HandleTypeDef；CubeMX 工程里 main.h 已经包含它 */

/* 本文件就是日志模块对外的全部接口。缓冲区、读写下标、丢弃计数都藏在 log.c 里，
   别的文件看不到，也改不了，只能通过下面这些函数来用它。 */

/* 日志级别：数字越小越重要。log_set_level(LOG_INFO) 表示 ERR/WARN/INFO 会输出，DBG 被丢掉。
   级别只用来过滤，不会出现在输出里。 */
typedef enum { LOG_ERR = 0, LOG_WARN, LOG_INFO, LOG_DBG } log_level_t;

/* 在 MX_USART1_UART_Init() 之后调用一次。huart 是 HAL 的串口对象，通常传 &huart1。 */
void log_init(UART_HandleTypeDef *huart);

void log_set_level(log_level_t lv);

/* 非阻塞：格式化后写进环形缓冲就返回。输出的就是格式化后的原文，
   不加时间戳、不加级别标签、不补换行，需要换行请自己在格式串里写 "\r\n"。
   缓冲放不下时整行丢弃并计数。一行最多 127 字节，超出的部分被截掉。
   支持 %d %u %ld %lu %x %s %c，不支持浮点（%f）。 */
#if defined(__GNUC__)
void log_printf(log_level_t lv, const char *fmt, ...) __attribute__((format(printf, 2, 3)));
#else
void log_printf(log_level_t lv, const char *fmt, ...);
#endif

/* 二进制出口：把 n 个字节原样写进同一个发送环形缓冲。
   不加前缀，不受日志级别过滤。缓冲放不下就整段丢弃并计数，返回 0；放得下返回 n。 */
size_t log_write_raw(const uint8_t *p, size_t n);

/* 正常线程中尽力等待队列排空，达到时间或尝试预算即返回，不保证完全发完。
   ISR、HardFault、关中断或BASEPRI非零时不等待；不是故障处理接口。 */
void log_flush(void);

/* 到目前为止被丢弃的次数（一行日志或一段二进制算一次），用来判断缓冲是不是太小 */
uint32_t log_dropped(void);

#define LOG(lv, ...)  log_printf((lv), __VA_ARGS__)

#endif /* LOG_H */
```

然后是实现：

```c
#include "log.h"
#include <stdarg.h>
#include <stdio.h>

/* ---------- 可调参数 ---------- */
#define LOG_BUF_SIZE        1024u   /* 环形缓冲大小，必须是 2 的幂 */
#define LOG_LINE_MAX        128u    /* 一行日志最多多少字节（含结尾的 '\0'，所以实际最多 127 字节） */
#define LOG_FLUSH_TIMEOUT   100u    /* 正常线程尽力排空的时基预算，单位ms；另有有限尝试次数 */

#define LOG_BUF_MASK        (LOG_BUF_SIZE - 1u)

/* 编译期检查：LOG_BUF_SIZE 不是 2 的幂就让数组长度变成负数，直接编译不过 */
typedef char log_buf_size_must_be_power_of_two[((LOG_BUF_SIZE & (LOG_BUF_SIZE - 1u)) == 0u) ? 1 : -1];

/* ---------- 私有状态 ----------
   整个模块的状态都收在这一个结构体里，并且是 static：别的文件看不到它。
   这就是这个模块的"对象"，log.h 里的函数是它唯一的对外方法。
   head / tail 是只增不减的"累计字节数"，真正的下标用 & LOG_BUF_MASK 取出来。
   这样 head - tail 永远等于缓冲里还没发完的字节数，不用留空位区分满和空。 */
typedef struct {
    UART_HandleTypeDef *huart;     /* 发送用的串口对象，由 log_init 传进来 */
    uint8_t buf[LOG_BUF_SIZE];     /* 环形缓冲 */
    volatile uint32_t head;        /* 写入的累计字节数（生产者推进） */
    volatile uint32_t tail;        /* 已经发送完毕的累计字节数（发送完成时推进） */
    volatile uint32_t inflight;    /* 正在被 DMA 发送的字节数，0 表示 DMA 空闲 */
    volatile uint32_t dropped;     /* 被丢弃的次数 */
    volatile log_level_t level;    /* 当前级别 */
} log_ctx_t;

static log_ctx_t s_log;            /* 不赋初值，放在 .bss，不占 Flash 里的初始化数据 */

/* ---------- 关中断小工具 ----------
   主循环和中断都可能写缓冲、都可能启动发送，所以改状态的那几行要关中断。
   保存并恢复 PRIMASK，是为了在"本来就关着中断"的地方调用也不会误开。 */
static inline uint32_t irq_save(void)
{
    uint32_t primask = __get_PRIMASK();
    __disable_irq();
    return primask;
}

static inline void irq_restore(uint32_t primask)
{
    __set_PRIMASK(primask);
}

/* ---------- 后端：只有下面这三处会碰硬件 ----------
   1. tx_kick：启动一段发送
   2. log_flush：正常线程中有界地等待异步队列排空
   3. HAL_UART_TxCpltCallback：一段发完后续发
   想把日志改发到别处（RTT、USB 虚拟串口……），只需要改这三处，log.h 一个字不用动。 */

/* 如果 DMA 空闲且缓冲里有货，就把"从 tail 开始的一段连续数据"交给 DMA。
   调用时必须已经关中断。一次最多发到缓冲末尾，绕回头的部分等下一轮。 */
static void tx_kick(void)
{
    if (s_log.huart == NULL || s_log.inflight != 0u) {
        return;
    }

    uint32_t pending = s_log.head - s_log.tail;
    if (pending == 0u) {
        return;
    }

    uint32_t start  = s_log.tail & LOG_BUF_MASK;
    uint32_t to_end = LOG_BUF_SIZE - start;
    uint32_t len    = (pending < to_end) ? pending : to_end;

    if (HAL_UART_Transmit_DMA(s_log.huart, &s_log.buf[start], (uint16_t)len) == HAL_OK) {
        s_log.inflight = len;
    }
    /* 没启动成功（比如串口正被别处占用）就什么都不改，数据留在缓冲里，
       下一次写入或发送完成回调会再试。 */
}

/* 把 len 字节整段放进环形缓冲并尝试启动发送。放不下就整段丢弃、计数，返回 0。 */
static size_t ring_put(const uint8_t *p, size_t len)
{
    size_t written = 0u;

    if (len == 0u) {
        return 0u;
    }

    uint32_t primask = irq_save();

    uint32_t used = s_log.head - s_log.tail;
    if ((LOG_BUF_SIZE - used) < len) {
        s_log.dropped++;                             /* 放不下：整段丢弃，不写半截 */
    } else {
        for (size_t i = 0; i < len; i++) {
            s_log.buf[(s_log.head + i) & LOG_BUF_MASK] = p[i];
        }
        s_log.head += (uint32_t)len;
        written = len;
        tx_kick();
    }

    irq_restore(primask);
    return written;
}

/* ---------- 对外接口 ---------- */
void log_init(UART_HandleTypeDef *huart)
{
    uint32_t primask = irq_save();
    s_log.huart    = huart;
    s_log.head     = 0u;
    s_log.tail     = 0u;
    s_log.inflight = 0u;
    s_log.dropped  = 0u;
    s_log.level    = LOG_INFO;
    irq_restore(primask);
}

void log_set_level(log_level_t lv)
{
    s_log.level = lv;
}

uint32_t log_dropped(void)
{
    return s_log.dropped;
}

void log_printf(log_level_t lv, const char *fmt, ...)
{
    if (s_log.huart == NULL || (unsigned)lv > (unsigned)s_log.level) {
        return;
    }

    /* 第一步：在自己的栈上把这一行拼好。这一步最慢，所以放在关中断之外。 */
    char line[LOG_LINE_MAX];

    va_list ap;
    va_start(ap, fmt);
    int m = vsnprintf(line, sizeof line, fmt, ap);
    va_end(ap);
    if (m <= 0) {
        return;
    }
    if ((size_t)m >= sizeof line) {
        m = (int)sizeof line - 1;                    /* 太长就截断 */
    }

    /* 第二步：整行放进环形缓冲（里面会短暂关中断）。 */
    (void)ring_put((const uint8_t *)line, (size_t)m);
}

size_t log_write_raw(const uint8_t *p, size_t n)
{
    if (s_log.huart == NULL || p == NULL) {
        return 0u;
    }
    return ring_put(p, n);
}

void log_flush(void)
{
    /* Normal thread context only; IRQ-driven transmission must be able to progress. */
    if (s_log.huart == NULL || __get_IPSR() != 0u ||
        __get_PRIMASK() != 0u || __get_BASEPRI() != 0u) {
        return;
    }

    uint32_t start = HAL_GetTick();
    /* A finite fallback budget also terminates when the HAL timebase stops. */
    for (uint32_t tries = 0u; tries < 1000000u; ++tries) {
        uint32_t primask = irq_save();
        int empty = (s_log.head == s_log.tail);
        if (!empty) {
            tx_kick();
        }
        irq_restore(primask);
        if (empty || (uint32_t)(HAL_GetTick() - start) >= LOG_FLUSH_TIMEOUT) {
            return;
        }
    }
}

/* 一段 DMA 发送完成（整段字节都已经从串口移位寄存器发出去）后，HAL 会调用这里。
   在这里把 tail 往前推，再接着发下一段。
   注意：这个弱函数只能在一个文件里重写。别的文件不要再写同名函数。 */
void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart != s_log.huart) {
        return;
    }

    uint32_t primask = irq_save();
    s_log.tail += s_log.inflight;
    s_log.inflight = 0u;
    tx_kick();
    irq_restore(primask);
}
```

这份代码一百五十行左右，不用逐行背。抓住下面几点就够了：

- **先拼后锁**。`log_printf` 先在自己栈上把整行拼好，这一步最慢，不关中断。然后才关中断，把整行拷进环形缓冲、启动发送，这一步只有几十个字节的拷贝，很快。所以主循环和中断同时调用它，缓冲也不会被写乱。
- **输出的就是原文**。`LOG()` 不加时间戳，不加级别标签，也不补换行：你写什么就发什么，换行要自己在格式串末尾写 `"\r\n"`（串口助手需要 `\r\n` 才会换到下一行行首）。级别只用来过滤，`LOG_DBG` 的内容在级别设成 `LOG_INFO` 时直接不发。想要时间戳，自己在格式串里写：练习里有。
- **head 和 tail 只增不减**。它们是累计字节数，下标靠 `& LOG_BUF_MASK` 取出来。`head - tail` 永远等于还没发完的字节数，不用留空位区分"满"和"空"。这也是为什么缓冲大小必须是 2 的幂。
- **满了丢整段，不写半截**。丢了就让 `dropped` 加一，随时可以用 `log_dropped()` 查。
- **发送完成回调续发**。DMA 一次只能发一段连续的内存。一段发完，HAL 调用 `HAL_UART_TxCpltCallback`，我们在里面把 `tail` 往前推，再接着发下一段。这个弱函数只能在一个文件里重写，别的文件不要再写同名函数。
- **`log_flush` 只是正常线程中的尽力排空**。它保持中断可推进，仅在短临界区检查队列和启动发送，达到时基超时或尝试预算就返回；不停止 DMA，也不保证所有字节已经发完。ISR、HardFault、关中断或 BASEPRI 掩蔽环境直接拒绝等待。尝试次数不是精确毫秒定时，故障日志需要另做最小现场采集，见 [3.2](/lessons/3-2)。
- **缓冲放普通 SRAM**。F407 里有一块只有 CPU 能访问的 CCM 内存，DMA 够不着。别用链接脚本把缓冲放进去（以参考手册为准）。

**二进制出口**。有时要发的不是文字，而是几个原始字节，比如一帧数据。`log_write_raw()` 就是为这个准备的：字节原样进同一个环形缓冲，不加任何前缀，也不受日志级别过滤。放得下返回写入的字节数，放不下整段丢弃、计入 `log_dropped()`，返回 0。

```c
  /* 二进制出口：原样发出 4 个字节，不加任何前缀，也不受日志级别影响 */
  const uint8_t frame[4] = { 0xAA, 0x55, 0x01, 0x02 };
  if (log_write_raw(frame, sizeof frame) == 0) {
      LOG(LOG_WARN, "raw frame dropped\r\n");   /* 缓冲放不下，已经计入 log_dropped() */
  }
```

文字日志和二进制数据走的是同一个缓冲，会按先后顺序排在一起。串口助手里看二进制要切到 HEX 显示。把二进制和文字混着发，对方怎么区分，是 6.3 设计协议要解决的事。

**这个模块其实是一个"对象"**。我们没有写 `class`，但思路是一样的：

- **状态藏起来**。缓冲、读写下标、丢弃计数，全都收在 `log.c` 里的一个 `static` 结构体里，别的文件看不到，也改不了。对外只有 `log.h` 里那几个函数。这样你以后改缓冲的实现，调用方不受影响。
- **HAL 本身就是对象**。`UART_HandleTypeDef huart1` 是 HAL 的串口对象：串口的配置、状态、DMA 句柄都装在这个结构体里；`HAL_UART_Transmit(&huart1, ...)` 是对它的"方法调用"，对象指针放在第一个参数。你从 2.2 起就一直在用面向对象的东西，只是没人告诉你。`huart1` 的声明来自 CubeMX 生成的 `usart.h`，`main.c` 里已经包含了它。
- **依赖传进来，不写死**。`log_init(&huart1)` 把串口对象传给日志模块，`log.c` 里一次也没有出现 `huart1` 这个名字。换一个串口，只改这一处调用。
- **后端可以换**。注释里写了：整个模块只有三处会碰硬件，启动发送、正常线程的尽力排空、发送完成回调。UART 加 DMA 只是其中一种实现。把这三处换成 SEGGER RTT 或 USB 虚拟串口，`log.h` 不变，所有调用 `LOG()` 的代码一个字都不用改。

这套"数据装进结构体、操作以对象指针为首参、硬件细节藏在接口后面"的写法，后面每个驱动都会用。它为什么能让代码好复用，以及 C++ 的 `class` 和它是什么关系，见文末「想深入」里的《C 语言里的面向对象》。

相邻两行的 tim6 count 应该相差约 500，因为主循环每 500 ms 打一行，而 TIM6 每毫秒数一次。LED 照常闪烁，`dropped` 一直是 0。

现在回到开头那个探针，把它放大。故意在中断里打日志，看看日志层怎么应对。把回调换成下面这样：

```c
/* USER CODE BEGIN 4 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM6) {
        s_tim6_count++;
        /* 探针：故意在中断里打日志，一行约 35 个字节 */
        LOG(LOG_INFO, "tim6 isr, count=%lu, tick=%lu\r\n",
            (unsigned long)s_tim6_count, (unsigned long)HAL_GetTick());
    }
}
/* USER CODE END 4 */
```

先猜：这一行大约 35 个字节，每毫秒一次，每秒需要发约 35000 字节，而串口一秒最多发约 11500 字节。会发生什么？

> [!success]- 揭晓
> 按算术，只有大约三分之一的行能放进缓冲，其余被丢掉。你会看到：
> 1. 串口助手里刷屏，但 `count=` 和 `tick=` 后面的数字不连续，隔几步就跳一下。这就是丢行。
> 2. LED 依然在闪。主循环没有被拖住，这是和 printf 版最大的区别。
> 3. `loop` 那几行有时也会不见，因为缓冲经常是满的，它也一起被丢了。
>
> 这是按算术推出来的预测，作者没有在板子上实测，具体丢多少以你看到的为准。

所以日志层的底线是：**满了不卡你，只是丢**。但能撑住不等于该这么干：拼一行字本身也要时间，丢行又会让你看不全。所以规矩依然是中断里只记一个标志或计数，让主循环去打印。试完记得把回调改回只数数的版本。

最后补一个坑。日志层用的 `vsnprintf` 在 CubeMX 默认的精简 C 库（newlib-nano）下**不支持 `%f`**。写 `LOG(LOG_INFO, "%f\r\n", x)`，大概率打不出你想要的数字（以你的工程设置为准）。办法有两个：一是给链接器加上 `-u _printf_float`，在 CMake 里写成 `target_link_options(${CMAKE_PROJECT_NAME} PRIVATE -Wl,-u,_printf_float)`（放在顶层 `CMakeLists.txt` 的用户区，具体写法以你工程为准，待核对），代价是固件多出好几 KB；二是像下面这样转成整数打印，本教程用的是这一种。

```c
float t = 23.456f;                       /* 假设这是一个温度读数 */
int t_milli = (int)(t * 1000.0f);         /* 先放大 1000 倍，变成整数 23456 */
LOG(LOG_INFO, "temp = %d.%03d C\r\n", t_milli / 1000, t_milli % 1000);   /* 输出 23.456，只适用于非负数 */
```

这个写法的原理在 [[【拓展】浮点与定点|浮点与定点]] 里展开。

## 刚才发生了什么

你把"寄件"从柜台前搬到了快递柜。对照表如下：

| 比喻 | 真名 | 在代码里 |
|---|---|---|
| 站在柜台前等 | 阻塞发送 | `HAL_UART_Transmit` |
| 快递柜 | 环形缓冲区 | `buf`、`head`、`tail`（都在私有的 `s_log` 里） |
| 快递员 | DMA | `HAL_UART_Transmit_DMA` |
| 快递员送完打电话 | 发送完成回调 | `HAL_UART_TxCpltCallback` |
| 柜子满了，包裹不收 | 丢弃并计数 | `dropped`、`log_dropped()` |

`printf` 慢的账，我们算了其中一笔：时间。115200 波特率下一个字节 86.8 µs，一句 20 字节的话要 1.8 ms。它还有体积、栈占用、不可重入几笔账，放在分支里一笔一笔算。

至于为什么中断里这么容易出事，是因为中断是"插队"的：它会打断主循环，在它做完之前，被打断的代码一动不动。把一个又慢又会等的动作放进去，整个程序都跟着等。

回到开头：寄件人站在柜台前，同时还要照看每毫秒一次的电机，这事现在你能回答了。站着等的代价由 CPU 的时间来付。快递柜换来的是：寄出的动作只花拷贝几十个字节的时间，剩下的路交给 DMA。

## 记住这几条

1. 会阻塞的东西不进中断，也不进控制环路。`printf` 是最典型的阻塞。
2. 板上输出统一用 `LOG()`，不再直接 `printf`。日志层独占 `huart1` 的发送，别处不要再调 `HAL_UART_Transmit(&huart1, ...)`。
3. `LOG()` 输出的就是格式化后的原文：不加前缀，不补换行，格式串自己写 `"\r\n"`；只用 `%d %u %ld %lu %x %s %c`，不用 `%f`，浮点先转成整数再打印。要发原始字节用 `log_write_raw()`。
4. 缓冲会满。满了丢整行并计数，想知道丢了多少，看 `log_dropped()`。
5. 中断里只记标志或计数，主循环里再打日志。
6. `log_flush()` 只在正常线程中尽力排空，必须允许相关中断推进；它不是 HardFault 或关中断时的可靠日志出口。
7. 一个模块 = 一个对象：状态藏在 `static` 里，只通过头文件里的接口使用，硬件对象（如 `huart1`）从外面传进来。

## 练习

1. （复现）把第四步中断回调里的字符串缩短成 `"t\r\n"`，只用 `printf`。预测 LED 会怎样，再运行验证。
2. （改造）让主循环里每一行日志都以毫秒时间戳开头，比如 `[503] loop 2`。提示：时间戳要你自己在格式串里写，用 `HAL_GetTick()`，别忘了 `%lu` 配 `(unsigned long)`。再把 `LOG_BUF_SIZE` 改成 64，在中断回调里按探针那样打日志，看 `log_dropped()` 怎么变。
3. （预测）把 CubeMX 和串口助手的波特率都改成 9600，中断里按探针那样每毫秒一句约 35 字节的 `LOG`。预测每秒大约能完整发出多少行，再数一数。

> [!success]- 提示与答案方向
> 1. 3 个字节约 260 µs，占 1 ms 的四分之一多，LED 应该能闪，只是主循环慢了一点。
> 2. 格式串写成 `"[%lu] loop %lu, ...\r\n"`，参数多传一个 `(unsigned long)HAL_GetTick()`。缓冲小了，更容易满，`log_dropped()` 增长得更快，主循环仍然不被拖住。5.2 之后可以把 `HAL_GetTick()` 换成 `g_ms`。
> 3. 9600 波特率下每秒约 960 个字节，除以 35 约 27 行。与你数出来的比一比，差距就是丢行和其他行共用带宽造成的。
