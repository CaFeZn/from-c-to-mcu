# 5.4 中断与主循环共享数据

> **这一节你会做出**：亲手撞见两种"数据被半路改掉"的事故，再用五种办法逐个修好，其中包括一个可以建多个实例的环形缓冲对象，并学会在新场景里判断该用哪一种。
> **前置**：[[5.1_中断入门]]、[[5.2_定时器与节拍]]　｜　**预计**：阅读 + 动手 60 分钟

> [!tip] 跳读自测：这一节你可能不用读
> 先回答下面四个问题（写下来，别只在心里答）。**全部答对**就直接跳到 [[5.5_定时精度]]；有一题拿不准，就从头读。
> 1. 下面的代码里，ISR 每毫秒执行一次 `n++`，主循环也执行 1000 次 `n++`。主循环跑完，`n` 一定等于 1000 加 ISR 进来的次数吗？为什么？
>    ```c
>    volatile uint32_t n = 0;
>    void on_tick_isr(void) { n++; }
>    void loop_part(void)   { for (uint32_t i = 0; i < 1000U; i++) { n++; } }
>    ```
> 2. 在 Cortex-M 上，下面四种访问，哪几种可能被中断"插队"而出问题？a. 读一个对齐的 `uint32_t`　b. 读一个 `uint64_t`　c. 连读 `sec`、`ms` 两个相关字段　d. `x |= 1`
> 3. 找问题：函数 `f` 里写了 `__disable_irq(); update(); __enable_irq();`。如果 `f` 被另一段已经关了中断的代码调用，会有什么隐患？怎么改？
> 4. 工程里要同时有两路串口接收缓冲，大小不同。环形缓冲的代码需要写两份吗？它的 `head`、`tail`、存储区指针该放在哪里？
>
> > [!success]- 答案，以及跳过后要带走的东西
> > 1. 不一定，可能偏小。`n++` 是读、加、写三步，ISR 插在中间，它加的那一下会被主循环手里的旧值盖掉。`volatile` 只保证每次真去读写，不保证中间不被插队。
> > 2. b、c、d。a 是一条指令，不会被撕开。b、c 是"一次读多个字"，d 是"读改写"。
> > 3. `f` 返回前就把中断打开了，调用它的那段代码本来想保护的后半段不再受保护。改成先保存 PRIMASK，退出时恢复保存的值，不要无条件打开（`irq_save()` / `irq_restore()`）。
> > 4. 不用写两份。把存储区指针、容量、`head`、`tail` 放进一个 `ringbuf_t` 对象，函数的第一个参数是对象指针，每一路建一个实例。状态写成全局变量就做不到这一点。
> >
> > **带走清单**：
> > - `critical.h`（`irq_save()` / `irq_restore()`），放 `User/Inc/critical.h`，5.5 要用。
> > - `ringbuf.h` / `ringbuf.c`（单生产者、单消费者的字节环形缓冲对象 `ringbuf_t`：`ringbuf_init` / `ringbuf_put` / `ringbuf_get`），放 `User/Inc/ringbuf.h` 和 `User/Src/ringbuf.c`，是通用工具，建议收下。
> > - `event.h` / `event.c`（按键等事件的"对账"计数对象 `event_t`），放 `User/Inc/event.h` 和 `User/Src/event.c`。
> > - 放在 `User/Inc`、`User/Src` 下的文件，CMake 会自动收进来；新增文件后重新配置一次（见 2.2）。
> > - 约定：共享变量先想单写者；多字或读改写用临界区；临界区里不等待、不调 `HAL_Delay`；模块写成"对象"，实例先 `init` 再开中断。
> > - 本节的 `stamp.*`、`count.*`、`seqtest.*` 只是实验，后文不会用到。

## 先看一个怪现象

教室里有块白板，值日生每分钟擦掉重写一次当前时间。你在白板前抄时间，刚抄下 `1`、`2`、`:`，值日生就把 `12:59` 擦了，换成 `13:00`。你接着抄后两位，纸上变成了 `12:00`。

这个时间从来没存在过。白板上的每一版都是对的，你抄的每一笔也都没抄错，错在"抄到一半被换了"。

放到单片机里：抄写的人，是主循环；值日生，是中断服务函数（ISR）；白板，是它们共用的变量。

> [!question] 先猜一猜
> 下面这段代码里，ISR 每 1 ms 执行一次 `count++`，主循环也执行 200 万次 `count++`，两边加的是同一个变量。`count` 已经按 5.1 的规矩加了 `volatile`。
> ```c
> volatile uint32_t count = 0;
>
> void on_tick_isr(void)             /* 每 1 ms 进来一次 */
> {
>     count++;
> }
>
> void main_loop_part(void)
> {
>     for (uint32_t i = 0; i < 2000000U; i++) {
>         count++;
>     }
> }
> ```
> 主循环跑完后，`count` 理应等于 200 万加上 ISR 进来的次数。实际会是：
> A. 刚好相等　B. 比它小　C. 比它大　D. 看运气，有时相等，有时不等
> 先选一个，我们马上量。

> [!success]- 揭晓
> 不等的时候，一定是 B：只会偏小，不会偏大，每次丢多少还不一样。所以 B 和 D 各对一半。
> 为什么会丢，丢的是谁加的，下面第三步亲眼看。

## 动手做

### 第一步：确认现场，约定写法

这一节的实验建立在前面几节上，先确认三件事：

- 5.2 的 1 ms 节拍已经在跑：`htim6` 的更新中断回调里有 `g_ms++`；`g_ms` 在 `main.h` 里 `extern`，在 `main.c` 里定义。5.2 的软件定时器 `soft_due()` 在 `main.c` 的 `USER CODE 0` 区，本节主循环会用它。
- 3.1 的日志层可用：`log_init(&huart1)` 之后可以用 `LOG()`。
- 下面新建的 `.h` 放 `User/Inc`，`.c` 放 `User/Src`，名字不要改，后面互相引用。2.2 里已经让顶层 `CMakeLists.txt` 自动收进这两个目录下的文件；每新增一个文件，重新配置一次 CMake（见 2.2），再构建。

`LOG()` 不会自动补换行，所以本节的格式串都自己写了 `\r\n`。日志层不支持浮点，本节只用整数和字符串。

> [!note] 本节的写法：一个东西，一个[[【原理】C语言里的面向对象|对象]]
> 本节每个模块都是一个 `struct` 加一组函数，函数的第一个参数是这个 `struct` 的指针，比如 `stamp_tick(&stamp)`、`ringbuf_put(&rb, b)`。状态全在 `struct` 里，`.c` 文件里没有任何全局变量，所以同一份代码可以建任意多个实例。
> 这套写法你早就在用了：`UART_HandleTypeDef huart1` 是对象，`HAL_UART_Transmit(&huart1, ...)` 是它的方法。实例放在 `main.c` 里，先 `init`，再开中断，因为中断一进来就会用到它们。
> C++ 把这套写法做成了语言特性（`class`），这里不展开。

### 第二步：撞见"半新半旧"

先说明为什么用 64 位。

> [!note] 为什么不用 32 位
> 在 Cortex-M 上，一个**对齐的 32 位变量**，读一次、写一次各是一条指令，中断插不进一条指令的中间。所以一次读到的 32 位值，要么全旧，要么全新，不会半新半旧。8 位、16 位单片机上读 32 位要分好几步，这类事故是家常便饭；换到 Cortex-M，想撞见它，就得找"一次装不下"的数据：64 位整数、"秒 + 毫秒"这样的两个相关字段、一个结构体。
> 本节用 64 位时间戳。
> 关于 `uint64_t` 本身：我用 arm-none-eabi-gcc 12.3 编译过，它会把 `volatile uint64_t` 的读编成一条双字指令。但手册并不保证这条指令对外是个不可分割的整体，所以不能靠它。为了让这个实验在每个人的工程里都能复现，我们把 64 位显式拆成低、高两个 32 位字。这也是"多字段"最简单的形态。

新建 `User/Inc/stamp.h`，时间戳就是一个对象：

```c
#ifndef STAMP_H
#define STAMP_H

#include "main.h"

/* 一个 64 位时间戳对象。64 位拆成低、高两个 32 位字，只有 stamp_tick() 写它们 */
typedef struct {
    volatile uint32_t lo;
    volatile uint32_t hi;
    uint32_t step;          /* 每次 tick 加多少 */
} stamp_t;

typedef uint64_t (*stamp_read_fn)(const stamp_t *s);

/* step 是每次 tick 加的数。真实的 1 ms 时间戳传 1；本节实验传一个大数，见 stamp.c */
void stamp_init(stamp_t *s, uint32_t step);

/* 只在中断里调用，每 1 ms 一次 */
void stamp_tick(stamp_t *s);

/* 直接读 */
uint64_t stamp_read_unsafe(const stamp_t *s);

/* 连续读 3 秒，数一数"时间倒退"了几次 */
void stamp_demo(const stamp_t *s, stamp_read_fn read, const char *name);

#endif /* STAMP_H */
```

再新建 `User/Src/stamp.c`：

```c
#include "stamp.h"
#include "log.h"    /* 3.1 的日志层 */

/* 真实的 1 ms 时间戳，低 32 位要 49.7 天才进一次位，没人等得起。
 * 实验里给 stamp_init() 传一个大步长，比如 0x80000000：
 * 每次加 2^31，每两次 tick 就进一次位。除了步长，其余和真正的时间戳一模一样。 */
void stamp_init(stamp_t *s, uint32_t step)
{
    s->lo = 0U;
    s->hi = 0U;
    s->step = step;
}

void stamp_tick(stamp_t *s)
{
    uint32_t old_lo = s->lo;
    uint32_t new_lo = old_lo + s->step;

    s->lo = new_lo;
    if (new_lo < old_lo) {              /* 低 32 位绕回去了：向高位进一 */
        s->hi = s->hi + 1U;
    }
}

/* 直接读：先读低 32 位，再读高 32 位。两次读之间，ISR 可能插进来 */
uint64_t stamp_read_unsafe(const stamp_t *s)
{
    uint32_t lo = s->lo;
    uint32_t hi = s->hi;
    return ((uint64_t)hi << 32) | lo;
}

void stamp_demo(const stamp_t *s, stamp_read_fn read, const char *name)
{
    uint64_t prev = read(s);
    uint32_t reads = 0U;
    uint32_t back = 0U;
    uint32_t t0 = g_ms;

    while ((uint32_t)(g_ms - t0) < 3000U) {
        uint64_t now = read(s);
        if (now < prev) {               /* 时间戳只增不减，倒退就是读坏了 */
            back++;
        }
        prev = now;
        reads++;
    }
    LOG(LOG_INFO, "[stamp:%s] reads=%lu back=%lu\r\n",
        name, (unsigned long)reads, (unsigned long)back);
}
```

在 `main.c` 里，包含头文件，定义实例：

```c

```

```c

/* USER CODE END PV */
```

在 `htim6` 的回调里，让它每毫秒走一步：

```c
{

}
/* USER CODE END 4 */
```

最后在 `main()` 里跑实验：

```c

```

构建，下载（见 2.2），打开串口助手。你应该看到类似这样的一行：

```
[stamp:unsafe] reads=xxxxxx back=yyy
```

`reads` 是个很大的数，`back` 不是 0。具体数字每次不同，每块板子也不同。

> [!tip] 如果 back 一直是 0
> 先别急着怀疑理论。大概率是 `stamp_tick()` 根本没被调用：检查 `g_ms` 在不在涨，`HAL_TIM_Base_Start_IT(&htim6)` 有没有执行。

时间戳只增不减，`back` 大于 0，说明主循环读到了"倒退"的时间。谁干的？

> [!failure] 猜想 1：忘了 volatile，编译器偷懒
> 两个字都是 `volatile`，每次都真的去读。划掉。

> [!failure] 猜想 2：ISR 把时间戳写坏了
> ISR 每次进来都先写低 32 位，需要时再写高 32 位，写完才退出。主循环插不进 ISR 的中间；而且每一版写出来的值都比上一版大。划掉。

两个猜想都不成立，嫌疑只剩一个：主循环读 `stamp_read_unsafe()` 的两行之间，ISR 插进来了。把这一幕摆开：

| 时刻 | 主循环 | ISR | 主循环手里的值 |
|---|---|---|---|
| ① | 读低 32 位，读到 `0x80000000` | | 低 = `0x80000000` |
| ② | | 进来：低 32 位绕回 `0x00000000`，高 32 位加一，变成 1 | |
| ③ | 读高 32 位，读到 1 | | 拼出 `0x1_80000000` |

真实的时间是 `0x0_80000000`（②之前）或 `0x1_00000000`（②之后），主循环拼出来的 `0x1_80000000` 两个都不是，比两者都大。下一次读到正确的 `0x1_00000000`，就比上一次小了：`back` 加一。

> [!question] 先猜一猜
> 我们给 `stamp_init()` 传了 `0x80000000` 当步长，所以每两毫秒进位一次。如果改成真实的 `1U`，每毫秒只加一，`back` 还会大于 0 吗？
> 动手改一下，重新构建，对比你的猜测。

> [!success]- 揭晓
> 几乎看不到。真实的毫秒计数，低 32 位要 2^32 毫秒，也就是约 49.7 天才进一次位，3 秒的实验里碰不上。
> 这正是这类问题的可怕之处：桌上测不出来，产品跑了一个多月，某一次进位恰好撞上读，时间戳突然跳了 49.7 天，然后又好了，谁也复现不了。

### 第三步：撞见"丢计数"

新建 `User/Inc/count.h`：

```c
#ifndef COUNT_H
#define COUNT_H

#include "main.h"

/* 一个两边都会改的计数器对象 */
typedef struct {
    volatile uint32_t value;        /* 主循环和 ISR 都会改它 */
    volatile uint32_t isr_calls;    /* 只有 ISR 写：中断一共进来了几次 */
} count_t;

typedef void (*bump_fn)(count_t *c);

void count_init(count_t *c);
void count_isr(count_t *c);                     /* 只在中断里调用，每 1 ms 一次 */
void count_bump_plain(count_t *c);              /* 主循环这一边的 count++ */
void count_demo(count_t *c, bump_fn bump, const char *name);

#endif /* COUNT_H */
```

新建 `User/Src/count.c`：

```c
#include "count.h"
#include "log.h"

#define COUNT_LOOPS 2000000UL

void count_init(count_t *c)
{
    c->value = 0U;
    c->isr_calls = 0U;
}

void count_isr(count_t *c)
{
    c->value++;
    c->isr_calls++;
}

/* 主循环这一边的 count++ */
void count_bump_plain(count_t *c)
{
    c->value++;
}

/* 主循环 bump 200 万次，同时 ISR 也在 bump。
 * 账本：应该有 200 万 + ISR 进来的次数。 */
void count_demo(count_t *c, bump_fn bump, const char *name)
{
    /* 这个演示函数只在 main 里调用，不会被别的临界区套着，
     * 所以直接开关中断。自己写的库函数请用后面的 irq_save / irq_restore */
    __disable_irq();
    c->value = 0U;
    c->isr_calls = 0U;
    __enable_irq();

    for (uint32_t i = 0U; i < COUNT_LOOPS; i++) {
        bump(c);
    }

    /* 数账前先冻结现场，保证 value 和 isr_calls 取自同一时刻 */
    __disable_irq();
    uint32_t got = c->value;
    uint32_t isr = c->isr_calls;
    __enable_irq();

    uint32_t expect = (uint32_t)COUNT_LOOPS + isr;
    LOG(LOG_INFO, "[count:%s] expect=%lu got=%lu lost=%lu\r\n",
        name, (unsigned long)expect, (unsigned long)got,
        (unsigned long)(expect - got));
}
```

`main.c` 里再加一个实例，回调里再加一行，`main()` 里初始化并跑实验：

```c
static count_t counter;        /* PV 区追加 */
```

```c
        count_isr(&counter);         /* 新增 */
```

```c
count_init(&counter);              /* 放在 HAL_TIM_Base_Start_IT 之前 */
```

```c
count_demo(&counter, count_bump_plain, "plain");   /* 放在 stamp_demo 之后 */
```

你应该看到：

```
[count:plain] expect=xxxxxxx got=xxxxxxx lost=nnn
```

`lost` 大于 0，每次都不一样。丢的永远是 ISR 加的那几下。为什么？因为 `count++` 看着是一行，机器却分三步做：读出来、加一、写回去。

| 步 | 主循环 | ISR | `value` |
|---|---|---|---|
| ① | 读出 `value`，手里是 100 | | 100 |
| ② | | 读 100，加一，写回 101 | 101 |
| ③ | 手里的 100 加一，得 101 | | 101 |
| ④ | 写回 101 | | 101 |

ISR 加的那一下，被主循环的"旧值加一"盖掉了。

`arm-none-eabi-gcc` 是一个[[【原理】交叉编译与工具链|交叉编译器]]：在 PC 上编译，产物给 ARM 内核跑。我用它的 12.3 版，按 Release 构建类型（`-Os`）编译 `count_bump_plain`，得到的核心三行是这样的，`r0` 里装的就是对象指针 `c`，读、加、写各占一条：

```
ldr   r3, [r0]        @ 读
adds  r3, r3, #1      @ 加
str   r3, [r0]        @ 写
```

> [!question] 再猜一猜
> 既然 `count++` 会被插队，那主循环里单独一句 `x = counter.value;` 呢？它会读到半新半旧的值吗？

> [!success]- 揭晓
> 不会。对齐的 32 位读是一条 `ldr`，中断插不进一条指令的中间，读到的要么是旧的，要么是新的。
> 所以真正危险的，是两类操作：**读改写**（`x++`、`x |= 1`、`x -= n`）和**一次读多个字**（64 位、多字段、结构体）。单个 32 位变量"一方写、一方读"的单次访问，是安全的，5.1 的 flag 就是这种。

### 第四步：五种办法

先给一张地图，读完整节再回来对照：

| 你的情况 | 优先用 |
|---|---|
| 一方写、一方读，单个 32 位以内 | `volatile` 就够（5.1 的 flag） |
| 要数事件的个数，不能漏、不能合并 | flag 升级成"对账" |
| 两边都要改同一个变量 | 拆成单写者；拆不开才关中断 |
| 要一次读多个字（64 位、结构体） | 关中断读，或读两次比较 |
| 一串连续的数据（字节流、采样值） | 环形缓冲 |

#### 办法一：单写者

最干净的办法不是"防止被插队"，而是"不给插队的机会"：每个共享变量只允许一方写。主循环只写自己的计数，ISR 只写自己的计数，要总数时相加。

在 `count.h` 的 `#endif` 之前加上这个新对象：

```c
/* 单写者版：主循环和 ISR 各记各的 */
typedef struct {
    volatile uint32_t from_main;    /* 只有主循环写 */
    volatile uint32_t from_isr;     /* 只有 ISR 写 */
} dual_count_t;

void dual_init(dual_count_t *d);
```

#### 办法二：关中断临界区

有时拆不开：两边确实都要改同一个东西，或者要一口气读好几个字。这时可以在这件事做完之前，不让 ISR 进来：关中断。

新建 `User/Inc/critical.h`：

```c
#ifndef CRITICAL_H
#define CRITICAL_H

#include "main.h"   /* 带进 CMSIS：__get_PRIMASK / __set_PRIMASK / __disable_irq */

/* 进入临界区：先记下"进来之前中断是开着还是关着"，再关中断。
 * 返回值要原样交给 irq_restore()。 */
static inline uint32_t irq_save(void)
{
    uint32_t primask = __get_PRIMASK();
    __disable_irq();
    return primask;
}

/* 离开临界区：恢复成进来之前的样子，而不是无条件打开。
 * 这样临界区套着临界区，也不会提前把中断放出去。 */
static inline void irq_restore(uint32_t primask)
{
    __set_PRIMASK(primask);
}

#endif /* CRITICAL_H */
```

> [!warning] 为什么要"保存再恢复"，不能直接 __disable_irq() 然后 __enable_irq()
> 看这个反例：
> ```c
> void g(void)
> {
>     __disable_irq();
>     /* 临界区里的操作 */
>     __enable_irq();      /* 无条件打开 */
> }
>
> void f(void)
> {
>     __disable_irq();
>     g();                 /* g 返回时，中断已经被打开了 */
>     /* f 后半段本来想受保护，现在不受了 */
>     __enable_irq();
> }
> ```
> `f` 想保护的是整段，可 `g` 返回时无条件打开了中断，`f` 的后半段已经裸奔。`irq_save()` 记下的是"进来之前的状态"，`irq_restore()` 还原成那个状态，套多少层都对。
> 前面的 `count_demo` 直接用 `__disable_irq()`，是因为它只会从 `main` 里调用，不会被别的临界区套着。自己写的库函数，一律用 `irq_save()`。

在 `stamp.c` 的 `#include` 区加一行 `#include "critical.h"`，末尾追加：

```c
/* 关中断读：读的这一小段时间里，ISR 进不来 */
uint64_t stamp_read_locked(const stamp_t *s)
{
    uint32_t primask = irq_save();
    uint32_t lo = s->lo;
    uint32_t hi = s->hi;
    irq_restore(primask);
    return ((uint64_t)hi << 32) | lo;
}
```

在 `stamp.h` 的 `#endif` 之前加一行：

```c
uint64_t stamp_read_locked(const stamp_t *s);    /* 关中断读 */
```

在 `count.c` 的 `#include` 区同样加 `#include "critical.h"`，再把 `count_bump_locked` 追加进去：

```c
/* 同样是 count++，但"读、加、写"整套被关中断包起来 */
void count_bump_locked(count_t *c)
{
    uint32_t primask = irq_save();
    c->value++;
    irq_restore(primask);
}
```

`count.h` 里对应加一行：

```c
void count_bump_locked(count_t *c);             /* 带关中断保护的 count++ */
```

`main()` 里把实验补全：

```c
stamp_demo(&stamp, stamp_read_locked, "locked");
count_demo(&counter, count_bump_locked, "locked");
```

你应该看到 `[stamp:locked]` 的 `back=0`，`[count:locked]` 的 `lost=0`。

临界区有代价：关中断期间，所有可配置优先级的中断都被挡在门外，挡得越久，中断响应越晚。所以守三条规矩：

- 里面只放几条指令，读个值、改个值就出来。
- 里面不等任何东西：不调 `HAL_Delay`，不等串口，不死等标志位。
- 能用单写者解决的，不要用临界区。

关中断多久会出问题？下一节会实测。

#### 办法三：读两次比较

如果数据只有 ISR 写，主循环只读，还有一个不关中断的办法：读两遍，两遍一样，说明读的过程中没被改过；不一样就重读。

在 `stamp.c` 末尾再追加：

```c
/* 读两次比较：两遍读到的一样，说明中间没被改过；不一样就重来 */
uint64_t stamp_read_twice(const stamp_t *s)
{
    uint32_t lo1, hi1, lo2, hi2;
    do {
        lo1 = s->lo;
        hi1 = s->hi;
        lo2 = s->lo;
        hi2 = s->hi;
    } while (lo1 != lo2 || hi1 != hi2);
    return ((uint64_t)hi1 << 32) | lo1;
}
```

在 `stamp.h` 的 `#endif` 之前再加一行 `uint64_t stamp_read_twice(const stamp_t *s);`，`main()` 里加上 `stamp_demo(&stamp, stamp_read_twice, "twice");`。你应该看到 `back=0`。

它有适用条件，用之前对一下：

- 只有 ISR 写，主循环只读。
- 数值不会很快回到原样（时间戳只增不减，满足）。
- ISR 两次进来的间隔，远大于读一遍所用的时间；否则可能一直重读。

好处是不影响中断响应，代价是代码比临界区绕一点。

#### 办法四：flag 升级成"对账"

5.1 的 flag：ISR 里 `flag = 1`，主循环里发现后 `flag = 0`。它有个漏洞：主循环处理的过程中，又来了一次事件，ISR 再置 1，主循环最后清 0，这一次就悄悄丢了。flag 只能表示"发生过"，不能表示"发生了几次"。

升级办法：ISR 只加"发生了几次"，主循环只加"我处理了几次"，两个数各有一个写者，相减就是还没处理的。这个小账本也是一个对象。

新建 `User/Inc/event.h`：

```c
#ifndef EVENT_H
#define EVENT_H

#include "main.h"

/* 事件计数对象：ISR 记"发生了几次"，主循环记"处理了几次" */
typedef struct {
    volatile uint32_t posted;   /* 只有 ISR 写 */
    uint32_t taken;             /* 只有主循环写 */
} event_t;

void event_init(event_t *e);
void event_post_from_isr(event_t *e);   /* 只在 ISR 里调用：记一笔"又发生了一次" */
uint32_t event_take(event_t *e);        /* 只在主循环里调用：返回新发生了几次，并销账 */

#endif /* EVENT_H */
```

新建 `User/Src/event.c`：

```c
#include "event.h"

void event_init(event_t *e)
{
    e->posted = 0U;
    e->taken = 0U;
}

void event_post_from_isr(event_t *e)
{
    e->posted = e->posted + 1U;
}

uint32_t event_take(event_t *e)
{
    uint32_t posted = e->posted;        /* 只读一次，后面都用这个快照 */
    uint32_t n = posted - e->taken;     /* 无符号相减，计数回绕也对 */
    e->taken = posted;
    return n;
}
```

`main.c` 里定义实例 `static event_t key_evt;`，`main()` 里 `event_init(&key_evt);`。把 5.1 里按键中断回调的置 flag 换成一行：

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == KEY_Pin) {
        event_post_from_isr(&key_evt);   /* 取代 5.1 里的 g_key_flag = 1 */
    }
}
```

主循环里这样用：

```c
uint32_t n = event_take(&key_evt); /* 按键事件：对账，一次不丢 */
if (n > 0U) {
    LOG(LOG_INFO, "key events: %lu\r\n", (unsigned long)n);
}
```

#### 办法五：环形缓冲

当 ISR 要交给主循环的是一串数据（串口收到的字节、一连串采样值），上面的办法都不够用了，该用环形缓冲：一个固定大小的数组，生产者往里放，消费者往外取，下标走到头回到开头。

关键设计，一句话：**生产者只写 `head`，消费者只写 `tail`**。两边各写各的，还是单写者，所以不用关中断。

它同样是一个对象。存储区由调用者提供，对象只借用指针；容量、`head`、`tail`、丢弃计数都在对象里。

新建 `User/Inc/ringbuf.h`：

```c
#ifndef RINGBUF_H
#define RINGBUF_H

#include "main.h"

/* 字节环形缓冲对象：单生产者、单消费者。
 * 所有状态都在对象里，模块里没有全局变量，所以同一份代码可以建任意多个实例。 */
typedef struct {
    uint8_t *buf;               /* 存储区由调用者提供，对象只借用，不拥有 */
    uint32_t cap;               /* 容量，必须是 2 的幂 */
    volatile uint32_t head;     /* 只有生产者写：下一个要写入的位置，只增不减 */
    volatile uint32_t tail;     /* 只有消费者写：下一个要读出的位置，只增不减 */
    volatile uint32_t dropped;  /* 只有生产者写：满了丢掉的字节数 */
} ringbuf_t;

/* 成功返回 0；cap 不是 2 的幂（或为 0、buf 为空）返回 -1 */
int ringbuf_init(ringbuf_t *rb, uint8_t *buf, uint32_t cap);

/* 生产者调用（例如在中断里）。成功返回 0；满了丢弃并返回 -1 */
int ringbuf_put(ringbuf_t *rb, uint8_t b);

/* 消费者调用（例如在主循环里）。取到返回 0；空了返回 -1 */
int ringbuf_get(ringbuf_t *rb, uint8_t *out);

/* 现有多少字节。消费者调用时是下限（生产者可能又放了新的） */
uint32_t ringbuf_count(const ringbuf_t *rb);

/* 一共丢过多少字节 */
uint32_t ringbuf_dropped(const ringbuf_t *rb);

#endif /* RINGBUF_H */
```

新建 `User/Src/ringbuf.c`：

```c
#include "ringbuf.h"

int ringbuf_init(ringbuf_t *rb, uint8_t *buf, uint32_t cap)
{
    if (buf == NULL || cap == 0U || (cap & (cap - 1U)) != 0U) {
        return -1;
    }
    rb->buf = buf;
    rb->cap = cap;
    rb->head = 0U;
    rb->tail = 0U;
    rb->dropped = 0U;
    return 0;
}

int ringbuf_put(ringbuf_t *rb, uint8_t b)
{
    /* head、tail 是只增不减的"总数"，相减就是现有字节数；
     * 它们回绕时，无符号减法的结果依然正确（前提是 cap 是 2 的幂） */
    if ((rb->head - rb->tail) >= rb->cap) {
        rb->dropped = rb->dropped + 1U;
        return -1;
    }
    rb->buf[rb->head & (rb->cap - 1U)] = b;
    /* 先把数据写进去，再公布 head。屏障防止编译器把这两步换顺序 */
    __COMPILER_BARRIER();
    rb->head = rb->head + 1U;
    return 0;
}

int ringbuf_get(ringbuf_t *rb, uint8_t *out)
{
    if (rb->head == rb->tail) {
        return -1;
    }
    *out = rb->buf[rb->tail & (rb->cap - 1U)];
    /* 先把数据取走，再公布 tail；否则生产者可能在我们读之前就覆盖它 */
    __COMPILER_BARRIER();
    rb->tail = rb->tail + 1U;
    return 0;
}

uint32_t ringbuf_count(const ringbuf_t *rb)
{
    return rb->head - rb->tail;
}

uint32_t ringbuf_dropped(const ringbuf_t *rb)
{
    return rb->dropped;
}
```

几个细节值得停一下：

- `head` 和 `tail` 只增不减，永远不手动回绕，所以现有字节数就是 `head - tail`。它们绕过 2^32 时，无符号减法依然对，前提是容量是 2 的幂；`ringbuf_init()` 会拒绝不是 2 的幂的容量。
- `__COMPILER_BARRIER()` 的作用是让编译器别把"写数据"和"公布 head"换顺序。为什么换了会出事，放到分支里讲。
- 满了怎么办：丢掉新数据并计数，不要阻塞。3.1 的日志层是同一个思路。
- 这是"一个生产者、一个消费者"的版本。多个生产者要另想办法。

对象的好处，现在可以验证。再写一个小对象 `seqtest_t`：生产者按固定间隔往缓冲里放递增序号，消费者取出来检查序号是否连续，缺口就是丢的数据。

新建 `User/Inc/seqtest.h`：

```c
#ifndef SEQTEST_H
#define SEQTEST_H

#include "main.h"
#include "ringbuf.h"

/* 验证环形缓冲的小对象：生产者按固定间隔往缓冲里放递增序号，
 * 消费者取出来检查序号是否连续，缺口就是丢的数据。 */
typedef struct {
    ringbuf_t *rb;              /* 借用的环形缓冲 */
    uint32_t period;            /* 每几次 tick 放一个字节 */
    uint32_t div;               /* 只有 ISR 用 */
    uint8_t seq_tx;             /* 只有 ISR 用 */
    uint8_t seq_expect;         /* 只有主循环用 */
    uint32_t got;               /* 只有主循环用 */
    uint32_t missing;           /* 只有主循环用 */
    volatile uint32_t on;       /* 只有主循环写，ISR 只读 */
} seqtest_t;

void seqtest_init(seqtest_t *t, ringbuf_t *rb, uint32_t period);
void seqtest_start(seqtest_t *t);       /* 主循环里调用一次：从现在起 ISR 开始放字节 */
void seqtest_tick(seqtest_t *t);        /* 只在中断里调用，每 1 ms 一次 */
void seqtest_drain(seqtest_t *t);       /* 主循环里反复调用：取出所有字节并检查序号 */
void seqtest_report(const seqtest_t *t, const char *name);

#endif /* SEQTEST_H */
```

新建 `User/Src/seqtest.c`：

```c
#include "seqtest.h"
#include "log.h"

void seqtest_init(seqtest_t *t, ringbuf_t *rb, uint32_t period)
{
    t->rb = rb;
    t->period = period;
    t->div = 0U;
    t->seq_tx = 0U;
    t->seq_expect = 0U;
    t->got = 0U;
    t->missing = 0U;
    t->on = 0U;
}

void seqtest_start(seqtest_t *t)
{
    t->on = 1U;
}

void seqtest_tick(seqtest_t *t)
{
    if (t->on == 0U) {
        return;
    }
    t->div++;
    if (t->div >= t->period) {
        t->div = 0U;
        (void)ringbuf_put(t->rb, t->seq_tx);    /* 满了就丢，丢了会计数 */
        t->seq_tx++;
    }
}

void seqtest_drain(seqtest_t *t)
{
    uint8_t b;

    while (ringbuf_get(t->rb, &b) == 0) {
        t->missing += (uint8_t)(b - t->seq_expect);   /* 序号连续时这里是 0 */
        t->seq_expect = (uint8_t)(b + 1U);
        t->got++;
    }
}

void seqtest_report(const seqtest_t *t, const char *name)
{
    LOG(LOG_INFO, "[ring:%s] got=%lu missing=%lu dropped=%lu\r\n",
        name, (unsigned long)t->got, (unsigned long)t->missing,
        (unsigned long)ringbuf_dropped(t->rb));
}
```

> [!success]- 揭晓
> `a` 会丢，`dropped` 变大；`b` 不丢。主循环下次取数据时，`a` 发现序号有缺口，`missing` 随之变大，两个数大致对得上。
> 同一份代码，两个实例，各有各的容量，各有各的结局，互不影响。如果环形缓冲的 `head`、`tail` 是模块里的全局变量，第二路缓冲就得把整份代码抄一遍，改一套名字。
> 缓冲不是无底洞。要么消费得够快，要么把缓冲开大，要么接受丢弃并留下计数，让你知道丢过。

## 刚才发生了什么

你撞见的两类事故，名字叫**竞态**（race condition）：结果取决于 ISR 恰好插在哪里，而不是代码怎么写。

- 第二步是**撕裂**：一次读多个字，中间被插队，拿到半新半旧的值。
- 第三步是**丢更新**：`count++` 是读、改、写三步，中间被插队，ISR 那一下被覆盖。

根源是同一句话：**中断可以插在任意两条指令之间，所以"一行 C"不一定是"一步硬件"。** 回头看白板：你抄的每一笔都没错，错在值日生可以在两笔之间擦板子。

[[【原理】volatile与编译器优化|`volatile`]] 管的是另一件事：让编译器每次都真去读、真去写。它保证你读的是最新的，不保证"读到写完"的这一整套动作中间不被插队，所以 `volatile` 是必要的，但不是充分的。

五种办法的共同思路只有两条：要么让对方没机会插队（单写者、关中断），要么发现被插队了就重来（读两次比较）。环形缓冲和对账，是把单写者用到数据流和事件上。这些办法统称[[【原理】读改写与原子性|**原子性**]]的保障手段，一个操作要么完整做完，要么没开始，外人看不到中间状态。

顺带一提写法：本节每个模块都是"对象"，状态在 `struct` 里，实例在 `main.c` 里。这不只是好看。想想看，如果 `stamp` 的 `lo`、`hi` 是全局变量，要给另一个计时源也做一个时间戳，你只能抄代码。现在只需要多定义一个 `stamp_t`。

## 记住这几条

1. 对齐的 32 位及以下，**单次读或单次写**，在 Cortex-M 上不会被撕开。其余一律别假设：64 位、多字段、结构体，还有读改写（`x++`、`x |= m`）。
2. 共享变量先想"能不能只让一方写"。能，就不需要别的保护。
3. 两边都要写，或要一次读多个字：用 `irq_save()` / `irq_restore()` 包起来，不要无条件 `__enable_irq()`。
4. 临界区只放几条指令，里面不等待、不 `HAL_Delay`。
5. 事件别用 0/1 的 flag 去数个数，用 ISR 加、主循环对账的计数。
6. 一串数据用环形缓冲：一个生产者、一个消费者、容量是 2 的幂，满了丢弃并计数。
7. 带状态的模块写成对象：状态放 `struct`，函数以对象指针为第一个参数，先 `init` 再开中断。同一份代码才能建多个实例。
8. `volatile` 要加，但加了不等于安全。

## 练习

1. **复现**：分别用 Debug（`-O0 -g3`）和 Release（`-Os`）两种构建类型构建（切换方法见 2.2），跑 `count_demo(&counter, count_bump_plain, "plain")`，记下两次的 `lost`。哪次丢得多？两次都大于 0 吗？
2. **改造**：把时间戳换成"秒 + 毫秒"两个字段，也做成对象：ISR 每毫秒让 `ms` 加一，加到 1000 清零并让 `sec` 加一。写 `wall_init()`、`wall_tick()` 和 `wall_read()`，用"读两次比较"读出一致的 `sec` 和 `ms`。
3. **预测**：下面这段放在主循环里，会发生什么？先写下预测再试。

   ```c
   uint32_t primask = irq_save();
   HAL_Delay(10U);
   irq_restore(primask);
   ```

> [!success]- 提示与答案方向
> 1. 两次都大于 0。构建类型改变了循环的长短，也就改变了"ISR 刚好落在读和写之间"的概率，但不会让它消失，不要指望换成 Release 来修竞态。
> 2. 参考写法：
> ```c
> typedef struct {
>     volatile uint32_t sec;      /* 只有 wall_tick 写 */
>     volatile uint32_t ms;       /* 只有 wall_tick 写，0 到 999 */
> } wall_t;
>
> typedef struct {
>     uint32_t sec;
>     uint32_t ms;
> } wall_time_t;                  /* 读出来的一份快照 */
>
> void wall_init(wall_t *w)
> {
>     w->sec = 0U;
>     w->ms = 0U;
> }
>
> void wall_tick(wall_t *w)       /* 放进 htim6 回调，每 1 ms 一次 */
> {
>     uint32_t m = w->ms + 1U;
>     if (m >= 1000U) {
>         m = 0U;
>         w->sec = w->sec + 1U;
>     }
>     w->ms = m;
> }
>
> wall_time_t wall_read(const wall_t *w)
> {
>     uint32_t s1, m1, s2, m2;
>     do {
>         s1 = w->sec;
>         m1 = w->ms;
>         s2 = w->sec;
>         m2 = w->ms;
>     } while (s1 != s2 || m1 != m2);
>
>     wall_time_t t = { s1, m1 };
>     return t;
> }
> ```
> 3. 程序卡死。`HAL_Delay` 靠 SysTick 中断推进 `HAL_GetTick()`，中断被关了，时间就不走了，`HAL_Delay` 永远等不到。这也是"临界区里不等任何东西"的原因，下一节会专门讲 `HAL_Delay` 的其他坑。

回到开头那道题：主循环和 ISR 各自 `count++` 200 万次，结果为什么只会偏小？现在你可以自己答出来：ISR 加的那一下，被主循环手里的旧值盖掉了。
