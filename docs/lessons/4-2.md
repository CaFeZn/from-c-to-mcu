# 4.2 换个引脚与引脚复用

> **这一节你会做出**：把一个引脚搬到另一个引脚，一行用户代码都不改；看懂 CubeMX 的复用冲突提示；给每个引脚选对模式。
> **前置**：[[4.1_GPIO点灯按键蜂鸣器]]、[[2.3_怎么读手册]]　｜　**预计**：阅读 + 动手 45 分钟

> [!tip] 跳读自测：这一节你可能不用读
> 先回答下面几个问题（写下来，别只在心里答）。**全部答对**就直接跳到 [[5.1_中断入门]]；有一题拿不准，就从头读。
> 1. 用户代码里怎样引用 LED 引脚，才能在 CubeMX 里换引脚时一行代码都不用改？
> 2. 读代码找问题：LED 是高电平点亮，板上没有外部上拉。下面这段执行之后，灯会亮吗？为什么？
>    ```c
>    GPIO_InitStruct.Pin = LED_Pin;
>    GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_OD;
>    GPIO_InitStruct.Pull = GPIO_NOPULL;
>    HAL_GPIO_Init(LED_GPIO_Port, &GPIO_InitStruct);
>    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
>    ```
> 3. 一端接电源的按键，输入引脚该配上拉还是下拉？
> 4. 哪几类引脚不要随便改成普通 IO？换完引脚后不工作，排查顺序是什么？
>
> > [!success]- 答案，以及跳过后要带走的东西
> > 1. 用 CubeMX 的 User Label 生成的 `LED_GPIO_Port` 和 `LED_Pin`，不写死 `GPIOB`、`GPIO_PIN_13` 这类具体值。
> > 2. 不亮。开漏输出写 1 是"松手"，引脚悬空，不会输出高电平；没有外部上拉，就没有高电平。
> > 3. 下拉。按下时被接到电源，松开时由下拉电阻拉低。
> > 4. 调试口 SWD（F407 上通常是 PA13、PA14）、晶振引脚、BOOT 引脚、板载外设已占用的引脚。排查顺序：时钟，引脚，模式，数据。
> >
> > **带走清单**：本节没有新增代码文件。要带走的是约定：引脚一律用 User Label 宏；默认配置是输出推挽、按键上拉、速度 Low；CubeMX 的 SYS 页 Debug 保持 Serial Wire；开漏必须有上拉。

## 先看一个怪现象

想象一个人，名片夹里有好几张名片：一张印着"普通 IO"，一张印着"USART1_TX"，一张印着"TIM1_CH2"。你递哪张，对面就把他当哪种人。可他一次只能递一张。

单片机的一个引脚就是这样的人。芯片上引脚有限，外设却很多，于是一个引脚被设计成可以扮演好几种角色，由你来指定今天递哪张名片。这就是**引脚复用**，英文叫 alternate function，简称 AF。

这带来两个实际的问题。第一，板子上某个引脚被别的东西占了，想把功能搬到另一个引脚，要改多少代码？第二，两个外设同时看上了同一个引脚，谁让谁？

> [!question] 先猜一猜
> 你想把 LED 从现在的引脚搬到另一个空闲引脚。4.1 里的代码已经写完了，你预计要改多少处**用户代码**？
> A. 0 处　B. 1 到 2 处　C. 所有写了端口名的地方

## 动手做

### 第一步：在 CubeMX 里搬家

1. 在 Pinout 视图里，点旧的 LED 引脚，选 Reset_State，同时把它的 User Label 清空。
2. 点你想搬去的新引脚，选 GPIO_Output，在左侧 GPIO 配置里把 User Label 填成 `LED`，其余设置和 4.1 一样（推挽、无上下拉、速度 Low）。
3. 重新生成代码。

打开生成后的文件，对比一下变化。变的只有两处：`main.h` 里的两个宏，以及 `MX_GPIO_Init` 里多了一行新端口的时钟使能。下面以搬到 PE5 为例（只是举例，换成你自己的引脚）：

```c
/* main.h：CubeMX 根据 User Label 重新生成，只有这两行变了 */
#define LED_Pin GPIO_PIN_5
#define LED_GPIO_Port GPIOE

/* main.c 的 MX_GPIO_Init：多出一行，为新端口开时钟 */
__HAL_RCC_GPIOE_CLK_ENABLE();
```

> [!success]- 揭晓
> 答案是 A，0 处。你的用户代码只写 `LED_GPIO_Port` 和 `LED_Pin`，从来没写过 `GPIOB` 或 `GPIO_PIN_13`。搬家的时候，CubeMX 把这两个名字背后的值换掉了，你的代码毫不知情。
> 这就是 4.1 坚持用 User Label 的原因。
>
> 重新生成时被改动的，只有 CubeMX 自己管的文件（`Core/` 里的 `main.h`、`main.c` 的生成部分）。你放在 `User/Inc` 和 `User/Src` 里的 `key.c`、`buzzer.c` 这些模块，一个字都没被碰（目录约定见 2.2）。它们之所以不用改，是因为端口和引脚是 `xxx_init` 的参数，而不是写死在模块里。

**探针**：在工程的用户代码里搜 `GPIOB`、`GPIO_PIN_`，看有没有你自己写的。有的话，现在就改成标签宏。

**怎么验证搬家成功**：板载 LED 是焊死在原引脚上的，搬到新引脚后它不会再亮。要看到现象，有两个办法：

- 在新引脚上外接一颗 LED，**串一个限流电阻**再接地。阻值怎么算见本节末尾的拓展，别让 LED 直接接在引脚上。
- 用万用表量新引脚对地的电压，翻转时应该在接近 0 V 和接近 3.3 V 之间变化。

如果搬完不工作，按 [[3.2_调试与排错]] 的顺序查：时钟，引脚，模式，数据。上面多出来的那一行 `__HAL_RCC_GPIOE_CLK_ENABLE()`，就是"时钟"这一步。

### 第二步：撞一次复用冲突

在 Pinout 视图里找到你的 `huart1` 在用的 TX 引脚（板子上通常标着 USART1_TX）。试着把它改成 GPIO_Output。

你应该看到：左侧 USART1 对应的条目被高亮成醒目的颜色，鼠标悬停有一条说明，大意是它需要的引脚已经被别的功能占用。CubeMX 的颜色含义以你的版本为准，不用背，看到高亮和提示就知道出冲突了（我查阅的 CubeMX 用户手册里，无法解决的外设模式用紫红色高亮，被你改过的引脚用橙色高亮；你的版本可能不同）。

**撤销，换一种办法**：按住 Ctrl 点击那个 USART1_TX 引脚，CubeMX 会把同一个信号可以去的其他引脚标出来，你把它拖到新的引脚上，就是把这个外设"搬家"，而不是从中间抢走一个引脚。

这背后的规则很朴素：**一个引脚同一时刻只能递一张名片**。如果有人需要它，另一个人就得换引脚，没有商量。至于每个引脚到底有哪些名片可选，答案在数据手册的 Alternate function mapping 表里（怎么查见 [[2.3_怎么读手册]]）。CubeMX 的引脚下拉菜单，就是这张表的图形版。

> [!question] 先猜一猜
> 假设你为了凑够 LED 数量，把 PA13 和 PA14 也设成了 GPIO 输出，生成代码、下载一次。**再下载第二次**时会发生什么？
> PA13、PA14 在 F407 上是调试口 SWDIO 和 SWCLK（以你的数据手册为准）。

> [!success]- 揭晓
> 调试器很可能连不上板子了。调试器通过这两根线和芯片说话，你把它们改成了普通 IO，等于把调试器的门焊死。想救回来需要特殊办法，见分支。
> 所以有一条铁律：**不要动调试口的引脚**。在 CubeMX 的 SYS 页，Debug 要保持 Serial Wire。同理，接晶振的引脚、BOOT 引脚、板上已经接了别的东西的引脚，动之前先看原理图。

### 第三步：推挽、开漏、上拉、下拉，怎么选

这一步只讲"怎么选"，不讲电路原理。先看一遍 CubeMX 为 4.1 的三个引脚生成的 GPIO 初始化代码（版本不同，细节略有差别），你会发现你在界面里点的每个选项，对应的就是下面几行：

```c
static void MX_GPIO_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    /* 用到哪个端口，CubeMX 就替你打开哪个端口的时钟 */
    __HAL_RCC_GPIOE_CLK_ENABLE();
    __HAL_RCC_GPIOA_CLK_ENABLE();
    __HAL_RCC_GPIOB_CLK_ENABLE();

    /* 输出引脚先写好初始电平，再切成输出，避免上电瞬间闪一下 */
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
    HAL_GPIO_WritePin(BUZZER_GPIO_Port, BUZZER_Pin, GPIO_PIN_RESET);

    /* LED：推挽输出，不上下拉，低速 */
    GPIO_InitStruct.Pin = LED_Pin;
    GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
    GPIO_InitStruct.Pull = GPIO_NOPULL;
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(LED_GPIO_Port, &GPIO_InitStruct);

    /* 蜂鸣器：同上 */
    GPIO_InitStruct.Pin = BUZZER_Pin;
    GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
    GPIO_InitStruct.Pull = GPIO_NOPULL;
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(BUZZER_GPIO_Port, &GPIO_InitStruct);

    /* 按键：输入，内部上拉（按下接地） */
    GPIO_InitStruct.Pin = KEY_Pin;
    GPIO_InitStruct.Mode = GPIO_MODE_INPUT;
    GPIO_InitStruct.Pull = GPIO_PULLUP;
    HAL_GPIO_Init(KEY_GPIO_Port, &GPIO_InitStruct);
}
```

对应关系：

| CubeMX 里的选项 | 代码里的值 |
|---|---|
| GPIO mode：Output Push Pull | `GPIO_MODE_OUTPUT_PP` |
| GPIO mode：Output Open Drain | `GPIO_MODE_OUTPUT_OD` |
| GPIO Pull-up/Pull-down：No pull-up and no pull-down | `GPIO_NOPULL` |
| GPIO Pull-up/Pull-down：Pull-up | `GPIO_PULLUP` |
| Maximum output speed：Low | `GPIO_SPEED_FREQ_LOW` |

**输出引脚怎么选：**

| 你要驱动的东西 | 选 | 一句话理由 |
|---|---|---|
| LED、驱动三极管的蜂鸣器、给另一块芯片送高低电平 | 推挽，无上下拉 | 它能主动拉高，也能主动拉低，什么情况都能用 |
| 多个设备挂在同一根线上（比如 I2C）；对端电压和你不同，需要对端自己上拉 | 开漏，外加上拉电阻 | 它只会拉低，不会"推高"，多个设备同时说话也不会短路打架 |

**输入引脚怎么选：**

| 你接的东西 | 选 | 一句话理由 |
|---|---|---|
| 按键一端接地 | 输入，上拉 | 松开时有人把它拉高，按下时被接地 |
| 按键一端接电源 | 输入，下拉 | 反过来 |
| 对端是会主动输出高低电平的芯片或传感器 | 输入，无上下拉 | 对端自己负责给确定的电平 |

**速度（Maximum output speed）**：LED、蜂鸣器、普通控制信号都选 Low。速度越高，边沿越陡，干扰越大。有高速信号需要时再提高，不要默认选最高。

下面做两个探针，每个都改一处，看一个现象。

**探针一：把按键的上拉去掉。** 在 CubeMX 里把 KEY 的 Pull 改成 No pull-up and no pull-down，重新生成，再跑 4.1 第三步的那段计数代码。

你应该看到：松开状态下读数不稳定，可能自己乱跳，手靠近时更明显。引脚上没有任何东西给它一个确定的电平，这种状态叫**悬空**。如果你的板子上按键电路自己带了外部上拉电阻，则看不出差别，这时以原理图为准。

**探针二：把 LED 改成开漏。** 在 CubeMX 里把 LED 的 GPIO mode 改成 Output Open Drain，生成的代码里只有 Mode 一行不同。为了看得清楚，下面把它写成一个独立函数。先猜：LED 引脚改成开漏、无上拉，然后写入高电平，灯会亮吗？

```c
/* 探针：把 LED 改成开漏输出时，生成的代码只有 Mode 一行不同 */
static void led_open_drain(void)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};
    GPIO_InitStruct.Pin = LED_Pin;
    GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_OD;
    GPIO_InitStruct.Pull = GPIO_NOPULL;
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(LED_GPIO_Port, &GPIO_InitStruct);
}
```

然后执行：

```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);    /* 写 1 */
```

> [!success]- 揭晓
> 不会亮（按 LED 高电平点亮的假设）。开漏输出写 1，意思是"我松手，不管了"，引脚变成悬空，而不是输出高电平。没有外部上拉电阻，就没人把它拉高。即使你打开内部上拉，内部上拉电阻是几十千欧的量级（以数据手册为准）（待核对），驱动不了 LED。
> 记住：开漏输出的"1"是松手，不是推高。

## 刚才发生了什么

你这一节遇到的几个名词：

**复用（AF）**：一个引脚可以连接到好几个不同的功能，你用配置告诉它连哪个。默认是普通 GPIO，选了外设功能，它就归外设管。同一时刻只能选一个。

**推挽（push-pull）**：输出级里有两个开关，一个往上接电源，一个往下接地，二选一闭合，所以高低电平都由它主动给出。

**开漏（open-drain）**：输出级里只留了往下接地的那个开关。写 0 就接地，写 1 就断开。想要高电平，必须另外有电阻往上拉。

**上拉与下拉（pull-up、pull-down）**：给引脚接一个电阻到电源或地，避免它悬空。

这些开关在芯片里到底怎么接，放在 [[【原理】GPIO内部电路|GPIO 内部电路]]。主线只要你会选。

至于"为什么一个引脚能有那么多名片"，答案是引脚后面有一个选择开关，由配置寄存器控制。这个机制在 [[【原理】引脚复用机制|引脚复用机制]] 里讲，看不看都不影响你用 CubeMX。

回头看开头那位名片夹里有好几张名片的人。现在你知道：递哪张，是你在 CubeMX 里点的；两个人抢同一个位置，CubeMX 会提醒你；有些位置（比如调试口）最好别碰。

## 记住这几条

1. **引脚一律用 User Label 宏**。换引脚时只改 CubeMX，不改用户代码。
2. 动引脚之前先看原理图。板载外设占用的引脚、调试口（SWD）、晶振引脚，不要拿来当普通 IO。
3. CubeMX 的 SYS 页 Debug 保持 Serial Wire，除非你清楚后果。
4. 默认选择：输出用推挽，按键用上拉，速度选 Low。有理由再改。
5. 开漏必须有上拉电阻，否则写 1 等于什么都没输出。
6. 换完引脚不工作，按顺序查：时钟、引脚、模式、数据。

## 练习

1. 把蜂鸣器搬到另一个引脚，打开生成的文件，确认 `main.h` 里变了哪几行、`MX_GPIO_Init` 里时钟使能有没有变化。（复现）
2. 你的按键换成了另一种接法：一端接电源，按下为高电平。需要在 CubeMX 里和代码里各改哪些地方？（改造）
3. 把 LED 的 Maximum output speed 从 Low 改到 Very High，LED 会更亮或闪得更快吗？先写下预测，再想一想为什么。（预测）

> [!success]- 提示与答案方向
> 1. 如果新引脚在没用过的端口上，会多一行那个端口的 `__HAL_RCC_GPIOx_CLK_ENABLE()`。
> 2. CubeMX 里把 Pull 改成 Pull-down；代码里 `key.c` 的 `key_is_down()` 要把比较的电平反过来。4.1 把"极性"集中在一个函数里，这里只改一处就够。
> 3. 不会。速度只影响引脚电平切换时边沿的陡峭程度，对一个肉眼看的 LED 没有任何区别，反而可能带来更多干扰。
