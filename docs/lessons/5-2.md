# 5.2 定时器与节拍

> **这一节你会做出**：用 TIM6 做一个每 1 ms 走一格的节拍，维护全局毫秒计数 `g_ms`，再用它让 LED 闪烁、串口报时，主循环一刻也不被卡住。
> **前置**：[[5.1_中断入门]]　｜　**预计**：阅读 + 动手 45 分钟

> [!tip] 跳读自测：这一节你可能不用读
> 先回答下面几个问题（写下来，别只在心里答）。**全部答对**就直接跳到 [[5.3_PWM与输入捕获]]；有一题拿不准，就从头读。
> 1. TIM6 的输入时钟是 84 MHz，想要每 1 ms 一次更新中断，PSC 和 ARR 各填多少？
> 2. 下面这段软件定时器有什么隐患？
>    ```c
>    if (g_ms >= t_last + 500) { t_last += 500; HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin); }
>    ```
> 3. 在 `HAL_TIM_PeriodElapsedCallback` 里为什么要先判 `htim->Instance`？这个函数在整个工程里能写几份？
> 4. 能不能在这个回调里 `LOG` 一行再 `HAL_Delay(10)`？
>
> > [!success]- 答案，以及跳过后要带走的东西
> > 1. PSC = 83，ARR = 999（(83+1)×(999+1) = 84,000，84 MHz 除下来正好 1 kHz）。其他拆法只要 (PSC+1)×(ARR+1) = 84,000 且各自不超过 65,535 也行。
> > 2. `g_ms` 是 32 位，约 49.7 天回绕。`t_last + 500` 在 `t_last` 接近上限时会溢出成一个很小的数，条件立刻成立，灯会乱闪。应该写成 `g_ms - t_last >= 500`（无符号相减，回绕也对）。
> > 3. 所有基本定时器的更新中断都会进这个回调，要判是谁。全工程只能写一份，否则重复定义。
> > 4. 不能。中断里不输出、不阻塞、不调 `HAL_Delay`，回调里只做 `g_ms++`。
> >
> > **带走清单**（代码都在本节「第三步」，直接复制）：
> > - 本节不新增文件：全部写在 `Core/Inc/main.h` 和 `Core/Src/main.c` 的 USER CODE 区里，不用改 CMake。
> > - TIM6 配置：PSC = 83、ARR = 999，NVIC 里勾选 TIM6 global interrupt（第二步）。
> > - `volatile uint32_t g_ms`：定义放 `main.c` 的 PV 区，`extern` 声明放 `main.h` 的 EC 区；回调里判 `TIM6` 后 `g_ms++`；`HAL_TIM_Base_Start_IT(&htim6)` 放 USER CODE 2。
> > - `soft_due(uint32_t *last, uint32_t period_ms)`：软件定时器函数，放 USER CODE 0 区。后面章节会反复用到 `g_ms` 和 `soft_due`。

## 先看一个怪现象

乐队排练，十几个人，没有指挥，却能踩在同一个点上。靠的是墙上的一台节拍器：谁也不看自己的表，都听它那一声"咔哒"。

反过来想：如果每个人都拿一块秒表，自己数着时间演奏，会怎样？一个人盯着表数 500 毫秒的时候，他什么也干不了，更顾不上别人。

你在 2.2 里写的 `HAL_Delay(500)` 就是这种写法。它在这 500 ms 里原地数数，是"盯着秒表的人"。

> [!question] 先猜一猜
> 主循环这样写，想一边闪灯，一边每 10 ms 看一眼按键：
> ```c
> while (1) {
>     HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
>     HAL_Delay(500);
>     /* 想在这里每 10 ms 检查一次按键 */
> }
> ```
> 按键被按下后，最坏要等多久才会被检查到？如果按下后很快松开，又会怎样？

> [!success]- 揭晓
> 最坏要等将近 500 ms，因为 CPU 一直困在 `HAL_Delay` 里。要是按下到松开都落在这 500 ms 之内，靠轮询的检查根本看不到这次按键。
> 问题不在 500 这个数，而在"原地数数"这种写法：数的时候，什么别的事都做不了。

我们要的是墙上那台节拍器：它自己按固定节奏滴答，不占用主循环，所有人只需要抬头看一眼现在是第几下。

## 动手做

### 第一步：先算，再配

先别打开 CubeMX，先想清楚一件事：节拍器怎么才能走出"恰好 1 ms 一下"。

手里的"发条"是定时器的输入时钟，本节示例按 84 MHz 算，也就是每秒 84,000,000 下。里面有两个旋钮：

- **齿轮**：每 A 下才算一格，把飞快的发条变慢。
- **摆幅**：数满 B 格，才"咔哒"响一声。

> [!question] 先猜一猜
> 要让它每秒响 1000 次（每 1 ms 一次），A × B 要等于多少？A 和 B 各取几个数最顺手？
> 提示：先算总数，再拆成两个整数。

> [!success]- 揭晓
> A × B = 84,000,000 ÷ 1000 = 84,000。
> 最顺手的拆法是 A = 84，B = 1000：84 MHz 除以 84，得到 1 MHz，每格正好 1 µs，数满 1000 格就是 1 ms。
> 拆法不止一种，A = 840、B = 100 也行（840 × 100 = 84,000）。但 A = 1、B = 84,000 不行，因为 B 是一个 16 位数，装不下比 65,536 大的数。

现在给它们起真名。"齿轮"叫**预分频器**（Prescaler，简称 PSC），"摆幅"叫**自动重装载值**（Auto-Reload Register，简称 ARR）。

还有一个常见的陷阱。寄存器里要填的是 **A − 1** 和 **B − 1**，不是 A 和 B。所以示例要填：

- PSC = 83
- ARR = 999

> [!failure] 猜想：我直接填 PSC = 84，ARR = 1000，应该差不多吧
> 代入公式，实际总分频是 (84 + 1) × (1000 + 1) = 85,085，节拍频率是 84,000,000 ÷ 85,085 ≈ 987.2 Hz，每一拍约 1.0129 ms。
> 看着只差一点，但意味着你的"1 秒"其实是 1.0129 秒。这一条放在后面当探针，让现象自己说话。

周期公式记一条就够了：

> **节拍频率 = 定时器时钟 ÷ ((PSC + 1) × (ARR + 1))**

### 第二步：在 CubeMX 里配 TIM6

TIM6 是一个**基本定时器**：只会计数，没有输出引脚，专门用来做内部节拍，正合适。

先确认你自己的"发条"到底是多少。打开 CubeMX 的 Clock Configuration 页，找 APB1 对应的定时器时钟（名字类似 APB1 Timer clocks）。本节所有数字按 **84 MHz** 算，**以你自己时钟树上显示的为准**。如果你的显示不是 84 MHz，后面的 PSC、ARR 要重新算。时钟为什么会"翻倍"，放在[[【原理】时钟树|时钟树]]里讲，这里先照着读数用。

然后在 Pinout & Configuration 里：

| 位置 | 填写 |
|---|---|
| Timers → TIM6 | 勾选 Activated |
| Parameter Settings → Prescaler (PSC) | `83` |
| Parameter Settings → Counter Mode | Up |
| Parameter Settings → Counter Period (ARR) | `999` |
| Parameter Settings → auto-reload preload | 保持默认（节拍固定，不会再改） |
| NVIC Settings | 勾选 TIM6 global interrupt（F407 上名字叫 TIM6 and DAC global interrupt） |

界面文字以你的 CubeMX 版本为准。生成代码之后，别的事 CubeMX 已经替你做了：初始化 `htim6`，以及中断入口 `TIM6_DAC_IRQHandler`，里面会调用 `HAL_TIM_IRQHandler(&htim6)`。

### 第三步：写 g_ms 和回调

先让全工程都认识 `g_ms`。在 `main.h` 里声明：

```c
/* USER CODE BEGIN EC */
extern volatile uint32_t g_ms;   /* 全局毫秒计数，定义在 main.c，其他文件用它时包含 main.h 即可 */
/* USER CODE END EC */
```

然后在 `main.c` 里依次填几处。先包含日志层：

```c
/* USER CODE BEGIN Includes */
#include "log.h"   /* 3.1 里写好的日志层 */
/* USER CODE END Includes */
```

定义这个计数变量：

```c
/* USER CODE BEGIN PV */
/* 中断里写、主循环里读，所以必须 volatile（5.1 的规矩） */
volatile uint32_t g_ms = 0;
/* USER CODE END PV */
```

再写一个"软件定时器"的小函数，下一步会用到：

```c
/* USER CODE BEGIN 0 */
/* 软件定时器：到点返回 1，并把"下一个到点时刻"记进 *last。
 * 用"现在减去上次"和间隔比较：无符号减法在 g_ms 回绕时依然正确。
 * 用 += 而不是 = g_ms：每次的小误差不会累积成漂移。 */
static int soft_due(uint32_t *last, uint32_t period_ms)
{
    if ((uint32_t)(g_ms - *last) >= period_ms) {
        *last += period_ms;
        return 1;
    }
    return 0;
}
/* USER CODE END 0 */
```

启动 TIM6：

```c
/* USER CODE BEGIN 2 */
log_init(&huart1);                /* 已在 3.1 加过就不要重复 */
HAL_TIM_Base_Start_IT(&htim6);    /* 启动 TIM6，并打开它的更新中断 */
/* USER CODE END 2 */
```

最后，节拍到来时的那段代码，是重写 HAL 的弱函数：

```c
/* USER CODE BEGIN 4 */
/* 所有基本定时器的"计满一圈"都会进这个回调，必须认清是谁 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM6) {
        g_ms++;               /* 只做这一件事：短、不阻塞、不输出 */
    }
}
/* USER CODE END 4 */
```

> [!warning] 整个工程只能写一份 HAL_TIM_PeriodElapsedCallback
> 以后你用到别的定时器，它们的"计满一圈"也会进同一个回调。所以函数里一定要用 `htim->Instance` 判一下是谁，不要每个定时器各写一份，否则链接时会报重复定义。

### 第四步：主循环里放两个软件定时器

```c
  /* USER CODE BEGIN WHILE */
  uint32_t t_led = 0;     /* LED 软件定时器的"上次到点"时刻 */
  uint32_t t_log = 0;     /* 报时软件定时器 */
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    if (soft_due(&t_led, 500u)) {
        HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
    }
    if (soft_due(&t_log, 1000u)) {
        LOG(LOG_INFO, "alive, g_ms=%lu\r\n", (unsigned long)g_ms);
    }
  }
  /* USER CODE END 3 */
```

在 VS Code 里用 CMake Tools 构建并下载到板子（构建和下载的步骤见 [[2.2_开发环境与第一次点灯]]），打开串口助手（115200）。

你应该看到：

- LED 每 0.5 s 翻转一次，也就是 1 s 一个完整的亮灭。
- 串口每秒一行 `alive, g_ms=1000`、`alive, g_ms=2000` ……（数值基本是整千，偶尔可能差 1）。

这是按配置推演出来的现象，我这边没有上板，板子上以你实际看到的为准。

### 第五步：三个探针

**探针 1：让现象否定"差不多"。** 把 PSC 改成 84，ARR 改成 1000，重新构建并下载，对着手机秒表看串口日志。

> [!question] 先猜一猜
> 按前面算出的 987.2 Hz，等串口出完 60 行 alive，真实时间应该是多少？

> [!success]- 揭晓
> 每一拍约 1.0129 ms，所以 `g_ms` 数到 1000 时真实过去了约 1.0129 s。60 行大约是 60 × 1.0129 ≈ 60.8 s，比你的秒表读数多出近 1 s。改回 83 和 999，应当重新对齐。

**探针 2：换一种拆法。** PSC 改成 839，那 ARR 要填几才能保持 1 ms？先算，再改，看日志是不是照旧。

> [!success]- 答案
> (839 + 1) × (ARR + 1) = 84,000，所以 ARR = 99。

**探针 3：把 LED 放进回调里翻转。** 临时在 `g_ms++` 后面加 `HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);`，注意这只是实验，实验完要删掉。LED 每毫秒翻转一次，是一个 500 Hz 的方波，肉眼多半只看到一个不闪的"半亮"。有示波器或逻辑分析仪的话，应当量到 500 Hz。这个"快到看不出闪烁"的现象，正是 5.3 的主角。

## 刚才发生了什么

节拍器的每个零件，在单片机里都有真名：

| 零件 | 真名 | 它做什么 |
|---|---|---|
| 发条 | 定时器时钟（来自时钟树） | 每秒 84,000,000 下 |
| 齿轮 | 预分频器 PSC | 把时钟除以 PSC + 1 |
| 摆锤的位置 | 计数器 CNT | 每个分频后的时钟 +1 |
| 摆幅 | 自动重装载值 ARR | 数到 ARR 后回零重来 |
| "咔哒" | 更新事件，开了中断就是**更新中断** | 每圈一次，通知 CPU |
| 听到咔哒的人 | `HAL_TIM_PeriodElapsedCallback` | 你写的代码，做 `g_ms++` |

计数器怎么数、为什么 ARR 要少 1，放在[[【原理】定时器工作原理|定时器工作原理]]里。

整条路径是：计数器数满 → 更新中断 → [[【原理】中断与NVIC|NVIC]] 放行 → CPU 跳到 `TIM6_DAC_IRQHandler` → `HAL_TIM_IRQHandler` 清标志、分发 → 你的回调。你要写的只有最后一步，而且最好只做 `g_ms++`：这是 5.1 里讲过的中断规矩，要短、不阻塞、不输出。

有了 `g_ms`，"盯着秒表的人"就变成"抬头看钟的人"。`soft_due` 每次只问一句：自从上次到点，已经过去至少 period 毫秒了吗？没有就立刻往下走，有就做事。主循环于是可以同时托住好几件事，每件事都有自己的"上次到点"。

两处细节值得多想一下：

- **为什么是 `g_ms - *last >= period`，而不是 `g_ms >= *last + period`？** `g_ms` 是 32 位，约 49.7 天（2³² ms）会回绕到 0。设上次到点是 4,294,967,000，现在是 4,294,967,100，真实只过了 100 ms。写成 `g_ms >= *last + period` 时，右边 4,294,967,000 + 500 溢出成 204，条件马上成立，灯提前乱闪。写成"相减再比较"，无符号减法的结果依然是 100，对得上。这里的"回绕"道理在[[【原理】补码与整型转换|补码与整型转换]]里。这个差别在电脑上能亲眼看到，见下面的折叠示例。
- **为什么 `*last += period`，而不是 `*last = g_ms`？** 前者保持"按节拍对齐"，每次晚到的那几毫秒不会累加；后者每次都从"现在"重新开始数，误差会越积越多。代价是，主循环如果被卡住了很久，回来后会连续补发几次，所以主循环里不要放长时间阻塞的东西。

> [!example]- 在电脑上亲眼看：两种写法遇到回绕会怎样
> 用第 1 章的 c-lab 工程：把下面的文件存成 `src/wrap_cmp.c`，在 `CMakeLists.txt` 末尾加一行 `add_demo(wrap_cmp)`，然后构建并运行。
> ```c
> #include <stdio.h>
> #include <stdint.h>
>
> int main(void) {
>     uint32_t last = 4294967000u;      /* 上次到点的时刻，离 32 位上限只差 296 */
>     uint32_t now  = 4294967100u;      /* 现在，真实只过了 100 ms */
>     uint32_t period = 500u;
>
>     printf("g_ms >= last + period : %d\n", now >= last + period);               /* 右边溢出成 204 */
>     printf("g_ms - last >= period : %d\n", (uint32_t)(now - last) >= period);   /* 相减是 100 */
>     return 0;
> }
> ```
> 我在电脑上用 cmake、Ninja 和 gcc 构建运行，输出是：
> ```
> g_ms >= last + period : 1
> g_ms - last >= period : 0
> ```
> 第一行是 1：才过了 100 ms 就"到点"了。第二行是 0：正确地认为还没到。

HAL 自己也有一个毫秒计数，`HAL_GetTick()`，由 SysTick 提供。我们另起一个 `g_ms`，一是练手，二是后面几章统一用它。两者什么时候会不一致，到 5.5 讲精度时再碰到。

## 记住这几条

1. 节拍频率 = 定时器时钟 ÷ ((PSC + 1) × (ARR + 1))，寄存器里填的是比"你想要的数"少 1 的值。
2. 先看自己时钟树上的定时器时钟，再算 PSC 和 ARR。示例的 84 MHz 不一定是你的。
3. PSC 和 ARR 在 TIM6 上都是 16 位，最大 65,535，总分频要拆开。
4. `HAL_TIM_PeriodElapsedCallback` 全工程只写一份，里面先判 `htim->Instance`。
5. 回调里只做 `g_ms++`，不输出、不阻塞、不调 `HAL_Delay`。
6. 判断"到点没"一律写成"现在减去上次再和间隔比较"，别写成"现在大于上次加间隔"。
7. 要同时做几件事，别用 `HAL_Delay`，用 `g_ms` 做软件定时器。

## 练习

1. 把 LED 改成 100 ms 翻转，串口报时改成每 2 s 一次。（复现）
2. 再加第三个软件定时器：每 5 s 在日志里输出一次 `g_ms / 1000`（秒数）。注意这行日志写在主循环里，不要写进回调。（改造）
3. 假设你的时钟树显示 TIM6 的时钟是 42 MHz，还想要 1 ms 节拍，PSC 和 ARR 填多少？（预测）

> [!success]- 提示与答案方向
> 1. 把 `500u` 改成 `100u`，把 `1000u` 改成 `2000u`。
> 2. 照着 `t_log` 的样子再定义一个变量。
> 3. 总分频 = 42,000,000 ÷ 1000 = 42,000，可以取 PSC = 41、ARR = 999。

最后回到开头那道题。现在换成这样写：`soft_due(&t_key, 10u)` 每 10 ms 查一次按键，`soft_due(&t_led, 500u)` 管灯。按键最坏要等多久？大约 10 ms，加上主循环跑一圈的时间。那个"盯着秒表的人"，被换成了抬头看钟的人。
