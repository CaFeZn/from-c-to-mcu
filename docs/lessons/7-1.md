# 7.1 CAN发出第一帧

> **这一节你会做出**：把 F407 的 bxCAN 配成 500 kbit/s，先用回环模式在一块板上"自己发给自己"，再接上真正的总线（另一块板或 USB-CAN 工具）收发一帧。同时写好后面三节都要用的 `can_node_t` 对象。
> **前置**：[[5.2_定时器与节拍]]　[[6.1_串口命令行]]　｜　**预计**：阅读 + 动手 90 分钟

> [!tip] 跳读自测：这一节你可能不用读
> 先回答下面几个问题（写下来，别只在心里答）。**全部答对**就直接跳到 [[7.2_CAN仲裁与帧]]；有一题拿不准，就从头读。
> 1. 读代码找问题：回环模式下，下面这段程序的发送返回 0，发送完成计数也在涨，但接收回调一次都不触发。最可能漏了什么？
>    ```c
>    can_node_init(&g_can, &hcan1);
>    can_node_set_rx_handler(&g_can, on_can_rx, NULL);
>    can_node_start(&g_can);
>    ```
> 2. APB1 外设时钟 PCLK1 是 48 MHz，目标 500 kbit/s。写出一组 Prescaler、BS1、BS2，并算出采样点。
> 3. `can_node_send()` 返回 0，说明这一帧已经发到总线上了吗？
> 4. 总线两端各接了一个 120 Ω。断电后用万用表量 CAN_H 和 CAN_L 之间，大约读到多少？
>
> > [!success]- 答案，以及跳过后要带走的东西
> > 1. 没配过滤器。没有任何过滤器处于激活状态时，硬件把收到的帧全部丢掉。补上 `can_node_filter_all(&g_can);`。
> > 2. 总分频 48,000,000 ÷ 500,000 = 96，拆成 Prescaler × 每位的时间量子数。例如 Prescaler = 6，每位 16 个量子，BS1 = 13，BS2 = 2，采样点 (1 + 13) ÷ 16 = 87.5%。别的拆法也对，只要 Prescaler × (1 + BS1 + BS2) = 96。
> > 3. 不能。返回 0 只表示这一帧已经排进了发送邮箱。硬件确认发完了，要看 `tx_done`。
> > 4. 约 60 Ω。两个 120 Ω 并联。只有一个电阻会读到约 120 Ω，一个都没有则读数会远大于 120 Ω。
> >
> > **带走清单**：
> > - 文件：`can_msg.h`、`can_node.h`、`can_node.c`（本节「第三步」），头文件放 `User/Inc`，`can_node.c` 放 `User/Src`。顶层 `CMakeLists.txt` 里 2.2 讲过的那几行会自动把它们收进编译，新增文件后重新配置一次即可（见 2.2）。7.3 会给出加了过滤器和错误处理的终版，直接用终版也可以。
> > - CubeMX：CAN1 的 Prescaler 6、BS1 = 11 TQ、BS2 = 2 TQ、SJW = 1 TQ（PCLK1 = 42 MHz 时是 500 kbit/s，以你的时钟树为准）；Automatic Retransmission 选 Enable；NVIC 里勾 CAN1 TX interrupts 和 CAN1 RX0 interrupts；先选 Loopback 模式，上总线时改 Normal。
> > - 约定：只处理 11 位标准数据帧；接收回调在主循环里（`can_node_poll()` 里）被调用，不在中断里；`can_node_send()` 返回 0 成功、-1 参数错误、-2 邮箱满。
> > - 写法：一个 CAN 节点就是一个 `can_node_t` 对象，状态都在对象里，函数以对象指针为第一个参数。7.2 到 7.4 沿用。

## 先看一个怪现象

一间大会议室，所有人共用一张长桌说话。桌子两头各贴一块吸音棉，不让声音撞到墙上再反射回来，搅成一团。这张桌子就是**总线**，两头的吸音棉，对应总线两端各接的一个 120 Ω 电阻。

今天先不碰桌子，先在一个人的小房间里练习：自己对自己说一句话，再把它听回来。

你写好了发送，函数返回成功，发送完成的计数也在涨。可是接收的回调，一次都没有被调用。

> [!question] 先猜一猜
> 外设已经启动，波特率没问题，发送成功。接收回调就是不来。下面哪一项最可能是原因？
> A. 总线上没有接终端电阻
> B. 没有配置接收过滤器
> C. 没有接 CAN 收发器
> D. 波特率算错了

> [!success]- 揭晓
> 选 B。回环模式是外设内部把发送端接回接收端，不经过收发器，也不需要终端电阻，所以 A 和 C 都不是原因。波特率在回环里只影响收发的快慢，不影响能不能收到，所以 D 也不是。
> bxCAN 的接收端前面有一排**过滤器**。没有任何一个过滤器被激活的时候，所有收到的帧都被硬件直接丢掉，不进接收 FIFO，也不会有任何报错。下面我们会先故意不配它，亲眼看一次。

## 动手做

### 第一步：先算位时序

CAN 要求所有节点用同一个波特率。波特率不是填一个 500000 就行，而是要把"一位"切成若干小格，由你来决定怎么切。这一步先算清楚，再去 CubeMX 里填。

**CAN 用的是 APB1 外设时钟 PCLK1**，不是 5.2 里算定时器用的 84 MHz。示例的时钟树是 CPU 168 MHz、APB1 分频 4，所以 PCLK1 = 42 MHz。同一棵时钟树里，APB1 的定时器时钟是 84 MHz，因为 APB1 分频不为 1 时，定时器时钟会翻倍（原因见[[【原理】时钟树|时钟树]]）。**你的数字以 CubeMX 时钟树里 APB1 peripheral clocks 的读数为准。**

算法分四步：

1. **总分频** = PCLK1 ÷ 目标波特率 = 42,000,000 ÷ 500,000 = 84。
2. 把总分频拆成 **Prescaler × NTQ**。Prescaler 是预分频，决定一个"时间量子"（tq）有多长；NTQ 是一位里含多少个量子。
3. 一位 = 1 个同步段 + BS1 + BS2，所以 NTQ = 1 + BS1 + BS2。BS1 范围 1 到 16，BS2 范围 1 到 8，所以 NTQ 最大 25。
4. **采样点** = (1 + BS1) ÷ NTQ，也就是一位走到百分之几的位置去读电平。常见取在 75% 到 90% 之间。

> [!question] 先猜一猜
> 总分频是 84。如果选每位 14 个量子（NTQ = 14），Prescaler 取几？一个量子多长？
> 再想一想：84 还能拆成哪些 Prescaler × NTQ，NTQ 又必须不超过 25？

> [!success]- 揭晓
> Prescaler = 84 ÷ 14 = 6，一个量子 = 6 ÷ 42 MHz ≈ 142.86 ns，一位 = 14 × 142.86 ns = 2 µs，正好对应 500 kbit/s。
> 84 的约数里，NTQ ≤ 25 的有 12（Prescaler 7）、14（Prescaler 6）、21（Prescaler 4）等。

手算容易漏，写个小工具枚举。它是纯 C，在电脑上的 `c-lab` 工程里构建运行，和第 1 章是同一套做法。存成 `c-lab/src/can_timing.c`，在 `CMakeLists.txt` 末尾加一行 `add_demo(can_timing)`：

```c
#include <stdio.h>
#include <stdlib.h>

/* 用法：can_timing [CAN 时钟 Hz] [目标波特率]
 * 例如：can_timing 42000000 500000
 * 枚举所有能"精确"得到目标波特率的 (Prescaler, BS1, BS2) 组合，只列采样点在 75%~90% 的。 */
int main(int argc, char *argv[]) {
    unsigned long pclk = 42000000UL;   /* 默认：APB1 外设时钟 42 MHz */
    unsigned long baud = 500000UL;     /* 默认：500 kbit/s */

    if (argc >= 3) {
        pclk = strtoul(argv[1], NULL, 10);
        baud = strtoul(argv[2], NULL, 10);
    }
    if (pclk == 0UL || baud == 0UL) {
        printf("usage: can_timing PCLK_HZ BAUD\n");
        return 1;
    }

    printf("CAN clock = %lu Hz, target = %lu bit/s\n", pclk, baud);
    printf("%-9s %-4s %-4s %-4s %-10s %-9s\n", "Prescaler", "NTQ", "BS1", "BS2", "tq(ns)", "sample");

    int found = 0;
    for (unsigned long p = 1; p <= 1024UL; p++) {
        if (pclk % (p * baud) != 0UL) {
            continue;                              /* 不能整除，得不到精确的波特率 */
        }
        unsigned long ntq = pclk / (p * baud);     /* 每位含多少个时间量子 */
        if (ntq < 8UL || ntq > 25UL) {
            continue;                              /* 最大 1+16+8=25；太小则采样点分辨率太粗 */
        }
        for (unsigned long bs2 = 1; bs2 <= 8UL; bs2++) {
            unsigned long bs1 = ntq - 1UL - bs2;   /* 1 个同步段 + BS1 + BS2 = NTQ */
            if (bs1 < 1UL || bs1 > 16UL) {
                continue;
            }
            double sample = 100.0 * (double)(1UL + bs1) / (double)ntq;
            if (sample < 75.0 || sample > 90.0) {
                continue;
            }
            double tq_ns = 1e9 * (double)p / (double)pclk;
            printf("%-9lu %-4lu %-4lu %-4lu %-10.2f %.1f%%\n", p, ntq, bs1, bs2, tq_ns, sample);
            found = 1;
        }
    }
    if (!found) {
        printf("no exact combination, try another clock or baud rate\n");
    }
    return 0;
}
```

构建并运行 `./build/can_timing`（不带参数，就用默认的 42 MHz 和 500 kbit/s）：

你应该看到：

```
CAN clock = 42000000 Hz, target = 500000 bit/s
Prescaler NTQ  BS1  BS2  tq(ns)     sample
4         21   16   4    95.24      81.0%
4         21   15   5    95.24      76.2%
6         14   11   2    142.86     85.7%
6         14   10   3    142.86     78.6%
7         12   9    2    166.67     83.3%
7         12   8    3    166.67     75.0%
```

本教程选第三行：**Prescaler = 6，BS1 = 11，BS2 = 2，SJW = 1**，采样点 85.7%。SJW 是重新同步时一次最多能调整几个量子，取 1 就够用。

采样点为什么不放在最后？信号在线上传播、收发器处理都需要时间，读得太早，电平可能还没稳定；读得太晚，留给重新同步的余量就少了。总线上的节点最好用同样的波特率和相近的采样点。这背后的细节放在[[【原理】CAN位定时与采样点|位定时与采样点]]里。

换一个时钟再试一次，看看你自己的板子：

```
./build/can_timing 48000000 500000
```

> [!example] 探针：只动 BS1 和 BS2
> 把 BS1 从 11 改成 10，BS2 从 2 改成 3，Prescaler 不动。波特率还是 500 kbit/s 吗？采样点变成多少？
> 波特率不变，因为 NTQ 仍是 14，Prescaler 仍是 6。采样点变成 (1 + 10) ÷ 14 = 78.6%，也就是工具输出的第四行。波特率只由 Prescaler 和 NTQ 决定，BS1 与 BS2 只是在一位里挪动采样点的位置。

### 第二步：在 CubeMX 里配 CAN1

| 位置 | 填写 |
|---|---|
| Connectivity → CAN1 | 勾选 Activated |
| Parameter Settings → Prescaler (for Time Quantum) | `6` |
| Time Quanta in Bit Segment 1 | `11 Times` |
| Time Quanta in Bit Segment 2 | `2 Times` |
| ReSynchronization Jump Width | `1 Time` |
| Operating Mode | **Loopback**（先自测，7.1 后半段改成 Normal） |
| Time Triggered Communication Mode | Disable |
| Automatic Bus-Off Management | Disable（7.3 再讲） |
| Automatic Wake-Up Mode | Disable |
| Automatic Retransmission | **Enable**（出错或仲裁失败后硬件自动重发） |
| Receive Fifo Locked Mode | Disable |
| Transmit Fifo Priority | Disable（7.2 再讲） |
| NVIC Settings | 勾选 `CAN1 TX interrupts` 和 `CAN1 RX0 interrupts` |

界面文字以你的 CubeMX 版本为准。CubeMX 会在参数页上算出一个 Baud Rate，核对它是 500000 bit/s。这个读数也是检验你时钟树是否和示例一致的最快办法。

引脚怎么选：CAN1 常见三组，PA11 / PA12，PB8 / PB9，PD0 / PD1，**以数据手册的复用表和你的原理图为准**。PA11、PA12 同时是 USB 的引脚，如果你的板子用了 USB，就别选这一组。换引脚和复用冲突的处理见 4.2。

关键的一点：**CubeMX 只会生成初始化函数，不会替你配过滤器，也不会启动外设。** 这两件事得自己写，下一步就写。

### 第三步：写 can_node，一个 CAN 节点对象

HAL 给的 `hcan1` 本身就是一个对象：数据在 `CAN_HandleTypeDef` 里，操作是以 `&hcan1` 为第一个参数的 `HAL_CAN_Start()`、`HAL_CAN_AddTxMessage()`。我们要做的，是在它外面再包一层，把接收队列、计数、过滤器占用情况、回调函数也装进去。这样做之后，两路 CAN 可以各有一个 `can_node_t`，互不干扰；同一份应用代码也不用知道底下是哪个外设。这种写法的来龙去脉见[[【原理】C语言里的面向对象|C 语言里的面向对象]]。

先说放哪儿。从这一章起，板上的代码都按 2.2 的约定放：头文件进 `User/Inc`，`.c` 进 `User/Src`，不放进 CubeMX 管理的 `Core/`。顶层 `CMakeLists.txt` 里 2.2 讲过的那几行会自动把 `User/Src` 下的 `.c` 收进编译，并把 `User/Inc` 加进头文件搜索路径，所以不用改 `CMakeLists.txt`；新建了文件之后，让 CMake 重新配置一次就行。

先看三个文件，再讲要点。

`can_msg.h` 只描述"一帧"，**里面没有任何 HAL 类型**。这一点到 7.4 会派上用场：

```c
#ifndef CAN_MSG_H
#define CAN_MSG_H

#include <stdint.h>

/* 一帧标准数据帧的最小描述。里面没有任何 HAL 类型，所以在 PC 上也能编译、测试。 */
typedef struct {
    uint16_t id;        /* 11 位标准 ID，范围 0..0x7FF */
    uint8_t  dlc;       /* 数据字节数，0..8 */
    uint8_t  data[8];   /* 只有前 dlc 个字节有意义 */
} can_msg_t;

#endif /* CAN_MSG_H */
```

`can_node.h` 是对外的接口：类型和函数声明都在这里。

```c
#ifndef CAN_NODE_H
#define CAN_NODE_H

#include "main.h"          /* 带进来 HAL 和 CAN_HandleTypeDef */
#include "can_msg.h"

#define CAN_NODE_RXQ_LEN    16u   /* 软件接收队列的深度，必须是 2 的幂 */
#define CAN_NODE_MAX_BANKS  14u   /* CAN1 可用的过滤器组数（SlaveStartFilterBank 设为 14） */

/* 收到一帧时被调用。它在 can_node_poll() 里被调用，也就是在主循环里，不在中断里，
 * 所以回调里可以放心 LOG()。 */
typedef void (*can_rx_fn)(void *ctx, const can_msg_t *msg);

/* CAN 节点对象：把 HAL 的 CAN_HandleTypeDef 再包一层，加上接收队列、计数和回调。 */
typedef struct {
    /* ---- 配置：init 之后基本不变 ---- */
    CAN_HandleTypeDef *hcan;        /* 背后的 HAL 对象，例如 &hcan1 */
    can_rx_fn          on_rx;       /* 收到帧时的回调，可以是 NULL */
    void              *on_rx_ctx;   /* 回调的第一个参数，用来带上"谁在用我" */
    uint8_t            next_bank;   /* 下一个空闲的过滤器组，每配一个过滤器加一 */

    /* ---- 接收队列：中断只写 rx_head，主循环只写 rx_tail ---- */
    can_msg_t          rxq[CAN_NODE_RXQ_LEN];
    volatile uint32_t  rx_head;
    volatile uint32_t  rx_tail;

    /* ---- 计数，只读，别直接改 ---- */
    volatile uint32_t  tx_req;      /* 成功排进发送邮箱的帧数 */
    volatile uint32_t  tx_done;     /* 硬件确认发完的帧数 */
    volatile uint32_t  tx_full;     /* 三个邮箱都满，发送被拒绝的次数 */
    volatile uint32_t  rx_cnt;      /* 放进接收队列的帧数 */
    volatile uint32_t  rx_drop;     /* 接收队列已满，被丢掉的帧数 */
} can_node_t;

/* 初始化对象，并把它登记起来，好让 HAL 的全局回调能找到它。
 * 必须在 MX_CAN1_Init() 之后调用。 */
void can_node_init(can_node_t *n, CAN_HandleTypeDef *hcan);

/* 设置收到帧时的回调。 */
void can_node_set_rx_handler(can_node_t *n, can_rx_fn fn, void *ctx);

/* 配一个"全收"过滤器。返回 0 成功，-1 失败。必须在 can_node_start() 之前或之后都可以，
 * 但不配就收不到任何帧。 */
int can_node_filter_all(can_node_t *n);

/* 启动 CAN 外设并打开收发中断。返回 0 成功，-1 失败。 */
int can_node_start(can_node_t *n);

/* 发送一帧标准数据帧。
 * 返回 0：已排进发送邮箱（不代表已经发出去）；-1：参数错误；-2：三个邮箱都满。 */
int can_node_send(can_node_t *n, uint16_t id, const uint8_t *data, uint8_t len);

/* 在主循环里反复调用：把中断收进队列的帧取出来，逐帧调用 on_rx。 */
void can_node_poll(can_node_t *n);

#endif /* CAN_NODE_H */
```

`can_node.c` 是实现：

```c
#include "can_node.h"
#include <string.h>

#define RXQ_MASK  (CAN_NODE_RXQ_LEN - 1u)

/* 编译期检查：队列深度不是 2 的幂就让数组长度变成负数，编译不过 */
typedef char rxq_len_must_be_power_of_two[((CAN_NODE_RXQ_LEN & (CAN_NODE_RXQ_LEN - 1u)) == 0u) ? 1 : -1];

/* ---------- 登记表 ----------
 * HAL 的回调是全局函数，参数里只有 CAN_HandleTypeDef *。
 * 要从它找回对应的 can_node_t，就靠这张表。表是本文件私有的（static）。 */
#define CAN_NODE_MAX_INSTANCES  2u
static can_node_t *s_nodes[CAN_NODE_MAX_INSTANCES];

static can_node_t *find_node(const CAN_HandleTypeDef *hcan)
{
    for (uint32_t i = 0; i < CAN_NODE_MAX_INSTANCES; i++) {
        if (s_nodes[i] != NULL && s_nodes[i]->hcan == hcan) {
            return s_nodes[i];
        }
    }
    return NULL;
}

void can_node_init(can_node_t *n, CAN_HandleTypeDef *hcan)
{
    memset(n, 0, sizeof *n);
    n->hcan = hcan;

    for (uint32_t i = 0; i < CAN_NODE_MAX_INSTANCES; i++) {
        if (s_nodes[i] == NULL || s_nodes[i]->hcan == hcan) {
            s_nodes[i] = n;
            break;
        }
    }
}

void can_node_set_rx_handler(can_node_t *n, can_rx_fn fn, void *ctx)
{
    n->on_rx = fn;
    n->on_rx_ctx = ctx;
}

/* ---------- 过滤器 ---------- */
static int config_filter(can_node_t *n,
                         uint32_t id_hi, uint32_t id_lo,
                         uint32_t mk_hi, uint32_t mk_lo,
                         uint32_t mode, uint32_t scale)
{
    CAN_FilterTypeDef f;

    if (n->next_bank >= CAN_NODE_MAX_BANKS) {
        return -1;                                   /* 过滤器组用完了 */
    }
    memset(&f, 0, sizeof f);
    f.FilterIdHigh         = id_hi;
    f.FilterIdLow          = id_lo;
    f.FilterMaskIdHigh     = mk_hi;
    f.FilterMaskIdLow      = mk_lo;
    f.FilterFIFOAssignment = CAN_FILTER_FIFO0;
    f.FilterBank           = n->next_bank;
    f.FilterMode           = mode;
    f.FilterScale          = scale;
    f.FilterActivation     = CAN_FILTER_ENABLE;
    f.SlaveStartFilterBank = CAN_NODE_MAX_BANKS;     /* 0..13 归 CAN1，14.. 归 CAN2 */

    if (HAL_CAN_ConfigFilter(n->hcan, &f) != HAL_OK) {
        return -1;
    }
    n->next_bank++;
    return 0;
}

int can_node_filter_all(can_node_t *n)
{
    /* 32 位掩码模式，ID 和掩码全 0：每一位都"不关心"，什么帧都放行 */
    return config_filter(n, 0u, 0u, 0u, 0u, CAN_FILTERMODE_IDMASK, CAN_FILTERSCALE_32BIT);
}

/* ---------- 启动 ---------- */
static int enable_irqs(can_node_t *n)
{
    uint32_t its = CAN_IT_RX_FIFO0_MSG_PENDING    /* 收到帧 */
                 | CAN_IT_TX_MAILBOX_EMPTY;       /* 某个邮箱发完了 */
    return (HAL_CAN_ActivateNotification(n->hcan, its) == HAL_OK) ? 0 : -1;
}

int can_node_start(can_node_t *n)
{
    if (HAL_CAN_Start(n->hcan) != HAL_OK) {
        return -1;
    }
    return enable_irqs(n);
}

/* ---------- 发送 ---------- */
int can_node_send(can_node_t *n, uint16_t id, const uint8_t *data, uint8_t len)
{
    CAN_TxHeaderTypeDef h;
    uint8_t buf[8] = { 0 };       /* HAL_CAN_AddTxMessage 总是读 8 个字节，所以缓冲必须有 8 字节 */
    uint32_t mailbox;

    if (id > 0x7FFu || len > 8u || (len > 0u && data == NULL)) {
        return -1;
    }
    if (HAL_CAN_GetTxMailboxesFreeLevel(n->hcan) == 0u) {
        n->tx_full++;
        return -2;
    }

    memset(&h, 0, sizeof h);
    h.StdId = id;
    h.IDE   = CAN_ID_STD;
    h.RTR   = CAN_RTR_DATA;
    h.DLC   = len;
    h.TransmitGlobalTime = DISABLE;
    if (len > 0u) {
        memcpy(buf, data, len);
    }

    if (HAL_CAN_AddTxMessage(n->hcan, &h, buf, &mailbox) != HAL_OK) {
        return -1;
    }
    n->tx_req++;
    return 0;
}

/* ---------- 接收：中断里入队，主循环里出队 ---------- */
static void rxq_push(can_node_t *n, uint16_t id, uint8_t dlc, const uint8_t *d)
{
    uint32_t head = n->rx_head;

    if ((head - n->rx_tail) >= CAN_NODE_RXQ_LEN) {
        n->rx_drop++;                                /* 队列满：丢掉，并记一笔 */
        return;
    }
    can_msg_t *m = &n->rxq[head & RXQ_MASK];
    m->id  = id;
    m->dlc = dlc;
    memcpy(m->data, d, dlc);
    __DMB();                                         /* 先把帧写完整，再挪 head */
    n->rx_head = head + 1u;
    n->rx_cnt++;
}

/* HAL 在 FIFO0 里有帧时调用它（在中断里）。整个工程只能有一份这个函数。 */
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    can_node_t *n = find_node(hcan);
    CAN_RxHeaderTypeDef h;
    uint8_t d[8];

    if (n == NULL) {
        return;
    }
    while (HAL_CAN_GetRxFifoFillLevel(hcan, CAN_RX_FIFO0) > 0u) {
        if (HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0, &h, d) != HAL_OK) {
            break;
        }
        if (h.IDE != CAN_ID_STD || h.RTR != CAN_RTR_DATA) {
            continue;                                /* 本教程只处理标准数据帧 */
        }
        rxq_push(n, (uint16_t)h.StdId, (h.DLC > 8u) ? 8u : (uint8_t)h.DLC, d);
    }
}

void can_node_poll(can_node_t *n)
{
    while (n->rx_tail != n->rx_head) {
        can_msg_t m = n->rxq[n->rx_tail & RXQ_MASK];   /* 先拷出来 */
        __DMB();
        n->rx_tail = n->rx_tail + 1u;                  /* 再还回这个格子 */
        if (n->on_rx != NULL) {
            n->on_rx(n->on_rx_ctx, &m);
        }
    }
}

/* ---------- 发送完成：三个邮箱各有一个回调，都只做一件事 ---------- */
static void tx_done_hook(CAN_HandleTypeDef *hcan)
{
    can_node_t *n = find_node(hcan);
    if (n != NULL) {
        n->tx_done++;
    }
}

void HAL_CAN_TxMailbox0CompleteCallback(CAN_HandleTypeDef *hcan) { tx_done_hook(hcan); }
void HAL_CAN_TxMailbox1CompleteCallback(CAN_HandleTypeDef *hcan) { tx_done_hook(hcan); }
void HAL_CAN_TxMailbox2CompleteCallback(CAN_HandleTypeDef *hcan) { tx_done_hook(hcan); }
```

要点只有六条：

- **对象和方法**。数据在 `can_node_t` 里，每个函数的第一个参数都是对象指针。没有 `can_node.c` 以外的全局变量，唯一的例外是那张私有的登记表 `s_nodes`，原因下一条讲。
- **HAL 的回调是全局函数，对象要靠登记表接上**。`HAL_CAN_RxFifo0MsgPendingCallback()` 只给你一个 `CAN_HandleTypeDef *`。`can_node_init()` 把对象登记在表里，回调里再用 `find_node()` 找回对象。
- **中断只入队，主循环出队**。中断里把帧放进对象的接收队列，立刻返回；`can_node_poll()` 在主循环里取出来，调用你登记的回调。所以回调里可以 `LOG()`，这是 3.1 的规矩：中断里不输出。队列的读写方式是 5.4 的"单写者"模式：中断只改 `rx_head`，主循环只改 `rx_tail`。
- **数据缓冲必须有 8 字节**。`HAL_CAN_AddTxMessage()` 不管你的 `DLC` 是几，总是读 8 个字节。传一个只有 2 字节的数组进去，它会越界去读后面的内存。封装里用一个 8 字节的 `buf` 兜住了这件事。
- **三个返回值要分清**。0 是已排进邮箱，-1 是参数不对，-2 是三个邮箱都满了。邮箱满了不能硬塞，调用方自己决定重试还是放弃。
- **`tx_done` 是硬件确认**。每个发送邮箱发完，HAL 会调用对应的 `TxMailboxXCompleteCallback`，我们在里面把 `tx_done` 加一。`tx_req` 与 `tx_done` 的差，就是还在邮箱里排队的帧数。

整个工程里 `HAL_CAN_RxFifo0MsgPendingCallback` 和三个 `HAL_CAN_TxMailboxXCompleteCallback` 都只能有一份，它们现在在 `can_node.c` 里，别处不要再写同名函数。

### 第四步：回环自测

在 `main.c` 里依次加入下面几段。每段的 USER CODE 注释只表示放进哪个区，区里已有的内容保留，只追加。

包含头文件：

```c
/* USER CODE BEGIN Includes */

/* USER CODE END Includes */
```

对象和一个开关：

```c
/* USER CODE BEGIN PV */
/* 单板自测：这块板既发又收。接到真实总线后，一块板设为 1（发送方），另一块设为 0（接收方） */
#define DEMO_IS_SENDER  1

static can_node_t g_can;      /* CAN 节点对象：队列、计数、过滤器占用情况都在它里面 */
/* USER CODE END PV */
```

接收回调：

```c
/* USER CODE BEGIN 4 */
/* 收到一帧时由 can_node_poll() 调用，运行在主循环里，所以可以放心 LOG。
 * 本节的帧固定 4 字节，所以直接打印前 4 个字节。 */
static void on_can_rx(void *ctx, const can_msg_t *m)
{
    (void)ctx;
    LOG(LOG_INFO, "rx id=0x%03x dlc=%u data=%02x %02x %02x %02x\r\n",
        m->id, m->dlc, m->data[0], m->data[1], m->data[2], m->data[3]);
}
/* USER CODE END 4 */
```

初始化。这一段放在 `MX_CAN1_Init()` 之后，CubeMX 生成的顺序已经保证了：

```c
/* USER CODE BEGIN 2 */
  log_init(&huart1);                 /* 3.1 里加过的，保留 */
  HAL_TIM_Base_Start_IT(&htim6);     /* 5.2 里加过的，g_ms 的节拍，保留 */

  can_node_init(&g_can, &hcan1);                      /* 让对象绑定到 hcan1 */
  can_node_set_rx_handler(&g_can, on_can_rx, NULL);
  if (can_node_filter_all(&g_can) != 0 || can_node_start(&g_can) != 0) {
      LOG(LOG_ERR, "can init failed\r\n");
      log_flush();
      Error_Handler();
  }
  LOG(LOG_INFO, "can started\r\n");
/* USER CODE END 2 */
```

主循环里需要几个软件定时器的变量，放在 `while (1)` 之前：

```c
/* USER CODE BEGIN WHILE */
#if DEMO_IS_SENDER
  uint32_t t_send = 0;     /* 软件定时器：每秒发一帧 */
  uint8_t  seq = 0;        /* 帧里带一个序号，方便看有没有丢 */
#endif
  uint32_t t_stat = 0;     /* 软件定时器：每 5 秒报一次统计 */
/* USER CODE END WHILE */
```

循环体。`soft_due()` 是 5.2 里写的那个：

```c
/* USER CODE BEGIN 3 */
    can_node_poll(&g_can);                      /* 取出收到的帧，调用 on_can_rx */

#if DEMO_IS_SENDER
    if (soft_due(&t_send, 1000u)) {
        uint8_t payload[4] = { 0x11, 0x22, 0x33, seq };
        int rc = can_node_send(&g_can, 0x123u, payload, sizeof payload);
        LOG(LOG_INFO, "tx id=0x123 seq=%u rc=%d\r\n", seq, rc);
        seq++;
    }
#endif

    if (soft_due(&t_stat, 5000u)) {
        LOG(LOG_INFO, "stat: tx_req=%lu tx_done=%lu tx_full=%lu rx=%lu drop=%lu\r\n",
            (unsigned long)g_can.tx_req, (unsigned long)g_can.tx_done,
            (unsigned long)g_can.tx_full, (unsigned long)g_can.rx_cnt,
            (unsigned long)g_can.rx_drop);
    }
/* USER CODE END 3 */
```

构建并下载到板子（流程见 2.2），打开串口助手。你应该看到类似下面的输出，数字是示意：

```
[3 I] can started
[1000 I] tx id=0x123 seq=0 rc=0
[1000 I] rx id=0x123 dlc=4 data=11 22 33 00
[2000 I] tx id=0x123 seq=1 rc=0
[2000 I] rx id=0x123 dlc=4 data=11 22 33 01
[5000 I] stat: tx_req=5 tx_done=5 tx_full=0 rx=5 drop=0
```

每发一帧，立刻收到一帧，内容和序号都对得上，`tx_req`、`tx_done`、`rx` 三个数相等。这是回环模式的特点：帧从发送端出去，被外设内部接回接收端，又走了一遍过滤器和接收 FIFO。

> [!example] 探针：把过滤器那一句拿掉
> 把 `main.c` 里的 `can_node_filter_all(&g_can) != 0 ||` 删掉，只留 `can_node_start(&g_can) != 0`，重新下载。
> 按规则推演，你会看到：`tx` 行照常出现，`rc=0`；统计行里 `tx_done` 照常增加；但 `rx` 一直是 0，回调一次也不来，也没有任何报错。
> 发送一侧成功，接收一侧静默，这就是"没配过滤器"最典型的样子。看完把那一句恢复。

### 第五步：接上真正的总线

**先说明白三样东西**：

- **CAN 外设**，也就是 bxCAN：MCU 里的部分，对外只有两个逻辑电平引脚，CAN_TX 和 CAN_RX。
- **CAN 收发器**：一颗独立的芯片（常见的有 TJA1050、SN65HVD230 这类），把 MCU 的逻辑电平变成总线上的差分电压，反过来也一样。开发板上通常已经带了，具体型号以原理图为准。
- **总线**：两根线，CAN_H 和 CAN_L。为什么用一对差分线，放在[[【原理】CAN总线电气与仲裁|CAN 总线电气与仲裁]]里。

接线很简单，板上自带收发器的话，你只要引出 CAN_H、CAN_L 两根线：

| 一块板 | 另一块板（或 USB-CAN 工具） |
|---|---|
| CAN_H | CAN_H |
| CAN_L | CAN_L |
| GND | GND |

H 接 H，L 接 L，不要交叉。两块没有隔离的板子之间一般要共地，以你的原理图为准。

**终端电阻只讲怎么接**：总线最远的**两端**各接一个 120 Ω，一共两个，不是每个节点一个。很多板子上有一个跳线或拨码开关来接入板载的 120 Ω，两块板对接时两块板都接入。验证办法是断电后用万用表量 CAN_H 与 CAN_L：约 60 Ω 说明两端各有一个；约 120 Ω 说明只有一个；读数远大于 120 Ω 说明一个也没有。

如果用 USB-CAN 工具：工具侧把波特率设成 500 kbit/s，模式选正常模式，不要选"只听"，否则它不会对你的帧回应答。

然后改两处：

1. CubeMX 里把 Operating Mode 从 Loopback 改成 **Normal**，重新生成代码。
2. 两块板用同一份固件，但 `DEMO_IS_SENDER` 一块设为 1，另一块设为 0。

发送方的输出像回环时一样，但没有 `rx` 行；接收方没有 `tx` 行，每秒多一行 `rx id=0x123`，序号逐个加一。

> [!question] 先猜一猜
> 两块板都在 Normal 模式。把接收方断电，发送方的串口输出会怎么变？重点看 `stat` 行里的 `tx_req`、`tx_done`、`tx_full`。

> [!success]- 揭晓
> 按 CAN 的规则推演（作者没有上板，以你的实测为准）：
> 发送一帧之后，发送方要在应答位上听到有人回应。没有任何节点应答，这一帧就被判为失败，开了自动重发的话会一直重发。
> 所以：`tx_done` 停止增长；`tx_req` 在邮箱排满三帧之后也停住；之后每次发送返回 -2，`tx_full` 不断增加。
> 接收方重新上电后，邮箱里排着的帧会被发出去，`tx_done` 又开始增长。这里的"应答"是总线层面的，叫 ACK，只说明"有人听到了"，不说明对方处理了。

## 刚才发生了什么

你用了一条完整的链路。把比喻换成真名：

| 比喻 | 真名 | 在代码里 |
|---|---|---|
| 三个寄件窗口 | 发送邮箱（TX mailbox），共 3 个 | `HAL_CAN_AddTxMessage()` 选一个空的放进去 |
| 门口的保安，只放名单上的人进 | 接收过滤器 | `can_node_filter_all()` |
| 收件箱 | 接收 FIFO，每个 3 层 | 我们只用 FIFO0 |
| 有信到了，响铃 | 接收中断 | `HAL_CAN_RxFifo0MsgPendingCallback()` |
| 收件箱旁边的一个小筐 | 软件接收队列 | `rxq`，中断放进去，主循环取出来 |

发的路径是：`can_node_send()` → 发送邮箱 → 硬件逐位发到总线 → 邮箱发完，计数 `tx_done`。收的路径是：总线 → 过滤器 → FIFO0 → 接收中断 → 回调把帧放进软件队列 → `can_node_poll()` 取出 → `on_rx`。

为什么要多一层软件队列？因为中断里不能输出，也不该做长事。硬件 FIFO 只有 3 层，主循环万一忙一阵子就会溢出；软件队列是 16 层，能多扛一会儿。队列也满了，就丢掉并记一笔 `rx_drop`，宁可丢，也不卡住。

回头看开头那道题：发送成功、接收静默。现在你可以自己答了：发出去的帧回到了接收端，被过滤器挡在了门外，没配过滤器，门卫就一个人也不放。

## 记住这几条

1. CAN 的时钟是 APB1 外设时钟 PCLK1，不是定时器时钟。波特率 = PCLK1 ÷ (Prescaler × (1 + BS1 + BS2))，采样点 = (1 + BS1) ÷ (1 + BS1 + BS2)。
2. 同一条总线上所有节点用同一个波特率、相近的采样点。
3. **不配过滤器就收不到任何帧**，而且没有任何报错。"收不到"先查过滤器。
4. `can_node_send()` 返回 0 只表示排进了邮箱。看 `tx_done` 才知道硬件发完了。
5. `HAL_CAN_AddTxMessage()` 总是读 8 个字节，数据缓冲至少要有 8 字节。
6. 回环模式用来自测，不需要收发器和第二个节点；上总线要改回 Normal。
7. 120 Ω 终端电阻接在总线的两端，共两个。断电量 CAN_H 与 CAN_L 约 60 Ω。
8. 中断里只入队，主循环里处理，日志在主循环里打。

## 练习

1. 把发送间隔改成 200 ms，仍用回环模式，看 `stat` 行里 `tx_req`、`tx_done`、`rx` 是否仍然相等。（复现）
2. 假设你的 PCLK1 是 36 MHz，想要 500 kbit/s。用 `can_timing` 找一组 Prescaler、BS1、BS2，说明采样点。（改造）
3. 两块板在 Normal 模式下，总线上只有发送方这一个节点（接了收发器、没有别人），发送方的 `tx_req`、`tx_done` 各会停在多少？（预测）

> [!success]- 提示与答案方向
> 1. 三个数相等，说明每一帧都经过了完整的发送、过滤、接收。
> 2. 运行 `./can_timing 36000000 500000`。工具会列出多组，例如 Prescaler = 4、BS1 = 14、BS2 = 3，每位 18 个量子，采样点 83.3%。
> 3. `tx_done` 停在 0，因为没有人应答；`tx_req` 停在 3，因为三个邮箱排满之后，再发送就返回 -2、只增加 `tx_full`。这是按规则推演的结果，以实测为准。
