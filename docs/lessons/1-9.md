# 1.9 小项目 命令解析器

> **这一节你会做出**：一个在电脑终端里运行的小程序。你敲 `led on`，它回 `LED is ON`；敲 `help`，它列出所有命令；敲乱七八糟的东西，它也不会崩。代码按 1.6 到 1.8 学的对象风格组织：LED 是一个 `led_t` 对象，通用的解析器和 LED 互不认识，只在 `main.c` 里接起来。
> **前置**：[[1.5_数组与指针]] 到 [[1.8_预处理与多文件工程]]　｜　**预计**：阅读 + 动手 90 分钟

> [!tip] 跳读自测：这一节你可能不用读
> 先回答下面几个问题（写下来，别只在心里答）。**全部答对**就直接跳到 [[2.1_单片机里有什么]]；有一题拿不准，就从头读。
> 1. 对 `char line[] = "led   on\n";` 调用 `cmd_exec(table, n, line);`（原地分词，空白和换行都当分隔符）。命令函数收到的 `argc` 是几？随后 `printf("%s", line)` 会打印什么？
> 2. 为什么 `cmd_exec(table, n, "led on");`（直接传字符串字面量）会崩溃？
> 3. `fgets` 读到的内容末尾没有 `'\n'`，通常说明什么？该怎么处理？
> 4. `cmd_exec` 返回 0、-1、-2，分别表示什么？命令函数自己应该返回什么范围的值？
>
> > [!success]- 答案，以及跳过后要带走的东西
> > 1. `argc` 是 2（`argv[0]` 是 `led`，`argv[1]` 是 `on`）。`line` 被原地改了，第一个空格变成 `'\0'`，所以只会打印 `led`。
> > 2. 原地分词要往数组里写 `'\0'`，而字符串字面量放在只读内存里，写入属于未定义行为，在 PC 上通常是段错误。要传可写数组。
> > 3. 这一行比缓冲区长，没读完，剩下的还留在输入里。应该把剩余部分丢掉并提示"行太长"，否则它们会被当成下一条命令。
> > 4. 0 是成功（空行也算），-1 是未知命令，-2 是词太多。命令函数只返回 0 或正数，避免和 -1、-2 冲突。
> >
> > **带走清单**：这一节的 `cmd.h` 和 `cmd.c` 是全教程的接口，6.1 会原样拷进板子工程（`cmd.h` 放 `User/Inc`，`cmd.c` 放 `User/Src`，CMake 会自动收进来，新增文件后重新配置一次，见 2.2），不要丢。
> > - `cmd.h`：`cmd_t`（`name` / `fn` / `help`）、`CMD_MAX_ARGS`、`cmd_exec` 的声明。
> > - `cmd.c`：原地分词 `split` 和 `cmd_exec` 的实现。
> > - `led.h` 和 `led.c`：`led_ops_t`（硬件操作的函数表）、`led_t`（名字 + 函数表 + 状态）、`led_init` / `led_set` / `led_is_on`。到了板子上（6.1），LED 的逻辑原样用，只把 PC 版的 `pc_led_write` 换成调用 HAL 的版本。
> > - `projects/cmdline/CMakeLists.txt`：`cli` 目标的源文件列表（`src/main.c src/cmd.c src/led.c`）加 `include` 目录。板子工程不用它，那边由 `User/Src` 自动收集。
> > - `main.c` 里的写法：先声明命令函数、再定义命令表、最后写 `help`（它要读表）；用 `ARRAY_LEN` 求表的行数；程序里会变的状态装进一个 `app_t` 对象。6.1 的 `main.c` 要仿着这个结构写。

## 先看一个怪现象

你对餐厅服务员说："宫保鸡丁，少辣，再来碗米饭。"

他没有把你的话抄到另一张纸上。他在点菜单上划了几道线：这儿是菜名，这儿是要求，这儿是主食。然后拿着这张单子去后厨报单。后厨只管做菜，不管你当时是怎么说话的。

我们要写的程序就是这个服务员。它读一行文字，拆成一个个词，查菜单（命令表），把单子交给对应的"后厨"（命令函数）。服务员的真名，在代码里叫 `cmd_exec`。

> [!question] 先猜一猜
> 输入 `led on` 之后，程序要得到 `led` 和 `on` 两个独立的字符串。假设**不申请新内存，也不复制任何字符**，这能做到吗？如果能，怎么做？
> 提示：C 字符串靠什么标记"到这里结束"？

> [!success]- 揭晓
> 能。字符串的结尾靠一个 `'\0'` 字符。只要把词与词之间的空格改成 `'\0'`，再记下每个词的起点，原来那一行字就"变成"了几个字符串。服务员划线，不抄写。下面我们亲眼看它发生。

## 动手做

### 第一步：先想清楚数据怎么走

从你按下回车，到 LED 变亮，数据走这样一条路：

```
键盘输入 → fgets 读进 line → cmd_exec 分词 → 查命令表 → 调用命令函数 → 打印结果
```

分成下面几个文件，都放在 `c-lab/projects/cmdline/` 下（一个多文件项目，摆法和 1.8 的 `cmdtab` 一样）：

```
c-lab/projects/cmdline/
  CMakeLists.txt
  include/cmd.h
  include/led.h
  src/cmd.c
  src/led.c
  src/main.c
```

各自放什么：

| 文件 | 放什么 |
|---|---|
| `cmd.h` | 命令表的类型 `cmd_t`，以及 `cmd_exec` 的声明 |
| `cmd.c` | 分词和查表，`cmd_exec` 的实现 |
| `led.h` / `led.c` | LED 对象：`led_t` 和操作它的函数 |
| `CMakeLists.txt` | 构建说明：每个目标由哪些 `.c` 组成，去哪里找头文件（第四步起逐步写出来） |
| `main.c` | 具体的命令（`led` `help` `quit`）、命令表、读一行的循环，以及把各个部件接起来 |

这里 `cmd.h` 和 `cmd.c` 是"通用的"，里面没有一个字提到 LED。6.1 在板子上会把它们原样拷过去，只换掉"读一行"的方式。所以它们的接口是全教程统一的约定，不能各写各的。`led.h` 和 `led.c` 也是通用的：它只知道"一盏灯能亮能灭"，不知道什么命令行。只有 `main.c` 认识双方，负责把它们接在一起。

### 第二步：cmd.h

`projects/cmdline/include/cmd.h`：

```c
#ifndef CMD_H
#define CMD_H

#include <stddef.h>

/* 一行命令最多拆成几个词（含命令名本身） */
#define CMD_MAX_ARGS 8

/* 命令表的一行：名字、处理函数、一句话帮助 */
typedef struct {
    const char *name;                               /* 命令名，如 "led" */
    int (*fn)(int argc, char *argv[]);              /* 返回 0 成功，非 0 失败 */
    const char *help;                               /* 一句话帮助 */
} cmd_t;

/* 解析并执行一行命令。
 * 返回：0 成功或空行；-1 未知命令；-2 词太多；其余是命令函数自己的返回值。
 * 注意：会原地修改 line（把空白改成 '\0'），所以 line 必须是可写的数组。
 * 命令函数请返回 0 或正数，避免和 -1、-2 撞车。 */
int cmd_exec(const cmd_t *table, size_t n, char *line);

#endif /* CMD_H */
```

`cmd_t` 就是 1.7 里那个。`cmd_exec` 的返回值有明确的含义：

| 返回值 | 含义 |
|---|---|
| 0 | 成功（空行也算成功，什么都不做） |
| -1 | 未知命令 |
| -2 | 词太多，超过 `CMD_MAX_ARGS` |
| 其他 | 命令函数自己的返回值 |

所以命令函数请只返回 0 或正数，别和 -1、-2 撞车。

### 第三步：cmd.c，自己写分词

`projects/cmdline/src/cmd.c`：

```c
#include <string.h>
#include "cmd.h"

/* 自己判断空白，不依赖 <ctype.h>：空格、制表符、回车、换行都算 */
static int is_space(char c) {
    return c == ' ' || c == '\t' || c == '\r' || c == '\n';
}

/* 原地分词：不复制任何字符，只做两件事：
 *   1. 记下每个词的起点，放进 argv
 *   2. 把词后面的那个空白改成 '\0'，让每个词自己成为一个 C 字符串
 * 返回词的个数；词数超过 max_args 返回 -1。 */
static int split(char *line, char *argv[], int max_args) {
    int argc = 0;
    char *p = line;

    for (;;) {
        while (*p != '\0' && is_space(*p)) {   /* 跳过词前的空白 */
            p++;
        }
        if (*p == '\0') {                      /* 行读完了 */
            break;
        }
        if (argc == max_args) {                /* 放不下了，别越界 */
            return -1;
        }
        argv[argc++] = p;                      /* 记下词的起点 */

        while (*p != '\0' && !is_space(*p)) {  /* 走到词尾 */
            p++;
        }
        if (*p != '\0') {
            *p = '\0';                          /* 空白改成结束符 */
            p++;
        }
    }
    argv[argc] = NULL;                         /* 和 main 的 argv 一样，末尾放 NULL */
    return argc;
}

int cmd_exec(const cmd_t *table, size_t n, char *line) {
    char *argv[CMD_MAX_ARGS + 1];              /* +1 给末尾的 NULL */
    int argc;

    if (table == NULL || line == NULL) {
        return -1;
    }

    argc = split(line, argv, CMD_MAX_ARGS);
    if (argc < 0) {
        return -2;
    }
    if (argc == 0) {                           /* 空行：什么也不做，不算错 */
        return 0;
    }

    for (size_t i = 0; i < n; i++) {
        if (table[i].fn != NULL && strcmp(table[i].name, argv[0]) == 0) {
            return table[i].fn(argc, argv);
        }
    }
    return -1;
}
```

核心是 `split` 这一个函数。看一眼内存里发生了什么。输入 `"led on\n"` 在 `line` 数组里是这样的（`\0` 表示结束符）：

```
下标:    0   1   2   3   4   5   6   7
分词前:  l   e   d  ' '  o   n  \n  \0
分词后:  l   e   d  \0   o   n  \0  \0
         ↑argv[0]         ↑argv[1]
```

只改了两个字节：中间的空格和末尾的换行，都变成了 `\0`。`argv[0]` 指向下标 0，`argv[1]` 指向下标 4。没有复制，没有 `malloc`。

几处防护是故意写的：

- `argc == max_args` 时立刻返回，不会写出 `argv` 的边界。
- `argv` 多开一格放 `NULL`，和 `main` 的 `argv` 习惯一致。
- 空白包括 `\r`。Windows 的行尾是 `\r\n`，不处理它，命令名后面会粘着一个看不见的字符。
- 空行返回 0，而不是报错。

为什么不用标准库的 `strtok`？它能做同样的事，但它在内部偷偷记着"上次切到哪了"，这是一份藏在函数里的全局状态，你看不见，也管不了。自己写一遍，每个变量都摆在眼前。

### 第四步：把 LED 做成一个对象（led.h / led.c）

PC 上没有真的 LED，最省事的写法是一个全局变量 `g_led_on` 假装。但到了板子上（6.1），LED 要通过引脚去点亮，"亮不亮"也该是这盏灯自己的状态，而不是全程序共用的一个变量。所以这一次，我们按 1.6 的对象写法，把 LED 做成一个对象；再借 1.7 的函数表，把"怎么真正点亮"从逻辑里分出来。

`projects/cmdline/include/led.h`：

```c
#ifndef LED_H
#define LED_H

/* 接口：LED 的硬件操作，由"实现者"提供。
 * name 表示"哪一盏灯"。PC 上用名字代替，到了板子上它会变成引脚。 */
typedef struct {
    void (*write)(const char *name, int on);
} led_ops_t;

/* 一盏 LED 就是一个对象：名字、硬件操作、当前状态都装在里面 */
typedef struct {
    const char      *name;   /* 哪一盏灯 */
    const led_ops_t *ops;    /* 依赖：怎么真正点亮或熄灭，由外面注入 */
    int              on;     /* 状态：属于这盏灯自己，不是全局变量 */
} led_t;

void led_init(led_t *led, const char *name, const led_ops_t *ops);
void led_set(led_t *led, int on);
int  led_is_on(const led_t *led);

#endif /* LED_H */
```

`projects/cmdline/src/led.c`：

```c
#include <stddef.h>
#include "led.h"

void led_init(led_t *led, const char *name, const led_ops_t *ops) {
    led->name = name;
    led->ops = ops;
    led->on = 0;
}

void led_set(led_t *led, int on) {
    led->on = on ? 1 : 0;
    /* 1.7 的规矩：调用函数指针之前，先确认它不是 NULL */
    if (led->ops != NULL && led->ops->write != NULL) {
        led->ops->write(led->name, led->on);
    }
}

int led_is_on(const led_t *led) {
    return led->on;
}
```

两处值得说：

- `led_t` 装着三样东西：名字、函数表指针 `ops`、当前状态 `on`。`led_init` 负责把它们设好，创建对象和使用对象是两件事。
- `led_set` 自己不知道硬件，它只"拨" `ops->write` 这个号码（1.7 的函数表，调用前先确认不是 `NULL`）。电脑版的实现往屏幕打印，板子版的实现去写引脚。上层逻辑一行不用改。

先不接命令行，单独用一用它。存成 `projects/cmdline/src/two_leds.c`，创建两个 LED 对象：

```c
#include <stdio.h>
#include "led.h"

static void pc_led_write(const char *name, int on) {
    printf("%s is %s\n", name, on ? "ON" : "OFF");
}

static const led_ops_t g_pc_led_ops = { pc_led_write };

int main(void) {
    led_t red, green;                     /* 两个对象，互不干扰 */
    led_init(&red, "RED", &g_pc_led_ops);
    led_init(&green, "GREEN", &g_pc_led_ops);

    led_set(&red, 1);
    led_set(&green, 0);
    printf("red=%d green=%d\n", led_is_on(&red), led_is_on(&green));
    return 0;
}
```

它是项目里的一个小实验，在 CMake 里是单独的一个目标。先建 `projects/cmdline/CMakeLists.txt`，目前只有这一个目标：

```cmake
# 小实验：两盏灯，共用一份 led.c
add_executable(two_leds src/two_leds.c src/led.c)
target_include_directories(two_leds PRIVATE include)
```

再在 `c-lab/CMakeLists.txt` 末尾加一行 `add_subdirectory(projects/cmdline)`，配置、构建，运行 `./build/projects/cmdline/two_leds`。

你应该看到：

```
RED is ON
GREEN is OFF
red=1 green=0
```

两盏灯各有各的名字和状态，用的是同一份 `led_set`。要第三盏灯，多一行 `led_init` 就行。这是 1.6 里"一份代码管任意多个实例"的好处，现在落在了真实的小部件上。

### 第五步：main.c

`projects/cmdline/src/main.c`：

```c
#include <stdio.h>
#include <string.h>
#include "cmd.h"
#include "led.h"

#define ARRAY_LEN(a) (sizeof(a) / sizeof((a)[0]))
#define LINE_MAX_LEN 64          /* 64 字节 = 最多 62 个字符 + 换行 + 结尾的 '\0' */

/* PC 版的"硬件操作"：往屏幕上打印。
 * 到了板子上（6.1），只需要把这一份换成调用 HAL_GPIO_WritePin 的版本。 */
static void pc_led_write(const char *name, int on) {
    printf("%s is %s\n", name, on ? "ON" : "OFF");
}

static const led_ops_t g_pc_led_ops = { pc_led_write };

/* 程序里所有"会变的东西"装进一个对象。
 * 命令函数的签名是全教程约定好的，没有地方把对象传进来，
 * 所以这里只留这一个全局的 app，LED 和运行标志都是它的成员。 */
typedef struct {
    led_t led;
    int   running;       /* quit 命令把它清零 */
} app_t;

static app_t g_app;

/* help 要读命令表，而命令表里又要放 cmd_help，所以先声明 */
static int cmd_led(int argc, char *argv[]);
static int cmd_help(int argc, char *argv[]);
static int cmd_quit(int argc, char *argv[]);

static const cmd_t g_cmds[] = {
    { "led",  cmd_led,  "led on|off : turn the LED on or off" },
    { "help", cmd_help, "help : list all commands" },
    { "quit", cmd_quit, "quit : leave the program" },
};

static int cmd_led(int argc, char *argv[]) {
    if (argc != 2) {
        printf("usage: led on|off\n");
        return 1;
    }
    if (strcmp(argv[1], "on") == 0) {
        led_set(&g_app.led, 1);
    } else if (strcmp(argv[1], "off") == 0) {
        led_set(&g_app.led, 0);
    } else {
        printf("led: unknown argument '%s'\n", argv[1]);
        return 1;
    }
    return 0;
}

static int cmd_help(int argc, char *argv[]) {
    (void)argc;
    (void)argv;
    for (size_t i = 0; i < ARRAY_LEN(g_cmds); i++) {
        printf("  %-5s %s\n", g_cmds[i].name, g_cmds[i].help);
    }
    return 0;
}

static int cmd_quit(int argc, char *argv[]) {
    (void)argc;
    (void)argv;
    g_app.running = 0;
    return 0;
}

/* 丢掉这一行剩下的字符，防止它们被当成下一条命令 */
static void discard_rest_of_line(void) {
    int ch;
    while ((ch = getchar()) != '\n' && ch != EOF) {
    }
}

int main(void) {
    char line[LINE_MAX_LEN];

    led_init(&g_app.led, "LED", &g_pc_led_ops);
    g_app.running = 1;

    printf("type 'help' for commands\n> ");
    while (g_app.running && fgets(line, sizeof line, stdin) != NULL) {
        size_t len = strlen(line);

        if (len > 0 && line[len - 1] != '\n' && !feof(stdin)) {
            discard_rest_of_line();
            printf("line too long (max %d chars)\n", LINE_MAX_LEN - 2);
        } else {
            int rc = cmd_exec(g_cmds, ARRAY_LEN(g_cmds), line);
            if (rc == -1) {
                printf("unknown command, try: help\n");
            } else if (rc == -2) {
                printf("too many words (max %d)\n", CMD_MAX_ARGS);
            } else if (rc != 0) {
                printf("command failed (code %d)\n", rc);
            }
        }
        if (g_app.running) {
            printf("> ");
        }
    }
    printf("\nbye\n");
    return 0;
}
```

读一遍，有几处值得说：

- `cmd.h` 和 `cmd.c` 一个字没动，`cmd_t` 和 `cmd_exec` 的约定、返回值的约定都原样保留。
- `cmd_led` 现在只做一件事：检查参数，然后调用 `led_set`。亮灭的逻辑和状态都在 `led_t` 里，不在命令函数里。
- `app_t` 把程序里所有会变的东西（LED 和运行标志）装进一个对象。命令函数的签名是全教程约定好的，没有地方把对象传进来，所以这里留了一个全局的 `g_app`，它是整个程序唯一的全局状态；`led.c` 里没有任何全局变量。
- `cmd_help` 要遍历命令表，而命令表里又要放 `cmd_help`，互相需要。办法是先声明三个函数，再定义表，最后在后面写函数体。
- `ARRAY_LEN` 就是 1.8 的那个宏。`g_cmds` 在这里是真数组，所以能用。
- `fgets(line, sizeof line, stdin)` 永远带上缓冲区大小。如果一行比缓冲区长，`fgets` 只读走前一截，剩下的还留在输入里，下一轮会被当成一条新命令。所以读完要检查行尾有没有 `'\n'`；没有，说明这行太长，把它剩下的部分丢掉并提示。
- 输入结束（管道读完、或者你按了 Ctrl+D，Windows 上是 Ctrl+Z 再回车）时 `fgets` 返回 `NULL`，循环自然结束。

### 第六步：构建，跑起来

把 `cli` 目标加进 `projects/cmdline/CMakeLists.txt`：

```cmake
add_executable(cli
    src/main.c
    src/cmd.c
    src/led.c
)
target_include_directories(cli PRIVATE include)
```

保存后重新配置，构建，进到输出目录：

```
cmake --build build
cd build/projects/cmdline
./cli
```

下面的命令都在这个输出目录里执行（Windows 的命令提示符里用 `cli.exe`）。

`add_executable(cli ...)` 列了三个 `.c`，CMake 让它们各自编译成目标文件，再统一链接，这就是 1.8 的"分别编译"。如果漏写了 `src/led.c`，链接时会报 `undefined reference`，说找不到 `led_set` 的定义，你已经认识这个报错了。

你可以手动敲 `help`、`led on`、`led off`、`quit`。为了让输出能贴在这里，我们改用管道喂输入（Windows 请用 Git Bash 或 MSYS2 终端；或者把内容存进 `input.txt`，用 `./cli < input.txt`，效果一样）：

```
printf 'help\nled on\nled off\n' | ./cli
```

管道里的输入不会回显，所以结果紧挨在提示符 `>` 后面。我这台机器上的输出：

```
type 'help' for commands
>   led   led on|off : turn the LED on or off
  help  help : list all commands
  quit  quit : leave the program
> LED is ON
> LED is OFF
>
bye
```

### 第七步：故意喂坏输入

一个能用的解析器，不是看它对"好输入"怎么样，而是看它对"坏输入"怎么样。一口气喂七种：

```
printf 'led\nled blink\nfoo\n   led    on  \n\nled on off 1 2 3 4 5 6\nled on 1 2 3 4 5 6\n' | ./cli
```

> [!question] 先猜一猜
> 这七行输入，各自会得到什么？特别留意：第 4 行前后有一堆多余空格，第 5 行是空行，第 6 行有 9 个词，第 7 行有 8 个词。

> [!success]- 揭晓
> 我这台机器上的输出：
> ```
> type 'help' for commands
> > usage: led on|off
> command failed (code 1)
> > led: unknown argument 'blink'
> command failed (code 1)
> > unknown command, try: help
> > LED is ON
> > > too many words (max 8)
> > usage: led on|off
> command failed (code 1)
> >
> bye
> ```
> 逐行对照：
> 1. `led`：缺参数，命令函数返回 1，主程序打印 `command failed (code 1)`。
> 2. `led blink`：参数不认识，同样返回 1。
> 3. `foo`：表里没有，`cmd_exec` 返回 -1，主程序提示 `unknown command`。
> 4. `   led    on  `：多余空白被分词吃掉了，照常点亮。
> 5. 空行：什么也没发生，只多出一个提示符（所以输出里有 `> >`）。
> 6. 9 个词：超过 8，返回 -2。
> 7. 8 个词：刚好不超限，分词成功，但 `led` 命令只接受 2 个词，所以报 usage。

再试一行超长输入（100 个 `x`，后面跟一条正常命令）：

```
LONG=$(printf 'x%.0s' $(seq 1 100))
printf "$LONG\nled on\n" | ./cli
```

输出：

```
type 'help' for commands
> line too long (max 62 chars)
> LED is ON
>
bye
```

超长的那行被整体丢掉，后面的 `led on` 没有受到污染。如果当初没有丢弃剩下的部分，那一百个 `x` 会被切成两三条"未知命令"。

另外两种情况我也各试了一次：最后一行没有换行（`printf 'led on' | ./cli`）会正常执行；Windows 的 `\r\n` 行尾（`printf 'led off\r\nquit\r\n' | ./cli`）也正常，`quit` 之后程序直接结束。

### 第八步：探针，看看 line 变成了什么

这个小实验也是一个独立的目标，先在 `projects/cmdline/CMakeLists.txt` 里加上：

```cmake
add_executable(probe src/probe.c src/cmd.c)
target_include_directories(probe PRIVATE include)
```

再存成 `projects/cmdline/src/probe.c`，构建后在输出目录里运行 `./probe`：

```c
#include <stdio.h>
#include "cmd.h"

static int cmd_led(int argc, char *argv[]) {
    (void)argc;
    printf("argv[1] = %s, offset from line = %ld\n", argv[1], (long)(argv[1] - argv[0]));
    return 0;
}

int main(void) {
    const cmd_t table[] = { { "led", cmd_led, "led on|off" } };
    char line[16] = "led on\n";     /* 数组，可写 */

    cmd_exec(table, 1, line);
    printf("line now: [%s]\n", line);
    for (int i = 0; i < 8; i++) {
        putchar(line[i] == '\0' ? '_' : line[i]);   /* 把 '\0' 显示成下划线 */
    }
    printf("\n");
    return 0;
}
```

> [!question] 先猜一猜
> `cmd_exec` 返回之后，`printf("line now: [%s]\n", line)` 会打印什么？后面那个把 `\0` 显示成 `_` 的循环，又会打印什么？

> [!success]- 揭晓
> ```
> argv[1] = on, offset from line = 4
> line now: [led]
> led_on__
> ```
> `line` 被原地改了：打印它只看到 `led`，因为第一个空格变成了 `\0`，C 字符串到那里就结束了。`argv[1]` 比 `argv[0]` 靠后 4 个字节，它指向的就是 `line` 的内部。

现在可以起名字了：把一行文字拆成一个个词，叫**分词**；直接在原来的数组上改、不另外复制，叫**原地**处理。你写的这个把"文字"变成"命令和参数"的东西，叫**解析器**。

## 刚才发生了什么

数据走过的那条路，现在每一站你都亲手写过了：`fgets` 把一行读进 `line`；`split` 原地把它划成几个词；`cmd_exec` 拿第一个词去命令表里 `strcmp` 查名字；找到了就拨出表里的号码（1.7 的函数指针），把 `argc` 和 `argv` 交给命令函数；命令函数干完活，返回 0 或错误码，由 `main` 负责告诉用户。

有两条要紧的后果，都来自"原地"：

- 传给 `cmd_exec` 的 `line` 必须是**可写的数组**。如果传一个字符串字面量，程序会试图改只读内存，直接崩溃。练习 3 会让你看到。
- `argv` 里的指针指向 `line` 内部。`cmd_exec` 返回后，下一轮 `fgets` 会把 `line` 覆盖，那些指针就不再可信了。命令函数想长期保存某个参数，要自己复制一份。

这里的分词规则很简单：遇到空白就切。一旦规则变复杂，比如要支持带引号的 `"hello world"`、转义字符，一个循环加几个 `if` 就不够用了，需要换一种更清晰的写法，叫[[【拓展】状态机设计|状态机]]。6.1 你会再见到这段分词代码，到时候它还是这一份。

回头看开头那道题：不申请内存、不复制字符，怎么得到两个字符串？现在你可以画出答案了：把空格改成 `\0`，再记下每个词的起点。

这个小项目的组织方式，值得再看一眼：`cmd` 是通用的解析器，不认识 LED；`led` 是通用的对象，不认识命令；`main.c` 才把它们接起来。换一种输入方式（6.1 从串口读），改的是读一行的那段；换一种硬件（板子上的 LED），改的是 `led_ops_t` 的实现。每一块都能单独拿走复用。这就是 1.6 到 1.8 一路学下来的东西，落在一个完整的小程序里。对象风格的更多细节，见 [[【原理】C语言里的面向对象|C语言里的面向对象]]。

顺便说一件事。你在这个项目里其实已经用上了几种常见的好做法：命令表和 `led_ops_t` 用函数表，把"做什么"和"怎么做"分开；`led_t` 加 `led_init`，把"创建"和"使用"分开。人们在大量设计实践中总结出来的经验和好的设计方式，并不是一种死板、必须照做的规则，它们有个统称，叫**设计模式**。本教程不展开，想知道它是什么、什么时候该用、什么时候不该用，见 [[【拓展】设计模式是什么|设计模式是什么]]。

## 记住这几条

1. 解析别人输入的字符串，先假设它是坏的：空行、超长、多余空白、词太多、不认识的命令，每一种都要有对策。
2. 原地分词会改原数组，所以传入的必须是可写数组，不能是字符串字面量。
3. `argv` 里的指针指向 `line` 内部，`cmd_exec` 返回后不要再依赖它们。
4. 用 `fgets` 读行，永远传 `sizeof`；用行尾有没有 `'\n'` 判断是不是超长，超长就丢掉剩余部分。
5. 命令函数只返回 0 或正数，`-1` 和 `-2` 留给 `cmd_exec`。
6. 加命令只做两件事：写一个函数，在命令表里加一行。
7. **一个部件一个对象**：LED 的状态装进 `led_t`，硬件操作通过函数表注入。通用的解析器、通用的对象、把它们接起来的 `main.c`，各管各的，才能复用。

## 练习

1. 把 `main.c` 里的 `LINE_MAX_LEN` 改成 8，依次输入 `led on`、`led off`、`led on`，看看结果。先算一算每行有几个字符。（复现）
2. 把 1.7 的 `echo` 命令搬进来：敲 `echo hello   world` 应该输出 `hello world`。（改造）
3. 把 `main.c` 里调用 `cmd_exec` 的地方临时换成 `cmd_exec(g_cmds, ARRAY_LEN(g_cmds), "led on");`（直接传字符串字面量）。编译时会有警告吗？运行时会发生什么？先写下预测。（预测）

> [!success]- 提示与答案
> **1.** `LINE_MAX_LEN` 为 8 时，缓冲区最多放 7 个字符，其中要给换行留一格，所以内容最多 6 个字符。`led on` 正好 6 个，通过；`led off` 有 7 个，被判超长。我这台机器上的输出是：
> ```
> type 'help' for commands
> > LED is ON
> > line too long (max 6 chars)
> > LED is ON
> >
> bye
> ```
> 第三行的 `led on` 没有受到第二行的影响，这正是"丢掉剩余部分"的作用。
>
> **2.** 先在文件顶部的声明里加 `static int cmd_echo(int argc, char *argv[]);`，在表里加 `{ "echo", cmd_echo, "echo WORDS : print them back" },`，再把函数体写在 `discard_rest_of_line` 前面：
> ```c
> static int cmd_echo(int argc, char *argv[]) {
>     for (int i = 1; i < argc; i++) {
>         printf("%s%s", argv[i], (i + 1 < argc) ? " " : "");
>     }
>     printf("\n");
>     return 0;
> }
> ```
> 我这台机器上，输入 `echo hello   world` 得到 `hello world`；单独输入 `echo` 得到一个空行；`help` 里多出一行 `echo`。
>
> **3.** 构建不会警告（`-Wall -Wextra` 下我这台机器没有任何提示），运行时崩溃，报 `Segmentation fault`。用管道喂输入时，崩溃前的提示符还留在缓冲区里没来得及输出，所以我这台机器上屏幕上什么也没有，只看到崩溃。字符串字面量放在只读内存里，原地分词要往里写 `\0`，写不进去。C 标准里修改字面量属于未定义行为，这次碰巧崩得很干脆。修法是先拷进数组：`char line[] = "led on";`。
