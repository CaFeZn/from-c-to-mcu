# 5.3 PWM与输入捕获

> **这一节你会做出**：用 TIM3 输出 PWM，做一盏呼吸灯，再让蜂鸣器唱出音阶；然后用 TIM2 的输入捕获把这路信号"听回来"，测出它的频率。过程中顺手做出四个可复用的小对象：PWM 输出、呼吸灯、音阶播放、频率计。

## 先看一个怪现象

电影院里放的不是动作，而是每秒几十格静止的画面。一格一格换得够快，你的眼睛就把它们连成了动作。

灯也能这样骗你。有一只手，每秒把开关拨 1000 个来回，每一圈里只让灯亮其中一小段时间。你的眼睛来不及分辨每一次开关，只觉得：这盏灯，不太亮。

> [!question] 先猜一猜
> LED 每秒被开关 1000 次，每一圈里亮 30% 的时间，其余时间是灭的。你看到的是什么？
> A. 明显在闪　B. 稳定的、偏暗的亮度　C. 和一直亮着没区别

> [!success]- 揭晓
> 选 B。1000 次每秒远远超过眼睛能分辨的速度，所以看不到闪，只看到一个稳定的、比全亮暗一些的亮度。人眼对亮度的感觉不是线性的，所以不能严格说成"30% 的亮度"。
> 后面有一个探针，让你自己把这只手放慢，亲眼看灯其实一直在闪。

这一节我们就是要训练这只"拨开关的手"，再装一个耳朵去听它拨得有多快。

### 第一步：先把两个旋钮算清楚

这只手有两个旋钮：

- **圈速**：每秒拨多少圈。
- **每圈亮多久**：一圈里有多大一段时间开着。

> [!question] 先猜一猜
> 做呼吸灯，要让灯一明一暗地变化。运行中该去动哪个旋钮：圈速，还是每圈亮多久？如果你动的是另一个，会发生什么？

> [!success]- 揭晓
> 呼吸灯动的是"每圈亮多久"，圈速不动。动圈速改变的是闪得多快，不是多亮：低到几赫兹，你就看到灯在闪了。
> 反过来，蜂鸣器的音调是圈速决定的，做音调时要动的就是圈速，第四步会用到。

现在给它们起真名。

- 圈速由 TIM3 的 **PSC**、**ARR** 决定，公式和 5.2 一样。
- "每圈亮多久"由 **CCR** 决定。CCR 是**捕获/比较寄存器**（Capture/Compare Register），计数器在每一圈里从 0 数到 ARR，数值小于 CCR 时，输出引脚为高。
- 开着的时间占一圈的比例，叫**占空比**（duty）。这种靠调开着的时间来控制平均能量的办法，叫 **PWM**（Pulse Width Modulation，脉宽调制）。

两条公式，请抄下来：

> **PWM 频率 = 定时器时钟 ÷ ((PSC + 1) × (ARR + 1))**
> **占空比 = CCR ÷ (ARR + 1)**

用文字推演一遍，看它们是否自洽。取 PSC = 83，ARR = 999，CCR = 300，定时器时钟 84 MHz：

- 计数时钟 = 84 MHz ÷ 84 = 1 MHz，一格 1 µs。
- 一圈数 1000 格（0 到 999），共 1000 µs，频率 = 1000 Hz。公式给出 84,000,000 ÷ (84 × 1000) = 1000 Hz，对得上。
- 计数值是 0 到 299 时，小于 CCR，输出为高，共 300 格 = 300 µs。占空比 = 300 ÷ 1000 = 30%。公式给出 300 ÷ 1000，对得上。
- 两端：CCR = 0 时没有任何计数值小于 0，输出恒低，0%。CCR = 1000（即 ARR + 1）时，计数值 0 到 999 全都小于 1000，输出恒高，100%。

所以 CCR 从 0 变到 1000，占空比就从 0% 变到 100%，每步 0.1%，正好分成 1000 级，用起来很顺。

定时器时钟还是以**你 CubeMX 时钟树上的读数为准**，本节示例按 84 MHz 算。TIM3 是 16 位定时器，PSC 和 ARR 最大都是 65,535。

### 第二步：在 CubeMX 里配 TIM3 通道 1

| 位置 | 填写 |
|---|---|
| Timers → TIM3 → Clock Source | Internal Clock |
| Channel1 | PWM Generation CH1 |
| Parameter Settings → Prescaler (PSC) | `83` |
| Parameter Settings → Counter Period (ARR) | `999` |
| Parameter Settings → auto-reload preload | Enable（第四步改 ARR 时需要，先开着） |
| PWM Generation Channel 1 → Mode | PWM mode 1 |
| PWM Generation Channel 1 → Pulse | 0 |
| PWM Generation Channel 1 → CH Polarity | High |
| PWM Generation Channel 1 → Output compare preload | 保持默认（Enable） |

界面文字以你的 CubeMX 版本为准。

接线要留心。TIM3 的通道 1 只能从几个固定引脚出来，常见是 PA6、PB4、PC6，**以数据手册的引脚复用表和你的原理图为准**，CubeMX 通常会默认分配其中一个。这几个引脚不一定是你板载 LED 的引脚。你可以这样办：

- 把一只 LED 串上限流电阻，接到 TIM3_CH1 的引脚上。接法沿用你在 4.1 里的做法。
- 注意极性：如果 LED 是"引脚给高电平才亮"，占空比越大越亮；如果接成"引脚给低电平才亮"，占空比越大反而越暗。

### 第三步：把 PWM 做成对象，再做呼吸灯

到这里先停一下。直接在 main.c 里到处写 `__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, ...)` 也能让灯亮，但换一个通道、再加一路输出，就得把一堆代码复制一遍。有一种更好的办法：**一个东西，一个对象**。后面的 5.4 和第 6 章会反复用到它。

本节新增的文件，头文件放 `User/Inc`，源文件放 `User/Src`，不要放进 CubeMX 管理的 `Core/`。顶层 `CMakeLists.txt` 会自动把它们收进来，新增文件后重新配置一次（见 [[2.2_开发环境与第一次点灯]]）。

PWM 输出是一个东西。它要记住的：哪个定时器、哪个通道、计数时钟多快、现在的 ARR 是多少、现在的占空比是多少。它要提供的：开始输出、设占空比、设频率。把这些收进一个结构体 `pwm_t`，每个函数的第一个参数都是指向它的指针。

占空比用**千分比**（0 到 1000）来表示。对象自己按当前的 ARR 换算成 CCR，你不用再关心 ARR 是 999 还是 1999：

```c
#ifndef PWM_H
#define PWM_H

#include "main.h"

/* PWM 输出对象：绑定一个定时器通道，状态全在对象里。 */
typedef struct {
    TIM_HandleTypeDef *htim;      /* 哪个定时器，如 &htim3 */
    uint32_t           channel;   /* 哪个通道，如 TIM_CHANNEL_1 */
    uint32_t           clk_hz;    /* 计数时钟 = 定时器时钟 ÷ (PSC+1)，由调用者告诉对象 */
    uint32_t           arr;       /* 当前 ARR，一圈共 arr + 1 格 */
    uint32_t           duty_pm;   /* 当前占空比，千分比 0..1000 */
} pwm_t;

/* ARR 取 CubeMX 里配好的值，占空比初始为 0 */
void pwm_init(pwm_t *p, TIM_HandleTypeDef *htim, uint32_t channel, uint32_t clk_hz);
void pwm_start(pwm_t *p);                        /* 开始输出，不需要中断 */
void pwm_set_duty(pwm_t *p, uint32_t permille);  /* 0..1000，超过按 1000 算 */
int  pwm_set_freq(pwm_t *p, uint32_t freq_hz);   /* 成功返回 0；频率超范围返回 -1，保持原样 */

#endif /* PWM_H */
```

```c
#include "pwm.h"

/* 占空比（千分比）换算成 CCR。permille <= 1000、arr + 1 <= 65536（16 位定时器），乘积装得下 32 位 */
static uint32_t ccr_for(const pwm_t *p, uint32_t permille)
{
    return (permille * (p->arr + 1u)) / 1000u;
}

void pwm_init(pwm_t *p, TIM_HandleTypeDef *htim, uint32_t channel, uint32_t clk_hz)
{
    p->htim = htim;
    p->channel = channel;
    p->clk_hz = clk_hz;
    p->arr = __HAL_TIM_GET_AUTORELOAD(htim);
    p->duty_pm = 0;
}

void pwm_start(pwm_t *p)
{
    HAL_TIM_PWM_Start(p->htim, p->channel);
}

void pwm_set_duty(pwm_t *p, uint32_t permille)
{
    if (permille > 1000u) {
        permille = 1000u;
    }
    p->duty_pm = permille;
    __HAL_TIM_SET_COMPARE(p->htim, p->channel, ccr_for(p, permille));
}

int pwm_set_freq(pwm_t *p, uint32_t freq_hz)
{
    uint32_t period;                         /* 一圈多少格，就是 ARR + 1 */

    if (freq_hz == 0u) {
        return -1;
    }
    period = p->clk_hz / freq_hz;
    if (period < 2u || period > 65536u) {    /* 16 位定时器：ARR 最大 65535 */
        return -1;
    }
    p->arr = period - 1u;
    __HAL_TIM_SET_AUTORELOAD(p->htim, p->arr);
    /* ARR 变了，CCR 必须按比例跟着变，占空比才不变 */
    __HAL_TIM_SET_COMPARE(p->htim, p->channel, ccr_for(p, p->duty_pm));
    return 0;
}
```

`pwm_set_freq` 里有一行很要紧：改了 ARR 之后，CCR 按保存的占空比重新算一遍。这就是第一步里说的"ARR 和 CCR 要一起改"，现在被封进了函数里，调用者不会忘。

呼吸灯是另一个东西。它要记住：驱动哪个 PWM、多久动一步、现在的亮度级和方向。它**借用**一个 `pwm_t`，不拥有它。时间由调用者传进来，对象内部不读全局变量：

```c
#ifndef BREATH_H
#define BREATH_H

#include "main.h"
#include "pwm.h"

/* 呼吸灯对象：驱动一路 pwm_t，亮度来回渐变。 */
typedef struct {
    pwm_t    *pwm;         /* 借用的 PWM 对象 */
    uint32_t  period_ms;   /* 每隔多久动一步 */
    uint32_t  t_last;      /* 软件定时器的"上次到点"时刻 */
    int16_t   level;       /* 当前亮度级，0..1000 */
    int16_t   step;        /* 每步增减多少 */
    int8_t    dir;         /* +1 变亮，-1 变暗 */
} breath_t;

void breath_init(breath_t *b, pwm_t *pwm, uint32_t period_ms, int16_t step, uint32_t now_ms);
void breath_update(breath_t *b, uint32_t now_ms);   /* 在主循环里反复调用，不阻塞 */

#endif /* BREATH_H */
```

```c
#include "breath.h"

void breath_init(breath_t *b, pwm_t *pwm, uint32_t period_ms, int16_t step, uint32_t now_ms)
{
    b->pwm = pwm;
    b->period_ms = period_ms;
    b->t_last = now_ms;          /* 从现在开始计时，不会一上来就补发一串 */
    b->level = 0;
    b->step = step;
    b->dir = 1;
}

void breath_update(breath_t *b, uint32_t now_ms)
{
    int32_t next;

    if ((uint32_t)(now_ms - b->t_last) < b->period_ms) {   /* 5.2 的写法：相减再比较 */
        return;
    }
    b->t_last += b->period_ms;

    next = (int32_t)b->level + (int32_t)b->dir * b->step;
    if (next >= 1000) {
        next = 1000;
        b->dir = -1;
    } else if (next <= 0) {
        next = 0;
        b->dir = 1;
    }
    b->level = (int16_t)next;

    /* 平方一下，让亮度变化在人眼看来更均匀；level = 1000 时仍是 1000，即 100% */
    pwm_set_duty(b->pwm, ((uint32_t)next * (uint32_t)next) / 1000u);
}
```

**探针 1：把手放慢。** 把 CubeMX 里的 PSC 改成 8399，ARR 改成 1999。先算，再改：

> [!question] 先猜一猜
> 新的 PWM 频率是多少？灯会是什么样？灯还能从全灭渐变到全亮吗？

> [!success]- 揭晓
> 84,000,000 ÷ (8400 × 2000) = 5 Hz。每秒闪 5 下，肉眼能清楚看到灯在一闪一闪，呼吸的感觉变成了抖动。第一步里"其实一直在闪，只是你看不出来"的说法，这样就被你亲手验证了。
> 灯仍然能从全灭渐变到全亮：`pwm_init` 读到的 ARR 是 1999，`pwm_set_duty` 按千分比换算 CCR，最亮时 CCR = 2000。这就是把 ARR 的细节收进对象的好处。改完记得恢复到 83 和 999。

`breath.c` 里把 `level` 平方了一下，是因为人眼对亮度的感觉不是线性的。你可以把那一行改成 `pwm_set_duty(b->pwm, (uint32_t)next);` 对比：线性时，最暗的那一段变化显得特别快，最亮的那一段几乎看不出变化。

### 第四步：蜂鸣器音调

圈速换来了音调：蜂鸣器每秒振动的次数，就是 PWM 的频率。

先说一个硬条件。**有源蜂鸣器**里自带振荡电路，通电就响一个固定的音，PWM 改不了它的音调；这一步需要的是**无源蜂鸣器**（只管被推着振动，音调由你给的频率决定）。把它接到 TIM3_CH1 的引脚上，驱动方式以你的原理图为准。如果你的蜂鸣器不在 PA6、PB4、PC6 上，就把它改接到这几个引脚之一，或者改用它所在引脚对应的定时器通道，公式不变。

> [!question] 先猜一猜
> 440 Hz 是标准的 A 音（A4）。要让音高一个八度，也就是 880 Hz，ARR 要怎么改？CCR 呢？

> [!success]- 揭晓
> 八度就是频率翻倍，周期（ARR + 1）减半。如果 PSC 不变，ARR + 1 从 2272 变成 1136，也就是 ARR 从 2271 变成 1135。
> CCR 也得跟着减半，才能保持占空比 50%：从 1136 变成 568。只改 ARR 不改 CCR，占空比就变了。

套公式：PSC = 83 时计数时钟是 1 MHz，所以 ARR + 1 = 1,000,000 ÷ 目标频率，CCR = (ARR + 1) × 占空比。我们取整数，会有一点点误差：

| 目标频率 | ARR + 1 | 实际频率 |
|---|---|---|
| 262 Hz（C4） | 3816 | 约 262.05 Hz |
| 440 Hz（A4） | 2272 | 约 440.14 Hz |
| 880 Hz（A5） | 1136 | 约 880.28 Hz |

频率越高，取整的误差越大：目标 15,000 Hz 时 ARR + 1 取 66，实际约 15,152 Hz，差 1%。对一只蜂鸣器来说够用。1 MHz 的计数时钟下，`pwm_set_freq` 能设的范围大约是 16 Hz 到 500 kHz，超出范围返回 -1 并保持原样；这些边界我在电脑上用桩试过。

这一步要实时改 ARR，所以第二步里的 **auto-reload preload** 必须开着：新值会等当前这一圈走完才生效，不会在半圈里把周期"撕开"。如果关着，新的 ARR 比当前计数值还小，计数器可能要一路数到 65,535 回绕才算一圈，就会多出一个异常长的周期，听起来是一声杂音。

要提醒一点：`pwm_t` 里缓存了 ARR。同一个定时器的几个通道共用一个 ARR，所以本节里**一个定时器只挂一个 `pwm_t`**。如果两个对象指向同一个定时器，一个改了频率，另一个缓存的 ARR 就过期了。

音阶播放也是一个对象：它借用 `pwm_t`，记住频率表、播到第几个音、每个音多长：

```c

#define MELODY_H

} melody_t;

void melody_init(melody_t *m, pwm_t *pwm, const uint16_t *notes, uint8_t count,
                 uint32_t note_ms, uint32_t now_ms);
void melody_update(melody_t *m, uint32_t now_ms);   /* 在主循环里反复调用，不阻塞 */

```

```c
#include "melody.h"

void melody_init(melody_t *m, pwm_t *pwm, const uint16_t *notes, uint8_t count,
                 uint32_t note_ms, uint32_t now_ms)
{
    m->pwm = pwm;
    m->notes = notes;
    m->count = count;
    m->idx = 0;
    m->note_ms = note_ms;
    m->t_last = now_ms;
}

void melody_update(melody_t *m, uint32_t now_ms)
{
    uint16_t freq;

    if (m->count == 0u || (uint32_t)(now_ms - m->t_last) < m->note_ms) {
        return;
    }
    m->t_last += m->note_ms;

    freq = m->notes[m->idx];
    if (freq != 0u && pwm_set_freq(m->pwm, freq) == 0) {
        pwm_set_duty(m->pwm, 500u);          /* 方波，占空比 50% */
    } else {
        pwm_set_duty(m->pwm, 0u);            /* 休止，或频率超范围：静音 */
    }
    m->idx = (uint8_t)((m->idx + 1u) % m->count);
}
```

### 第五步：输入捕获，把信号听回来

最简单的信号源，就是刚才自己输出的这路 PWM。用一根杜邦线把 TIM3_CH1 的引脚，接到 TIM2_CH1 的引脚上。TIM2_CH1 常见的是 PA0、PA5、PA15，**以数据手册和你的原理图为准**，PA0 如果被按键占了就别用。信号一律不要超过 3.3 V，除非手册明确写了该引脚耐 5 V。

先想一想怎么测。

> [!question] 先猜一猜
> TIM3 输出 1000 Hz。TIM2 的计数时钟是 1 MHz，一直在往上数。每来一个上升沿，我们记下当时的计数值。相邻两个上升沿之间，计数值差多少？由它怎么算出频率？

> [!success]- 揭晓
> 1000 Hz 的周期是 1000 µs，1 MHz 一格 1 µs，所以相邻两次记录相差 1000。
> 频率 = 计数时钟 ÷ 差值 = 1,000,000 ÷ 1000 = 1000 Hz。

"边沿一来，硬件自动把当时的计数值抄下来"，这件事叫**输入捕获**（Input Capture）。抄下来的数就放在 CCR 里，同一个寄存器，输出时是"比较值"，输入时是"抄下来的值"。这种"量两次边沿的间隔"的方法，叫测周法。

在 CubeMX 里配 TIM2：

| 位置 | 填写 |
|---|---|
| Timers → TIM2 → Clock Source | Internal Clock |
| Channel1 | Input Capture direct mode |
| Parameter Settings → Prescaler (PSC) | `83` |
| Parameter Settings → Counter Period (ARR) | `4294967295`（TIM2 是 32 位） |
| Input Capture Channel 1 → Polarity Selection | Rising Edge |
| Input Capture Channel 1 → IC Selection | Direct TI |
| Input Capture Channel 1 → Prescaler Division Ratio | No division |
| Input Capture Channel 1 → Input Filter | 0 |
| NVIC Settings | 勾选 TIM2 global interrupt |

TIM2 用 32 位，只是顺手点一句：计数器 1 MHz 时，16 位的会在 65.5 ms 就回绕一次，测慢一点的信号就得自己处理溢出；32 位的要 71 分钟才回绕，基本可以不管。

频率计也是一个对象。它记住：用哪个定时器和通道、计数时钟多快、最近一个周期的计数、是否有新数据、上一个上升沿的计数值：

```c
#ifndef FREQ_METER_H
#define FREQ_METER_H

#include "main.h"

/* 频率计对象：用定时器输入捕获，量相邻两个上升沿的间隔（测周法）。
 * 要求定时器是 32 位的（如 TIM2），这样计数器回绕也只需要无符号相减。 */
typedef struct {
    TIM_HandleTypeDef  *htim;        /* 哪个定时器，如 &htim2 */
    uint32_t            channel;     /* 哪个通道，如 TIM_CHANNEL_1 */
    uint32_t            active;      /* 对应的 HAL_TIM_ACTIVE_CHANNEL_x，回调里用来认通道 */
    uint32_t            clk_hz;      /* 计数时钟，由调用者告诉对象 */
    volatile uint32_t   ticks;       /* 最近一个周期有多少个计数（中断写） */
    volatile uint8_t    ready;       /* 1：ticks 是还没被取走的新数据（中断置 1，主循环清 0） */
    uint32_t            last;        /* 上一个上升沿的计数值（只有中断用） */
    uint8_t             have_last;   /* 是否已经有上一个上升沿（只有中断用） */
} freq_meter_t;

void freq_meter_init(freq_meter_t *m, TIM_HandleTypeDef *htim, uint32_t channel, uint32_t clk_hz);
void freq_meter_start(freq_meter_t *m);     /* 开始捕获，并打开捕获中断 */

/* 有新数据就取走，填好 ticks 和换算出的频率，返回 1；没有新数据返回 0 */
int  freq_meter_read(freq_meter_t *m, uint32_t *ticks, uint32_t *hz);

#endif /* FREQ_METER_H */
```

```c
#include <stddef.h>
#include "freq_meter.h"

/* HAL 的捕获回调只给一个 htim 指针，不知道它属于哪个频率计。
 * 所以和第 6 章的串口接收器一样，做一张登记表：init 时登记，回调里按 htim 和通道找回对象。 */
#define FREQ_METER_MAX  2
static freq_meter_t *s_registry[FREQ_METER_MAX];

static uint32_t active_of(uint32_t channel)
{
    switch (channel) {
    case TIM_CHANNEL_1: return HAL_TIM_ACTIVE_CHANNEL_1;
    case TIM_CHANNEL_2: return HAL_TIM_ACTIVE_CHANNEL_2;
    case TIM_CHANNEL_3: return HAL_TIM_ACTIVE_CHANNEL_3;
    default:            return HAL_TIM_ACTIVE_CHANNEL_4;
    }
}

void freq_meter_init(freq_meter_t *m, TIM_HandleTypeDef *htim, uint32_t channel, uint32_t clk_hz)
{
    m->htim = htim;
    m->channel = channel;
    m->active = active_of(channel);
    m->clk_hz = clk_hz;
    m->ticks = 0;
    m->ready = 0;
    m->last = 0;
    m->have_last = 0;
    for (int i = 0; i < FREQ_METER_MAX; i++) {
        if (s_registry[i] == m) {
            return;                           /* 已经登记过 */
        }
    }
    for (int i = 0; i < FREQ_METER_MAX; i++) {
        if (s_registry[i] == NULL) {
            s_registry[i] = m;
            return;
        }
    }
}

void freq_meter_start(freq_meter_t *m)
{
    HAL_TIM_IC_Start_IT(m->htim, m->channel);
}

int freq_meter_read(freq_meter_t *m, uint32_t *ticks, uint32_t *hz)
{
    uint32_t t;

    if (!m->ready) {
        return 0;
    }
    m->ready = 0;
    t = m->ticks;
    if (t == 0u) {
        return 0;
    }
    *ticks = t;
    *hz = m->clk_hz / t;
    return 1;
}

/* 输入捕获回调：每来一个上升沿，硬件已经把当时的计数值锁进了捕获寄存器。
 * 只读值、存值、置标志，换算留给主循环 */
void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim)
{
    for (int i = 0; i < FREQ_METER_MAX; i++) {
        freq_meter_t *m = s_registry[i];

        if (m != NULL && m->htim == htim && htim->Channel == m->active) {
            uint32_t now = HAL_TIM_ReadCapturedValue(htim, m->channel);

            if (m->have_last) {
                m->ticks = now - m->last;     /* 无符号减法：计数器中途回绕也对 */
                m->ready = 1;
            }
            m->last = now;
            m->have_last = 1;
        }
    }
}
```

这里有一件需要说明的事：HAL 调用捕获回调时，只给你一个 `htim` 指针，它不知道这个定时器"属于"哪个频率计。所以做了一张小登记表：`freq_meter_init` 时登记，回调里按 `htim` 和通道找回对象，第 6 章里的串口接收器会用同一个办法。这张表是模块里唯一的静态数据，原因是 HAL 规定的回调函数没有"上下文"参数。

回调里用的是无符号相减，即使计数器在两次捕获之间回绕过一次，结果也是对的，这里的道理和 5.2 里 `g_ms` 回绕是同一回事，见[[【原理】补码与整型转换|补码与整型转换]]。

包含头文件加上 `freq_meter.h`，对象、初始化和主循环如下。信号源固定在 50%，是为了保证每一圈都有上升沿：

```c

/* USER CODE END PV */
```

```c

```

```c

  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    if (soft_due(&t_rep, 500u)) {                      /* 每 500 ms 报告一次 */
        uint32_t ticks, hz;

        if (freq_meter_read(&meter, &ticks, &hz)) {
            LOG(LOG_INFO, "ticks=%lu, freq=%lu Hz\r\n", (unsigned long)ticks, (unsigned long)hz);

  /* USER CODE END 3 */
```

你应该看到串口每 500 ms 一行：`ticks=1000, freq=1000 Hz`。

这里有一个提醒：你测的是自己输出的信号，两边吃的是同一个时钟，晶振的误差互相抵消了，所以读数会特别准。测别人的信号时，晶振的误差、对方的抖动都会算进去，不会这么漂亮。

**探针 2：改占空比。** 把 `pwm_set_duty(&pwm3, 500u)` 改成 `100u`，频率读数变不变？

> [!success]- 揭晓
> 不变。周期由 ARR 管，占空比只管每圈里高多久，上升沿之间的距离还是 1000 µs。这是对前面"哪个旋钮管什么"的又一次验证。

**探针 3：把计数时钟调粗。** TIM2 的 PSC 改成 8399，同时把 `freq_meter_init` 的最后一个参数改成 `10000u`。计数时钟 10 kHz，每格 100 µs。

> [!question] 先猜一猜
> 1000 Hz 的信号，ticks 是多少？如果某一次 ticks 抖成了 9 或 11，换算出来的频率是多少？

> [!success]- 揭晓
> ticks = 1000 µs ÷ 100 µs = 10，频率 = 10,000 ÷ 10 = 1000 Hz。
> 抖成 9 就是 10,000 ÷ 9 ≈ 1111 Hz，抖成 11 就是 10,000 ÷ 11 ≈ 909 Hz，一次抖动就是 10% 的误差。
> 分辨率就是每一格占整个周期的比例：1 µs 一格测 1 kHz，分辨率是 0.1%；测 10 kHz，周期只有 100 µs，一格就是 1%。想测得准，计数时钟要比被测信号快得多。

## 刚才发生了什么

整件事就两个动作。

- **输出**：计数器在 0 到 ARR 之间循环，和 CCR 比较，小于 CCR 输出高，其余输出低。你动 CCR，改的是占空比，也就是亮度；你动 ARR（和 PSC），改的是频率，也就是闪得多快、音调多高。
- **输入**：边沿一来，硬件把计数值抄进 CCR 并触发捕获中断，你的回调把它读出来，和上一次相减。

这几个旋钮，现在都被收进了对象的函数里：

| 想做的事 | 调用的函数 | 底下的 HAL 接口 |
|---|---|---|
| 灯的亮度 | `pwm_set_duty` | `__HAL_TIM_SET_COMPARE` |
| 灯闪的快慢、蜂鸣器的音调 | `pwm_set_freq`（CCR 自动跟着变） | `__HAL_TIM_SET_AUTORELOAD` 加 `__HAL_TIM_SET_COMPARE` |
| 测一路信号的频率 | `freq_meter_read` | `HAL_TIM_ReadCapturedValue` |

你写进 CCR 或 ARR 的新值，不是立刻改掉当前这一圈，而是等下一圈开头才生效，这叫**预装载**。这样占空比不会在半圈里突然换掉，多出一个不完整的脉冲。预装载的机制放在[[【原理】PWM与预装载|PWM与预装载]]里。

再看看这一节搭出来的东西：`pwm_t` 是个"驱动"，呼吸灯 `breath_t` 和音阶 `melody_t` 借用它；它们都没有函数里的 `static` 变量，也没有全局变量，状态全在对象里，时间从外面传进来。所以想要第二盏呼吸灯，再建一个 `breath_t` 就行，代码不用改（别忘了前面说过：同一个定时器只挂一个 `pwm_t`，第二盏灯要接在另一个定时器的通道上）。

`htim3` 本身也是一个对象：`TIM_HandleTypeDef` 记着这个定时器的一切，`HAL_TIM_PWM_Start(&htim3, ...)` 是它的方法。我们的 `pwm_t` 只是在它上面再包了一层更贴近"我想要什么"的接口。这种写法在 C 里怎么做得更彻底，见[[【原理】C语言里的面向对象|C语言里的面向对象]]。

输出这一侧，CPU 几乎不参与：启动之后，波形全由定时器硬件产生，你只在要换亮度时碰一下 CCR。输入这一侧则要小心：每个上升沿进一次中断，中断的次数等于信号的频率。1 kHz 毫无压力，但如果信号高到每秒几十万次，CPU 光是进出中断就多半忙不过来。遇到高频信号换思路：不量周期，改成数一段固定时间里有几个边沿，见[[【拓展】测频法与测周法|测频法与测周法]]。

`freq_meter_t` 里的 `ticks` 和 `ready` 是中断和主循环之间共享的数据，沿用了 5.1 的 flag 套路，更多的安全写法在 [[5.4_中断与主循环共享数据]]。

最后回到开头那道题。灯每秒被开关 1000 次，你看到的却是稳定的偏暗。现在你可以自己答了：1000 是圈速，由 PSC 和 ARR 定；偏暗是每圈只亮 30%，由 CCR 定。眼睛看不出来，是因为圈速足够快。

## 记住这几条

1. PWM 频率 = 定时器时钟 ÷ ((PSC + 1) × (ARR + 1))，占空比 = CCR ÷ (ARR + 1)。
2. 调亮度动占空比，调音调动频率；改 ARR 的同时 CCR 要按比例一起改，`pwm_set_freq` 已经替你做了。运行中改 ARR，先打开 auto-reload preload。
3. 要让蜂鸣器变音调，必须是无源蜂鸣器；有源的只会响一个音。
4. 占空比是"引脚为高的比例"，LED 接成低电平亮时，亮度方向是反的。
5. 捕获的差值用无符号相减，不用担心计数器回绕。一路没有边沿的信号（占空比 0% 或 100%）测不出频率，不等于频率为零，要处理"没有新数据"。
6. 测周法的分辨率是 1 个计数相对于整个周期：信号越快，要求计数时钟越高。
7. 一个东西一个对象：状态放结构体，函数第一个参数是对象指针，不用函数里的 `static` 变量；时间从外面传进来。同一个定时器的通道共用 ARR，一个定时器只挂一个 `pwm_t`。
8. HAL 的回调只给定时器句柄，要靠登记表找回对象；回调里只读值、存值、置标志，换算和输出放到主循环里做。

## 练习
