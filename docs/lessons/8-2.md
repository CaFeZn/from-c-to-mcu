# 8.2 ADC 采集电压

> **这一节你会做出**：把电位器的电压读成数字，换算成伏特，用 `LOG()` 每 200 ms 报一次；再换成 DMA 连续采集，让 CPU 不必一次次去等转换。
> **前置**：[[5.1_中断入门]]、[[5.2_定时器与节拍]]、[[3.1_串口与日志]]　｜　**预计**：阅读 + 动手 75 分钟

> [!tip] 跳读自测：这一节你可能不用读
> 先回答下面几个问题（写下来，别只在心里答）。**全部答对**就直接跳到 [[8.3_综合项目]]；有一题拿不准，就从头读。
> 1. 12 位 ADC，参考电压 3.3 V。读数是 2048，对应大约多少伏？读数 4095 呢？
> 2. 读代码找问题：下面这段为什么打不出你想要的电压？怎么改？
>    ```c
>    float v = raw * 3.3f / 4095.0f;
>    LOG(LOG_INFO, "v=%f\r\n", v);
>    ```
> 3. 要测一节 0 到 12 V 的电池电压，能直接把它接到 ADC 引脚上吗？怎么办？
> 4. ADC 用 DMA 循环模式连续采集时，"半满回调"和"全满回调"分别表示什么？回调里应该做什么？
>
> > [!success]- 答案，以及跳过后要带走的东西
> > 1. 约 1.65 V（2048 ÷ 4095 × 3.3）；4095 约 3.3 V，即满量程。
> > 2. 日志层不支持 `%f`。改成整数毫伏：`mv = raw * 3300u / 4095u;`，打印时分成整数部分和小数部分，如 `%lu.%03lu V`。
> > 3. 不能。ADC 引脚的输入不能超过 VDDA（通常 3.3 V，以数据手册为准），超过会损坏芯片。要用两个电阻分压，把电压降到 3.3 V 以内再接入，读数换算时再乘回分压比。
> > 4. 半满：缓冲的前一半已经写满，DMA 正在写后一半。全满：后一半写满，DMA 绕回去写前一半。回调里只置标志（5.1 的规矩），主循环看到标志再处理刚写满的那一半。
> >
> > **带走清单**：
> > - 代码：本节「第三步」的 `adc_drv.h` 和 `adc_drv.c`（对象类型 `adc_t`，函数 `adc_init(&a, &hadc1, 参考电压mV)`、`adc_read_mv(&a, n)`、`adc_start_dma(&a)`、`adc_dma_poll(&a)`、`adc_last_mv(&a)` 等），分别放进 `User/Inc` 和 `User/Src`（CMake 自动收进构建，新增文件后重新配置一次，见 2.2）。`main.c` 里的调用写法见「第三步」（轮询）和「第六步」（DMA，需要在 `HAL_ADC_ConvHalfCpltCallback` 和 `HAL_ADC_ConvCpltCallback` 里转交给对象）。依赖 5.2 的 `soft_due` 和 `g_ms`（它们是 `main.c` 里的 `static` 函数和全局变量，调用代码因此写在 `main.c` 里），以及 3.1 的 `log.h`。
> > - 命名：模块文件起名 `adc_drv`，是为了避开 CubeMX 在选了"外设单独成对"时可能生成的 `adc.h`、`adc.c`。
> > - CubeMX：ADC1 的一路输入（示例 ADC1_IN1，PA1），12 位，右对齐，采样时间 56 周期，轮询用单次转换；DMA 版改为连续转换加 DMA 循环模式、半字宽度。
> > - 约定：参考电压作为参数传给 `adc_init`，以板子为准，不写死在模块里；换算全用整数毫伏，不用浮点；一个东西一个对象（4.1）。

## 先看一个怪现象

你拿一把尺子量桌子，读出来的是"第几格"，不是"几米"。要得到米，你得知道两件事：这把尺子一共多长，一共分成多少格。

ADC 就是一把量电压的尺子。它读出来的也只是一个整数，"第几格"。要把格数变回伏特，你得知道它的总长（参考电压）和总格数（分辨率）。

> [!question] 先猜一猜
> 假设这把尺子总长 3.3 V，一共分成 4096 格，读数从 0 到 4095。读数是 1000，电压大约是多少？读数是 2048 呢？

> [!success]- 揭晓
> 读数 1000 约等于 1000 ÷ 4095 × 3.3 ≈ 0.806 V；读数 2048 约 1.65 V，正好是一半。关系是线性的：读数 ÷ 满量程读数 = 电压 ÷ 参考电压。
> 这条线性关系，就是后面全部换算的出发点。

## 动手做

### 第一步：接线

找一个 10 kΩ 左右的电位器（或者用板子上自带的电位器）：

| 电位器的脚 | 接到 |
|---|---|
| 一端 | 3V3 |
| 另一端 | GND |
| 中间滑动端 | 你选的 ADC 引脚（示例用 PA1，对应 ADC1_IN1） |

两条规矩：

- **ADC 引脚的电压不能超过 VDDA**（通常是 3.3 V，以数据手册为准）。千万别把 5 V 直接接上去。
- 选引脚前先看原理图，确认它没被板上的别的东西占用（见 4.2）。能做 ADC 的引脚，CubeMX 的引脚图里会标 `ADCx_INy`。

### 第二步：在 CubeMX 里配 ADC1（轮询用）

1. 在 Pinout 视图里，把 PA1 设成 `ADC1_IN1`。CubeMX 会自动把这个引脚设成模拟模式。
2. 打开 Analog → ADC1，按下表填写。界面文字以你的 CubeMX 版本为准。

| 位置 | 填写 |
|---|---|
| ADC_Settings → Clock Prescaler | PCLK2 divided by 4 |
| ADC_Settings → Resolution | 12 bits |
| ADC_Settings → Data Alignment | Right alignment |
| ADC_Settings → Scan Conversion Mode | Disabled |
| ADC_Settings → Continuous Conversion Mode | Disabled |
| ADC_Settings → DMA Continuous Requests | Disabled |
| ADC_Settings → End Of Conversion Selection | EOC flag at the end of single conversion |
| ADC_Regular_ConversionMode → Number Of Conversion | 1 |
| Rank 1 → Channel | Channel 1 |
| Rank 1 → Sampling Time | 56 Cycles |

3. 生成代码。CubeMX 会在 `main.c` 里生成 `ADC_HandleTypeDef hadc1;` 和 `MX_ADC1_Init()`。本节的 `adc_drv.c` 不需要 `extern`，因为 `hadc1` 的地址是作为参数传给 `adc_init` 的，在 `main.c` 里取 `&hadc1` 即可。

时钟前提：示例按 APB2 为 84 MHz 来算，ADC 的时钟是它的四分之一，即 21 MHz。以你时钟树上显示的为准。

### 第三步：把 ADC 做成一个对象，轮询读一次

先写最简单的：启动一次转换，等它完成，取走结果。按 4.1 的套路，**一路 ADC 采集 = 一个对象**：用哪个 ADC 外设、参考电压是多少、最近一次读数，都装进一个 `struct`，操作它的函数第一个参数传对象指针。新建 `adc_drv.h` 和 `adc_drv.c`，放进 `User/Inc` 和 `User/Src`，**重新配置一次 CMake**（见 2.2）：

```c
/* User/Inc/adc_drv.h */
#ifndef ADC_DRV_H
#define ADC_DRV_H

#include <stdint.h>
#include "main.h"                 /* 提供 ADC_HandleTypeDef */

#define ADC_FULL_SCALE  4095u     /* 12 位：满量程读数 */
#define ADC_DMA_LEN     256u      /* DMA 缓冲点数，偶数；前一半、后一半各 128 个 */

/* 一路 ADC 采集 = 一个对象。成员是它的内部状态，请只通过下面的函数访问 */
typedef struct {
    ADC_HandleTypeDef *hadc;      /* 用哪个 ADC 外设（CubeMX 生成的句柄，如 &hadc1） */
    uint32_t           vref_mv;   /* 参考电压（毫伏），以板子为准，由 adc_init 传入 */
    uint32_t           last_raw;  /* 最近一次得到的读数（轮询的平均值，或 DMA 一段的平均值） */
    uint16_t           buf[ADC_DMA_LEN];  /* DMA 版：DMA 往这里写，半字一个点。第六步才用 */
    volatile uint8_t   half_ready;        /* DMA 版：前半段写满了（中断里置位） */
    volatile uint8_t   full_ready;        /* DMA 版：后半段写满了（中断里置位） */
} adc_t;

/* 初始化对象。hadc 和 vref_mv 都是传进来的，adc_drv.c 里不认识具体哪个 ADC、多少伏 */
void     adc_init(adc_t *a, ADC_HandleTypeDef *hadc, uint32_t vref_mv);

/* 读数换算成毫伏：整数运算，先乘后除 */
uint32_t adc_raw_to_mv(const adc_t *a, uint32_t raw);

/* ---------- 轮询 ---------- */
/* 轮询读一次。成功返回 0..4095，失败返回 -1 */
int      adc_read_raw(adc_t *a);
/* 连读 n 次取平均，返回毫伏；失败返回 -1。n 不要太大，否则主循环被占住太久 */
int      adc_read_mv(adc_t *a, uint32_t n);

/* ---------- DMA 连续采集 ---------- */
/* 启动 DMA 连续采集。成功返回 0，失败返回 -1 */
int      adc_start_dma(adc_t *a);
/* 在 HAL 的半满、全满回调里调用，只置标志（5.1 的规矩） */
void     adc_dma_half_isr(adc_t *a);
void     adc_dma_full_isr(adc_t *a);
/* 每圈主循环调用一次：哪一半写满了，就把那一半求平均，存进 last_raw。有更新返回 1 */
int      adc_dma_poll(adc_t *a);

/* ---------- 取最近一次的结果 ---------- */
uint32_t adc_last_raw(const adc_t *a);
uint32_t adc_last_mv(const adc_t *a);

#endif /* ADC_DRV_H */
```

```c
/* User/Src/adc_drv.c */
#include "adc_drv.h"

void adc_init(adc_t *a, ADC_HandleTypeDef *hadc, uint32_t vref_mv)
{
    a->hadc       = hadc;
    a->vref_mv    = vref_mv;
    a->last_raw   = 0;
    a->half_ready = 0;
    a->full_ready = 0;
    for (uint32_t i = 0; i < ADC_DMA_LEN; i++) {
        a->buf[i] = 0;
    }
}

uint32_t adc_raw_to_mv(const adc_t *a, uint32_t raw)
{
    /* 最大 4095 * 3300 约 1350 万，32 位装得下 */
    return raw * a->vref_mv / ADC_FULL_SCALE;
}

int adc_read_raw(adc_t *a)
{
    if (HAL_ADC_Start(a->hadc) != HAL_OK) {
        return -1;
    }
    if (HAL_ADC_PollForConversion(a->hadc, 10) != HAL_OK) {   /* 最多等 10 ms */
        HAL_ADC_Stop(a->hadc);
        return -1;
    }
    uint32_t v = HAL_ADC_GetValue(a->hadc);
    HAL_ADC_Stop(a->hadc);
    return (int)v;
}

int adc_read_mv(adc_t *a, uint32_t n)
{
    if (n == 0) {
        n = 1;
    }
    uint32_t sum = 0;
    for (uint32_t i = 0; i < n; i++) {
        int v = adc_read_raw(a);
        if (v < 0) {
            return -1;
        }
        sum += (uint32_t)v;
    }
    a->last_raw = sum / n;
    return (int)adc_raw_to_mv(a, a->last_raw);
}

int adc_start_dma(adc_t *a)
{
    a->half_ready = 0;
    a->full_ready = 0;
    if (HAL_ADC_Start_DMA(a->hadc, (uint32_t *)a->buf, ADC_DMA_LEN) != HAL_OK) {
        return -1;
    }
    return 0;
}

void adc_dma_half_isr(adc_t *a)
{
    a->half_ready = 1;      /* 前半段写满：DMA 接着写后半段，我们可以放心读前半段 */
}

void adc_dma_full_isr(adc_t *a)
{
    a->full_ready = 1;      /* 后半段写满：DMA 绕回去写前半段，我们读后半段 */
}

/* 对 buf 里的 n 个点求平均 */
static uint32_t average_u16(const uint16_t *buf, uint32_t n)
{
    uint32_t sum = 0;
    for (uint32_t i = 0; i < n; i++) {
        sum += buf[i];
    }
    return sum / n;
}

int adc_dma_poll(adc_t *a)
{
    int updated = 0;

    if (a->half_ready) {
        a->half_ready = 0;
        a->last_raw = average_u16(&a->buf[0], ADC_DMA_LEN / 2u);
        updated = 1;
    }
    if (a->full_ready) {
        a->full_ready = 0;
        a->last_raw = average_u16(&a->buf[ADC_DMA_LEN / 2u], ADC_DMA_LEN / 2u);
        updated = 1;
    }
    return updated;
}

uint32_t adc_last_raw(const adc_t *a)
{
    return a->last_raw;
}

uint32_t adc_last_mv(const adc_t *a)
{
    return adc_raw_to_mv(a, a->last_raw);
}
```

这个文件里有三处值得看：

- `hadc` 和 `vref_mv` 是**传进来**的。`adc_drv.c` 里没有 `hadc1`，也没有 3300，它不认识具体哪块板子。想换一路 ADC，或者换一个参考电压，只改 `adc_init` 的调用。
- 换算全用整数：先乘后除，最大 4095 × 3300 约 1350 万，32 位装得下。**不用浮点**，日志层也不支持 `%f`（3.1）。
- `HAL_ADC_PollForConversion` 带了超时，失败时返回错误，而不是一直等下去。

DMA 相关的成员和函数（`buf`、`half_ready`、`adc_start_dma` 这些）第六步才用，先放着。

然后改 `main.c`。`soft_due` 和 `g_ms` 是 5.2 里 `main.c` 中的东西，你已经有了：

```c
/* USER CODE BEGIN Includes */
#include "log.h"
#include "adc_drv.h"
/* USER CODE END Includes */

/* USER CODE BEGIN 1 */
adc_t adc_user;                      /* 用户的 ADC 对象 */
/* USER CODE END 1 */

/* USER CODE BEGIN 2 */
adc_init(&adc_user, &hadc1, 3300u);  /* 参考电压 3300 mV，以你的板子为准 */
/* USER CODE END 2 */
```

（`log_init(&huart1)` 应该已经在 `USER CODE BEGIN 2` 里调用过了，不要重复。）

主循环，放在 `USER CODE BEGIN 3` 区：

```c
/* USER CODE BEGIN WHILE */
uint32_t t_adc = 0;
while (1)
{
  /* USER CODE END WHILE */

  /* USER CODE BEGIN 3 */
  if (soft_due(&t_adc, 200u)) {
      int mv = adc_read_mv(&adc_user, 16u);          /* 连读 16 次取平均 */
      if (mv < 0) {
          LOG(LOG_ERR, "adc read failed\r\n");
      } else {
          LOG(LOG_INFO, "adc raw=%lu  %d.%03d V\r\n",
              (unsigned long)adc_last_raw(&adc_user), mv / 1000, mv % 1000);
      }
  }
}
/* USER CODE END 3 */
```

构建，下载，打开串口助手。

> [!example] 你应该看到什么
> 每 200 ms 出一行，类似（数字是示意）：
> ```
> [1204 I] adc raw=2051  1.653 V
> [1404 I] adc raw=2049  1.651 V
> ```
> 旋转电位器，读数跟着变：一端接近 0，另一端接近 4095。读数不会恰好到 0 或 4095，有一点余量是正常的。

### 第四步：三个探针

**探针 1：让它悬空。** 把电位器中间那根线拔掉，让 ADC 引脚什么也不连。

> [!question] 先猜一猜
> 引脚悬空，读数会是 0、4095，还是别的什么？

> [!success]- 揭晓
> 按我们对电路的理解，悬空的输入没有确定的电压，读数多半会乱漂，手靠近时更明显。它不是 0，也不是某个固定值。这和 4.2 里"输入引脚悬空"是同一个道理。你的现象以你看到的为准，有的板子在这个引脚上带有上下拉电阻，那就会固定在一端。

**探针 2：同一个电压，读十次。** 电位器停在某处不动，看串口输出。

> [!question] 先猜一猜
> 电压没变，每一行的读数应该完全相同吗？

> [!success]- 揭晓
> 通常不会。最后几位会上下跳动，这是噪声。ADC 读到的永远是"真实电压加上一点噪声"。上面的 `adc_read_mv(&adc_user, 16u)` 就是为了压住它：连读 16 次取平均。如果噪声是随机的、各次互相独立，平均 N 次大约能把它降到原来的 1 ÷ √N，16 次约降到四分之一。

把 `16u` 换成 `1u`，对比两种方式下读数的跳动范围。

**探针 3：改采样时间。** 把 CubeMX 里的 Sampling Time 从 56 Cycles 改成 3 Cycles，重新生成、下载，看读数是否更跳、有没有偏。如果你手边有一个几十 kΩ 以上的大电位器，现象会更明显。原因在下一步讲。

### 第五步：采样时间怎么设

只讲怎么设，不讲电路为什么。

ADC 每次转换分两段：先**采样**（把输入电压"攥"进内部的小电容里），再**转换**（把攥住的电压量成数字）。采样的这一段多长，由你选。选项有 3、15、28、56、84、112、144、480 个 ADC 时钟周期。

选法只有一条原则：**信号源的内阻越大，采样时间越要长**。

| 你接的信号源 | 怎么选 |
|---|---|
| 运放输出、稳压电源直接引出（内阻很小） | 短的就够 |
| 电位器、电阻分压（内阻几 kΩ 到几十 kΩ） | 选中等偏长，示例用 56 周期 |
| 内阻更大，或读数偏低、跳动大 | 往长了选 |
| 拿不准 | 选长一点 |

选长的代价只是单次转换更慢。一路低速采集，慢一点没有任何损失。内阻与采样时间的具体对应关系，查数据手册里 ADC 特性表的采样时间与源阻抗那一项（待核对）。

单次转换需要多久：约等于（采样周期数 + 12）÷ ADC 时钟。在 ADC 时钟 21 MHz 的前提下：

| 采样周期数 | 单次转换时间（约） |
|---|---|
| 3 | 0.71 µs |
| 56 | 3.24 µs |
| 144 | 7.43 µs |
| 480 | 23.4 µs |

这是按 `(周期数 + 12) ÷ 21 MHz` 算出来的，其中 12 个周期的转换时间以参考手册为准（待核对），ADC 时钟以你的时钟树为准。

### 第六步：换成 DMA 连续采集

轮询版的毛病是：每次读都要 CPU 陪着等。采一路慢信号没关系，要连续采、采得快，CPU 就被拖住了。

换法和 3.1 里的日志层是同一个思路：让 [[【原理】DMA工作原理|DMA]] 这个"快递员"自己把结果一个个搬进内存里的缓冲，CPU 只在一半满了、全满了的时候收个通知。

**CubeMX 里改这几处：**

| 位置 | 改成 |
|---|---|
| ADC_Settings → Continuous Conversion Mode | Enabled |
| ADC_Settings → DMA Continuous Requests | Enabled |
| ADC1 → DMA Settings → Add → ADC1 | Mode 选 Circular，Peripheral 和 Memory 的 Data Width 都选 Half Word，只勾 Memory 的 Increment Address |
| NVIC Settings | 确认 DMA 对应的 Stream 中断已经勾上（CubeMX 通常会自动勾，F407 上 ADC1 默认用 DMA2 Stream 0，以你的版本为准） |

**代码：** `adc_drv.c` 里 DMA 要用的部分，第三步已经写好了：`adc_start_dma` 启动，`adc_dma_half_isr` 和 `adc_dma_full_isr` 在中断里置标志，`adc_dma_poll` 在主循环里把写满的那一半求平均。你只需要改 `main.c` 三处，轮询用的 `adc_read_mv` 那段主循环去掉。

第一处，对象要从 `main` 的局部变量搬到文件级，放在 `USER CODE BEGIN PV`。原因是 HAL 的两个回调是中断里调用的，它们够不着 `main` 的局部变量：

```c
/* USER CODE BEGIN PV */
adc_t adc_user;                  /* 回调要访问它，所以放文件级，不放 main 的局部 */
/* USER CODE END PV */
```

（第三步 `USER CODE BEGIN 1` 里的那一行 `adc_t adc_user;` 要删掉。）

第二处，两个回调。先认清是哪个 ADC，再把活交给对象，回调里只置标志：

```c
/* USER CODE BEGIN 4 */
/* HAL 从中断里调用这两个回调。先认清是哪个 ADC，再把活交给对象，只置标志 */
void HAL_ADC_ConvHalfCpltCallback(ADC_HandleTypeDef *hadc)
{
    if (hadc == adc_user.hadc) {
        adc_dma_half_isr(&adc_user);
    }
}

void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc)
{
    if (hadc == adc_user.hadc) {
        adc_dma_full_isr(&adc_user);
    }
}
/* USER CODE END 4 */
```

第三处，启动和主循环：

```c
/* USER CODE BEGIN 2 */
adc_init(&adc_user, &hadc1, 3300u);
if (adc_start_dma(&adc_user) != 0) {
    LOG(LOG_ERR, "adc dma start failed\r\n");
}
/* USER CODE END 2 */

/* USER CODE BEGIN WHILE */
uint32_t t_log = 0;
while (1)
{
  /* USER CODE END WHILE */

  /* USER CODE BEGIN 3 */
  adc_dma_poll(&adc_user);                        /* 哪一半写满了，就算那一半的平均 */

  if (soft_due(&t_log, 200u)) {
      uint32_t mv = adc_last_mv(&adc_user);
      LOG(LOG_INFO, "adc avg=%lu  %lu.%03lu V\r\n",
          (unsigned long)adc_last_raw(&adc_user),
          (unsigned long)(mv / 1000u), (unsigned long)(mv % 1000u));
  }
}
/* USER CODE END 3 */
```

> [!question] 先猜一猜
> 按前面的假设（56 周期，ADC 时钟 21 MHz），缓冲是 256 个点。半满回调大约多久来一次？如果你在回调里直接 `LOG()`，会怎样？

> [!success]- 揭晓
> 单次转换约 3.24 µs，256 个点约 0.83 ms 写满一圈，半满回调约每 0.41 ms 一次，也就是每秒两千多次。每次打一行日志，远远超出串口 115200 的承受能力，缓冲很快满，日志就被丢。
> 所以回调里只置标志（5.1 的规矩）。主循环里 `adc_dma_poll` 把一半数据算成平均值，再靠 `soft_due` 每 200 ms 才打一行。数字是按前面的假设推算的，以你的配置为准。

几个要点：

- **半字**：ADC 的结果是 12 位，放在 16 位的变量里，所以缓冲用 `uint16_t`，DMA 宽度选 Half Word。写成 8 位或 32 位，数据会错位。
- **缓冲放普通 SRAM**：F407 里有一块 DMA 够不着的 CCM 内存，别把缓冲放进去（3.1 提过，以参考手册为准）。
- **处理要比半缓冲填满更快**：DMA 不会等你。如果主循环处理一半数据的时间超过另一半被写满的时间，那一半数据在你读的时候就被新数据覆盖了，这是一种竞态，5.4 讲怎么看待它。
- 想**定速**采样（比如每 1 ms 一个点），需要用定时器触发 ADC 转换，而不是让它连续狂转。放在拓展里。

## 刚才发生了什么

用尺子的比喻，把各个名词对上：

| 比喻 | 真名 | 本节的值 |
|---|---|---|
| 尺子 | **ADC**（模数转换器） | ADC1 |
| 尺子总长 | **参考电压** VREF | 3.3 V（`adc_init` 的 `vref_mv` 参数，以板子为准） |
| 总格数 | **分辨率** | 12 位，读数 0 到 4095 |
| 每一格的宽度 | **1 LSB** | 3300 ÷ 4095 ≈ 0.81 mV |
| 读出来的"第几格" | 原始读数 raw | `HAL_ADC_GetValue` |
| 攥住电压的那一小会儿 | **采样时间** | 56 周期 |
| 读出刻度 | **转换时间** | 约 12 周期 |

换算公式只有一条：

> **电压（mV）= 读数 × 参考电压（mV）÷ 4095**

分辨率不等于精度。1 LSB 只有 0.81 mV，但实际读数还会被噪声、参考电压的稳定性、信号源内阻拖累，所以不要期望读到毫伏级的准确度。具体精度指标看数据手册里的 ADC 特性（待核对）。

**测更高的电压**：用两个电阻分压，R1 接被测电压，R2 接地，ADC 接在两者中间：

> **被测电压 = ADC 引脚电压 × (R1 + R2) ÷ R2**

R1 = 20 kΩ、R2 = 10 kΩ 时，分压比是 3，能测的上限是 3.3 × 3 = 9.9 V。电阻要用精度够的，电阻本身的误差会直接叠加到结果里。

轮询和 DMA 的区别，可以一句话说完：轮询是 CPU 陪着等每一次转换，DMA 是 CPU 只收通知。后者在 CPU 忙别的事时依然能连续采集。

如果你的读数不对，先回到 8.1 的四步：

| 现象 | 先查什么 |
|---|---|
| 读数一直是 0 | 引脚是否真的接了信号？是否共地？引脚是否设成了模拟模式？ |
| 读数一直是 4095 | 输入是否被接到了 3.3 V？参考电压是否正常？ |
| 读数乱跳 | 引脚悬空？信号源内阻大而采样时间太短？电源有干扰？ |
| 读数比预期的比例偏大或偏小 | 传给 `adc_init` 的 `vref_mv` 是否与板子实际的参考电压一致？ |
| 完全读不到，函数返回出错 | ADC 的时钟、`MX_ADC1_Init` 是否被调用了？ |

回头看开头那把尺子：现在你知道，读数只是"第几格"，要变回伏特，必须知道尺子多长、分几格。这两个数写错一个，读数再准，换算出来也是错的。

## 记住这几条

1. ADC 引脚的输入电压不能超过 VDDA（通常 3.3 V，以数据手册为准）。高电压用电阻分压后再接入。
2. 参考电压作为参数传给 `adc_init`，以板子为准，不写死在模块里。换算全用整数毫伏，先乘后除，不用浮点。
3. 12 位 ADC 的满量程读数是 4095。
4. 采样时间随信号源内阻选：内阻越大越要长，拿不准选长一点。
5. 单次读数有噪声，平均能压低。平均 N 次约降到 1 ÷ √N（噪声独立随机时）。
6. DMA 采集：回调只置标志，缓冲放普通 SRAM，处理要比半缓冲填满更快。
7. 读数不对，先按 8.1 的顺序查：时钟、引脚、模式、数据。

## 练习

1. 用 `adc_read_raw(&adc_user)` 在电位器不动的情况下连续读 100 次，记下最大值和最小值，算出抖动范围。再换成采样时间 3 周期、144 周期各做一次，比较。（复现）
2. 把电位器换成 R1 = 20 kΩ、R2 = 10 kΩ 的分压，被测电压是 9 V 以内的直流。给 `adc_t` 加一个 `adc_raw_to_input_mv(const adc_t *a, uint32_t raw, uint32_t r1, uint32_t r2)` 函数（在 `adc_drv.h` 里声明，`adc_drv.c` 里实现），要求用整数，并验证：读数 2000 时输出应是多少毫伏？（改造）
3. 假设板子的参考电压实际是 3.0 V，而 `adc_init` 传进去的 `vref_mv` 仍是 3300。真实输入是 1.5 V，串口会显示多少？先写下预测，再算。（预测）

> [!success]- 提示与答案方向
> 1. 一般采样时间越长，抖动越小；3 周期时尤其是大内阻信号源，读数可能偏低且更抖。以你的实测为准。
> 2. 把分压比也乘在前面，一次算完，精度比先算 mV 再乘 3 更好：`raw * a->vref_mv * (r1 + r2) / (r2 * ADC_FULL_SCALE)`（先乘后除，注意中间结果别溢出 32 位）。具体到本例，等价于 `raw * 3300u * 3u / 4095u`。读数 2000 时：2000 × 3300 × 3 ÷ 4095 ≈ 4835 mV。如果先算出 1611 mV 再乘 3，得 4833 mV，差了 2 mV，这是整数除法截断造成的。最大值 4095 × 3300 × 3 约 4054 万，32 位依然装得下。
> 3. 真实读数约 1.5 ÷ 3.0 × 4095 ≈ 2047，代入错误的 3300，显示约 1649 mV，比真实值高 10%。参考电压写错，整体比例都会错。
