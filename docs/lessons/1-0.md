# 1.0 装好工具，在 VS Code 里跑通 hello

> **这一节你会做出**：在 VS Code 里运行一个 C 程序，让屏幕显示 `hello, world`。后面的练习就从这个工程接着做。
> **前置**：无　｜　**预计**：阅读 + 动手 40 分钟（下载安装的时间另算）

这一节先不接单片机。我们要把几行 C 代码写进一个文件，让它在电脑上输出一句话。

写代码用 **VS Code**，它是编辑器，负责让你写、改和查看文件。写好的 `.c` 文件仍然是文字，不能直接当程序运行；把它变成程序的工具叫**编译器**，这里用 gcc。你现在只需要分清这两件事：在哪里写，以及谁把它做成能运行的程序。

下面按 **64 位 Windows** 走一条路线：装好工具 → 打开练习文件夹 → 跑出 hello → 保留旧例子、再加一个新例子 → 检查补全和跳转。详细的编译过程不在这里展开，其他系统的安装入口放在文末。

## 第一步：装好要用的软件

### 1. 安装 VS Code，建立 C-PC Profile

先从 [VS Code 官网](https://code.visualstudio.com/) 下载并安装 VS Code，然后打开它。

这一章先在电脑上练纯 C，后面还会用同一个 VS Code 写单片机程序。两种用途需要的扩展和设置不完全一样，可以把它们分别保存成 **Profile（配置文件）**，需要哪套就切到哪套，不必把所有开发工具都塞进同一个配置里。

| Profile 名称 | 本课程里的用途 | 什么时候准备 |
|---|---|---|
| `C-PC` | 纯 C 学习：让程序在电脑上运行 | 现在创建 |
| `STM32` | 单片机开发：构建、下载和调试板上的程序 | 到 2.2 再创建 |

现在只建立 `C-PC`：

1. 如果 VS Code 自动打开了以前的项目，先用“文件 → 新建窗口”（`Ctrl+Shift+N`）打开一个空窗口。不要在原有日常项目窗口里直接创建这套配置，以免改变它的 Profile 关联。
2. 从“文件 → 首选项 → 配置文件（Profiles）”，或左下角的管理齿轮进入 **Profiles 编辑器**。
3. 点 **New Profile**，名字填 `C-PC`，**Copy from** 选 **None**，从空配置开始。确认 **Settings** 和 **Extensions** 也使用空内容，而不是继续共用 Default 的内容；暂时不用勾选 **Use for New Windows**。
4. 点 **Create**。如果当前窗口没有自动切到它，点 `C-PC` 旁的 **Use this Profile for Current Window**；也可以用 `Ctrl+Shift+P` 执行 `Profiles: Switch Profile`，选择 `C-PC`。
5. 在 Profiles 编辑器里确认 `C-PC` 标为 **In use**。它现在就是这个窗口正在用的配置；你原来的 Default 配置不用删除。

接着，**在 C-PC 当前窗口里**按 `Ctrl+Shift+X`，安装这两个扩展：

- **C/C++**，发布者 Microsoft，扩展 ID `ms-vscode.cpptools`。
- **CMake Tools**，发布者 Microsoft，扩展 ID `ms-vscode.cmake-tools`。

**C/C++** 帮你看代码、补全和跳转；**CMake Tools** 把这个工程的配置、构建和运行接到 VS Code 的命令与按钮上。注意：装扩展不等于装好了编译器，下一步才把实际干活的工具装上。

先沿用这一组，不需要同时装 Code Runner、clangd 和一套单片机插件。安装、启用或调整这些扩展前，先确认当前窗口是 `C-PC`；不要把开发扩展设为所有 Profile 共用。以后遇到需要更换代码分析工具的情况，再单独处理。

Profile 管的是编辑器的设置、扩展等配置，**不是另一台电脑或虚拟环境**。它不会替你安装 gcc，也不会自动隔离 Windows 的 `Path`。下面的工具仍要正常安装，实际用哪个编译器，还要在工程的 CMake 配置中确认。

### 2. 安装配套工具

1. 打开 [MSYS2 官网](https://www.msys2.org/)，下载适合自己电脑的安装程序。下面使用常见的 x86-64 Windows 电脑。
2. 安装位置保持默认的 `C:\msys64`。安装完成后，从开始菜单打开 **MSYS2 UCRT64**。
3. 展开下面的安装命令，在 **MSYS2 UCRT64** 窗口中粘贴执行。询问是否继续安装时，输入 `Y` 并回车，等待完成。

> [!example]- 点开复制：安装本教程要用的工具
> ```bash
> pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja
> ```

这次会装好 gcc、CMake 和 Ninja。gcc 负责把代码做成程序；CMake 读取工程里的文件清单、准备构建安排，Ninja 按这个安排调用工具。它们配合完成我们接下来点的“构建”，所以现在一起装好。到文件变多时，再展开 CMake 怎样组织工程。

### 3. 让 VS Code 找到刚装的工具

1. 在 Windows 开始菜单里搜索并打开“编辑账户的环境变量”。
2. 在**用户变量**中选中 `Path`，点“编辑”，再点“新建”。不要删除已有条目。
3. 加入 `C:\msys64\ucrt64\bin`，逐层点“确定”。安装位置不是默认值时，把前面的 `C:\msys64` 换成自己的位置。
4. 关掉 VS Code 和已经打开的终端，再重新打开 VS Code。
5. 在菜单中选择“终端 → 新建终端”，展开下面的检查命令，在下方出现的窗口里逐条输入：

> [!example]- 点开检查：VS Code 能不能找到工具
> ```powershell
> gcc --version
> cmake --version
> ninja --version
> ```

三条命令都显示版本号，就可以继续。版本号不必和教程一模一样；CMake 需要 3.20 或更高。如果提示“不是内部或外部命令”或“无法将……识别为……”，先对照上面第 2、3、4 步检查，不用往下猜。

## 第二步：给第一份程序准备一个地方

在资源管理器里新建 `C:\dev\c-lab`。本教程的工程路径统一用英文、不带空格，减少后面更换工具时的路径问题。

在 VS Code 菜单里选择“文件 → 打开文件夹”，打开刚建的 `c-lab`。要打开的是**文件夹**，不是某一个文件。如果出现信任提示，确认这是自己刚创建的文件夹后再信任。

打开后再执行一次 `Profiles: Switch Profile`，选择 `C-PC`。VS Code 会把这套 Profile 关联到当前 `c-lab` 文件夹；以后重新打开**同一个文件夹**，会自动启用它。可以在 Profiles 编辑器的 **Folders & Workspaces** 中核对关联，别只凭某个图标猜当前配置。

接下来在 VS Code 左侧的资源管理器中，使用“新建文件夹”和“新建文件”按钮，建出下面的内容：

```text
c-lab/
  .vscode/
    settings.json
  CMakeLists.txt
  src/
    hello.c
  projects/
```

`projects` 暂时留空，后面做多文件练习时再用。文件名照着写，尤其是 `CMakeLists.txt` 的大小写；不要让文件变成 `hello.c.txt`。

### 写入三个文件

先把下面的内容放进 `.vscode/settings.json`，按 `Ctrl+S` 保存：

```json
{
  "cmake.generator": "Ninja",
  "cmake.buildDirectory": "${workspaceFolder}/build"
}
```

刚才写的是 `c-lab` 的**工作区设置**，跟着这个工程走，不是 Profile 的用户设置。本节这些选项如果两边都写了，工作区设置优先；切换 Profile 不会把 `.vscode/settings.json` 清空。构建目录等项目专属内容继续放在工程里。

接下来要告诉 CMake：这个文件夹里有一个 `hello` 程序，要用 `src/hello.c` 来构建。把下面这份模板放进根目录的 `CMakeLists.txt`，保存。

先用这份能工作的模板，暂时只留意最后一行 `add_demo(hello)`。以后增加例子，我们改的就是这份清单，不需要每次重新搭环境；模板中其余配置的含义，等真正用到时再解释。

```cmake
cmake_minimum_required(VERSION 3.20)
project(c_lab C)
set(CMAKE_C_STANDARD 99)
set(CMAKE_C_STANDARD_REQUIRED ON)
set(CMAKE_C_EXTENSIONS OFF)
add_compile_options(-Wall -Wextra)

# 每个单文件例子：把 src/<name>.c 编成可执行文件 <name>
function(add_demo name)
  add_executable(${name} src/${name}.c)
endfunction()

add_demo(hello)
```

最后打开 `src/hello.c`，写入下面的代码并保存。它这次只负责检查环境是否正常：

```c
#include <stdio.h>

int main(void) {
    printf("hello, world\n");
    return 0;
}
```

建文件过程中，如果 CMake Tools 提前弹出配置提示，可以先取消，等三个文件都保存好后再做下一步。

接下来都在 VS Code 里操作。按 `Ctrl+Shift+P` 打开命令面板，输入下面给出的命令名称，再选中执行。不要用其他扩展提供的“运行当前文件”按钮，先用这里列出的 CMake 命令。

### 1. 选一次工具

执行 `CMake: Select a Kit`。在列表里选择刚安装的 gcc；名字会随版本变化，路径应对应 `C:\msys64\ucrt64\bin\gcc.exe`。

列表为空时，先执行 `CMake: Scan for Kits`，再选一次。暂时不要选 `arm-none-eabi-gcc`，那是到单片机章节才会用的工具。

### 2. 配置并构建

先执行 `CMake: Configure`，等它结束；再执行 `CMake: Build`。

配置完成后，输出中会出现 `Configuring done`、`Generating done`；构建完成后会生成 `hello.exe`。这次不用逐行读日志，先检查有没有 `error:`。

> [!example]- 对照：成功时的输出大致长这样
> ```text
> Configuring done
> Generating done
> Building C object CMakeFiles/hello.dir/src/hello.c.obj
> Linking C executable hello.exe
> ```
> 配置和构建是先后执行的两次操作，这里只摘出各自的关键行；路径、进度编号随环境变化。

这时左侧的 `build` 文件夹里应该已经有了 `hello.exe`。如果出现 `CMake Error` 或 `error:`，先停在这里，按后面的排错表处理，不要继续点运行。

### 3. 让程序开口

执行 `CMake: Set Launch/Debug Target`，选择 `hello`；然后执行 `CMake: Run Without Debugging`。

在底部终端里，你应该看到：

```text
hello, world
```

**看到这行字，环境就搭好了。** 这句话是刚才那个程序输出的。下一节会从修改它开始，逐步认识 C 代码。

CMake Tools 的面板位置会随版本变化，这里使用命令名称，避免依赖某个版本的按钮位置。找不到输出时，在“终端”面板看程序输出，在“输出”面板选择名称含 CMake 的通道看配置和构建记录。

## 第四步：保留 hello，再写一个新程序

第一个程序跑通了，下一份练习不必把它覆盖掉，也不必重新装软件。我们把新的程序放进同一个 `c-lab`，让两个例子都能单独运行。

你只需要做两件事：**新建一个 `.c` 文件，再登记它的名字。**

先新建 `src/greet.c`，写入并保存：

```c
#include <stdio.h>

int main(void) {
    printf("hi, c-lab\n");
    return 0;
}
```

然后在 `CMakeLists.txt` 末尾加一行，保留原来的 `add_demo(hello)`：

```cmake
add_demo(greet)
```

再次执行 `CMake: Configure` 和 `CMake: Build`，用 `CMake: Set Launch/Debug Target` 选中 `greet`，再执行 `CMake: Run Without Debugging`。这次看到的是：

```text
hi, c-lab
```

以后文中写“保存为 `src/xxx.c`，加一行 `add_demo(xxx)`”，就是刚才这套操作。两个地方的 `xxx` 必须一样，括号里不写 `.c`。如果只是修改已有代码，保存后重新构建并运行即可。

## 第五步：程序能跑，让编辑器也看懂它

现在试两个小动作：把鼠标停在 `printf` 上，看是否出现函数提示；按住 `Ctrl` 点击 `#include` 里的 `stdio.h`，看是否能打开头文件。能看到提示、能跳转，而且没有“找不到头文件”的红线，就继续下一节，不必更换扩展。

如果**构建已经成功**，但这些提示仍不正常，先别改能运行的代码。构建工具和编辑器里的代码分析是两条工作链：CMake 知道该用哪个 gcc、头文件在哪里，C/C++ 扩展还需要拿到同一份信息。

在当前工程的 `.vscode/settings.json` 中加入配置提供者。连同前面两项，完整文件是：

```json
{
  "cmake.generator": "Ninja",
  "cmake.buildDirectory": "${workspaceFolder}/build",
  "C_Cpp.default.configurationProvider": "ms-vscode.cmake-tools"
}
```

保存，确认 Kit 仍是前面选的 gcc，再执行一次 `CMake: Configure`。等待扩展处理完成后，重新检查提示和跳转。若 VS Code 询问是否允许 CMake Tools 为 C/C++ 提供配置，选择允许。

这不是“关闭红线”。我们是在把工程的真实构建信息交给代码分析扩展；如果构建本身也报错，仍然应当先修那条错误。

本教程的起步路线先用 C/C++ 扩展。已经在使用 clangd，或确实需要切换时，再看 [[【拓展】让VSCode看懂CMake工程]]；那里从“能构建但提示不对”的现象出发配置 clangd，而不是要求所有新手再装一套工具。

## 卡住时，按这里检查

| 看到的现象 | 先做什么 |
|---|---|
| 找不到 `CMake: Build`，或扩展像是没装 | 确认当前窗口使用 `C-PC`，并检查 CMake Tools 是否在这个 Profile 中启用；装在另一套配置里，不代表当前窗口也能用。 |
| `gcc`、`cmake` 或 `ninja` 无法识别 | 检查工具是否安装完成、用户 `Path` 是否加入 `C:\msys64\ucrt64\bin`，然后完全退出并重开 VS Code。 |
| `No CMAKE_C_COMPILER could be found` | 先确认 `gcc --version` 有输出，再执行 `CMake: Select a Kit` 选择安装好的 gcc。 |
| `Cannot find source file: src/xxx.c` | 核对文件名、所在文件夹和 `add_demo(xxx)`，确认文件已保存。 |
| `Does not match the generator used previously` | 旧的 `build` 使用了另一种配置。确认里面没有自己保存的代码后，仅删除本工程的 `build` 文件夹，再执行 Configure 和 Build。不要删除 `src`、`projects` 或整个工程。 |
| 构建出现 `FAILED` 和多条 `error:` | 从第一条错误开始看，核对它指出的文件和行号；先检查示例是否复制完整。 |
| 找不到 `hello.exe` 或 `greet.exe` | 先检查构建是否成功，再检查运行目标是否选对。 |
| 新增例子后仍显示上一句问候 | 用 `CMake: Set Launch/Debug Target` 切换到刚添加的程序，再运行。 |

清理 `build` 只适用于旧配置冲突，不能修好缺少的软件或写错的代码。先保留第一条报错，再决定要改什么。

> [!tip]- 需要在终端里操作时
> 在 VS Code 的终端中，确认当前位置是 `c-lab` 文件夹，然后依次执行。Windows PowerShell 用：
> ```powershell
> cmake -S . -B build -G Ninja
> cmake --build build
> .\build\hello.exe
> ```
> 这三条分别对应配置、构建和运行。要运行另一个例子，把最后一条的 `hello` 换成它的名字。Linux、macOS 或 Bash 的运行命令写成 `./build/hello`。
> 如果命令行与 VS Code 选到了不同的工具，不要在同一个旧 `build` 上反复尝试；先核对 `gcc` 的路径并统一选择，再重新配置。

## 带走这个工程，继续下一节

- 保留整个 `c-lab` 文件夹，后面的练习沿用它；PC 练习继续使用关联好的 `C-PC` Profile。
- 单片机用的 `STM32` Profile 到 [[2.2_开发环境与第一次点灯#先建立 STM32 Profile|2.2]] 再建，不需要现在把它的扩展也装进来。
- 新例子放在 `src`，并在 `CMakeLists.txt` 末尾加一行 `add_demo(名字)`。
- 修改后先保存、再构建；运行前确认选中了要运行的那个程序。

现在 hello 已经能跑，可以顺手留下两样东西：按[用 Git 保存每一次可用的进展](/notes/git-workflow)给当前工程做一次本地提交；按[用 Markdown 写清楚工程](/notes/markdown-notes)写一个短 README，记下构建、运行方法和实际输出。第一次只做到这一步，不必立刻学分支、上传仓库或复杂排版。

接下来进入 [[1.1_Hello_World]]，让程序输出你自己的内容。等学会函数、程序变成多个文件时，[[1.8_预处理与多文件工程]] 会接着解释：为什么在清单里登记文件，CMake 怎样把它们组织成同一个程序。下面的补充现在都可以不读。

> [!tip]- 需要搬到另一台电脑时：导出 Profile
> Profiles 编辑器可以导出、导入配置；先导出为本地 `.code-profile` 文件，换电脑后再导入。它带走的是选中的设置和扩展清单等，不会连同工程、gcc、CubeCLT 或硬件驱动一起打包。
> 分享前检查里面是否包含个人路径、令牌或其他私有配置；不用为了本教程把个人 Profile 发布到网上。

> [!info]- 其他系统与验证说明
> - Debian / Ubuntu：可用 `sudo apt install build-essential cmake ninja-build` 安装所需工具。
> - macOS：先执行 `xcode-select --install`，已经安装 Homebrew 时再执行 `brew install cmake ninja`；VS Code 中选择 Apple Clang。
> - 这两条安装路线未在本轮的新环境上实测，遇到版本差异以各工具的官方说明为准。正文以 Windows 为主，不要求同时配置几套环境。
> - 本文的 Windows 安装路径和工具包名称已对照 [VS Code 官方 MinGW 配置说明](https://code.visualstudio.com/docs/cpp/config-mingw)、[MSYS2 安装说明](https://www.msys2.org/)、[CMake 工具包](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-cmake) 和 [Ninja 工具包](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-ninja) 核对；这不等于在一台全新电脑上执行过完整安装。
> - Profile 的创建、切换、文件夹关联与导出已对照 [VS Code Profiles 官方文档](https://code.visualstudio.com/docs/configure/profiles)；工作区设置的范围见 [Settings 官方文档](https://code.visualstudio.com/docs/configure/settings)。界面文字以当前版本为准，这里没有代替读者修改本机 Profile。
> - 示例原先在 Windows 的 MinGW gcc 6.3.0、CMake 3.28.1、Ninja 1.11.1 上构建运行过。新的工具版本可能显示不同的日志，不必逐字对照。
> - 工程使用英文无空格路径是本教程的统一约定，不是说所有中文路径都无法使用。此前遇到过 STM32 工程的路径问题，具体触发条件仍待核对。
