# 1.7 函数指针与回调

> **这一节你会做出**：一张"命令名 → 处理函数"的命令表，让程序按名字找到函数并调用；再用 `qsort` 亲眼看一次"你写函数，别人回头来调你"，最后认出：函数表就是一份接口。
> **前置**：[[1.5_数组与指针]]　[[1.6_结构体枚举与typedef]]　｜　**预计**：阅读 + 动手 50 分钟

> [!tip] 跳读自测：这一节你可能不用读

> 1. 下面的命令表里，哪一行会让编译器给出警告？警告的大意是什么？
>    ```c
>    static int cmd_a(int argc, char *argv[]) { (void)argc; (void)argv; return 0; }
>    static int cmd_b(void) { return 0; }
>
>    static const cmd_t t[] = {
>        { "a", cmd_a, "run a" },
>        { "b", cmd_b, "run b" },
>    };
>    ```
> 2. `int (*fn)(int, char *[])` 和 `int *fn(int, char *[])` 有什么区别？
> 3. 在 `main` 里用 `sizeof(g_cmds) / sizeof(g_cmds[0])` 能得到命令条数；把同样的算式搬进 `dispatch(const cmd_t *table, ...)` 里对 `table` 计算，为什么不行？
> 4. 给 `qsort` 写比较函数时，返回值怎么表示"a 排在 b 前面"？为什么不建议直接 `return x - y;`？
>
> > [!success]- 答案，以及跳过后要带走的东西
> > 1. 第二行 `{ "b", cmd_b, "run b" }`。`cmd_b` 没有参数，和表里要求的 `int (*)(int, char *[])` 签名不一致，编译器会警告"从不兼容的指针类型初始化"。
> > 2. 前者是"指向函数的指针变量"；后者没有括号，`*` 先和 `int` 结合，成了"返回 `int *` 的函数声明"。
> > 3. 数组传进函数后变成指针，`sizeof(table)` 是指针的大小，不是数组的大小，算不出条数。所以要另外传个数 `n`。
> > 4. 返回负数表示 a 排在 b 前面，0 表示相等，正数表示排在后面。减法在两数相差很大时可能溢出。
> >
> > **带走清单**：命令表的约定，后面 1.9 的 `cmd.h`、6.1 的板子版会原样使用。
> > - `cmd_t` 结构体：`name`、`fn`（签名 `int (*)(int argc, char *argv[])`，返回 0 成功、非 0 失败）、`help`。
> > - 命令函数约定：`argv[0]` 是命令名本身，参数从 `argv[1]` 开始。
> > - 查表分发的写法：遍历命令表，`strcmp` 比名字，找到就调用 `fn`；表的行数要另外传。
> > - 函数表就是接口：用一张函数指针表把"做什么"和"怎么做"分开，上层只认签名，换实现只换表。本节第五步的 `led_ops_t` 写法，1.9 的 `led.h` 会原样用。
> > - 完整的 `cmd_t` 与 `cmd_exec` 在 1.9 的 `cmd.h` / `cmd.c`，本节的 `cmd_table.c` 不用保留。

## 先看一个怪现象

手机通讯录里存的是"名字 → 号码"。你想找张三，点的是名字，手机替你拨号。张三换了号码，你只改通讯录里的一行，其余地方一概不用动。

现在换到代码里。一个函数，说到底是内存里的一段指令。那它有没有"号码"？这个号码能不能存进变量、传给别人、放进一张表，等到运行的时候再决定拨给谁？

先看一段只有十几行的程序（存成 `src/fp1.c`）：

```c
#include <stdio.h>

static void say_hi(void) {
    printf("hi\n");
}

int main(void) {
    void (*p)(void) = say_hi;   /* p 是"指向 无参数、无返回值 函数"的指针 */
    p();                        /* 通过 p 调用 */
    (*p)();                     /* 另一种写法，效果一样 */
    printf("%d\n", p == say_hi);
    return 0;
}
```

> [!question] 先猜一猜
> 它会输出几行，分别是什么？最后一行比较的 `p == say_hi`，你觉得是真还是假？

> [!success]- 揭晓
> 三行：`hi`、`hi`、`1`。`1` 表示"真"。
> `say_hi` 这个名字，本身就是那段指令的号码。把它交给 `p`，两者手里拿的是同一个号码，所以相等。`p()` 的意思是：拨 `p` 里存的这个号。

## 动手做

### 第一步：拿到函数的号码

在 `c-lab/CMakeLists.txt` 末尾加一行 `add_demo(fp1)`，然后按 1.0 的三步构建并运行：

```
cmake -S . -B build -G Ninja
cmake --build build
./build/fp1
```

Windows 的命令提示符里把最后一行换成 `build\fp1.exe`。在 VS Code 里，就是 CMake Tools 状态栏上的配置、生成、运行。以后凡是「存成 `src/xxx.c`」的例子，都是这个流程：末尾加一行 `add_demo(xxx)`，构建，运行。

你应该看到：

```
hi
hi
1
```

声明怎么读？`void (*p)(void)` 从里往外看：`(*p)` 说明 `p` 是个指针，它指向的东西是"没有参数、没有返回值的函数"。括号是关键。

> [!example] 探针：去掉括号
> 把那一行改成 `void *p(void) = say_hi;`，再构建。
> 我这台机器上（MinGW gcc 6.3），构建输出里编译器抱怨 `function 'p' is initialized like a variable`，措辞因版本而异。
> 没有括号，`*` 先和 `void` 结合，整句话成了"声明一个返回 `void *` 的函数 `p`"，而不是一个指针变量。

现在可以给它起名字了：指向函数的指针，叫**函数指针**。

### 第二步：把号码当参数传

存成 `src/fp2.c`，末尾加 `add_demo(fp2)`：

```c
#include <stdio.h>

/* 给"接收两个 int、返回 int 的函数指针"起个短名字 */
typedef int (*binop_t)(int, int);

static int add(int a, int b) { return a + b; }
static int sub(int a, int b) { return a - b; }
static int mul(int a, int b) { return a * b; }

/* apply 不知道 op 是加、减还是乘，它只管"拨这个号码" */
static int apply(binop_t op, int a, int b) {
    return op(a, b);
}

int main(void) {
    binop_t ops[] = { add, sub, mul };
    const char *names[] = { "add", "sub", "mul" };

    for (int i = 0; i < 3; i++) {
        printf("%s(6, 3) = %d\n", names[i], apply(ops[i], 6, 3));
    }
    return 0;
}
```

> [!question] 先猜一猜
> 输出三行是什么？`apply` 的函数体里一个 `+ - *` 都没有，它凭什么算出三个不同的结果？

> [!success]- 揭晓
> ```
> add(6, 3) = 9
> sub(6, 3) = 3
> mul(6, 3) = 18
> ```
> `apply` 只负责"拨号"。接电话的是谁，由传进来的 `op` 决定。

`typedef int (*binop_t)(int, int);` 和 1.6 的 `typedef` 是一回事，只是新名字夹在括号里面。有了它，`binop_t ops[]` 读作"`binop_t` 的数组"，比 `int (*ops[])(int, int)` 好认得多。

还有一处别扭：`names` 和 `ops` 是两个数组，靠下标一一对应。哪天只改了其中一个，名字和函数就错位，编译器还不会提醒你。名字和函数能不能焊在一起？1.6 学过：用结构体。

### 第三步：命令表

把"名字 + 函数 + 一句话帮助"做成一个结构体，再做成数组，这就是命令表。下面的 `cmd_t` 长什么样是整个教程的约定，1.9 和 6.1 都会原样用它。

存成 `src/cmd_table.c`，末尾加 `add_demo(cmd_table)`（目标名不叫 `cmdtab`，因为 1.8 会用这个名字）：

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* 命令表的一行：名字、处理函数、一句话帮助 */
typedef struct {
    const char *name;
    int (*fn)(int argc, char *argv[]);   /* 返回 0 成功，非 0 失败 */
    const char *help;
} cmd_t;

/* 三个命令。约定：argv[0] 是命令名本身，参数从 argv[1] 开始 */
static int cmd_hello(int argc, char *argv[]) {
    (void)argc;
    (void)argv;
    printf("hello from the table\n");
    return 0;
}

static int cmd_add(int argc, char *argv[]) {
    if (argc != 3) {
        printf("usage: add A B\n");
        return 1;
    }
    printf("%d\n", atoi(argv[1]) + atoi(argv[2]));
    return 0;
}

static int cmd_echo(int argc, char *argv[]) {
    for (int i = 1; i < argc; i++) {
        printf("%s%s", argv[i], (i + 1 < argc) ? " " : "");
    }
    printf("\n");
    return 0;
}

/* 命令表：新增命令就是在这里加一行 */
static const cmd_t g_cmds[] = {
    { "hello", cmd_hello, "say hello" },
    { "add",   cmd_add,   "add A B: print A+B" },
    { "echo",  cmd_echo,  "echo WORDS: print them back" },
};

/* 按名字查表，找到就"拨号"；找不到返回 -1 */
static int dispatch(const cmd_t *table, size_t n, int argc, char *argv[]) {
    for (size_t i = 0; i < n; i++) {
        if (strcmp(table[i].name, argv[0]) == 0) {
            return table[i].fn(argc, argv);
        }
    }
    return -1;
}

/* 打印一次调用的结果，方便观察 */
static void run(const cmd_t *table, size_t n, int argc, char *argv[]) {
    printf("> %s\n", argv[0]);
    printf("  rc=%d\n", dispatch(table, n, argc, argv));
}

int main(void) {
    /* g_cmds 是真正的数组，sizeof 除法能算出行数（1.5 的规矩） */
    size_t n = sizeof(g_cmds) / sizeof(g_cmds[0]);

    char *t1[] = { "hello" };
    char *t2[] = { "add", "3", "4" };
    char *t3[] = { "echo", "a", "b", "c" };
    char *t4[] = { "fly" };

    run(g_cmds, n, 1, t1);
    run(g_cmds, n, 3, t2);
    run(g_cmds, n, 4, t3);
    run(g_cmds, n, 1, t4);
    return 0;
}
```

构建并运行 `./build/cmd_table`，你应该看到：

```
> hello
hello from the table
  rc=0
> add
7
  rc=0
> echo
a b c
  rc=0
> fly
  rc=-1
```

几处值得停一下：

- 命令函数的约定：`argv[0]` 是命令名本身，参数从 `argv[1]` 开始，和 `main` 的 `argv` 一样。这里我们手工造了 `argv`，1.9 会让程序自己从一行文字里拆出来。
- 返回 0 表示成功，非 0 表示失败。`dispatch` 找不到命令时返回 -1，所以命令函数自己最好别返回 -1。
- 行数 `n` 为什么在 `main` 里算？因为 `g_cmds` 是真正的数组，`sizeof` 除法才算得对。数组一旦传进函数就变成指针（1.5 的老朋友），在函数里算不出个数，所以 `dispatch` 要另外收一个 `n`。后面契约里的 `cmd_exec` 也带着 `n`，原因就在这里。

> [!question] 先猜一猜
> 现在想加第四条命令 `ver`，打印版本号。`dispatch` 要改吗？一共要动几处？

> [!success]- 揭晓
> `dispatch` 一个字都不用改。只动两处：写一个命令函数，在表里加一行。

动手试试。函数这样写：

```c
static int cmd_ver(int argc, char *argv[]) {
    (void)argc;
    (void)argv;
    printf("cmd_table 0.1\n");
    return 0;
}
```

表里加一行：

```c
    { "ver",   cmd_ver,   "print version" },
```

再在 `main` 里加一次测试调用 `char *t5[] = { "ver" }; run(g_cmds, n, 1, t5);`。输出末尾会多出：

```
> ver
cmd_table 0.1
  rc=0
```

> [!example] 探针：签名对不上
> 把 `cmd_hello` 改成 `static int cmd_hello(void)`（删掉两个参数），重新构建。
> 构建输出里会出现警告 `initialization from incompatible pointer type`（MinGW gcc 6.3 的措辞），指着表里那一行。
> 这是 `-Wall -Wextra` 在替你看门。放进同一张表的函数，参数和返回值必须完全一致，这条警告不要放过。

### 第四步：让别人来调你的函数

命令表里，是 `dispatch` 在拨号。再看一个更常见的场景：标准库的 `qsort` 能给任何类型的数组排序，但它不知道你的元素是整数还是结构体，更不知道你想升序还是降序。所以它向你要一样东西：一个"比较两个元素"的函数的号码。

存成 `src/sortdemo.c`，末尾加 `add_demo(sortdemo)`：

```c
#include <stdio.h>
#include <stdlib.h>

static int g_calls = 0;   /* 数一数 qsort 回头调用了我们几次 */

/* qsort 规定的比较函数：a 该排在 b 前面返回负数，相等返回 0，排在后面返回正数。
 * 参数是 const void *，因为 qsort 不知道元素是什么类型。 */
static int cmp_asc(const void *a, const void *b) {
    int x = *(const int *)a;
    int y = *(const int *)b;
    g_calls++;
    /* 不要写 return x - y：两数相差很大时减法本身会溢出 */
    return (x > y) - (x < y);
}

/* 降序：把两个参数换个位置交给 cmp_asc 就行 */
static int cmp_desc(const void *a, const void *b) {
    return cmp_asc(b, a);
}

static void print_arr(const char *title, const int *a, size_t n) {
    printf("%s:", title);
    for (size_t i = 0; i < n; i++) {
        printf(" %d", a[i]);
    }
    printf("\n");
}

int main(void) {
    int data[] = { 42, 7, 19, -3, 100, 0 };
    size_t n = sizeof(data) / sizeof(data[0]);

    print_arr("raw ", data, n);

    qsort(data, n, sizeof(data[0]), cmp_asc);
    print_arr("asc ", data, n);
    printf("cmp_asc was called %d times\n", g_calls);

    qsort(data, n, sizeof(data[0]), cmp_desc);
    print_arr("desc", data, n);
    return 0;
}
```

> [!question] 先猜一猜
> `main` 里一次也没有写过 `cmp_asc(...)` 这样的调用。那 `cmp_asc` 会被执行吗？如果会，是谁调的，执行几次？

> [!success]- 揭晓
> 会执行，是 `qsort` 在排序过程中反复回头调用它。我这台机器上排 6 个数调了 15 次；次数取决于 C 库怎么实现排序，你的数字可能不同。

构建并运行 `./build/sortdemo`，我这台机器上的输出：

```
raw : 42 7 19 -3 100 0
asc : -3 0 7 19 42 100
cmp_asc was called 15 times
desc: 100 42 19 7 0 -3
```

> [!example] 探针：只改一行
> 把 `cmp_asc` 里的 `(x > y) - (x < y)` 改成 `(x < y) - (x > y)`，其余一个字不动，重新构建并运行。
> `asc` 那一行会变成降序，`desc` 那一行变成升序。排序的人（`qsort`）没变，变的只是你交给它的那个号码背后的规则。

现在可以给这种写法起名字了：把函数的号码交给别人，让别人在合适的时候回头调用你，叫**回调**（callback）。`cmp_asc` 是 `qsort` 的回调。命令表是同样的思路：`dispatch` 不认识任何一条具体命令，它只拨表里的号码。

### 第五步：函数表就是接口

回头看命令表。每一行里的 `fn`，其实是一份约定：收 `(int argc, char *argv[])`，返回 `int`。`dispatch` 只认这份约定，不认识任何具体命令。这样一份"只规定能做什么，不规定怎么做"的约定，有个名字，叫**接口**。把接口做成一张函数指针表，是 C 里把"做什么"和"怎么做"分开的常用办法。

再看一张只有一个格子的表。点亮一盏 LED，在电脑上可以打印一行字，在板子上要去写引脚。上层逻辑不该关心这些。存成 `src/iface.c`，末尾加 `add_demo(iface)`：

```c
#include <stdio.h>

/* 接口：一张只有一个格子的函数表。
 * 上层只知道"LED 能被设成亮或灭"，不知道怎么做到。
 * name 表示"哪一盏灯"，板子上它会变成引脚。 */
typedef struct {
    void (*write)(const char *name, int on);
} led_ops_t;

/* 实现一：往屏幕上打印文字 */
static void write_console(const char *name, int on) {
    printf("[console] %s %s\n", name, on ? "ON" : "OFF");
}

/* 实现二：只输出 1 和 0，方便别的程序读 */
static void write_bits(const char *name, int on) {
    (void)name;
    printf("%d\n", on ? 1 : 0);
}

static const led_ops_t g_console_ops = { write_console };
static const led_ops_t g_bits_ops    = { write_bits };

/* 应用代码：闪两下。它只认识 led_ops_t，不认识任何具体实现。 */
static void blink_twice(const led_ops_t *ops, const char *name) {
    ops->write(name, 1);
    ops->write(name, 0);
    ops->write(name, 1);
    ops->write(name, 0);
}

int main(void) {
    blink_twice(&g_console_ops, "LED1");
    blink_twice(&g_bits_ops, "LED1");
    return 0;
}
```

> [!question] 先猜一猜
> `blink_twice` 里的四个调用一个字也没变。两次调用 `blink_twice`，输出会一样吗？

> [!success]- 揭晓
> 构建并运行 `./build/iface`，输出是：
>
> ```
> [console] LED1 ON
> [console] LED1 OFF
> [console] LED1 ON
> [console] LED1 OFF
> 1
> 0
> 1
> 0
> ```
>
> 不一样。`blink_twice` 只认识 `led_ops_t` 这份接口，你递哪张表，它就用哪种做法。同一份应用代码，换实现，只换表，上层一个字不改。

`name` 表示"哪一盏灯"。在电脑上它只是个名字，到了板子上它会变成引脚。1.9 的 LED 就用这样一张表，到了板子上，只要把电脑版的实现换成调用 HAL 的版本，上层的逻辑一行不用动。

## 刚才发生了什么

函数名在表达式里，一般就代表这个函数的地址。函数指针里存的就是这个地址。通过它调用函数，叫[[【原理】函数指针与间接调用|间接调用]]：跳到哪里，要到运行的时候才知道。

为什么放进同一张表的函数，签名必须一致？因为调用的一方只知道"这是一个收 `(int, char *[])`、返回 `int` 的函数"，它就按这个约定放参数、取返回值。对不上，轻则警告，重则运行时乱套。

回调带来的是分工。写排序的人不需要知道你的数据长什么样，你也不需要自己写排序；写 `dispatch` 的人不需要认识任何命令，你加命令也不需要动 `dispatch`。双方只约定一件事：那个函数的签名。

到了板子上，这个思路会反复出现。芯片的[[【原理】中断与NVIC|中断向量表]]，本质上就是一张存着函数号码的表：哪个中断来了，就拨表里对应的号码。5.1 我们会细讲。

再往前走一步。如果一个结构体里既放数据（这盏灯现在亮不亮），又放一个指向函数表的指针（这盏灯怎么点亮），那每个对象就自带一份"操作手册"，上层拿着对象就能用，不必知道背后是什么硬件。这个思路叫[[【拓展】函数指针与虚表|虚表]]，1.9 的 `led_t` 就是这样做的。C++ 的虚函数，就是编译器替你造并维护这样一张表。写起来省事，也带来隐藏的开销和风险。本教程主线只用 C，未来会有专门的 C++ 篇，想先看一眼的，见 [[【拓展】C++入门与嵌入式C++|C++入门与嵌入式C++]]。接口、函数表这些做法为什么能让代码复用，见 [[【原理】C语言里的面向对象|C语言里的面向对象]]。

回头看开头那道题：`p == say_hi` 为什么是 1？因为函数名本来就是号码，`p` 只是把它抄了一份。通讯录那句"号码换了，只改一行"，在代码里就是命令表：加命令，只加一行。

## 记住这几条

1. 函数指针的声明要带括号：`int (*fn)(int, char *[])`。类型太长就用 `typedef` 起个短名。
2. 放进同一张表的函数，参数和返回值必须完全一致。编译器的 `incompatible pointer type` 警告不要放过。
3. 调用函数指针之前，确认它不是 `NULL`。空函数指针一调就崩：PC 上是段错误，板子上通常是 HardFault。
4. 命令表是真数组时，用 `sizeof(a) / sizeof(a[0])` 算行数；传进函数后算不出来，要另外传个数。
5. `qsort` 的比较函数返回负数、0、正数。不要用 `return x - y`，两数相差很大时减法本身会溢出。
6. 想给程序加功能时，先问一句：能不能只加一行表项？
7. **函数表就是接口**：上层代码只依赖函数的签名，不依赖具体实现。想换实现，只换表，不改上层。

## 练习

1. 把 `fp2.c` 里的 `typedef` 去掉，直接写 `int (*op)(int, int)` 和 `int (*ops[])(int, int)`，让它仍然能编译运行。感受一下 `typedef` 省了什么。（复现）
2. 定义 `reading_t`（一个字符串名字加一个整数值），建一个有四项的数组，先按名字排序，再按数值从大到小排序，都用 `qsort`。（改造）
3. 下面这段程序，请先写下预测：会输出什么？程序会正常结束吗？（预测）
   ```c
   #include <stdio.h>

   int main(void) {
       void (*p)(void) = NULL;
       printf("before\n");
       fflush(stdout);
       p();
       printf("after\n");
       return 0;
   }
   ```

> [!success]- 提示与答案
> **1.** 完整写法如下，注意 `apply` 的参数和 `ops` 数组的声明：
>
> ```c
> #include <stdio.h>
>
> static int add(int a, int b) { return a + b; }
> static int sub(int a, int b) { return a - b; }
> static int mul(int a, int b) { return a * b; }
>
> /* 不用 typedef：每个地方都得把整串类型写全 */
> static int apply(int (*op)(int, int), int a, int b) {
>     return op(a, b);
> }
>
> int main(void) {
>     int (*ops[])(int, int) = { add, sub, mul };
>     for (int i = 0; i < 3; i++) {
>         printf("%d\n", apply(ops[i], 6, 3));
>     }
>     return 0;
> }
> ```
>
> 每个用到这个类型的地方都得把整串写全，这就是 `typedef` 省下的力气。
>
> **2.** 比较函数里取出两个元素的指针，按名字用 `strcmp`，按数值用大小比较：
>
> ```c
> #include <stdio.h>
> #include <stdlib.h>
> #include <string.h>
>
> typedef struct {
>     const char *name;
>     int value;
> } reading_t;
>
> static int cmp_by_name(const void *a, const void *b) {
>     const reading_t *x = a;
>     const reading_t *y = b;
>     return strcmp(x->name, y->name);
> }
>
> static int cmp_by_value_desc(const void *a, const void *b) {
>     const reading_t *x = a;
>     const reading_t *y = b;
>     return (y->value > x->value) - (y->value < x->value);
> }
>
> static void show(const reading_t *r, size_t n) {
>     for (size_t i = 0; i < n; i++) {
>         printf("%s=%d ", r[i].name, r[i].value);
>     }
>     printf("\n");
> }
>
> int main(void) {
>     reading_t r[] = { {"temp", 25}, {"humi", 60}, {"light", 300}, {"co2", 410} };
>     size_t n = sizeof(r) / sizeof(r[0]);
>
>     qsort(r, n, sizeof(r[0]), cmp_by_name);
>     show(r, n);
>     qsort(r, n, sizeof(r[0]), cmp_by_value_desc);
>     show(r, n);
>     return 0;
> }
> ```
>
> 我这台机器上的输出：
> ```
> co2=410 humi=60 light=300 temp=25
> co2=410 light=300 humi=60 temp=25
> ```
>
> **3.** 先输出 `before`，然后程序崩溃，`after` 不会出现。我这台机器上 bash 报 `Segmentation fault`。`fflush` 是为了让 `before` 在崩溃前真正写出来。板子上同样的事故通常表现为 HardFault，3.2 会教你认这个现场。
