> 1. 读代码预测：`can_node_filter_mask(&g_can, 0x100u, 0x7F0u);` 之后，ID 为 0x10A、0x110、0x0FF 的帧各会不会被收到？
> 2. 用列表过滤器只想收两个 ID，另外两个空位该填什么？为什么不能填 0？
> 3. 一个节点连续发送失败，每次失败发送错误计数 TEC 加 8。从 0 开始，失败几次进入被动错误？几次进入总线关闭？
> 4. `HAL_CAN_ErrorCallback()` 是在中断里被调用的。为什么我们只在里面记标志，把日志放到主循环里打？
>
> > [!success]- 答案，以及跳过后要带走的东西
> > 1. 0x10A 会，0x110 和 0x0FF 不会。掩码 0x7F0 的意思是高 7 位必须一致，低 4 位不管，放行 0x100 到 0x10F。
> > 2. 重复填第一个 ID。填 0 的话，ID 0x000 会被意外放行（它还是优先级最高的 ID）。
> > 3. 16 次（TEC = 128，超过 127，进入被动错误）；32 次（TEC = 256，超过 255，进入总线关闭）。
> > 4. 3.1 的规矩：中断里不输出、不阻塞。回调只把标志存进对象，主循环里的 `can_node_poll()` 取走标志再调用你登记的 `on_err`。
> >
> > **带走清单**：
> > - 文件：本节「第二步」的 `can_node.h` 和 `can_node.c` 终版，**直接覆盖 7.1 的同名文件**（`User/Inc/can_node.h`、`User/Src/can_node.c`，CMake 已经收着它们，不用重新配置），接口向下兼容。`can_msg.h` 不变。
> > - CubeMX：在 7.1 的基础上再勾 `CAN1 SCE interrupt`；Automatic Bus-Off Management 看你想用哪种恢复方式（见「第七步」）。
> > - 代码：「第三步」里的 `on_can_err()` 是一个可以直接复用的错误回调，7.4 会再用一次。
> > - 规矩：过滤器组共 14 个可用；列表模式空位重复填第一个 ID；错误回调在中断里，只记标志。

## 先看一个怪现象

过滤器像一只只听和自己有关的话的耳朵。总线上说什么的都有，你不需要每句都听。

先看一个让人不安的现象。你在回环模式下依次发七个 ID：0x0FF、0x100、0x105、0x10F、0x110、0x200、0x7E0，接收端配了一个过滤器。串口里发送七行，接收只出现几行，没有警告，没有错误，没有丢失计数。

> [!question] 先猜一猜
> 过滤器配的是"id = 0x100，mask = 0x7F0"。这七个 ID 里，哪几个会被收到？

> [!success]- 揭晓
> 0x100、0x105、0x10F 三个会被收到，其余四个悄悄被丢弃。下面我们会算出来，再在板子上验证。

## 动手做

### 第一步：掩码和列表，先在纸面上算一遍

bxCAN 的过滤器有两种模式：

- **掩码模式**：给一个"过滤 ID"和一个"掩码"。掩码里为 1 的位，来的 ID 必须和过滤 ID 一致；掩码为 0 的位，不管。
- **列表模式**：给一张 ID 清单，来的 ID 必须和清单里某一个完全相同。

把"id = 0x100，mask = 0x7F0"展开：0x7F0 = 111 1111 0000，高 7 位必须和 0x100 的高 7 位一致，低 4 位随便。这恰好放行 0x100 到 0x10F。

写一个 PC 小工具，用同样的规则判断，顺便把要填进 HAL 的字段值算出来：

```c
#include <stdio.h>

/* 掩码过滤器的判断规则：掩码里为 1 的位，来的 ID 必须和过滤器 ID 一致；为 0 的位不管。 */
static int mask_pass(unsigned rx_id, unsigned filter_id, unsigned mask) {
    return ((rx_id ^ filter_id) & mask) == 0U;
}

/* 列表过滤器：来的 ID 必须和列表里某一项完全相同 */
static int list_pass(unsigned rx_id, const unsigned *ids, unsigned n) {
    for (unsigned i = 0; i < n; i++) {
        if (rx_id == ids[i]) {
            return 1;
        }
    }
    return 0;
}

int main(void) {
    const unsigned tests[] = { 0x0FFU, 0x100U, 0x105U, 0x10FU, 0x110U, 0x200U, 0x7E0U };
    const unsigned list[] = { 0x100U, 0x200U, 0x7E0U };
    const unsigned fid = 0x100U, mask = 0x7F0U;

    printf("mask filter: id=0x%03X mask=0x%03X\n", fid, mask);
    printf("list filter: 0x100 0x200 0x7E0\n\n");
    printf("rx_id  mask  list\n");
    for (unsigned i = 0; i < sizeof tests / sizeof tests[0]; i++) {
        printf("0x%03X  %-4s  %-4s\n", tests[i],
               mask_pass(tests[i], fid, mask) ? "pass" : "drop",
               list_pass(tests[i], list, 3U) ? "pass" : "drop");
    }

    /* 寄存器里怎么摆：标准 ID 放在 32 位寄存器的高 11 位，也就是高半字的 [15:5] */
    printf("\n32-bit mask mode, HAL fields:\n");
    printf("  FilterIdHigh     = 0x%04X\n", (fid & 0x7FFU) << 5);
    printf("  FilterIdLow      = 0x%04X\n", 0U);
    printf("  FilterMaskIdHigh = 0x%04X\n", (mask & 0x7FFU) << 5);
    printf("  FilterMaskIdLow  = 0x%04X\n", 0x0006U);   /* IDE 位和 RTR 位都要求为 0 */

    /* 16 位列表模式：4 个 ID，每个放在 16 位的 [15:5]。HAL 字段的对应关系见正文。 */
    printf("\n16-bit list mode, HAL fields:\n");
    printf("  FilterIdLow      = 0x%04X\n", (list[0] & 0x7FFU) << 5);
    printf("  FilterMaskIdLow  = 0x%04X\n", (list[1] & 0x7FFU) << 5);
    printf("  FilterIdHigh     = 0x%04X\n", (list[2] & 0x7FFU) << 5);
    printf("  FilterMaskIdHigh = 0x%04X   (unused slot: repeat list[0])\n", (list[0] & 0x7FFU) << 5);
    return 0;
}
```

```
0x10F  pass  drop

  FilterMaskIdLow  = 0x4000

```

上半部分回答了开头的问题：掩码过滤器放行 0x100、0x105、0x10F。下半部分是 HAL 要的字段值：标准 ID 在 32 位寄存器里占最高 11 位，所以要左移 5 位放进高半字；`FilterMaskIdLow = 0x0006` 是把 IDE 位和 RTR 位也纳入比较，要求它们都是 0，也就是只放行标准数据帧。

列表模式在 16 位刻度下，一个过滤器组能放 4 个 ID，HAL 的四个字段依次是 `FilterIdLow`、`FilterMaskIdLow`、`FilterIdHigh`、`FilterMaskIdHigh`，名字叫"Mask"但此时放的是 ID。用不满 4 个时，空位重复填第一个 ID：

> [!example] 探针：空位填 0 会怎样
> 想一想：如果空位填 0，ID 0x000 的帧会通过吗？
> 会。0 在列表里就是一个合法的 ID，0x000 恰好是优先级最高的那个。这就是列表过滤器里"重复填第一个 ID"的原因。

### 第二步：can_node 终版

把 7.1 的 `can_node.h` 和 `can_node.c` 用下面两份**整个覆盖**。接口向下兼容，7.1、7.2 的代码不用改。新增的部分都标了 `[7.3 新增]`。

`can_node.h`：

```c
#ifndef CAN_NODE_H
#define CAN_NODE_H

#include "main.h"          /* 带进来 HAL 和 CAN_HandleTypeDef */
#include "can_msg.h"

#define CAN_NODE_RXQ_LEN    16u   /* 软件接收队列的深度，必须是 2 的幂 */
#define CAN_NODE_MAX_BANKS  14u   /* CAN1 可用的过滤器组数（SlaveStartFilterBank 设为 14） */

/* 收到一帧时被调用。它在 can_node_poll() 里被调用，也就是在主循环里，不在中断里，
 * 所以回调里可以放心 LOG()。 */
typedef void (*can_rx_fn)(void *ctx, const can_msg_t *msg);

/* 总线出问题时被调用，同样在 can_node_poll() 里。flags 是 HAL_CAN_ERROR_xxx 的组合。 */
typedef void (*can_err_fn)(void *ctx, uint32_t flags);

/* CAN 节点对象：把 HAL 的 CAN_HandleTypeDef 再包一层，加上接收队列、计数和回调。 */
typedef struct {
    /* ---- 配置：init 之后基本不变 ---- */
    CAN_HandleTypeDef *hcan;        /* 背后的 HAL 对象，例如 &hcan1 */
    can_rx_fn          on_rx;       /* 收到帧时的回调，可以是 NULL */
    void              *on_rx_ctx;   /* 回调的第一个参数，用来带上"谁在用我" */
    can_err_fn         on_err;      /* [7.3 新增] 出错时的回调，可以是 NULL */
    void              *on_err_ctx;  /* [7.3 新增] */
    uint8_t            next_bank;   /* 下一个空闲的过滤器组，每配一个过滤器加一 */

    /* ---- 接收队列：中断只写 rx_head，主循环只写 rx_tail ---- */
    can_msg_t          rxq[CAN_NODE_RXQ_LEN];
    volatile uint32_t  rx_head;
    volatile uint32_t  rx_tail;

    /* ---- 中断记下的错误标志，主循环取走并清零 ---- */
    volatile uint32_t  err_flags;   /* [7.3 新增] */

    /* ---- 计数，只读，别直接改 ---- */
    volatile uint32_t  tx_req;      /* 成功排进发送邮箱的帧数 */
    volatile uint32_t  tx_done;     /* 硬件确认发完的帧数 */
    volatile uint32_t  tx_full;     /* 三个邮箱都满，发送被拒绝的次数 */
    volatile uint32_t  rx_cnt;      /* 放进接收队列的帧数 */
    volatile uint32_t  rx_drop;     /* 接收队列已满，被丢掉的帧数 */
} can_node_t;

/* 初始化对象，并把它登记起来，好让 HAL 的全局回调能找到它。
 * 必须在 MX_CAN1_Init() 之后调用。 */
void can_node_init(can_node_t *n, CAN_HandleTypeDef *hcan);

/* 设置回调。 */
void can_node_set_rx_handler(can_node_t *n, can_rx_fn fn, void *ctx);
void can_node_set_err_handler(can_node_t *n, can_err_fn fn, void *ctx);   /* [7.3 新增] */

/* ---- 过滤器：都返回 0 成功，-1 失败（参数不对或过滤器组用完了）----
 * 每调用一次占用一个过滤器组。不配任何过滤器，就收不到任何帧。 */
int can_node_filter_all(can_node_t *n);                                       /* 全收 */
int can_node_filter_mask(can_node_t *n, uint16_t id, uint16_t mask);          /* [7.3 新增] 掩码模式 */
int can_node_filter_list(can_node_t *n, const uint16_t *ids, uint8_t count);  /* [7.3 新增] 列表模式，count 为 1..4 */

/* 启动 CAN 外设并打开中断。返回 0 成功，-1 失败。 */
int can_node_start(can_node_t *n);

/* 发送一帧标准数据帧。
 * 返回 0：已排进发送邮箱（不代表已经发出去）；-1：参数错误；-2：三个邮箱都满。 */
int can_node_send(can_node_t *n, uint16_t id, const uint8_t *data, uint8_t len);

/* 在主循环里反复调用：取出收到的帧，逐帧调用 on_rx；有错误标志就调用 on_err。 */
void can_node_poll(can_node_t *n);

/* ---- 总线状态 [7.3 新增] ----
 * HAL 没有提供读错误计数的函数，这里直接读状态寄存器 ESR（本教程唯一一处）。
 * 发送错误计数 TEC 只返回低 8 位：TEC 超过 255 就是 bus-off，此时这个值没有意义。 */
uint32_t can_node_tec(const can_node_t *n);
uint32_t can_node_rec(const can_node_t *n);
int      can_node_is_bus_off(const can_node_t *n);

/* 手动恢复：停一下再启动。只在没开 AutoBusOff 时需要；不能在中断里调用。 */
int can_node_recover(can_node_t *n);                                          /* [7.3 新增] */

#endif /* CAN_NODE_H */
```

`can_node.c`：

```c
#include "can_node.h"
#include <string.h>

#define RXQ_MASK  (CAN_NODE_RXQ_LEN - 1u)

/* 编译期检查：队列深度不是 2 的幂就让数组长度变成负数，编译不过 */
typedef char rxq_len_must_be_power_of_two[((CAN_NODE_RXQ_LEN & (CAN_NODE_RXQ_LEN - 1u)) == 0u) ? 1 : -1];

/* ---------- 登记表 ----------
 * HAL 的回调是全局函数，参数里只有 CAN_HandleTypeDef *。
 * 要从它找回对应的 can_node_t，就靠这张表。表是本文件私有的（static）。 */
#define CAN_NODE_MAX_INSTANCES  2u
static can_node_t *s_nodes[CAN_NODE_MAX_INSTANCES];

static can_node_t *find_node(const CAN_HandleTypeDef *hcan)
{
    for (uint32_t i = 0; i < CAN_NODE_MAX_INSTANCES; i++) {
        if (s_nodes[i] != NULL && s_nodes[i]->hcan == hcan) {
            return s_nodes[i];
        }
    }
    return NULL;
}

void can_node_init(can_node_t *n, CAN_HandleTypeDef *hcan)
{
    memset(n, 0, sizeof *n);
    n->hcan = hcan;

    for (uint32_t i = 0; i < CAN_NODE_MAX_INSTANCES; i++) {
        if (s_nodes[i] == NULL || s_nodes[i]->hcan == hcan) {
            s_nodes[i] = n;
            break;
        }
    }
}

void can_node_set_rx_handler(can_node_t *n, can_rx_fn fn, void *ctx)
{
    n->on_rx = fn;
    n->on_rx_ctx = ctx;
}

void can_node_set_err_handler(can_node_t *n, can_err_fn fn, void *ctx)   /* [7.3 新增] */
{
    n->on_err = fn;
    n->on_err_ctx = ctx;
}

/* ---------- 过滤器 ---------- */
static int config_filter(can_node_t *n,
                         uint32_t id_hi, uint32_t id_lo,
                         uint32_t mk_hi, uint32_t mk_lo,
                         uint32_t mode, uint32_t scale)
{
    CAN_FilterTypeDef f;

    if (n->next_bank >= CAN_NODE_MAX_BANKS) {
        return -1;                                   /* 过滤器组用完了 */
    }
    memset(&f, 0, sizeof f);
    f.FilterIdHigh         = id_hi;
    f.FilterIdLow          = id_lo;
    f.FilterMaskIdHigh     = mk_hi;
    f.FilterMaskIdLow      = mk_lo;
    f.FilterFIFOAssignment = CAN_FILTER_FIFO0;
    f.FilterBank           = n->next_bank;
    f.FilterMode           = mode;
    f.FilterScale          = scale;
    f.FilterActivation     = CAN_FILTER_ENABLE;
    f.SlaveStartFilterBank = CAN_NODE_MAX_BANKS;     /* 0..13 归 CAN1，14.. 归 CAN2 */

    if (HAL_CAN_ConfigFilter(n->hcan, &f) != HAL_OK) {
        return -1;
    }
    n->next_bank++;
    return 0;
}

int can_node_filter_all(can_node_t *n)
{
    /* 32 位掩码模式，ID 和掩码全 0：每一位都"不关心"，什么帧都放行 */
    return config_filter(n, 0u, 0u, 0u, 0u, CAN_FILTERMODE_IDMASK, CAN_FILTERSCALE_32BIT);
}

/* [7.3 新增] 掩码模式：(收到的 ID ^ id) & mask 为 0 才放行。
 * 32 位寄存器里，标准 ID 放在最高 11 位，所以要左移 5 位放进高半字。
 * 低半字的 0x0006 把 IDE 位和 RTR 位也纳入比较，且要求它们为 0，即只放行标准数据帧。 */
int can_node_filter_mask(can_node_t *n, uint16_t id, uint16_t mask)
{
    return config_filter(n,
                         ((uint32_t)id   & 0x7FFu) << 5, 0u,
                         ((uint32_t)mask & 0x7FFu) << 5, 0x0006u,
                         CAN_FILTERMODE_IDMASK, CAN_FILTERSCALE_32BIT);
}

/* [7.3 新增] 列表模式：16 位刻度下一个过滤器组能放 4 个 ID，收到的 ID 必须和其中之一完全相同。
 * HAL 的四个字段在 16 位列表模式下依次是：IdLow、MaskIdLow、IdHigh、MaskIdHigh。
 * 用不满 4 个时，空位要重复填第一个 ID。填 0 的话，ID 0x000 会被意外放行。 */
int can_node_filter_list(can_node_t *n, const uint16_t *ids, uint8_t count)
{
    uint32_t slot[4];

    if (ids == NULL || count == 0u || count > 4u) {
        return -1;
    }
    for (uint32_t i = 0; i < 4u; i++) {
        uint16_t v = (i < count) ? ids[i] : ids[0];
        if (v > 0x7FFu) {
            return -1;
        }
        slot[i] = (uint32_t)v << 5;                  /* 16 位刻度下，标准 ID 在 [15:5] */
    }
    return config_filter(n, slot[2], slot[0], slot[3], slot[1],
                         CAN_FILTERMODE_IDLIST, CAN_FILTERSCALE_16BIT);
}

/* ---------- 启动 ---------- */
static int enable_irqs(can_node_t *n)
{
    uint32_t its = CAN_IT_RX_FIFO0_MSG_PENDING    /* 收到帧 */
                 | CAN_IT_TX_MAILBOX_EMPTY        /* 某个邮箱发完了 */
                 | CAN_IT_RX_FIFO0_OVERRUN        /* [7.3 新增] 硬件接收 FIFO 溢出 */
                 | CAN_IT_ERROR                   /* [7.3 新增] 错误中断的总开关，下面三个都要先开它 */
                 | CAN_IT_ERROR_WARNING           /* [7.3 新增] 错误计数达到警告线 */
                 | CAN_IT_ERROR_PASSIVE           /* [7.3 新增] 进入被动错误状态 */
                 | CAN_IT_BUSOFF;                 /* [7.3 新增] 总线关闭 */
    return (HAL_CAN_ActivateNotification(n->hcan, its) == HAL_OK) ? 0 : -1;
}

int can_node_start(can_node_t *n)
{
    if (HAL_CAN_Start(n->hcan) != HAL_OK) {
        return -1;
    }
    return enable_irqs(n);
}

/* ---------- 发送 ---------- */
int can_node_send(can_node_t *n, uint16_t id, const uint8_t *data, uint8_t len)
{
    CAN_TxHeaderTypeDef h;
    uint8_t buf[8] = { 0 };       /* HAL_CAN_AddTxMessage 总是读 8 个字节，所以缓冲必须有 8 字节 */
    uint32_t mailbox;

    if (id > 0x7FFu || len > 8u || (len > 0u && data == NULL)) {
        return -1;
    }
    if (HAL_CAN_GetTxMailboxesFreeLevel(n->hcan) == 0u) {
        n->tx_full++;
        return -2;
    }

    memset(&h, 0, sizeof h);
    h.StdId = id;
    h.IDE   = CAN_ID_STD;
    h.RTR   = CAN_RTR_DATA;
    h.DLC   = len;
    h.TransmitGlobalTime = DISABLE;
    if (len > 0u) {
        memcpy(buf, data, len);
    }

    if (HAL_CAN_AddTxMessage(n->hcan, &h, buf, &mailbox) != HAL_OK) {
        return -1;
    }
    n->tx_req++;
    return 0;
}

/* ---------- 接收：中断里入队，主循环里出队 ---------- */
static void rxq_push(can_node_t *n, uint16_t id, uint8_t dlc, const uint8_t *d)
{
    uint32_t head = n->rx_head;

    if ((head - n->rx_tail) >= CAN_NODE_RXQ_LEN) {
        n->rx_drop++;                                /* 队列满：丢掉，并记一笔 */
        return;
    }
    can_msg_t *m = &n->rxq[head & RXQ_MASK];
    m->id  = id;
    m->dlc = dlc;
    memcpy(m->data, d, dlc);
    __DMB();                                         /* 先把帧写完整，再挪 head */
    n->rx_head = head + 1u;
    n->rx_cnt++;
}

/* HAL 在 FIFO0 里有帧时调用它（在中断里）。整个工程只能有一份这个函数。 */
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    can_node_t *n = find_node(hcan);
    CAN_RxHeaderTypeDef h;
    uint8_t d[8];

    if (n == NULL) {
        return;
    }
    while (HAL_CAN_GetRxFifoFillLevel(hcan, CAN_RX_FIFO0) > 0u) {
        if (HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0, &h, d) != HAL_OK) {
            break;
        }
        if (h.IDE != CAN_ID_STD || h.RTR != CAN_RTR_DATA) {
            continue;                                /* 本教程只处理标准数据帧 */
        }
        rxq_push(n, (uint16_t)h.StdId, (h.DLC > 8u) ? 8u : (uint8_t)h.DLC, d);
    }
}

void can_node_poll(can_node_t *n)
{
    while (n->rx_tail != n->rx_head) {
        can_msg_t m = n->rxq[n->rx_tail & RXQ_MASK];   /* 先拷出来 */
        __DMB();
        n->rx_tail = n->rx_tail + 1u;                  /* 再还回这个格子 */
        if (n->on_rx != NULL) {
            n->on_rx(n->on_rx_ctx, &m);
        }
    }

    /* [7.3 新增] 取走中断记下的错误标志。中断也会改它，所以取走并清零这两步要关中断。 */
    uint32_t primask = __get_PRIMASK();
    __disable_irq();
    uint32_t flags = n->err_flags;
    n->err_flags = 0u;
    __set_PRIMASK(primask);

    if (flags != 0u && n->on_err != NULL) {
        n->on_err(n->on_err_ctx, flags);
    }
}

/* ---------- 发送完成：三个邮箱各有一个回调，都只做一件事 ---------- */
static void tx_done_hook(CAN_HandleTypeDef *hcan)
{
    can_node_t *n = find_node(hcan);
    if (n != NULL) {
        n->tx_done++;
    }
}

void HAL_CAN_TxMailbox0CompleteCallback(CAN_HandleTypeDef *hcan) { tx_done_hook(hcan); }
void HAL_CAN_TxMailbox1CompleteCallback(CAN_HandleTypeDef *hcan) { tx_done_hook(hcan); }
void HAL_CAN_TxMailbox2CompleteCallback(CAN_HandleTypeDef *hcan) { tx_done_hook(hcan); }

/* ---------- [7.3 新增] 错误处理 ---------- */

/* HAL 在出错时调用它（在中断里）。这里只做一件事：把标志记下来，让主循环去处理。
 * HAL 的 ErrorCode 是只增不减的，所以取走后要 ResetError，下次才看得出新的错误。
 * 整个工程只能有一份这个函数。 */
void HAL_CAN_ErrorCallback(CAN_HandleTypeDef *hcan)
{
    can_node_t *n = find_node(hcan);
    uint32_t e = HAL_CAN_GetError(hcan);

    (void)HAL_CAN_ResetError(hcan);
    if (n != NULL) {
        n->err_flags |= e;
    }
}

uint32_t can_node_tec(const can_node_t *n)
{
    return (n->hcan->Instance->ESR & CAN_ESR_TEC) >> CAN_ESR_TEC_Pos;
}

uint32_t can_node_rec(const can_node_t *n)
{
    return (n->hcan->Instance->ESR & CAN_ESR_REC) >> CAN_ESR_REC_Pos;
}

int can_node_is_bus_off(const can_node_t *n)
{
    return (n->hcan->Instance->ESR & CAN_ESR_BOFF) != 0u;
}

int can_node_recover(can_node_t *n)
{
    if (HAL_CAN_Stop(n->hcan) != HAL_OK) {
        return -1;
    }
    return can_node_start(n);          /* 重新启动，硬件会先等总线空闲再回到总线上 */
}
```

新增的内容可以分四组看：

- **两个过滤器函数**，用 `config_filter()` 统一填 HAL 结构体。每调用一次占用一个过滤器组，对象里的 `next_bank` 记着用到第几个了。CAN1 可用 14 个组，组数用完返回 -1。
- **错误回调**。`HAL_CAN_ErrorCallback()` 在中断里，只把错误标志或进对象的 `err_flags`；`can_node_poll()` 在主循环里取走标志，调用你登记的 `on_err`。取走标志时关一下中断，因为中断也会改它（5.4 的临界区）。
- **状态查询**。HAL 没有提供读错误计数的函数，所以 `can_node_tec()` 和 `can_node_rec()` 直接读状态寄存器 `ESR`，这是本教程里唯一一处。TEC 只有低 8 位，bus-off 时它没有意义。
- **手动恢复**。`can_node_recover()` 先停再启，用于没开 AutoBusOff 的情况。它会等待外设应答，不能在中断里调用。

CubeMX 里还要做一处：NVIC Settings 再勾上 `CAN1 SCE interrupt`，错误中断走这一路。Automatic Bus-Off Management 先保持 Disable，「第七步」再对比两种恢复方式。

### 第五步：错误计数与三种状态

过滤器管"听什么"，下面这部分管"说错了怎么办"。

CAN 的每个节点里有两个计数器：**发送错误计数 TEC** 和 **接收错误计数 REC**。规则简化后是：

| 事件 | 变化 |
|---|---|
| 发送时出错 | TEC 加 8 |
| 接收时出错 | REC 加 1 |
| 成功发出一帧 | TEC 减 1 |
| 成功收到一帧 | REC 减 1（大于 0 时） |

靠这两个数，节点自己判断自己的健康状况：

| 状态 | 条件 | 行为 |
|---|---|---|
| 错误主动（Error Active） | TEC 和 REC 都不超过 127 | 正常工作，发现错误会发出会影响全网的主动错误标志 |
| 错误警告 | 任一计数达到 96 | 仍然正常，只是提醒（HAL 里是 EWG） |
| 错误被动（Error Passive） | 任一计数超过 127 | 只发不影响别人的被动错误标志，发送也变得更克制 |
| 总线关闭（Bus-Off） | TEC 超过 255 | 节点自己脱离总线，不收也不发 |

> [!question] 先猜一猜
> 一个节点每次发送都失败，TEC 每次加 8，从 0 开始。失败几次进入被动错误？几次进入总线关闭？

> [!success]- 揭晓
> 8 × 16 = 128，超过 127，所以 16 次失败进入被动错误。8 × 32 = 256，超过 255，所以 32 次失败进入总线关闭。
> 一帧失败后如果开了自动重发，下一次尝试就在几十到一百多位之后，所以 32 次失败只需要很短的时间。

把这套机制想成会议室的规矩：一个节点说错话的次数越多，计数越高。到警戒线先提醒，过了线就收敛一些，再过线就被"请出会议室"。它保护的是别的节点，一个坏节点不会无休止地用错误帧搅乱整条总线。

不过有一个例外要知道。如果总线上**只有你一个节点**，没有任何人对你的帧回应答，发送方会不断收到应答错误。按 CAN 错误计数规则，错误被动发送者遇到 ACK 错误，且发送被动错误标志期间没有检测到显性位时，TEC 不因这次错误继续增加。因此“只有缺 ACK、没有其他错误”的孤立节点可停在错误被动，而非必然 bus-off；出现其他位错误时结论会改变。详见[CAN 错误状态机](/notes/can-error-states)引用的 Bosch CAN 2.0 错误限制规则。

### 第六步：看见错误

下面三个实验需要 Normal 模式，并且接了收发器。它们都是按协议规则推演的结果，作者没有上板，**以你的实测为准**。

先在 CubeMX 里把 Operating Mode 改成 Normal，再在 `main.c` 里沿用第三步的代码（面板每秒打印 TEC、REC）。

**实验 1：总线上只有你一个节点。** 接好收发器，什么也不连。预测：

- `tx_done` 不增长，`tx_req` 增长到 3 之后不再增长。
- TEC 以 8 为步长往上走，到 96 附近出现 `error warning`，超过 127 出现 `error passive`，停在 128，不再继续。
- 不会出现 `bus-off`。

**实验 2：两块板，波特率故意不一致。** 一块保持 500 kbit/s，另一块把 CubeMX 里的 Prescaler 改成 12，也就是 250 kbit/s。预测：两边的错误计数都会上升，面板里 TEC、REC 不再是 0。具体停在哪个状态，与双方谁先进入被动状态有关，这里不下结论。

**实验 3（有条件的读者再做）：制造总线关闭。** 如果你的板子上 MCU 的 CAN_TX 到收发器 TXD 之间是可以拔掉的跳线，发送期间把它拔掉。预测：MCU 发出显性位，但读回来是隐性，每次都是位错误，TEC 每次加 8，32 次之后进入总线关闭，日志里出现 `can: bus-off`。这个实验涉及动手拔线，不方便就跳过。

> [!example] 探针：打开"最后一个错误码"中断
> 在 `can_node.c` 的 `enable_irqs()` 里，给 `its` 加上 `CAN_IT_LAST_ERROR_CODE`，重新构建。
> 实验 1 里，每次重发失败都会触发一次，日志里会出现大量 `flags=0x20`（应答错误）。这类中断来得非常频繁，所以我们默认不开它。看完记得去掉。

### 第七步：从总线关闭里回来

总线关闭之后，节点怎么回到总线上？有两种办法，CubeMX 里一个开关决定：

| Automatic Bus-Off Management | 谁来恢复 | 怎么恢复 |
|---|---|---|
| Enable | 硬件 | 观察到 128 次各含 11 个连续隐性位的序列后恢复；不是要求 1408 位始终连成一串。500 kbit/s 持续空闲时最低计数时间为 2.816 ms，并非实际墙钟恢复时间的保证 |
| Disable | 软件 | 你的代码发现 bus-off 后调用 `can_node_recover()`（停一下再启动），硬件同样要等上面的那段时间 |

第三步里的 `on_can_err()` 已经把两种情况都写好了：它先打印状态，再判断 `n->hcan->Init.AutoBusOff`，没开自动的话就自己恢复。这正是把配置放在对象里的好处：回调靠对象自己就能知道该怎么做，不需要再多传一个开关。

两种办法各试一遍：先用 Disable，做实验 3，日志里应该依次看到 `can: bus-off`、`can: manual recovery`；再改成 Enable，日志里只有 `can: bus-off`，没有 `manual recovery`，节点自己回来。

无论哪种，恢复只是让节点回到总线上，**根因还在**。如果故障没排除，它会很快又掉下去。所以不要在回调里不断重试，记日志，报给上层，必要时降级。

## 刚才发生了什么

两件事，都是"硬件替你做，软件只负责知道"。

- **过滤器在硬件里判断**。不在名单上的帧，CPU 一次也不会被打扰。该收什么，是你在启动时用 `can_node_filter_xxx()` 告诉硬件的，不是收到之后再用 `if` 判断。
- **错误状态在硬件里转换**。计数、升降级、自己闭嘴，全是外设自动完成。软件做的只是通过错误中断得知，再决定要不要恢复、要不要报警。

HAL 里把这两件事的入口放得有点零散：过滤器要 `HAL_CAN_ConfigFilter()`，错误要 `HAL_CAN_ActivateNotification()` 加 `HAL_CAN_ErrorCallback()`。我们把它们包进了 `can_node_t`，以后别的代码只和对象打交道。

错误状态机的完整细节，包括每个状态下的行为差异，放在[[【原理】CAN错误状态机|CAN 错误状态机]]里。

回头看开头那道题：发七个 ID 只收到三个，没有任何提示。现在你知道不是丢了，是过滤器在硬件里把另外四个拒了。

## 记住这几条

1. 不配过滤器收不到；配错了默默丢，不报错。"收不到"先查过滤器。
2. 掩码模式：掩码里为 1 的位必须一致。列表模式：必须完全相同。列表有空位，重复填第一个 ID，不要填 0。
3. 过滤器由硬件执行，被拒绝的帧不触发中断。
4. TEC 超过 127 进入被动错误，超过 255 进入总线关闭；发送失败一次加 8。
5. `HAL_CAN_ErrorCallback()` 在中断里，只记标志，日志在主循环里打。
6. 想让节点自动回来，开 AutoBusOff；不开就自己调 `can_node_recover()`。恢复了也要查根因。
7. 错误中断可能非常频繁，回调要极短；最后一个错误码的中断默认不开。

## 练习

1. 用掩码过滤器跑通回环实验，对照 `filter_sim` 的 mask 列，确认哪几个 ID 被收到。（复现）
2. 想只收 0x200 到 0x2FF，过滤 ID 和掩码各填多少？算出对应的 `FilterIdHigh` 和 `FilterMaskIdHigh`。（改造）
3. 一个节点 TEC 是 0，连续 20 次发送失败，每次加 8，没有成功过。它现在处于哪个状态？（预测）

> [!success]- 提示与答案方向
> 1. 0x100、0x105、0x10F 被收到，0x0FF、0x110、0x200、0x7E0 被丢弃。
> 2. id = 0x200，mask = 0x700（高 3 位必须一致，低 8 位不管）。`FilterIdHigh` = 0x200 << 5 = 0x4000，`FilterMaskIdHigh` = 0x700 << 5 = 0xE000。
> 3. 20 × 8 = 160，超过 127、没超过 255，处于被动错误，还没有到总线关闭。再失败 12 次就是 256。
