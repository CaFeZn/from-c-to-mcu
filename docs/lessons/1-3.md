> 1. 下面这段程序打印 `yes` 还是 `no`？
>    ```c
>    int a = -1;
>    unsigned b = 1;
>    if (a < b) { puts("yes"); } else { puts("no"); }
>    ```
> 2. `uint8_t a = 200, b = 100;` 之后，`printf("%d", a + b);` 打印多少？
> 3. 写出两条语句：把 `uint8_t` 变量 `x` 的第 5 位置 1，再把第 2 位清 0。
> 4. 这个判断有什么问题？`if ((x & (1u << 3)) == 1) { /* 第 3 位是 1 */ }`
>
> > [!success]- 答案，以及跳过后要带走的东西
> > 1. `no`。`int` 和 `unsigned` 比较时，-1 被当成无符号数，变成 4294967295。
> > 2. 300。`a + b` 在 `int` 里算，不会回绕；存回 `uint8_t` 才会变成 44。
> > 3. `x |= 1u << 5;` 和 `x &= ~(1u << 2);`
> > 4. 第 3 位为 1 时，`x & (1u << 3)` 的结果是 8，不是 1，所以条件永远为假。应写 `if (x & (1u << 3))`。
> >
> > **带走清单**：下面这套位操作宏（本节 `bits.c` 的上半部分，原样复制即可；1.8 会学到怎么把它们放进头文件），后面讲寄存器和标志位时会沿用这套写法。
> > ```c
> > #define BIT(n)           (1u << (n))
> > #define BIT_SET(x, n)    ((x) |=  BIT(n))
> > #define BIT_CLR(x, n)    ((x) &= ~BIT(n))
> > #define BIT_TOG(x, n)    ((x) ^=  BIT(n))
> > #define BIT_GET(x, n)    (((x) >> (n)) & 1u)
> > ```
> > 约定：位号从 0 数起，掩码写 `1u << n`，存数据和寄存器值用 `uint8_t` / `uint16_t` / `uint32_t`；算经过的时间用"现在 减 起点"。STM32 的头文件里自带 `SET_BIT` 等宏，收的是掩码不是位号，别混用。

### 第一步：一排开关，两本说明书

一个 8 位的变量，就是一排 8 个开关。每个开关叫一个**位**（bit），只有开（1）和关（0）两种状态。8 个位凑成 1 **字节**。

一排 0 和 1 太长，写起来费眼。所以大家改用**十六进制**：一个十六进制数字，正好对应 4 个开关，权重从左到右是 8、4、2、1。以 `0xA5` 为例（开头的 `0x` 表示十六进制）：

- A 是 10，等于 8 + 2，对应开关 `1010`
- 5 等于 4 + 1，对应开关 `0101`
- 所以 `0xA5` 就是 `1010 0101`

这个换算以后每次都要用，现在多看两眼。

> [!question] 先猜一猜
> 开关 `1111 1111`，按无符号读是 255。按有符号的 `int8_t` 读，是多少？
> 再猜一个：`1000 0000` 呢？

下面的程序把几排开关分别用两种读法读出来（存成 `src/readings.c`，加 `add_demo(readings)`，构建并运行；运行方式同 1.2：`cmake --build build`，再 `./build/readings`）。里面的 `print_bin8` 函数是 1.4 的内容，现在照抄使用即可。

```c
#include <stdio.h>
#include <stdint.h>

/* 把 8 位数从高位到低位打印成 0 和 1。函数下一节细讲，现在照抄使用即可 */
void print_bin8(uint8_t v) {
    for (int i = 7; i >= 0; i--) {
        putchar(((v >> i) & 1) ? '1' : '0');
        if (i == 4) {
            putchar(' ');      /* 中间空一格，好读 */
        }
    }
}

/* 同一串比特，分别按无符号和有符号读一遍 */
void show(uint8_t v) {
    printf("  ");
    print_bin8(v);
    printf("%10u%8d\n", v, (int8_t)v);
}

int main(void) {
    printf("  %-9s%10s%8s\n", "bits", "unsigned", "signed");
    show(0x00);
    show(0x01);
    show(0x7F);
    show(0x80);
    show(0xFF);

    printf("\nsize and range on this machine:\n");
    printf("int8_t   %lu byte  %ld .. %ld\n",
           (unsigned long)sizeof(int8_t), (long)INT8_MIN, (long)INT8_MAX);
    printf("uint8_t  %lu byte  0 .. %lu\n",
           (unsigned long)sizeof(uint8_t), (unsigned long)UINT8_MAX);
    printf("int16_t  %lu byte  %ld .. %ld\n",
           (unsigned long)sizeof(int16_t), (long)INT16_MIN, (long)INT16_MAX);
    printf("uint16_t %lu byte  0 .. %lu\n",
           (unsigned long)sizeof(uint16_t), (unsigned long)UINT16_MAX);
    printf("int32_t  %lu byte  %ld .. %ld\n",
           (unsigned long)sizeof(int32_t), (long)INT32_MIN, (long)INT32_MAX);
    printf("uint32_t %lu byte  0 .. %lu\n",
           (unsigned long)sizeof(uint32_t), (unsigned long)UINT32_MAX);

    printf("\nint is %lu byte(s), long is %lu byte(s)\n",
           (unsigned long)sizeof(int), (unsigned long)sizeof(long));
    return 0;
}
```

你应该看到：

```
  bits       unsigned  signed
  0000 0000         0       0
  0000 0001         1       1
  0111 1111       127     127
  1000 0000       128    -128
  1111 1111       255      -1

size and range on this machine:
int8_t   1 byte  -128 .. 127
uint8_t  1 byte  0 .. 255
int16_t  2 byte  -32768 .. 32767
uint16_t 2 byte  0 .. 65535
int32_t  4 byte  -2147483648 .. 2147483647
uint32_t 4 byte  0 .. 4294967295

int is 4 byte(s), long is 4 byte(s)
```

> [!example] 我这台机器上的结果（Windows，MinGW gcc 6.3.0；`int` 和 `long` 的宽度换平台可能不同）

> [!success]- 揭晓
> `1111 1111` 按有符号读是 -1，`1000 0000` 是 -128。开关一个都没动，变的是读法：无符号那本说明书读出 255，有符号那本读出 -1。
> 有符号的读法叫**补码**，规则放在 [[【原理】补码与整型转换|补码与整型转换]] 里。现在只需要记住：8 位有符号数的范围是 -128 到 127，最高位是 1 就是负数。
> 另外，`(int8_t)v` 这一步，C 标准把结果交给编译器决定。gcc 等主流编译器都按上面的方式读。

下半截输出，就是 `stdint.h` 里这些类型的全家福。名字里直接写着宽度：

| 类型 | 字节 | 范围 | 常见用途 |
|---|---|---|---|
| `uint8_t` | 1 | 0 到 255 | 一个字节的数据、一排 8 个开关 |
| `int8_t` | 1 | -128 到 127 | 小范围的带符号数 |
| `uint16_t` | 2 | 0 到 65535 | ADC 读数、两字节的数据 |
| `int16_t` | 2 | -32768 到 32767 | 传感器的带符号读数 |
| `uint32_t` | 4 | 0 到 4294967295 | 32 位寄存器、毫秒计数 |
| `int32_t` | 4 | -2147483648 到 2147483647 | 较大的带符号数 |

为什么不直接用 `int`？因为 `int` 到底几位，由编译器和平台决定。我用 arm-none-eabi-gcc 做了编译期检查。它是在电脑上编译、给 ARM 单片机用的编译器，这种做法叫[[【原理】交叉编译与工具链|交叉编译]]，2.2 会亲手用。在这套 STM32 常用的工具链上，`int` 是 4 字节，`short` 是 2，`long` 是 4，`long long` 是 8。换一个平台，数字就可能不同，而你的代码如果依赖 `int` 的宽度，就会悄悄出错。`stdint.h` 的这些类型把宽度写进了名字，走到哪里都一样。

### 第二步：谁被当成了大数

把开头那段程序存成 `src/cmp0.c`，加 `add_demo(cmp0)`，构建并运行。构建时留意输出，gcc 会说话：

```
cmake --build build
./build/cmp0
```

> [!success]- 揭晓
> 打印 `a >= b`。-1 不比 1 小？构建时 gcc 还会警告：`comparison between signed and unsigned integer expressions`。

有一个很自然的猜想，用现象检验一下：

> [!failure] 猜想 1：编译器比大小的功能有毛病
> 如果它不会比大小，换成别的类型也应该出错。我们换换看。

把比较扩成三组，同样是"-1 对 1"（存成 `src/cmp.c`，加 `add_demo(cmp)`，构建并运行）：

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    int      a = -1;
    unsigned b = 1;

    if (a < b) {
        printf("a < b\n");
    } else {
        printf("a >= b\n");
    }
    printf("a read as unsigned = %u\n", (unsigned)a);

    /* 探针：把两边换成窄类型 */
    int8_t  x = -1;
    uint8_t y = 1;
    if (x < y) {
        printf("x < y\n");
    } else {
        printf("x >= y\n");
    }

    /* 再换成 32 位的一对 */
    int32_t  p = -1;
    uint32_t q = 1;
    if (p < q) {
        printf("p < q\n");
    } else {
        printf("p >= q\n");
    }
    return 0;
}
```

你应该看到：

```
a >= b
a read as unsigned = 4294967295
x < y
p >= q
```

> [!example] 编译时 gcc 在第 8 行和第 27 行各给了一条 `-Wsign-compare` 警告，也就是 `int` 对 `unsigned`、`int32_t` 对 `uint32_t` 那两组。8 位的那组没有警告，结果也是对的。

猜想 1 被划掉了：8 位这一组比得好好的。区别在宽度。规则其实只有两条：

1. **比 `int` 窄的类型（8 位、16 位），一进运算就先升格成 `int`。** 所以 `x < y` 比的是 -1 和 1 这两个 `int`，结果正常。
2. **`int` 和 `unsigned` 同台时，有符号的一方被当成无符号。** -1 的开关是 32 个 1，按无符号读就是 4294967295，当然比 1 大。

第一条叫**整型提升**，第二条叫**常用算术转换**。名字不用背，记住现象：窄的安全，宽的危险；混着比，有符号的会变成大数。

这个坑在单片机里很常见。比如 `uint32_t len`，写 `if (len - 10 < 0)`：无符号数减出来永远不会小于 0，这个判断永远为假，而且没有报错。

### 第三步：六个位运算符

前面的 `&&`、`||` 把整个数当作一个真假。位运算符不一样，它们逐位操作，每个开关各算各的：

| 运算符 | 名字 | 规则 |
|---|---|---|
| `&` | 与 | 两位都是 1，结果才是 1 |
| `\|` | 或 | 两位有一个是 1，结果就是 1 |
| `^` | 异或 | 两位不同，结果才是 1 |
| `~` | 取反 | 0 变 1，1 变 0 |
| `<<` | 左移 | 整排开关往高位挪，低位补 0 |
| `>>` | 右移 | 整排开关往低位挪 |

左移 n 位，只要没移出格子，就相当于乘以 2 的 n 次方；无符号数右移 n 位，相当于除以 2 的 n 次方（向下取整）。负数右移，结果由编译器决定，别这么写。

> [!question] 先猜一猜
> 下面的程序里，`a` 是 `0xA5`，`~a` 打印出来是 `0101 1010`，也就是 `0x5A`。程序最后有个 `if (~a == 0x5A)`，它会走哪个分支？

```c
#include <stdio.h>
#include <stdint.h>

/* 把 8 位数从高位到低位打印成 0 和 1。函数下一节细讲，现在照抄使用即可 */
void print_bin8(uint8_t v) {
    for (int i = 7; i >= 0; i--) {
        putchar(((v >> i) & 1) ? '1' : '0');
        if (i == 4) {
            putchar(' ');      /* 中间空一格，好读 */
        }
    }
}

int main(void) {
    uint8_t a = 0xA5;      /* 1010 0101 */
    uint8_t b = 0x0F;      /* 0000 1111 */

    printf("a      = "); print_bin8(a);      printf("\n");
    printf("b      = "); print_bin8(b);      printf("\n");
    printf("a & b  = "); print_bin8(a & b);  printf("\n");
    printf("a | b  = "); print_bin8(a | b);  printf("\n");
    printf("a ^ b  = "); print_bin8(a ^ b);  printf("\n");
    printf("~a     = "); print_bin8(~a);     printf("\n");
    printf("a << 1 = "); print_bin8(a << 1); printf("\n");
    printf("a >> 2 = "); print_bin8(a >> 2); printf("\n");

    /* 探针：~a 真的等于 0x5A 吗？ */
    printf("~a printed as a whole number: 0x%X\n", ~a);
    if (~a == 0x5A) {
        printf("~a == 0x5A\n");
    } else {
        printf("~a != 0x5A\n");
    }
    return 0;
}
```

存成 `src/bitops.c`，加 `add_demo(bitops)`，构建并运行：

```
cmake --build build
./build/bitops
```

你应该看到：

```
a      = 1010 0101
b      = 0000 1111
a & b  = 0000 0101
a | b  = 1010 1111
a ^ b  = 1010 1010
~a     = 0101 1010
a << 1 = 0100 1010
a >> 2 = 0010 1001
~a printed as a whole number: 0xFFFFFF5A
~a != 0x5A
```

> [!success]- 揭晓
> 走 `!=` 那一支。`~a` 在运算时已经升格成 32 位的 `int`，32 个开关全部取反，成了 `0xFFFFFF5A`。`print_bin8` 的参数只有 8 位，接收时把高位截掉了，所以打印出来才像 `0x5A`。
> 这和 1.2 里的 `level + 1 = 256` 是同一回事：算的时候宽，存的时候窄。
> 要比较，就先把它存回原类型的变量：`uint8_t na = (uint8_t)~a;`，再拿 `na` 去比。我试过，`na == 0x5A` 成立，编译也没有警告。

### 第四步：四件套

寄存器操作，说到底就是四个动作：把某一位置成 1，把某一位清成 0，把某一位翻个面，看某一位是几。

套路是先造一个**掩码**：只有第 n 位是 1，其余全是 0。然后：

| 动作 | 写法 | 为什么这样 |
|---|---|---|
| 置位 | `x \| mask` | 或 1 一定得 1，或 0 不改变原值 |
| 清位 | `x & ~mask` | 取反后的掩码只有第 n 位是 0，与 0 得 0，与 1 不改变 |
| 翻转 | `x ^ mask` | 异或 1 翻面，异或 0 不动 |
| 取位 | `(x >> n) & 1` | 先把第 n 位挪到最低位，再把其他位清掉 |

做成四个宏，再配一排"8 盏灯"来看效果：

```c
#include <stdio.h>
#include <stdint.h>

/* 位操作四件套。n 是位号，从 0 开始数，最低位是第 0 位 */
#define BIT(n)           (1u << (n))              /* 只有第 n 位是 1 的掩码 */
#define BIT_SET(x, n)    ((x) |=  BIT(n))         /* 置位：第 n 位变 1 */
#define BIT_CLR(x, n)    ((x) &= ~BIT(n))         /* 清位：第 n 位变 0 */
#define BIT_TOG(x, n)    ((x) ^=  BIT(n))         /* 翻转：0 变 1，1 变 0 */
#define BIT_GET(x, n)    (((x) >> (n)) & 1u)      /* 取位：得到 0 或 1 */

/* 把 8 位数从高位到低位打印成 0 和 1。函数下一节细讲，现在照抄使用即可 */
void print_bin8(uint8_t v) {
    for (int i = 7; i >= 0; i--) {
        putchar(((v >> i) & 1) ? '1' : '0');
        if (i == 4) {
            putchar(' ');      /* 中间空一格，好读 */
        }
    }
}

/* 把 8 个"灯"画出来：亮是 *，灭是 . */
void show(const char *what, uint8_t port) {
    printf("%-10s", what);
    for (int i = 7; i >= 0; i--) {
        putchar(BIT_GET(port, i) ? '*' : '.');
    }
    printf("   ");
    print_bin8(port);
    printf("   0x%02X\n", port);
}

int main(void) {
    uint8_t port = 0;                 /* 8 盏灯，全灭 */
    show("start", port);

    BIT_SET(port, 0);   show("set 0", port);
    BIT_SET(port, 3);   show("set 3", port);
    BIT_SET(port, 7);   show("set 7", port);
    BIT_TOG(port, 3);   show("toggle 3", port);
    BIT_TOG(port, 3);   show("toggle 3", port);
    BIT_CLR(port, 0);   show("clear 0", port);

    printf("\nbit 7 is %u, bit 0 is %u\n", BIT_GET(port, 7), BIT_GET(port, 0));

    /* 探针：直接用 & 取位，得到的是什么？ */
    printf("port & BIT(3) = %u\n", port & BIT(3));
    printf("BIT_GET(port, 3) = %u\n", BIT_GET(port, 3));
    return 0;
}
```

存成 `src/bits.c`，加 `add_demo(bits)`，构建并运行：

```
cmake --build build
./build/bits
```

你应该看到：

```
start     ........   0000 0000   0x00
set 0     .......*   0000 0001   0x01
set 3     ....*..*   0000 1001   0x09
set 7     *...*..*   1000 1001   0x89
toggle 3  *......*   1000 0001   0x81
toggle 3  *...*..*   1000 1001   0x89
clear 0   *...*...   1000 1000   0x88

bit 7 is 1, bit 0 is 0
port & BIT(3) = 8
BIT_GET(port, 3) = 1
```

几个细节：

- 位号从 0 开始数，最低位是第 0 位。
- 掩码写 `1u << n`，不写 `1 << n`。有符号的 `1` 左移到最高位，结果是未定义行为，`1u` 没有这个问题。
- **探针**：最后两行，同样是看第 3 位，直接 `port & BIT(3)` 得到的是 8，而 `BIT_GET` 得到 1。所以判断某一位是不是 1，写 `if (port & BIT(3))`，别写 `== 1`，否则永远为假。
- 一次操作多个位也可以：`port |= BIT(1) | BIT(4);`。

> [!warning] 名字撞车预警
> STM32 的头文件里，自带 `SET_BIT`、`CLEAR_BIT`、`READ_BIT` 三个宏。它们的用法是 `SET_BIT(寄存器, 掩码)`，收的是**掩码**，不是位号。我把本节的宏取名为 `BIT_SET` 等，就是为了不和它们重名。第 2 章遇到它们时，别把位号当掩码传。

### 第五步：回绕有时是朋友

最后一个小实验（存成 `src/elapsed.c`，加 `add_demo(elapsed)`）。1.2 里我们把回绕当成事故，但它有时反而能帮忙。

> [!question] 先猜一猜
> 一个 8 位的计数器，开始计时时读数是 250。过了一会儿，它数过 255、回绕到 0，又数到 4。现在用 `现在 - 起点` 算经过了多少个计数，答案会是 -246 吗？

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint8_t start = 250;   /* 开始计时时，8 位计数器读数是 250 */
    uint8_t now   = 4;     /* 数过了 255，回绕到 0，又数到 4 */

    uint8_t elapsed = (uint8_t)(now - start);   /* 无符号减法，结果仍是 8 位 */
    printf("elapsed = %u\n", elapsed);
    return 0;
}
```

> [!success]- 揭晓
> ```
> elapsed = 10
> ```
> 减法在 `int` 里算，得到 -246，转回 `uint8_t` 时又回绕一圈，加上 256，正好是 10。起点和现在各回绕了一次，抵消掉了。
> 这个套路在第 5 章会反复用到：用毫秒计数器计时，永远用 `现在 - 起点` 算经过的时间，计数器回绕了结果也不会错。

## 刚才发生了什么

同一排开关，读法是由类型决定的。比较和运算时，如果两边读法不一致，编译器会替你统一，方向是往无符号靠，这就是 -1 变成 4294967295 的原因。

位运算四件套，可以背成一句话：点亮用或，熄灭用与非，翻转用异或，查看先右移再与一。

这些在板子上长什么样？第 2 章的**寄存器**，就是一排 32 个开关，每个开关管硬件的一件事。手册上写"第 5 位置 1 表示……"，你要做的就是对第 5 位置位。这些内容放在 [[【原理】寄存器与内存映射|寄存器与内存映射]] 里。

即使你一直用 HAL 库，位运算也躲不掉。HAL 经常把一堆状态拼在同一个数里，用不同的位表示不同的情况，你要用 `&` 来查：

```c
#include "main.h"

/* 示意：HAL 用不同的位表示不同的串口错误，几种错误可以同时出现 */
void uart_error_demo(void) {
    uint32_t err = HAL_UART_GetError(&huart1);

    if (err & HAL_UART_ERROR_ORE) {
        /* 溢出错误：数据来得太快，来不及取走 */
    }
    if (err & HAL_UART_ERROR_FE) {
        /* 帧错误：常见原因是两边波特率对不上 */
    }
}
```

这段在后面的串口章节会正式用到，现在只需要看懂 `err & 某个位` 这个写法。

现在回头看开头那道题。`int a = -1` 和 `unsigned b = 1` 放在一起比，-1 的 32 个开关被当成无符号读，变成 4294967295，所以 `a < b` 为假。你可以不查资料自己讲出来了。

## 记住这几条

1. **存数据、寄存器值、协议字节，一律用 `uint8_t` `uint16_t` `uint32_t` 这类带宽度的类型**。需要负数才用 `int8_t` 等。`int` 只留给不在乎宽度的小计数。
2. **有符号和无符号混着比较，有符号的一方会变成大数**。比较前先统一类型，别无视 `-Wsign-compare` 的警告。
3. **掩码写 `1u << n`**，不要写 `1 << n`。
4. **置位 `|`，清位 `& ~`，翻转 `^`，取位 `>> n` 再 `& 1`**。
5. **判断某一位是否为 1，写 `if (x & BIT(n))`**，不要写 `== 1`。
6. **对 8 位、16 位的数做 `~` 和 `<<`，结果已经升格成 `int`**。要比较时，先存回原类型的变量：`uint8_t na = (uint8_t)~a;`。

## 练习

1. （复现）改 `src/bits.c`：在 `main` 里写一个 `for` 循环，让 8 盏灯从第 0 位到第 7 位依次点亮，每亮一盏就 `show` 一次。
2. （改造）写一个宏 `FIELD_GET(x, pos, width)`：取出 `x` 里从第 `pos` 位开始、宽 `width` 位的字段。用 `0xA5` 测试，取第 4 到第 6 位，以及第 0 到第 1 位。
3. （预测）先手算，再写下预测，最后运行验证：
   - `0xA5` 翻转第 3 位和第 7 位，结果是多少？（不用计算器）
   - 下面这个程序打印什么？（存成 `src/u8_add.c`，加 `add_demo(u8_add)`）

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint8_t a = 200;
    uint8_t b = 100;

    printf("%d %d\n", a + b, (uint8_t)(a + b));
    printf("0x%02X\n", (uint8_t)(0xA5 ^ 0x88));
    return 0;
}
```

> [!success]- 提示与答案方向
> 1. 把 `BIT_SET(port, 0)` 那几行之前加上：
>    ```c
>    for (int i = 0; i < 8; i++) {
>        BIT_SET(port, i);
>        show("chase", port);
>    }
>    port = 0;
>    ```
>    会看到灯一盏一盏亮满，最后是 `0xFF`。
> 2. 参考写法（我编译运行过）：
>    ```c
>    #define FIELD_GET(x, pos, width)  (((x) >> (pos)) & ((1u << (width)) - 1u))
>    ```
>    先右移把字段挪到最低位，再用宽度为 `width` 的全 1 掩码截取。`0xA5` 的第 4 到第 6 位是 `010`，结果 2；第 0 到第 1 位是 `01`，结果 1。
> 3. `0xA5` 是 `1010 0101`，第 3 位权重 8，第 7 位权重 128，即 `0x88`。`1010 0101 ^ 1000 1000 = 0010 1101`，也就是 `0x2D`。程序打印 `300 44` 和 `0x2D`：`a + b` 在 `int` 里算，是 300；转回 `uint8_t` 装不下，300 减去 256 得 44。
