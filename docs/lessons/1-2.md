>    x += 10;
>    printf("%u %d %.1f\n", x, 7 / 2, 7 / 2.0);
>    ```
> 2. 下面的循环有什么问题？
>    ```c
>    for (uint8_t i = 3; i >= 0; i--) { /* ... */ }
>    ```

> > 3. 相同。不调用 `srand` 等同于 `srand(1)`，起点固定。
> > 4. 会接着执行下一个 `case` 里的代码（穿透）。
> >

## 先看一个怪现象

1980 年的街机游戏吃豆人有一个出名的"第 256 关"：玩到这里，屏幕右半边会变成一堆乱码，游戏再也过不去。据拆解分析，是画水果的那段代码在第 256 关发生了整数溢出（细节待核对）。

你不用玩到 256 关。几行代码，就能在自己电脑上造一个同款事故现场。

> [!question] 先猜一猜
> 下面这段程序里，`uint8_t` 先读作"一个 8 位的格子"，后面会细说。关卡数从 254 开始，连加三次，每次打印。三行输出各是什么？
> A. 255　256　257
> B. 255　0　1
> C. 打印 255 之后程序报错停下
> 先选一个，等会儿我们跑。

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint8_t level = 254;   /* 一个只有 8 位的格子 */

    level++;
    printf("%u\n", level);
    level++;
    printf("%u\n", level);
    level++;
    printf("%u\n", level);
    return 0;
}
```

## 动手做

### 第一步：认识整数的格子

先说格子，因为后面的事故全出在格子上。

从这一节起，所有例子都按 [[1.0_搭建环境]] 的约定运行：把代码存成 `src/名字.c`，在 `CMakeLists.txt` 末尾加一行 `add_demo(名字)`，然后构建并运行：

```
cmake --build build
./build/名字
```

Windows 命令提示符里第二条换成 `build\名字.exe`。后面不再重复，只告诉你名字。现在把下面的代码存成 `src/vars.c`，加 `add_demo(vars)`，构建并运行：

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    int      count = 42;       /* 普通整数，宽度由平台决定 */
    uint8_t  level = 200;      /* 8 位无符号整数，只能装 0..255 */
    uint32_t total = 70000;    /* 32 位无符号整数 */

    printf("count = %d, size = %lu byte(s)\n", count, (unsigned long)sizeof(count));
    printf("level = %u, size = %lu byte(s)\n", level, (unsigned long)sizeof(level));
    printf("total = %lu, size = %lu byte(s)\n",
           (unsigned long)total, (unsigned long)sizeof(total));
    return 0;
}
```

你应该看到：

```
count = 42, size = 4 byte(s)
level = 200, size = 1 byte(s)
total = 70000, size = 4 byte(s)
```

> [!example] 我这台机器上的结果（Windows，MinGW gcc 6.3.0；换平台后 `int` 的字节数可能不同）

- 每个变量都是"类型 名字 = 初值;"。你可以把它想成一个贴了标签的储物格：标签是名字，格子的大小由类型决定，里面放的是值。这就是**变量**和**类型**。
- `sizeof` 量出格子占几个字节。`level` 只占 1 字节，也就是 8 个二进制位。
- 格子的大小在声明那一刻就定了，之后不会变。记住这一点，后面用得上。
- 输出里我故意用了英文。终端对中文的支持因系统而异，第一节说过，乱码不是你写错了。

### 第二步：字符、小数和 const

整数之外，还有三样东西天天用：字符、小数、不许改的值。

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    const double VREF = 3.3;        /* const：声明之后不许再改 */
    char     letter = 'A';          /* 字符用单引号 */
    char     next   = letter + 1;   /* 字符是小整数，可以做加法 */
    float    f = 1.0f / 3.0f;       /* 单精度 */
    double   d = 1.0 / 3.0;         /* 双精度 */
    uint32_t big = 3000000000u;
    int      n = 42;

    printf("letter = %c, next = %c, next as number = %d\n", letter, next, next);
    printf("float : %.10f\n", f);
    printf("double: %.10f\n", d);
    printf("VREF = %.1f V\n", VREF);
    printf("hex: %x and %X\n", 255, 255);
    printf("[%5d] [%-5d] [%05d]\n", n, n, n);
    printf("big = %lu\n", (unsigned long)big);
    printf("%s, 100%%\n", "done");
    return 0;
}
```

存成 `src/types.c`，加 `add_demo(types)`，构建并运行：

你应该看到：

```
letter = A, next = B, next as number = 66
float : 0.3333333433
double: 0.3333333333
VREF = 3.3 V
hex: ff and FF
[   42] [42   ] [00042]
big = 3000000000
done, 100%
```

- **`char`**：装一个字符，用单引号写，如 `'A'`。它本质上是个 1 字节的小整数，所以可以做加法，`'A' + 1` 就是 `'B'`。整串文字（字符串）放到 1.5。
- **`float` 和 `double`**：装带小数的数。`float` 是单精度，约 7 位有效数字；`double` 是双精度，约 15 到 16 位。输出里同样是 1/3，`float` 在第 8 位就开始跑偏了。
- **`const`**：声明之后不许再改。试试在 `types.c` 里加一行 `VREF = 5.0;`，编译器会直接报 `assignment of read-only variable 'VREF'`。不该变的值加上 `const`，手滑改了立刻被发现。

> [!question] 先猜一猜
> 把 0.1 加十次，结果等于 1.0 吗？下面的程序存成 `src/fp.c`，加 `add_demo(fp)`，构建并运行就知道。

```c
#include <stdio.h>

int main(void) {
    double sum = 0.0;
    for (int i = 0; i < 10; i++) {
        sum += 0.1;               /* 加十次 0.1，理论上正好是 1 */
    }
    printf("sum == 1.0 ? %d\n", sum == 1.0);
    printf("sum = %.17g\n", sum);
    printf("0.1 = %.17g\n", 0.1);
    return 0;
}
```

> [!success]- 揭晓
> ```
> sum == 1.0 ? 0
> sum = 0.99999999999999989
> 0.1 = 0.10000000000000001
> ```
> 不等于。小数在内存里是二进制的近似值，0.1 本来就存不精确，加十次攒出一点误差。所以比较不同计算路径得到的近似量时，通常应按问题的误差预算判断，而不是要求 `==`；精确可表示的值、哨兵值或同一结果的复制则可能适合精确比较。

> [!note] 先打个预告：板子上对浮点要小心
> F407 这类芯片带有单精度浮点硬件，`double` 却要靠软件模拟，慢很多（以你的芯片手册和工程配置为准）。板上精简版的 `printf` 通常也不带 `%f`，第 3 章会遇到。所以很多单片机项目偏好用整数、定点数。这个话题放在 [[【拓展】浮点与定点|浮点与定点]]，现在只要知道有这回事。

`printf` 的格式，一次列全，对不上参数类型时 `-Wall` 会警告：

| 格式 | 打印什么 | 例子 |
|---|---|---|
| `%d` | 有符号整数 | `42` |
| `%u` | 无符号整数 | `200` |
| `%lu` | `unsigned long`，打印 `uint32_t` 时先强转成它 | `3000000000` |
| `%x` `%X` | 十六进制，小写 / 大写 | `ff` `FF` |
| `%c` | 一个字符 | `A` |
| `%s` | 一串文字 | `done` |
| `%f` `%.2f` | 小数，后者保留两位 | `3.30` |
| `%5d` `%-5d` `%05d` | 宽 5：右对齐 / 左对齐 / 补零 | `[   42]` `[42   ]` `[00042]` |
| `%%` | 百分号本身 | `%` |

后面板子上的日志（第 3 章）支持的，基本就是这里的 `%d %u %ld %lu %x %s %c`，不支持浮点。

### 第三步：运算符

> [!question] 先猜一猜
> `a` 是 7，`b` 是 2。`a / b` 等于几？`a / 2.0` 呢？
> 再猜：`-a / b` 和 `-a % b` 呢？
> 程序存成 `src/ops.c`，加 `add_demo(ops)`，构建并运行。

```c
#include <stdio.h>

int main(void) {
    int a = 7;
    int b = 2;

    printf("a / b   = %d\n", a / b);        /* 两个整数相除 */
    printf("a %% b   = %d\n", a % b);        /* 取余数 */
    printf("a / 2.0 = %.1f\n", a / 2.0);    /* 有一边是小数 */
    printf("-a / b  = %d\n", -a / b);
    printf("-a %% b  = %d\n", -a % b);

    printf("a > b: %d, a == b: %d\n", a > b, a == b);
    printf("(a > 5) && (b > 5): %d\n", (a > 5) && (b > 5));
    printf("(a > 5) || (b > 5): %d\n", (a > 5) || (b > 5));
    printf("!(a > 5): %d\n", !(a > 5));
    return 0;
}
```

> [!success]- 揭晓
> ```
> a / b   = 3
> a % b   = 1
> a / 2.0 = 3.5
> -a / b  = -3
> -a % b  = -1
> a > b: 1, a == b: 0
> (a > 5) && (b > 5): 0
> (a > 5) || (b > 5): 1
> !(a > 5): 0
> ```
> 两边都是整数，`/` 就做整数除法，小数部分直接丢掉，所以是 3。只要有一边是小数，才按小数算，所以是 3.5。`%` 取余数。负数的结果是向 0 靠拢的：-3 和 -1。

运算符分四类，先认识就够了：

| 种类 | 运算符 | 备注 |
|---|---|---|
| 算术 | `+` `-` `*` `/` `%` | 整数除法会丢小数 |
| 比较 | `==` `!=` `<` `>` `<=` `>=` | 结果只有 0 或 1 |
| 逻辑 | `&&`（并且）`\|\|`（或者）`!`（取反） | 0 是假，非 0 是真 |
| 赋值 | `=` `+=` `-=` `++` `--` | `x += 3` 就是 `x = x + 3` |

注意：判断相等写两个等号 `==`，一个等号 `=` 是赋值。把它写错是最常见的低级事故，`-Wall` 会替你盯着。

### 第四步：造事故现场

把开头那段代码存成 `src/wrap.c`，加 `add_demo(wrap)`，构建并运行：

```
cmake --build build
./build/wrap
```

你应该看到：

```
255
0
1
```

> [!success]- 揭晓
> 答案是 B。注意编译时没有任何警告，运行时也没有任何报错。

有两个很自然的猜想，用现象来检验一下：

> [!failure] 猜想 1：数太大了，程序会报错停下
> 编译零警告，运行不报错，三行照常打印。划掉。

> [!failure] 猜想 2：这一步算出了 256，只是显示成了 0
> 第一步量过，`level` 只占 1 字节，也就是 8 个二进制位。8 个位一共只能排出 256 种状态，刚好是 0 到 255。256 没有位置可放。划掉。

**探针**：把 `wrap.c` 里的 `uint8_t` 改成 `int`，再构建运行。你会看到 255、256、257。同样的代码，格子换大了，现象就消失了。事故不出在加法，出在格子的大小上。

再来一个探针，看看"算"和"存"是两回事（存成 `src/probe12.c`，加 `add_demo(probe12)`）：

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint8_t level = 255;
    printf("level + 1 = %d\n", level + 1);   /* 只算，不存 */
    level = level + 1;                          /* 存回 8 位格子 */
    printf("level     = %u\n", level);
    return 0;
}
```

```
level + 1 = 256
level     = 0
```

算的时候，结果是 256，没有任何问题。存回 8 位的格子时才装不下，多出来的部分被悄悄丢掉。到这里，这个现象可以起名字了：数超出格子能表示的范围，叫**溢出**。无符号整数数到顶、回到 0，也叫**回绕**。C 语言不会为此报任何信号，为什么这样设计，放在后面的分支里。

### 第五步：循环、判断和 switch

程序不会只顺着往下执行。它有三种走法：顺序、分支（`if`、`switch`）、循环（`for`、`while`）。

> [!question] 先猜一猜
> 用 `for` 把 1 加到 100，总和是 5050。如果装总和的格子只有 8 位，会得到多少？

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint8_t  small = 0;    /* 8 位的格子 */
    uint32_t big   = 0;    /* 32 位的格子 */

    /* for：事先知道要转几圈 */
    for (int i = 1; i <= 100; i++) {
        small += i;
        big   += i;
    }
    printf("1+2+...+100: uint8_t says %u, uint32_t says %lu\n",
           small, (unsigned long)big);

    /* while：不知道转几圈，只知道什么时候停 */
    int n = 0;
    int total = 0;
    while (total < 1000) {
        n++;
        total += n;
    }
    printf("sum reaches 1000 at n = %d (sum = %d)\n", n, total);

    /* continue 跳过本圈，break 直接离开循环 */
    for (int i = 1; i <= 10; i++) {
        if (i % 2 == 0) {
            continue;          /* 偶数不要 */
        }
        if (i > 7) {
            break;             /* 超过 7 就收工 */
        }
        printf("%d ", i);
    }
    printf("\n");

    /* switch：按一个整数或字符的值挑分支 */
    char cmd = 'b';
    switch (cmd) {
    case 'a':
        printf("command a\n");
        break;                 /* 没有 break，会接着执行下一个 case */
    case 'b':
    case 'c':                  /* b 和 c 共用这一段 */
        printf("command b or c\n");
        break;
    default:
        printf("unknown command\n");
        break;
    }
    return 0;
}
```

存成 `src/flow.c`，加 `add_demo(flow)`，构建并运行：

```
cmake --build build
./build/flow
```

你应该看到：

```
1+2+...+100: uint8_t says 186, uint32_t says 5050
sum reaches 1000 at n = 45 (sum = 1035)
1 3 5 7
command b or c
```

> [!success]- 揭晓
> 186。5050 除以 256 余 186：8 位的格子每装满一圈 256，就丢掉一圈，只留下余数。用 32 位的格子就没有这个问题。

这个程序里有这几样东西：

- `for (初始化; 继续条件; 每圈结束后做什么)`：事先知道要转几圈时用它。
- `while (条件)`：不知道转几圈，只知道什么时候停。循环体里一定要有能让条件改变的语句，否则永远停不下来。
- `if` / `else if` / `else`：按条件分支。
- `switch`：按一个整数或字符的值挑分支，适合"一个值对应一堆情况"，比如收到命令字符 `'a'`、`'b'`。每个 `case` 末尾都要写 `break`，`default` 处理其他情况。
- `continue` 跳过这一圈剩下的部分，`break` 直接离开整个循环（`switch` 里的 `break` 是离开 `switch`）。

**探针**：把 `cmd` 改成 `'a'`，再删掉 `case 'a'` 下面那行 `break;`，重新编译。输出会变成 `command a` 紧跟着 `command b or c`：没有 `break`，程序顺着掉进了下一个 `case`。这叫穿透，是 `switch` 最常见的事故。

### 第六步：猜数字小游戏

现在把格子、运算、循环合在一起。电脑想一个 1 到 100 的数，你来猜，每次它告诉你大了还是小了。

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

#define MAX_TRIES 7    /* 1..100 里每次猜中间，7 次一定够 */

int main(void) {
    srand((unsigned)time(NULL));          /* 用当前时间当起点 */
    int  secret = rand() % 100 + 1;       /* 1..100 里的一个数 */
    int  tries  = 0;
    int  guess;
    char line[32];                        /* 装一行输入的地方，1.5 节细讲 */

    printf("I picked a number from 1 to 100. You have %d tries.\n", MAX_TRIES);

    while (tries < MAX_TRIES) {
        printf("Try %d: ", tries + 1);
        fflush(stdout);                   /* 提示符没换行，手动刷新才能先看到它 */

        if (fgets(line, sizeof(line), stdin) == NULL) {   /* 输入被关掉了 */
            printf("\nInput closed. Bye.\n");
            return 1;
        }
        if (sscanf(line, "%d", &guess) != 1) {            /* 这一行不是数字 */
            printf("Please type a number.\n");
            continue;                     /* 不算一次机会 */
        }

        tries++;
        if (guess < secret) {
            printf("Too small.\n");
        } else if (guess > secret) {
            printf("Too big.\n");
        } else {
            printf("Correct! You used %d tries.\n", tries);
            return 0;
        }
    }

    printf("Out of tries. The number was %d.\n", secret);
    return 0;
}
```

存成 `src/guess.c`，加 `add_demo(guess)`，构建并运行：

```
cmake --build build
./build/guess
```

先看几个新东西：

- `rand()` 每次返回一个看起来随机的整数。`rand() % 100 + 1`：先取除以 100 的余数，得到 0 到 99，再加 1，就是 1 到 100。关于这个"随机"，有个藏得很深的反转，顺着这个[[【拓展】随机数与熵|彩蛋]]可以去看，也可以先往下做，第七步我们会遇到它。
- `srand(time(NULL))` 给 `rand()` 换一个起点。`time(NULL)` 返回当前时间，通常是从 1970 年 1 月 1 日起的秒数。
- **读一行输入**：`fgets(line, sizeof(line), stdin)` 把键盘上敲的一整行读进 `line`，返回 `NULL` 表示输入被关掉了。`char line[32]` 是能装 32 个字符的一排格子，1.5 再细讲；一行超过 31 个字符会被拆成两次读，这里先不管。
- **解析数字**：`sscanf(line, "%d", &guess)` 从那一行里取出一个整数，返回成功取到的个数，`!= 1` 就是"这行不是数字"。前面的 `&` 先照抄，1.5 讲指针时再解释。

那为什么不直接写 `scanf("%d", &guess)`？它更短，但碰到 `abc` 这种输入时，`abc` 会原封不动留在输入里，下一圈又读到它，一直失败，循环停不下来。先读整行、再从里面解析，出错时这一行已经被取走了。

`fflush(stdout)` 是因为提示符 `Try 1: ` 后面没有换行，不主动刷新的话，有些系统会先让你输入、后显示提示。

`MAX_TRIES` 定成 7 不是随便定的：每次猜剩余范围的中间值，一次砍掉一半，100 个数最多 7 次就能锁定。不信可以自己试一局。

> [!example] 我这台机器上的一局（秘密数字可能不同，你的过程也可能不一样）
> ```
> I picked a number from 1 to 100. You have 7 tries.
> Try 1: abc
> Please type a number.
> Try 1: 50
> Too small.
> Try 2: 75
> Too small.
> Try 3: 88
> Too big.
> Try 4: 81
> Too small.
> Try 5: 84
> Too small.
> Try 6: 86
> Correct! You used 6 tries.
> ```

注意第一行输入的 `abc`：程序没有崩，也没有扣次数。

### 第七步：把 srand 去掉

这是个小实验。先不看答案，想一想。

> [!question] 先猜一猜
> 把 `srand` 那一行删掉，只留下 `rand()`，在你的电脑上连续运行三次。三次打印出来的数字，一样还是不一样？

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    /* 故意不调用 srand */

}
```

存成 `src/rand_probe.c`，加 `add_demo(rand_probe)`，构建后连续运行三次：

```
cmake --build build
./build/rand_probe
./build/rand_probe
./build/rand_probe
```

> [!success]- 揭晓
> 三次一模一样。
> ```
> 41 18467 6334 26500 19169
> 41 18467 6334 26500 19169
> 41 18467 6334 26500 19169
> ```
> （我这台机器上的数字。换成 Linux 或 macOS，数字会不同，但同样是每次一样。）
> 很多人以为电脑上的随机数天生就是乱的，其实 C 标准规定，没调用过 `srand` 就等同于 `srand(1)`，起点固定，路也就固定。这是个反转，也是它在单片机上更要命的原因。详细的故事在 [[【拓展】随机数与熵|随机数与熵]] 里。

再对照一下加上 `srand(time(NULL))` 的版本（存成 `src/rand_time.c`，加 `add_demo(rand_time)`）：

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int main(void) {
    srand((unsigned)time(NULL));
    for (int i = 0; i < 5; i++) {
        printf("%d ", rand());
    }
    printf("\n");
    return 0;
}
```

每次运行之间隔一两秒，时间种子通常会改变，你可能看到不同的数字；有限范围仍可能碰巧重复：

```
20784 27440 3223 5851 13972
20787 5420 21088 29914 24286
20791 16169 6184 21209 1833
```

`time(NULL)` 的精度通常是秒，所以同一秒内启动两次，起点相同，数字也相同。

## 刚才发生了什么

**变量**是一块有名字、有大小的存储空间，**类型**决定它有多大、里面的比特该怎么读。格子在声明时就定了大小，不会因为你想装更大的数而自动变大。变量在内存里到底是什么样，放在 [[【原理】变量与内存|变量与内存]] 里。

**溢出**是 C 语言里一个很安静的事故：算出来的数装不进格子，就只保留装得下的那部分，不会有人通知你。无符号整数的表现是回绕：格子装满一圈，又从 0 开始数。有符号整数溢出要糟得多，1.3 会讲。

控制流只有三种形状：顺序、分支、循环。后面所有程序，包括单片机上的主循环，都是这三种的组合。

现在回头看开头那道题。吃豆人的关卡数装在一个 8 位的格子里，数到 255，再加一，格子里只剩 0。你现在可以用自己的话讲清楚了，也知道没有人会替你报警。

这件事在单片机上会反复出现。你以后会用计数器记时间，计数器的格子宽度决定了它多久回绕一次：8 位的数 256 次就回头；32 位的毫秒计数大约 49.7 天回头一次（2 的 32 次方毫秒）。选格子时多想一步，是写单片机程序的基本功。

## 记住这几条

1. **类型决定格子大小，C 不会在溢出时提醒你**。声明变量前先想它可能达到的最大值，格子装得下吗？无符号数做倒数循环尤其危险：`for (uint8_t i = 3; i >= 0; i--)` 永远不会结束，见练习 3。
2. **整数除法会丢掉小数**，想要小数结果至少让一边是小数。**近似浮点量的比较要结合误差预算**，不是一律禁用 `==`；详见[浮点与定点](/notes/float-fixed-point)。
3. **判断相等写 `==`**，一个等号是赋值。`c-lab` 的 `CMakeLists.txt` 已经开着 `-Wall -Wextra`，构建时它会提醒你"在判断里用了赋值"。
4. **`switch` 的每个 `case` 末尾写 `break`**，真的想穿透就写一行注释说明。
5. **不该变的值加 `const`**；每个 `while` 都要想好怎么停。
6. **读输入先用 `fgets` 读整行，再用 `sscanf` 解析**，别让一行坏输入把循环卡死。

## 练习

1. （复现）把 `src/wrap.c` 里的 `uint8_t` 换成 `uint16_t`，初值改成 65534，复现一次回绕。
2. （改造）给猜数字加功能：猜完一局（赢了或次数用完）后问一句 "Play again? (y/n)"，输入 y 就再来一局。
3. （预测）下面这段代码会打印什么？先写下预测，再构建运行。我加了 `count` 作保险，否则它真的会一直跑下去。存成 `src/countdown.c`，加 `add_demo(countdown)`。

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    int count = 0;
    for (uint8_t i = 3; i >= 0; i--) {
        printf("%u ", i);
        count++;
        if (count >= 8) {      /* 安全阀：防止真的跑不完 */
            break;
        }
    }
    printf("\n");
    return 0;
}
```

> [!success]- 提示与答案方向
> 1. 输出 65535、0、1。格子变成 16 位，回绕点从 255 搬到了 65535，现象不变。
> 2. 把 `main` 里除了 `srand` 以外的部分包进一个外层的 `while (1)`。每一局都要重新抽 `secret`、重置 `tries`。一局结束后：
>    ```c
>    printf("Play again? (y/n) ");
>    fflush(stdout);
>    if (fgets(line, sizeof(line), stdin) == NULL || line[0] != 'y') {
>        break;                   /* 不是 y 就结束 */
>    }
>    ```
>    （我编译运行过完整的改法。）
> 3. 输出 `3 2 1 0 255 254 253 252`。`i` 是无符号的，减到 0 再减一，回绕成 255，而 `i >= 0` 对无符号数永远为真，所以死循环。`-Wextra` 会警告 "comparison is always true due to limited range of data type"。改法：循环变量换成 `int`，或者改成 `i > 0` 并单独处理 0。
