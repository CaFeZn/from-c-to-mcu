# 7.4 CAN小节点

> **这一节你会做出**：按下这块板的按键，另一块板上 TIM3 输出的 PWM 占空比跟着变，灯一档一档变亮。同时你会把 GPIO、定时器、PWM、串口日志、CAN 全部串在一条路径上，并学会把"逻辑"和"硬件"分开写。

> > 4. `key: cmd sent`（按键，指令发出）、`cmd applied`（收到指令并执行）、`ack`（收到应答）。
> >

> > - 依赖：4.1 的 `key_obj_t`（`key_init`、`key_update`、`key_pressed`），5.2 的 `soft_due()` 和 `g_ms`，5.3 的 `pwm_t`（`pwm_init`、`pwm_start`、`pwm_set_duty`，配置是 TIM3 通道 1、PSC = 83、ARR = 999），3.1 的 `LOG()`，7.3 的终版 `can_node.*`。
> > - 约定：ID 0x100 是亮度指令、0x200 是应答；帧 3 字节，依次是亮度高字节、低字节、序号；亮度用千分比 0 到 1000。
> > - 板级配置：CAN1 按 7.1，再勾 SCE 中断（7.3）；先 Loopback 自测，再改 Normal；两块板用同一份固件。
> > - 对象的放法：`key_obj_t key_user;` 和 `pwm_t pwm3;` 声明在 `main` 的 `USER CODE BEGIN 1`，`key_init`、`pwm_init`、`pwm_start` 放 `USER CODE BEGIN 2`，循环里每圈 `key_update` 后 `key_pressed`（以 4.1 为准）。
> > - 写法：对象 `can_node_t` 和 `dimmer_t`，状态在对象里；依赖通过函数表 `dimmer_ops_t` 注入。

## 先看一个怪现象

遥控器。你按下这头的按键，另一个房间里的灯慢慢变亮。中间没有网络，只有一根两芯的线。

这件事你已经拥有了全部零件：按键（4.1），PWM 调光（5.3），日志（3.1），时间节拍（5.2），CAN 收发（7.1 到 7.3）。这一节不是学新东西，而是看你能不能把它们接成一条完整的路径，而且接得"可拆"：换一块板，不用重写逻辑。

> [!question] 先猜一猜
> 从你按下按键，到另一块板上的灯开始变化，整条路径上哪一段花的时间最长？
> A. 帧在总线上传输
> B. 按键消抖
> C. 接收方主循环轮询到这帧
> D. PWM 等下一个周期才生效

> [!success]- 揭晓
> 选 B。按 4.1 的做法，按键要稳定 20 ms 才确认。一帧 3 字节的指令，最坏 85 位，在 500 kbit/s 下 170 µs。接收方主循环转一圈通常只有几十微秒到几百微秒。PWM 的周期是 1 ms（PSC = 83、ARR = 999），新占空比最迟下一个周期生效。
> 加起来大约 21 ms，其中 20 ms 是消抖。后面会画出这条路径，并标上时间。这个量级以你的实现为准。

## 动手做

### 第一步：先画系统图，再分层

先画图，再写代码。数据从按键到灯，走这样一条路：

```
  控制端（板 A）                                     执行端（板 B）
 ┌──────────────────────────────┐                ┌──────────────────────────────┐
 │ KEY → key_update/key_pressed │                │ TIM3 CH1 PWM → LED           │
 │        │                     │                │        ▲                     │
 │        ▼                     │                │        │ ops->apply_level    │
 │   dimmer_on_key()            │                │   dimmer_on_msg()            │
 │        │ ops->send           │                │        ▲                     │
 │        ▼                     │                │        │ on_rx（主循环）     │
 │   can_node_send() ──────── 总线 CAN_H/CAN_L ──────► 过滤器 → FIFO → 队列     │
 └──────────────────────────────┘                └──────────────────────────────┘
```

两块板跑同一份固件，所以每块板里都有这两半，按键方向和 PWM 方向是对称的。图上有一道线很重要：**`dimmer` 这一层不认识 HAL，也不认识 CAN 外设**，它只通过两个函数和外界打交道：

| 层 | 对象 | 认识谁 |
|---|---|---|
| 逻辑层 | `dimmer_t` | 只认识 `can_msg_t` 和一张函数表 `dimmer_ops_t` |
| 硬件层 | `can_node_t`、`pwm_t`（5.3，背后是 `htim3`） | HAL |
| 胶水 | `main.c` 里的几个小函数 | 把前两层接在一起 |

这就是[[【原理】C语言里的面向对象|面向对象]]里"依赖注入"的做法：逻辑层不自己去找硬件，而是把硬件要做的两件事（发一帧、输出亮度）写成函数指针，由外面传进来。

### 第二步：先在电脑上把逻辑写对

因为逻辑层不认识 HAL，它可以直接在电脑上编译和测试，就像第 1 章那样：在 `c-lab` 里建一个项目 `projects/dimmer/`，把 `dimmer.h`、`can_msg.h` 放进它的 `include/`，`dimmer.c`、`dimmer_test.c` 放进 `src/`。这是这种写法最实惠的地方。

`dimmer.h`：

```c
#ifndef DIMMER_H
#define DIMMER_H

#include <stdint.h>
#include "can_msg.h"

#define DIMMER_ID_CMD     0x100u   /* 亮度指令：控制端 -> 执行端 */
#define DIMMER_ID_ACK     0x200u   /* 应答：执行端 -> 控制端 */
#define DIMMER_LEVEL_MAX  1000u    /* 亮度用千分比表示，0..1000，和 5.3 里 pwm_set_duty 的千分比一致 */

/* 依赖接口：硬件相关的事全部通过这两个函数做，dimmer 自己不认识 HAL，也不认识 CAN 外设。 */
typedef struct {
    int  (*send)(void *hw, const can_msg_t *msg);        /* 发一帧，返回 0 成功 */
    void (*apply_level)(void *out, uint16_t permille);   /* 把亮度送到输出端 */
} dimmer_ops_t;

/* 调光器对象：状态都在里面，没有全局变量。 */
typedef struct {
    const dimmer_ops_t *ops;   /* 依赖的函数表 */
    void     *hw;              /* 原样传给 ops->send（板上是 can_node_t *） */
    void     *out;             /* 原样传给 ops->apply_level（板上是 pwm_t *） */
    uint16_t  level;           /* 当前生效的亮度，千分比 */
    uint8_t   next_step;       /* 下一次按键要发第几档 */
    uint8_t   seq;             /* 下一条指令的序号 */
    uint32_t  cmd_sent;        /* 发出的指令数 */
    uint32_t  cmd_applied;     /* 收到并执行的指令数 */
    uint32_t  ack_got;         /* 收到的应答数 */
} dimmer_t;

typedef enum {
    DIMMER_EV_NONE = 0,        /* 与我无关，或数据不合法，忽略 */
    DIMMER_EV_CMD_SENT,        /* 按键：指令已发出 */
    DIMMER_EV_SEND_FAIL,       /* 按键：发送失败（比如邮箱满） */
    DIMMER_EV_CMD_APPLIED,     /* 收到指令并已执行，应答已发出 */
    DIMMER_EV_ACK              /* 收到对方的应答 */
} dimmer_event_t;

void dimmer_init(dimmer_t *d, const dimmer_ops_t *ops, void *hw, void *out);

/* 按键事件：切到下一档，发一条指令。本机的亮度不变，等指令绕一圈回来才变。 */
dimmer_event_t dimmer_on_key(dimmer_t *d);

/* 收到一帧：是指令就执行并回应答，是应答就记一笔。 */
dimmer_event_t dimmer_on_msg(dimmer_t *d, const can_msg_t *m);

#endif /* DIMMER_H */
```

`dimmer.c`：

```c
#include "dimmer.h"
#include <stddef.h>

/* 五档亮度，千分比。按一次键走一档，走到头回到第一档 */
static const uint16_t k_steps[] = { 0u, 250u, 500u, 750u, 1000u };
#define STEP_COUNT  (sizeof(k_steps) / sizeof(k_steps[0]))

void dimmer_init(dimmer_t *d, const dimmer_ops_t *ops, void *hw, void *out)
{
    d->ops         = ops;
    d->hw          = hw;
    d->out         = out;
    d->level       = 0u;
    d->next_step   = 1u;       /* 第一次按键发第 1 档（250），第 0 档是"关" */
    d->seq         = 0u;
    d->cmd_sent    = 0u;
    d->cmd_applied = 0u;
    d->ack_got     = 0u;
    d->ops->apply_level(d->out, 0u);
}

/* 三个字节：亮度高字节、亮度低字节、序号。指令和应答用同一种格式 */
static void pack(can_msg_t *m, uint16_t id, uint16_t level, uint8_t seq)
{
    m->id      = id;
    m->dlc     = 3u;
    m->data[0] = (uint8_t)(level >> 8);
    m->data[1] = (uint8_t)(level & 0xFFu);
    m->data[2] = seq;
}

dimmer_event_t dimmer_on_key(dimmer_t *d)
{
    can_msg_t m;

    pack(&m, DIMMER_ID_CMD, k_steps[d->next_step], d->seq);
    if (d->ops->send(d->hw, &m) != 0) {
        return DIMMER_EV_SEND_FAIL;       /* 没发出去就不前进，下次按键再试同一档 */
    }
    d->next_step = (uint8_t)((d->next_step + 1u) % STEP_COUNT);
    d->seq++;
    d->cmd_sent++;
    return DIMMER_EV_CMD_SENT;
}

dimmer_event_t dimmer_on_msg(dimmer_t *d, const can_msg_t *m)
{
    if (m->dlc != 3u) {
        return DIMMER_EV_NONE;            /* 总线上来的数据先校验，再使用 */
    }

    uint16_t level = (uint16_t)(((uint16_t)m->data[0] << 8) | m->data[1]);
    uint8_t  seq   = m->data[2];

    if (m->id == DIMMER_ID_CMD) {
        can_msg_t ack;

        if (level > DIMMER_LEVEL_MAX) {
            return DIMMER_EV_NONE;        /* 越界的亮度不执行 */
        }
        d->ops->apply_level(d->out, level);
        d->level = level;
        d->cmd_applied++;
        pack(&ack, DIMMER_ID_ACK, level, seq);
        (void)d->ops->send(d->hw, &ack);  /* 应答丢了也不影响已经执行的结果 */
        return DIMMER_EV_CMD_APPLIED;
    }
    if (m->id == DIMMER_ID_ACK) {
        d->ack_got++;
        return DIMMER_EV_ACK;
    }
    return DIMMER_EV_NONE;
}
```

几个要点：

- **按键只发指令，不改本机亮度**。亮度的改变，等指令从总线上绕一圈回来才发生。单板回环时，"绕一圈"就是回到自己；两块板时，是对面那块执行。
- **发送失败就不前进档位**。邮箱满了，这次按键没发出去，下次按键仍发同一档，而不是悄悄跳过一档。
- **收到的数据先校验**。长度不是 3 就忽略，亮度超过 1000 就忽略。总线上的帧不是你写的，不能假设它合法。
- **应答由执行端发回**。应答用同样的 3 字节格式，带着生效的亮度和原来的序号。

再写一个测试程序。它用两个假的"硬件"代替 CAN 和 PWM，把 A 发出的帧交给 B，把 B 的应答交回 A：

```c
#include <stdio.h>
#include <string.h>
#include "dimmer.h"

/* ---- 假的"硬件"：不碰任何 HAL，只记录 ---- */
typedef struct {
    can_msg_t last;       /* 最近一次"发出"的帧 */
    int       sent_count;
    int       fail_next;  /* 非 0 则让下一次发送失败 */
} fake_bus_t;

typedef struct {
    uint16_t pwm;         /* 假装是 TIM3 的 CCR */
} fake_pwm_t;

static int fake_send(void *hw, const can_msg_t *m)
{
    fake_bus_t *b = hw;
    if (b->fail_next) {
        b->fail_next = 0;
        return -2;
    }
    b->last = *m;
    b->sent_count++;
    return 0;
}

static void fake_apply(void *out, uint16_t permille)
{
    fake_pwm_t *p = out;
    p->pwm = permille;
}

static const dimmer_ops_t k_fake_ops = { fake_send, fake_apply };

static int g_fail = 0;
#define CHECK(cond) do { if (!(cond)) { printf("FAIL line %d: %s\n", __LINE__, #cond); g_fail++; } } while (0)

int main(void)
{
    fake_bus_t bus_a, bus_b;
    fake_pwm_t pwm_a, pwm_b;
    dimmer_t a, b;

    memset(&bus_a, 0, sizeof bus_a);
    memset(&bus_b, 0, sizeof bus_b);
    memset(&pwm_a, 0xFF, sizeof pwm_a);
    memset(&pwm_b, 0xFF, sizeof pwm_b);
    dimmer_init(&a, &k_fake_ops, &bus_a, &pwm_a);
    dimmer_init(&b, &k_fake_ops, &bus_b, &pwm_b);
    CHECK(pwm_a.pwm == 0 && pwm_b.pwm == 0);

    /* A 按键 6 次：每次把 A 发出的帧交给 B，再把 B 的应答交回 A */
    printf("press  sent-level  seq  B.pwm  A.acks\n");
    for (int i = 1; i <= 6; i++) {
        CHECK(dimmer_on_key(&a) == DIMMER_EV_CMD_SENT);
        can_msg_t cmd = bus_a.last;
        CHECK(dimmer_on_msg(&b, &cmd) == DIMMER_EV_CMD_APPLIED);
        can_msg_t ack = bus_b.last;
        CHECK(dimmer_on_msg(&a, &ack) == DIMMER_EV_ACK);
        printf("%-6d %-11u %-4u %-6u %-6lu\n", i,
               (unsigned)((cmd.data[0] << 8) | cmd.data[1]), (unsigned)cmd.data[2],
               (unsigned)pwm_b.pwm, (unsigned long)a.ack_got);
    }
    CHECK(pwm_a.pwm == 0);                 /* 发送方自己的亮度没变 */
    CHECK(a.cmd_sent == 6 && b.cmd_applied == 6 && a.ack_got == 6);

    /* 发送失败：不前进档位，下次还发同一档 */
    bus_a.fail_next = 1;
    uint8_t step_before = a.next_step;
    CHECK(dimmer_on_key(&a) == DIMMER_EV_SEND_FAIL);
    CHECK(a.next_step == step_before);

    /* 不合法的数据：长度不对、亮度越界、别的 ID，都必须被忽略 */
    can_msg_t bad;
    memset(&bad, 0, sizeof bad);
    bad.id = DIMMER_ID_CMD; bad.dlc = 2;
    CHECK(dimmer_on_msg(&b, &bad) == DIMMER_EV_NONE);
    bad.dlc = 3; bad.data[0] = 0x27; bad.data[1] = 0x10;      /* 10000 */
    uint16_t before = pwm_b.pwm;
    CHECK(dimmer_on_msg(&b, &bad) == DIMMER_EV_NONE);
    CHECK(pwm_b.pwm == before);
    bad.id = 0x555; bad.data[0] = 0; bad.data[1] = 10;
    CHECK(dimmer_on_msg(&b, &bad) == DIMMER_EV_NONE);

    printf(g_fail == 0 ? "all checks passed\n" : "SOME CHECKS FAILED\n");
    return g_fail;
}
```

### 第三步：板上的配置

CubeMX 里一共要有这些，每项的细节回到对应的小节：

| 项 | 内容 | 出处 |
|---|---|---|
| USART1 | 异步，115200，日志用 | 3.1 |
| TIM6 | 1 ms 节拍，PSC 83、ARR 999 | 5.2 |
| TIM3 CH1 | PWM 的配置见 5.3：PSC 83、ARR 999，计数时钟 1 MHz；外接 LED 到该通道引脚 | 5.3 |
| 按键 | 输入、上拉，User Label 填 `KEY` | 4.1 |
| CAN1 | Prescaler 6、BS1 = 11、BS2 = 2、SJW = 1；Automatic Retransmission Enable；先 Loopback | 7.1 |
| NVIC | CAN1 TX、CAN1 RX0、CAN1 SCE 三个中断 | 7.1、7.3 |
| 时钟前提 | CPU 168 MHz，APB1 定时器时钟 84 MHz、PCLK1 42 MHz，以你的时钟树为准 | 5.2、7.1 |

### 第四步：胶水，把逻辑接到硬件上

把 `dimmer.h` 放进 `User/Inc`，`dimmer.c` 放进 `User/Src`（同样由 CMake 自动收进来，新增了文件，让 CMake 重新配置一次），并确认 7.3 的终版 `can_node.*` 已就位。在 `main.c` 里依次加入下面几段。

```c
/* USER CODE BEGIN 1 */
  key_obj_t key_user;       /* 按键对象（4.1）。声明成 main 的局部变量，只有 main 能直接碰它 */
  pwm_t     pwm3;           /* TIM3 通道 1 的 PWM 输出对象（5.3） */
/* USER CODE END 1 */
```

胶水函数。这是整条路径上唯一同时认识两边的地方，全是几行的小函数：

```c
/* USER CODE BEGIN 4 */
/* ---- 板级胶水：把逻辑层要的两个动作，接到具体的硬件上 ---- */
static int hw_send(void *hw, const can_msg_t *m)
{
    return can_node_send((can_node_t *)hw, m->id, m->data, m->dlc);
}

static void pwm_apply(void *out, uint16_t permille)
{
    pwm_set_duty((pwm_t *)out, permille);      /* 5.3 的 PWM 对象，千分比 0..1000 */
}

static const dimmer_ops_t k_dim_ops = { hw_send, pwm_apply };

/* 收到帧：交给逻辑层处理，再按它报告的事件打日志 */
static void on_can_rx(void *ctx, const can_msg_t *m)
{
    dimmer_t *d = (dimmer_t *)ctx;

    switch (dimmer_on_msg(d, m)) {
    case DIMMER_EV_CMD_APPLIED:
        LOG(LOG_INFO, "cmd applied: level=%u seq=%u\r\n", d->level, m->data[2]);
        break;
    case DIMMER_EV_ACK:
        LOG(LOG_INFO, "ack: level=%u seq=%u acks=%lu\r\n",
            (unsigned)(((unsigned)m->data[0] << 8) | m->data[1]), m->data[2],
            (unsigned long)d->ack_got);
        break;
    default:
        break;
    }
}

/* 总线出错时由 can_node_poll() 调用，运行在主循环里 */
static void on_can_err(void *ctx, uint32_t flags)
{
    can_node_t *n = (can_node_t *)ctx;

    if (flags & HAL_CAN_ERROR_EWG) {
        LOG(LOG_WARN, "can: error warning\r\n");
    }
    if (flags & HAL_CAN_ERROR_EPV) {
        LOG(LOG_WARN, "can: error passive\r\n");
    }
    if (flags & HAL_CAN_ERROR_BOF) {
        LOG(LOG_ERR, "can: bus-off\r\n");
    }
    if (flags & HAL_CAN_ERROR_RX_FOV0) {
        LOG(LOG_ERR, "can: rx fifo overrun\r\n");
    }
    LOG(LOG_INFO, "can: flags=0x%x tec=%lu rec=%lu\r\n", (unsigned)flags,
        (unsigned long)can_node_tec(n), (unsigned long)can_node_rec(n));

    /* 没开 AutoBusOff 时，要自己把节点拉回总线 */
    if ((flags & HAL_CAN_ERROR_BOF) && n->hcan->Init.AutoBusOff == DISABLE) {
        LOG(LOG_WARN, "can: manual recovery\r\n");
        (void)can_node_recover(n);
    }
}
/* USER CODE END 4 */
```

初始化：

```c
/* USER CODE BEGIN 2 */
  log_init(&huart1);                                  /* 3.1 */
  HAL_TIM_Base_Start_IT(&htim6);                      /* 5.2 */
  pwm_init(&pwm3, &htim3, TIM_CHANNEL_1, 1000000u);   /* 5.3：TIM3 计数时钟 1 MHz */
  pwm_start(&pwm3);                                   /* 开始输出 PWM */

  key_init(&key_user, KEY_GPIO_Port, KEY_Pin);        /* 4.1：端口和引脚是传进去的 */

  can_node_init(&g_can, &hcan1);
  dimmer_init(&g_dim, &k_dim_ops, &g_can, &pwm3);    /* 把"怎么发""怎么输出"注入逻辑层 */
  can_node_set_rx_handler(&g_can, on_can_rx, &g_dim);
  can_node_set_err_handler(&g_can, on_can_err, &g_can);

  /* 这块板只关心两种 ID：指令和应答 */
  static const uint16_t k_ids[] = { DIMMER_ID_CMD, DIMMER_ID_ACK };
  if (can_node_filter_list(&g_can, k_ids, 2u) != 0 || can_node_start(&g_can) != 0) {
      LOG(LOG_ERR, "can init failed\r\n");
      log_flush();
      Error_Handler();
  }
  LOG(LOG_INFO, "dimmer node ready\r\n");
/* USER CODE END 2 */

    can_node_poll(&g_can);                       /* 收到的帧交给 on_can_rx */

    key_update(&key_user);                       /* 4.1：每圈推进一次消抖状态机 */

        if (dimmer_on_key(&g_dim) == DIMMER_EV_CMD_SENT) {

        } else {
            LOG(LOG_WARN, "key: send failed\r\n");
        }
    }

    if (soft_due(&t_stat, 5000u)) {
        LOG(LOG_INFO, "stat: sent=%lu applied=%lu ack=%lu tx_done=%lu rx=%lu drop=%lu\r\n",
            (unsigned long)g_dim.cmd_sent, (unsigned long)g_dim.cmd_applied,
            (unsigned long)g_dim.ack_got, (unsigned long)g_can.tx_done,
            (unsigned long)g_can.rx_cnt, (unsigned long)g_can.rx_drop);

/* USER CODE END 3 */
```

注意初始化里这一句：`dimmer_init(&g_dim, &k_dim_ops, &g_can, &htim3);`。四个参数依次是：调光器对象、函数表、传给 `send` 的 `hw`、传给 `apply_level` 的 `out`。逻辑层拿到的只是 `void *`，不知道它们背后是 `can_node_t` 和 `pwm_t`。

### 第五步：单板回环先跑通

CubeMX 里 CAN1 是 Loopback，一块板就够。构建并下载，按一次键，你应该看到：

```
[3 I] dimmer node ready
[8210 I] key: cmd sent, total=1
[8211 I] cmd applied: level=250 seq=0
[8211 I] ack: level=250 seq=0 acks=1
```

数字是示意。顺序是固定的：先是按键发出指令；指令从发送端绕回接收端，被执行；执行端发回应答，应答再绕回来被记下。TIM3 引脚上的 LED 亮度变成 25%。再按四次，亮度依次是 50%、75%、100%、0。每 5 秒还会多一行 `stat`。

### 第六步：接上两块板

1. CubeMX 里 CAN1 的 Operating Mode 改成 **Normal**，重新生成。两块板用同一份固件，都烧同一个版本。
2. 按 7.1 接线，CAN_H 对 CAN_H，CAN_L 对 CAN_L，两端各一个 120 Ω。
3. 两块板各自外接一只 LED 到 TIM3 通道 1 的引脚，上电。

> [!question] 先猜一猜
> 在板 A 上按一次键。A 自己的 LED 会变亮吗？B 的会吗？两块板的串口各出现什么？

> [!success]- 揭晓
> A 的 LED 不变，B 的 LED 亮度变成 25%。Normal 模式下，发送方不会收到自己发出的帧。
> A 的串口：`key: cmd sent`，随后收到 B 的应答，出现 `ack: level=250`。
> B 的串口：`cmd applied: level=250`。B 发出的应答 A 会处理，B 自己不会收到。
> 在 B 上按键，方向反过来。

这是按设计推演的结果，作者没有上板，以你的实测为准。

> [!example] 探针：拔线
> 把 CAN 线拔掉，在 A 上连按键 5 次。
> 按推演：前 3 次日志都是 `key: cmd sent`，因为三个发送邮箱还有空；这 3 帧没人应答，一直留在邮箱里重发，`tx_done` 不增长。第 4 次起，邮箱满了，发送返回 -2，日志变成 `key: send failed`。
> 这里有两个层次的"应答"：总线层的 ACK 位只说明有人收到，我们自己的 `ack` 帧才说明对方执行了。不要把两件事混为一谈。

## 刚才发生了什么

整件事能写得"可拆"，靠的是一条线：逻辑层只依赖函数表，不依赖任何 HAL 类型。

- **状态在对象里**。`can_node_t` 有队列、计数、过滤器占用；`dimmer_t` 有当前亮度、档位、序号。没有一个散落的全局变量，所以多挂一路 CAN、多放一个调光器都不会互相干扰。
- **依赖用函数表注入**。`dimmer_ops_t` 只有两项：发一帧、输出亮度。换一块板、换一种输出方式，只改这张表和它指向的两个小函数。
- **只暴露接口**。别的文件看到的是 `can_node.h` 和 `dimmer.h` 里的类型与函数；队列怎么实现、登记表怎么查，都是 `static` 的内部事务。
- **回调带着上下文**。`on_can_rx` 的第一个参数是 `void *ctx`，登记时传入 `&g_dim`，回调里转回来就用。这和 `HAL_UART_Transmit(&huart1, ...)` 的写法是同一个思路：对象指针放在第一个参数。

C++ 把这套写法变成了语言特性：`class`、构造函数、虚函数，大致就是上面这些的语法糖，同时也带来隐藏的开销和风险。这里不展开，想先看一眼的可以读[[【拓展】C++入门与嵌入式C++|C++ 入门与嵌入式 C++]]，未来会有专门的 C++ 篇。

最后把时间标在系统图上：

| 环节 | 时间 |
|---|---|
| 按键消抖 | 20 ms（4.1 里的 `KEY_DEBOUNCE_MS`） |
| 指令帧上总线 | 3 字节最坏 85 位，500 kbit/s 下 170 µs |
| 接收方取出并执行 | 主循环转一圈，通常几十微秒到几百微秒 |
| PWM 生效 | 最迟下一个 PWM 周期，1 ms |
| 合计 | 约 21 ms，其中 20 ms 是消抖 |

回头看开头那道题：最慢的是消抖，不是 CAN。优化之前先量，很多时候你以为的瓶颈根本不是瓶颈。

## 记住这几条

1. 逻辑和硬件分开：逻辑层只依赖函数表，不 `include` HAL。硬件细节集中在几个小的胶水函数里。
2. 状态放对象里，全局变量只留给 `g_ms` 这类确实全局的东西。
3. 总线来的数据先校验（长度、范围）再使用，不要假设对方合法。
4. 中断里只入队，主循环里处理，日志也在主循环里打。
5. 总线层 ACK 不等于应用层已处理。需要确认的指令，要有自己的应答帧。
6. 整条路径的延迟由最慢的环节决定。先量，再优化。
7. 能在电脑上测的逻辑，先在电脑上测。

## 练习

1. 单板回环下按 5 次键，记录每一次的串口日志，并在系统图上标出这一帧走过的每一站和时间。（复现）
2. 你的板子没有可用的 PWM 引脚，只有一个 LED。只改胶水，让亮度大于等于 500 时点亮，否则熄灭。写出需要改的函数和函数表。（改造）
3. 只上电板 B（A 断电），在 B 上连按键 4 次。预测 B 的串口日志。（预测）

> 1. 日志顺序是 `key: cmd sent`、`cmd applied`、`ack`。时间标注可参考上面的表。
