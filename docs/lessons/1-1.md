# 1.1 让程序说你自己的话

> **这一节你会做出**：改出自己的第一句问候，让程序分行输出，并修好一个漏写分号的小错误。
> **前置**：[[1.0_搭建环境]]　｜　**预计**：阅读 + 动手 25 分钟

> [!tip]- 已经写过 C 的读者：跳读自测
> 第一次写程序，直接从下面的正文开始。这几题只供已有基础的读者判断是否跳到 [[1.2_变量运算与控制流]]。
> 1. `printf("A\nB\n");` 会输出几行，分别是什么？
> 2. 只修改并保存代码，没有重新构建就运行原来的程序，会看到新内容吗？
> 3. `printf` 这一句漏了分号，错误却标在下一行的 `return`，应当先检查哪里？
>
> > [!success]- 答案与带走清单
> > 1. 两行，先是 A，再是 B。`\n` 表示换行。
> > 2. 不会，必须先重新构建；本教程的 CMake 运行命令可能代你触发构建，但不是保存动作让旧程序自动改变。
> > 3. 先检查 `return` 上一句是否缺少分号。
> > **带走清单**：沿用 `c-lab`，会保存、构建、选择 `hello` 并运行；会修改 `printf` 的文字和换行；遇到报错从第一条看起。没有新增的公共文件。

## 这次，让它说你自己的话

上一节，电脑已经显示了一句 `hello, world`。不过那还是示例替你写好的话。这一节，我们让这句话真正由你决定。

第一份程序不用做得很大。先改一句话，再多输出一行，最后亲手修好一个错误。完成这些，再去写有变量、有判断的程序。

## 第一步：打开已经跑通的程序

在 VS Code 里打开 `c-lab` 文件夹，再打开 `src/hello.c`。保留原来的 `CMakeLists.txt`，其中已经有 `add_demo(hello)`，不用重复添加。

代码应该是：

```c
#include <stdio.h>

int main(void) {
    printf("hello, world\n");
    return 0;
}
```

先执行 `CMake: Build`，再用 `CMake: Set Launch/Debug Target` 选中 `hello`，执行 `CMake: Run Without Debugging`。看到原来的问候后，开始修改。

## 第二步：换成自己的问候

把 `printf` 那一行换成：

```c
    printf("I can write C.\n");
```

按 `Ctrl+S` 保存，重新构建，再运行。你改的是 `hello.c` 里的文字，构建会更新 `hello.exe`；运行的是这个更新后的程序，不是编辑器里的文字本身：

```text
I can write C.
```

也可以换成别的英文。先保留双引号、后面的 `\n` 和末尾分号，只改双引号里的文字部分。若使用中文后看到乱码，先检查文件与终端的编码；这次可以先用英文完成操作。

现在认两个和刚才操作直接有关的写法：

- `printf("...");`：把双引号中的文字输出到终端。
- `\n`：换行。它在代码里写成反斜杠和字母 n，输出时不是这两个字符，而是换到下一行。

## 第三步：让它说两行

把程序改成下面这样：

```c
#include <stdio.h>

int main(void) {
    printf("first line\n");
    printf("second line\n");
    return 0;
}
```

保存、构建、运行，看到：

```text
first line
second line
```

本例中，两句 `printf` 按写下的顺序执行。接下来只改第一句：删掉它的 `\n`，在 `first line` 后面留一个空格。

> [!question] 先猜一猜
> 第一条不换行，第二条还会自己另起一行吗？先想好，再运行下面的改法。

```c
    printf("first line ");
    printf("second line\n");
```

> [!success]- 对照结果
> 输出变成一行：`first line second line`。调用两次 `printf` 不代表自动输出两行，换不换行取决于写进去的内容。

## 第四步：修好一个小错误

把代码恢复成上面的两行输出版本，然后故意删掉第一句 `printf` 末尾的分号，构建一次。

这次不会得到一个新的可运行程序。输出里可能出现类似这样的提示，具体措辞和行号随工具版本变化：

```text
error: expected ';' before 'printf'
```

它可能指着第二句 `printf`，但真正缺东西的是上一句。按下面的顺序处理：

1. 找到第一条 `error:`，打开它指出的文件和行。
2. 看这一行，也看它的上一行。
3. 把缺少的 `;` 补回去，保存，再构建、运行。

**报错的位置是工具发现不对劲的位置，不一定就是你漏写字符的位置。** 先修第一处错误，再看是否还有下一处，不必一次面对整屏报错。

## 这几个位置先保持原样

你已经知道怎么改输出了。其余几行，这次只认识到够用即可：

| 写法 | 现在用到的意思 |
|---|---|
| `#include <stdio.h>` | 使用 `printf` 时保留这一行。头文件的用法到多文件工程时再讲。 |
| `int main(void) { ... }` | 本例要执行的动作写在 `main` 的大括号里。名字和这一行的写法先保持原样。 |
| `return 0;` | 表示本次程序正常结束，暂时放在最后。 |
| 一句动作末尾的 `;` | 比如每句 `printf` 后面都需要它；不是要求每一行末尾都加分号。 |

这次不用展开预处理、汇编、链接，也不用先解释可执行文件的内部结构。那些内容已经放在 [[第0章_工具与构建_自学选读]]，**不读也能继续做下一节**。

## 再试两次

1. 输出三行英文，分别写自己的名字、喜欢的一件事、接下来想做的程序。（改造）
2. 把三句输出中的前两个 `\n` 换成空格，先判断它们会排成几行，再运行检查。（预测）

> [!success]- 检查方式
> 第一项应当有三行，每句文字由你自己决定；第二项会连在一行，直到第三句末尾的 `\n` 才换行。若输出没变化，先检查是否保存、是否重新构建，以及运行目标是否仍是 `hello`。

**带走清单**：保存后构建、选对程序再运行；用 `printf` 输出文字，用 `\n` 换行；从第一条错误查起。
