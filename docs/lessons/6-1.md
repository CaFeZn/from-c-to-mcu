# 6.1 串口命令行

> **这一节你会做出**：在串口助手里敲 `led on` 回车，板子上的 LED 真的亮；敲错了可以退格，敲太长不会崩。顺手搭出几个能反复使用的小零件：串口接收器、行编辑器、shell，并复用 5.4 的环形缓冲和 1.9 的命令解析器。

> 1. 用 `HAL_UART_Receive_IT(&huart1, &b, 1)` 收字节，收满一个字节后进回调。如果回调里没有再调用一次它，会怎样？
> 2. 下面这个回调违反了哪几条规矩？
>    ```c
>    void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
>    {
>        LOG(LOG_INFO, "got %c\r\n", rx_byte);
>        cmd_exec(g_cmds, n, line);
>        HAL_UART_Receive_IT(huart, &rx_byte, 1);
>    }
>    ```
> 3. 板子要在两个串口上各开一个命令行。如果行缓冲、已输入的长度都写成全局变量，会出什么问题？换成对象的写法怎么解决？
> 4. 传给 `cmd_exec` 的那一行，可以是字符串字面量吗？
>
> > [!success]- 答案，以及跳过后要带走的东西
> > 1. 只能收到第一个字节。`HAL_UART_Receive_IT` 只管一轮，收满就结束，要继续收必须再挂一次。
> > 2. 在中断里输出（LOG）、在中断里执行命令（可能很慢，还会原地改行缓冲）。回调里只该把字节放进队列，其余留给主循环。
> > 3. 两个串口会抢同一份状态，字符混在一起。把行缓冲、长度这些状态放进一个对象（结构体），每个串口建一个实例，函数以对象指针为第一个参数，互不干扰，代码不用改。
> > 4. 不行。`cmd_exec` 会原地把空白改成 `'\0'`，字面量在只读内存里，会崩。必须是可写的数组。
> >
> > **带走清单**（代码都在本节「第三步」，直接复制）：
> > - 文件位置：所有 `.h` 放 `User/Inc`，所有 `.c` 放 `User/Src`，CMake 会自动收进来，新增文件后重新配置一次（见 2.2）。
> > - 复用 1.9 的 `cmd.h` / `cmd.c`（原样拷进 `User/Inc` 和 `User/Src`，一个字都不改）和 5.4 的 `ringbuf.h` / `ringbuf.c`。
> > - 新增：`uart_rx.h/.c`（串口接收器，6.2 会整体替换它）、`line.h/.c`（行编辑器）、`shell.h/.c`（拼行 + 执行）、`app_cli.h/.c`（组装对象、定义命令）。
> > - `main.c` 三处：Includes 区包含 `app_cli.h`；USER CODE 2 里 `app_cli_init()`；主循环里 `app_cli_poll()`。
> > - CubeMX：USART1 的 NVIC 里勾选 USART1 global interrupt。
> > - 约定：`LOG` 不自动补换行，命令的输出自己写 `"\r\n"`；HAL 的 `HAL_UART_RxCpltCallback` 与 `HAL_UART_ErrorCallback` 全工程各只写一份。

## 先看一个怪现象

1.9 里的服务员读的是一整行文字。现在顾客不在店里了，他打电话来点菜，一个字一个字地往外说。

电话那头没有"一句话"这种东西，只有一连串的字。接线员得自己把字记下来，听到顾客说"完毕"，这一单才算数，才能把单子递给后厨。串口，就是这根电话线。

> [!question] 先猜一猜
> 你在串口助手里输入 `led on`，按回车发送。板子的串口一共会收到几个字节？它们依次是什么？
> 提示：回车键在串口里是一个（或两个）看不见的字符。

> [!success]- 揭晓
> 不是"一句话"，是 7 个字节：`6C 65 64 20 6F 6E 0D`，也就是 `l e d`、空格、`o n`，最后是回车 CR（0x0D）。如果串口助手的"发送新行"选的是 CR LF，后面还会多一个换行 LF（0x0A），共 8 个。
> 串口只负责把字节一个一个送到。哪几个字节算一句话，是接线员自己拼出来的。

接下来我们就雇一个接线员，再给他配一个收件篮。

## 动手做

### 第一步：先画分工图

数据从线上走到 LED，要经过这样一条路：

```
串口线 → 接收中断 → 收件篮 → 主循环取字节 → 拼成一行 → cmd_exec → 命令函数 → LED
        (uart_rx_t)  (ringbuf_t)              (line_t)      (1.9)      (app_cli.c)
```

接收中断每来一个字节，就丢进收件篮，别的什么都不干。主循环有空了，从篮子里一个个取出来，交给接线员拼成一行，凑够一行再交给 1.9 的 `cmd_exec`。

每个环节都做成一个独立的小零件：

| 零件 | 它记住什么（状态） | 它能干什么（函数） | 文件 |
|---|---|---|---|
| `ringbuf_t` 收件篮 | 存储区、读写位置、丢了几个 | 放一个、取一个 | 5.4 已有 |
| `uart_rx_t` 串口接收器 | 管哪个串口、字节放进哪个篮子 | 开始接收；收到后放进篮子 | `uart_rx.h/.c` |
| `line_t` 行编辑器 | 已拼的字符、有没有超长 | 喂一个字节，告诉你发生了什么 | `line.h/.c` |
| `shell_t` | 行编辑器、命令表、往哪输出 | 轮询：取字节、拼行、执行 | `shell.h/.c` |

注意每个零件的"状态"都收在它自己的结构体里，没有散落的全局变量。每个函数的第一个参数都是指向这个结构体的指针。这样一来，想要第二个串口的命令行，就再建一套，代码一行都不用改。

> [!question] 先猜一猜
> 中断回调拿到一个字节后，为什么不干脆直接在里面拼行、调 `cmd_exec`？那样不是少一个篮子吗？

> [!success]- 揭晓
> 5.1 讲过中断里的规矩：短，不阻塞，不输出。`cmd_exec` 里可能调 `LOG`、点灯，所有命令都能做任意事，时间没有上限；它还会原地改行缓冲。在中断里做这些，字节会在你处理上一行的时候继续涌进来。
> 所以中断只做最小的一件事：把字节放进篮子。篮子是"中断写、主循环读"，各管各的一头，这个套路在 5.4 里已经练过。

### 第二步：CubeMX 与串口助手

USART1 沿用 3.1 的配置：115200，8 位数据，无校验，1 位停止。这一节新增的只有一项：在 NVIC Settings 里确认 **USART1 global interrupt** 已勾选（3.1 如果已经勾了就不用动）。

串口助手里：波特率 115200，8N1；发送区勾选"发送新行"，CR、LF、CR LF 哪一种都可以，下面的行编辑器三种都认。

### 第三步：写零件

文件放哪：头文件放 `User/Inc`，源文件放 `User/Src`，不要放进 CubeMX 管理的 `Core/`。顶层 `CMakeLists.txt` 里的 `GLOB` 会自动把它们收进来；新增了文件，记得在 VS Code 里重新配置一次 CMake（见 [[2.2_开发环境与第一次点灯]]）。

**收件篮**直接用 5.4 的 `ringbuf.h` / `ringbuf.c`（见 [[5.4_中断与主循环共享数据]]），不再重写。它是一个"单生产者、单消费者"的字节环形缓冲：中断是唯一的生产者，主循环是唯一的消费者。

**命令解析**直接用 1.9 的 `cmd.h` / `cmd.c`（见 [[1.9_小项目_命令解析器]]），原样拷进来，一个字符都不改。它里面没有一个字提到 LED，也没有一个字提到 PC，所以在板子上照样能用。`cmd_exec` 的返回值约定也没变：0 成功，-1 未知命令，-2 词太多，其他是命令函数自己的返回值。

**串口接收器**。头文件：

```c
#ifndef UART_RX_H
#define UART_RX_H

#include <stdint.h>
#include "usart.h"
#include "ringbuf.h"

/* 串口接收器：把某个串口收到的字节，一个个放进指定的队列 */
typedef struct {
    UART_HandleTypeDef *huart;     /* 管哪个串口 */
    ringbuf_t          *sink;      /* 收到的字节放到哪个队列 */
    volatile uint32_t   events;    /* 接收回调被调用的次数，观察用 */
    volatile uint32_t   bytes;     /* 一共收到多少字节，观察用 */
    uint8_t             byte;      /* HAL 每收满一个字节，就放在这里 */
} uart_rx_t;

void uart_rx_init(uart_rx_t *rx, UART_HandleTypeDef *huart, ringbuf_t *sink);
void uart_rx_start(uart_rx_t *rx);   /* 开始接收，要在 MX_USART1_UART_Init 之后调用 */

#endif /* UART_RX_H */
```

源文件：

```c
#include <stddef.h>
#include "uart_rx.h"

/* HAL 的回调只给我们一个 huart 指针，不知道它属于哪个接收器。
 * 所以做一张小登记表：init 时登记，回调里按 huart 找回对象。 */
#define UART_RX_MAX  2
static uart_rx_t *s_registry[UART_RX_MAX];

static uart_rx_t *find_rx(UART_HandleTypeDef *huart)
{
    for (int i = 0; i < UART_RX_MAX; i++) {
        if (s_registry[i] != NULL && s_registry[i]->huart == huart) {
            return s_registry[i];
        }
    }
    return NULL;
}

void uart_rx_init(uart_rx_t *rx, UART_HandleTypeDef *huart, ringbuf_t *sink)
{
    rx->huart = huart;
    rx->sink = sink;
    rx->events = 0;
    rx->bytes = 0;
    rx->byte = 0;
    for (int i = 0; i < UART_RX_MAX; i++) {
        if (s_registry[i] == rx) {
            return;                           /* 已经登记过 */
        }
    }
    for (int i = 0; i < UART_RX_MAX; i++) {
        if (s_registry[i] == NULL) {
            s_registry[i] = rx;
            return;
        }
    }
}

void uart_rx_start(uart_rx_t *rx)
{
    HAL_UART_Receive_IT(rx->huart, &rx->byte, 1);
}

/* 收满 1 个字节时由 HAL 调用（在中断里）。只搬字节，其余都留给主循环 */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    uart_rx_t *rx = find_rx(huart);

    if (rx == NULL) {
        return;                               /* 不是我们管的串口 */
    }
    rx->events++;
    rx->bytes++;
    (void)ringbuf_put(rx->sink, rx->byte);   /* 队列满了会丢掉并计数 */
    HAL_UART_Receive_IT(huart, &rx->byte, 1); /* 再挂一次，否则只能收到第一个字节 */
}

/* 出错（比如主循环太久没取，来了溢出错误）后，HAL 可能已经停止接收，重新挂上 */
void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)
{
    uart_rx_t *rx = find_rx(huart);

    if (rx != NULL) {
        __HAL_UART_CLEAR_OREFLAG(huart);
        HAL_UART_Receive_IT(huart, &rx->byte, 1);
    }
}
```

这里有一件需要说明的事。HAL 调用回调时只给你一个 `huart` 指针，它不知道这个串口"属于"哪个接收器。所以做了一张小登记表：`uart_rx_init` 时登记，回调里按 `huart` 找回对象。这张表是模块里唯一的静态数据，原因是 HAL 规定的回调函数没有"上下文"参数。另外，`HAL_UART_ErrorCallback` 里重新挂接收是一道保险：出错后 HAL 是否已经停止接收，随 HAL 版本略有不同（待核对）。

**行编辑器**。它只管把字节拼成行，不输出任何东西，该不该回显、怎么报错，由使用者决定。

```c
#ifndef LINE_H
#define LINE_H

#include <stddef.h>
#include <stdint.h>

/* 行编辑器：一个字节一个字节地喂，它帮你拼成一行，处理退格、回车、超长。
 * 它不输出任何东西，是回显还是报错，由使用者决定。 */
typedef enum {
    LINE_NONE = 0,   /* 没什么要做 */
    LINE_ADDED,      /* 刚加进一个字符（就是刚喂进去的那个），可以回显 */
    LINE_ERASED,     /* 刚删掉一个字符（收到退格） */
    LINE_DONE,       /* 回车：一行完成，用 line_text() 取出来 */
    LINE_TOO_LONG    /* 回车：但这一行超长，已作废 */
} line_event_t;

typedef struct {
    char    *buf;        /* 存储空间，由使用者提供 */
    size_t   cap;        /* 容量，含结尾的 '\0' */
    size_t   len;        /* 已经拼了几个字符 */
    uint8_t  overflow;   /* 这一行是否已经超长 */
    uint8_t  done;       /* 上一次喂字节时刚好完成了一行 */
    uint8_t  prev;       /* 上一个字节，用来识别 CR LF 连着来 */
} line_t;

void         line_init(line_t *ln, char *storage, size_t cap);
line_event_t line_feed(line_t *ln, uint8_t ch);
char        *line_text(line_t *ln);   /* LINE_DONE 之后有效，到下一次 line_feed 之前 */

#endif /* LINE_H */
```

```c
#include "line.h"

void line_init(line_t *ln, char *storage, size_t cap)
{
    ln->buf = storage;
    ln->cap = cap;
    ln->len = 0;
    ln->overflow = 0;
    ln->done = 0;
    ln->prev = 0;
    if (cap > 0) {
        storage[0] = '\0';
    }
}

line_event_t line_feed(line_t *ln, uint8_t ch)
{
    if (ch == '\n' && ln->prev == '\r') {    /* CR LF 里的 LF：这一行已经处理过了 */
        ln->prev = ch;
        return LINE_NONE;
    }
    ln->prev = ch;

    if (ln->done) {                          /* 上一行已被取走，从头开始 */
        ln->len = 0;
        ln->overflow = 0;
        ln->done = 0;
    }

    if (ch == '\r' || ch == '\n') {          /* 回车：一行结束 */
        ln->done = 1;
        if (ln->overflow) {
            return LINE_TOO_LONG;
        }
        ln->buf[ln->len] = '\0';
        return LINE_DONE;
    }
    if (ch == 0x08 || ch == 0x7F) {          /* 退格 */
        if (ln->len > 0 && !ln->overflow) {
            ln->len--;
            return LINE_ERASED;
        }
        return LINE_NONE;
    }
    if (ch >= 0x20 && ch < 0x7F) {           /* 可打印字符 */
        if (ln->len + 1 < ln->cap) {         /* 留一格给结尾的 '\0' */
            ln->buf[ln->len++] = (char)ch;
            return LINE_ADDED;
        }
        ln->overflow = 1;                    /* 放不下了：先记下，等回车时一起报错 */
    }
    return LINE_NONE;                        /* 其他控制字符直接忽略 */
}

char *line_text(line_t *ln)
{
    return ln->buf;
}
```

**shell**。它把前面的零件串起来。注意它不知道输出去哪，只调用别人传进来的 `io->write`。

```c
#ifndef SHELL_H
#define SHELL_H

#include <stddef.h>
#include <stdint.h>
#include "ringbuf.h"
#include "cmd.h"
#include "line.h"

/* 输出接口：shell 不知道文字最后去了串口、屏幕还是别的地方，
 * 使用者把"怎么输出"这个函数传进来就行（依赖注入）。 */
typedef struct {
    void (*write)(const char *s);    /* 输出一段以 '\0' 结尾的文字 */
} shell_io_t;

typedef struct {
    line_t            line;     /* 拼行用的对象 */
    ringbuf_t        *rx;       /* 从哪个队列取字节 */
    const cmd_t      *cmds;     /* 命令表 */
    size_t            ncmds;
    const shell_io_t *io;       /* 往哪里输出 */
    uint8_t           echo;     /* 1：回显输入并显示提示符 */
} shell_t;

void shell_init(shell_t *sh, ringbuf_t *rx, char *line_mem, size_t line_cap,
                const cmd_t *cmds, size_t ncmds, const shell_io_t *io);
void shell_greet(shell_t *sh);              /* 打印欢迎语和第一个提示符 */
void shell_poll(shell_t *sh);               /* 主循环里反复调用 */
void shell_set_echo(shell_t *sh, int on);

#endif /* SHELL_H */
```

```c
#include "shell.h"

static void say(shell_t *sh, const char *s)
{
    sh->io->write(s);
}

static void prompt(shell_t *sh)
{
    if (sh->echo) {
        say(sh, "> ");
    }
}

/* 一行拼完了：交给 cmd_exec，再按返回值告诉用户结果 */
static void run_line(shell_t *sh)
{
    int rc = cmd_exec(sh->cmds, sh->ncmds, line_text(&sh->line));

    if (rc == -1) {
        say(sh, "unknown command, try: help\r\n");
    } else if (rc == -2) {
        say(sh, "too many words\r\n");
    } else if (rc != 0) {
        say(sh, "command failed\r\n");
    }
}

void shell_init(shell_t *sh, ringbuf_t *rx, char *line_mem, size_t line_cap,
                const cmd_t *cmds, size_t ncmds, const shell_io_t *io)
{
    line_init(&sh->line, line_mem, line_cap);
    sh->rx = rx;
    sh->cmds = cmds;
    sh->ncmds = ncmds;
    sh->io = io;
    sh->echo = 1;
}

void shell_greet(shell_t *sh)
{
    say(sh, "\r\ntype 'help' for commands\r\n");
    prompt(sh);
}

void shell_set_echo(shell_t *sh, int on)
{
    sh->echo = on ? 1 : 0;
}

void shell_poll(shell_t *sh)
{
    uint8_t ch;

    while (ringbuf_get(sh->rx, &ch) == 0) {
        switch (line_feed(&sh->line, ch)) {
        case LINE_ADDED:
            if (sh->echo) {
                char one[2] = { (char)ch, '\0' };
                say(sh, one);
            }
            break;
        case LINE_ERASED:
            if (sh->echo) {
                say(sh, "\b \b");           /* 光标退一格，写个空格盖掉，再退一格 */
            }
            break;
        case LINE_DONE:
            if (sh->echo) {
                say(sh, "\r\n");
            }
            run_line(sh);
            prompt(sh);
            break;
        case LINE_TOO_LONG:
            if (sh->echo) {
                say(sh, "\r\n");
            }
            say(sh, "line too long\r\n");
            prompt(sh);
            break;
        case LINE_NONE:
        default:
            break;
        }
    }
}
```

**组装**。哪些对象存在、谁和谁相连、有哪些命令，只在这一个文件里决定：

```c
#ifndef APP_CLI_H
#define APP_CLI_H

void app_cli_init(void);    /* 建好各个对象并开始接收，在 log_init 之后调用 */
void app_cli_poll(void);    /* 在主循环里反复调用 */

#endif /* APP_CLI_H */
```

```c
#include <string.h>
#include "main.h"
#include "usart.h"
#include "log.h"
#include "cmd.h"
#include "ringbuf.h"
#include "uart_rx.h"
#include "shell.h"
#include "app_cli.h"

#define ARRAY_LEN(a)  (sizeof(a) / sizeof((a)[0]))

/* ---- 在这里把各个对象"组装"起来：整个程序里只有这一个文件知道谁和谁连着 ---- */
static uint8_t          s_rxq_mem[64];     /* 队列的存储空间，容量 64（2 的幂） */
static ringbuf_t     s_rxq;
static uart_rx_t        s_rx;
static char             s_line_mem[64];    /* 行缓冲，一行最多 63 个字符 */
static shell_t          s_shell;

/* shell 的输出接口：文字交给日志层，日志层独占串口发送 */
static void log_write(const char *s)
{
    LOG(LOG_INFO, "%s", s);
}
static const shell_io_t s_io = { log_write };

/* ---- 命令 ---- */
static int cmd_led(int argc, char *argv[]);
static int cmd_echo(int argc, char *argv[]);
static int cmd_stat(int argc, char *argv[]);
static int cmd_help(int argc, char *argv[]);

static const cmd_t g_cmds[] = {
    { "led",  cmd_led,  "led on|off : turn the LED on or off" },
    { "echo", cmd_echo, "echo on|off : switch input echo" },
    { "stat", cmd_stat, "stat : show receive counters" },
    { "help", cmd_help, "help : list all commands" },
};

static int cmd_led(int argc, char *argv[])
{
    int on;

    if (argc != 2) {
        LOG(LOG_INFO, "usage: led on|off\r\n");
        return 1;
    }
    if (strcmp(argv[1], "on") == 0) {
        on = 1;
    } else if (strcmp(argv[1], "off") == 0) {
        on = 0;
    } else {
        LOG(LOG_INFO, "led: unknown argument '%s'\r\n", argv[1]);
        return 1;
    }
    /* 假定高电平点亮，和 4.1 一致；你的板子相反就把两个值对调 */
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, on ? GPIO_PIN_SET : GPIO_PIN_RESET);
    LOG(LOG_INFO, "LED is %s\r\n", on ? "ON" : "OFF");
    return 0;
}

static int cmd_echo(int argc, char *argv[])
{
    if (argc != 2) {
        LOG(LOG_INFO, "usage: echo on|off\r\n");
        return 1;
    }
    if (strcmp(argv[1], "on") == 0) {
        shell_set_echo(&s_shell, 1);
    } else if (strcmp(argv[1], "off") == 0) {
        shell_set_echo(&s_shell, 0);
    } else {
        LOG(LOG_INFO, "echo: unknown argument '%s'\r\n", argv[1]);
        return 1;
    }
    return 0;
}

static int cmd_stat(int argc, char *argv[])
{
    (void)argc;
    (void)argv;
    LOG(LOG_INFO, "rx bytes=%lu, dropped=%lu, events=%lu\r\n",
        (unsigned long)s_rx.bytes, (unsigned long)ringbuf_dropped(&s_rxq),
        (unsigned long)s_rx.events);
    return 0;
}

static int cmd_help(int argc, char *argv[])
{
    (void)argc;
    (void)argv;
    for (size_t i = 0; i < ARRAY_LEN(g_cmds); i++) {
        LOG(LOG_INFO, "  %s\r\n", g_cmds[i].help);
    }
    return 0;
}

/* ---- 对外接口 ---- */
void app_cli_init(void)
{
    (void)ringbuf_init(&s_rxq, s_rxq_mem, sizeof s_rxq_mem);
    uart_rx_init(&s_rx, &huart1, &s_rxq);
    shell_init(&s_shell, &s_rxq, s_line_mem, sizeof s_line_mem,
               g_cmds, ARRAY_LEN(g_cmds), &s_io);
    shell_greet(&s_shell);
    uart_rx_start(&s_rx);
}

void app_cli_poll(void)
{
    shell_poll(&s_shell);
}
```

### 第五步：四个探针

**探针 1：忘了再挂一次。** 把 `uart_rx.c` 回调里 `HAL_UART_Receive_IT(huart, &rx->byte, 1);` 那一行注释掉，构建并下载，打字。

> [!question] 先猜一猜
> 你会看到什么？

> [!success]- 揭晓
> 只有第一个字符会被回显，之后不管敲什么都没反应。`HAL_UART_Receive_IT` 收满一个字节就结束，没人再挂，串口接收就停了。改回来。

**探针 2：退格和超长。** 输入 `led onn`，按一下退格键，再回车，应该正常点亮。再粘贴一大串字符（超过 63 个），回车，应当看到 `line too long`，下一条命令不受影响。

**探针 3：边打字边输出。** 在主循环里再加一个 3 秒一次的输出，用的还是 5.2 的 `soft_due`：

```c
  /* USER CODE BEGIN WHILE */
  uint32_t t_hb = 0;
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    app_cli_poll();
    if (soft_due(&t_hb, 3000u)) {
        LOG(LOG_INFO, "[tick %lu]\r\n", (unsigned long)(g_ms / 1000u));
    }
  }
  /* USER CODE END 3 */
```

> [!question] 先猜一猜
> 你打到一半（比如已经敲了 `led o`），tick 输出插了进来。你接着敲 `n` 回车，命令还能正确执行吗？

> [!success]- 揭晓
> 能。屏幕上的字会被 tick 打断，看起来很乱，但你已经敲的字符都在行编辑器的缓冲里，输出和输入是两条互不相干的路。`LOG` 是非阻塞的，不会卡住你打字。测完删掉。

**探针 4：主循环被卡住。** 在主循环里临时加一句 `HAL_Delay(200);`，一次粘贴 100 个字符。然后输入 `stat`。

> [!question] 先猜一猜
> 篮子容量是 64。100 个字节一口气来，主循环卡着没人取，`stat` 里的 `dropped` 会是多少？

> [!success]- 揭晓
> 100 − 64 = 36。篮子满了，后来的字节被丢掉并计数。100 个字节在 115200 下大约 8.7 ms 就到齐（每字节 10 位，约 87 µs），远小于 200 ms。电脑上我用同一个 `ringbuf_t` 做过验证：不取直接放 100 个，`count` 是 64，`dropped` 是 36。测完把 `HAL_Delay` 删掉。

## 刚才发生了什么

字节的旅程是这样的：串口硬件收满一个字节，触发中断；HAL 调用 `HAL_UART_RxCpltCallback`；回调把字节放进 `ringbuf_t`，再挂上下一轮接收。回到主循环，`shell_poll` 一个个取出字节，交给 `line_feed`。行编辑器告诉 shell 刚发生了什么：加了一个字符、删了一个字符、一行完成、一行超长。shell 据此决定回显什么，一行完成时调用 `cmd_exec`，再按返回值报告结果。

你也许已经发现，这一节里我们一直在做同一件事：**一个东西，一个结构体，加上几个以它的指针为第一个参数的函数**。这叫**对象**。每个对象把自己的状态收在自己里面，外面只通过函数碰它。它带来的好处你已经见到了：

- 两个串口要两个命令行？再建一套对象，不改代码。
- shell 不知道文字最后去了串口还是屏幕，它只调用别人给它的 `write`。这叫**依赖注入**：硬件相关的部分从外面传进来。我在电脑上测 shell 时，传进去的 `write` 是打印到屏幕，换到板子上，传进去的是 `LOG`，shell 本身一个字没改。
- 6.2 要换一种接收方式，只需整个替换 `uart_rx.h` 和 `uart_rx.c`，shell、行编辑器、命令表都不用动。

你早就在用对象了。`UART_HandleTypeDef huart1` 就是一个对象，它记着这个串口的一切状态；`HAL_UART_Transmit(&huart1, ...)` 就是它的方法，第一个参数是对象指针。只是以前没人告诉你。这种写法在 C 里怎么做得更彻底，放在[[【原理】C语言里的面向对象|C语言里的面向对象]]里。

有一处不得不让步。1.9 定义的命令函数签名是 `int fn(int argc, char *argv[])`，没有"上下文"参数，所以 `cmd_echo` 想改 shell 的回显开关，只能通过 `app_cli.c` 里的文件级 `static` 对象 `s_shell`。这是组装文件的私有数据，不对外暴露。好的接口通常会多带一个 `void *ctx`，就像 `qsort` 的某些变体一样，细节也放在上面那个分支里。

接收字节的队列用的是[[【原理】环形缓冲区|环形缓冲区]]：生产者只改 `head`，消费者只改 `tail`，所以中断和主循环之间不需要关中断。为什么这样是安全的，5.4 已经讲过。

## 记住这几条

1. 串口收到的是字节流，不是句子。"一行"是你自己用回车拼出来的。
2. `HAL_UART_Receive_IT` 只管一轮，回调里必须再挂一次。
3. 回调里只把字节放进队列，拼行、执行命令、输出，全部留给主循环。
4. 中断与主循环之间用单生产者、单消费者的环形缓冲，满了就丢并计数，别阻塞。
5. 一个东西一个对象：状态放结构体，函数第一个参数是对象指针。需要第二份，就再建一个实例。
6. 硬件相关的部分（往哪输出、从哪取字节）从外面传进来，模块本身不认识具体硬件。
7. `HAL_UART_RxCpltCallback` 和 `HAL_UART_ErrorCallback` 全工程各只能写一份；`HAL_UART_TxCpltCallback` 归日志层，不要再写。
8. `cmd.h` / `cmd.c` 原样复用。加命令只做两件事：写函数，在命令表里加一行。

## 练习

1. 输入 `led on` 回车，再输入 `echo off`，然后继续输入 `led off`。看看屏幕上发生了什么变化，再用 `echo on` 恢复。（复现）
2. 加一个 `uptime` 命令，打印 `up N s`（N 是 `g_ms / 1000`）。要改几个地方？（改造）
3. 篮子容量从 64 改成 128，探针 4 的 100 字节还会丢吗？`stat` 里的 `dropped` 是多少？（预测）

> [!success]- 提示与答案方向
> 1. `echo off` 之后你敲的字符不再回显，提示符也不再出现，但命令照常执行，输出还在。
> 2. 两个：写 `cmd_uptime` 函数，在 `g_cmds` 表里加一行。别忘了在 `cmd_help` 之前声明它。函数里用 `LOG(LOG_INFO, "up %lu s\r\n", (unsigned long)(g_ms / 1000u));`。
> 3. 不会丢，`dropped` 是 0。100 个字节小于 128 的容量。注意 `ringbuf_init` 要求容量是 2 的幂，所以 128 可以，100 不行（会返回 -1）。

回到开头那道题：板子收到的是 7 个字节，不是一句话。现在你知道，"一句话"是怎么在主循环里，被你一个字节一个字节拼出来的。
